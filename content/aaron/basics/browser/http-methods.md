# HTTP 请求方法有哪些，GET 和 POST 有什么区别

## 核心回答

常见的方法有 GET 读取资源，HEAD 只取响应头，POST 提交处理，PUT 创建或整体替换目标资源，PATCH 部分修改，DELETE 删除，OPTIONS 查询允许的通信选项；另外还有 CONNECT 建立隧道、TRACE 做诊断回显。

GET 和 POST 最主要的区别是语义。GET 预期只是读取，不应该用来触发业务状态变更，而且重复请求在语义上是幂等的；POST 通常是提交数据让服务端处理，重复提交可能重复创建订单，所以经常要额外做幂等控制。

使用上，GET 参数一般放在 URL 查询串里，POST 数据通常放请求体。URL 可能进入历史记录和日志，但 POST 也不是天然加密，两者保护传输都要依靠 HTTPS。长度上要看浏览器、服务器和代理限制，不能背成 GET 固定多少字节、POST 完全无限制。

【GET 更常见于缓存，POST 在满足显式缓存条件时也可以被缓存，只是实际支持和使用场景不同。HTTP 所说的“安全方法”表示预期不改变服务端状态，不等于信息不会泄露；POST 也可以同时带 URL 查询参数。】

### GET 和 POST 的区别

| 对比 | GET | POST |
| --- | --- | --- |
| 标准语义 | 获取目标资源的当前表示 | 让目标资源按自身语义处理请求内容 |
| 安全方法 | 是，语义上应只读 | 否，通常可产生状态变更 |
| 幂等性 | 是 | 规范不保证，连续提交两次可能创建两笔数据 |
| 缓存 | 响应默认可缓存，仍受缓存首部限制 | 规范允许在显式条件下缓存，但实际支持较少 |
| 请求数据 | 通常放 URL query；不应依赖 GET body | 通常放 body，也可同时有 query |
| 常见用途 | 查询、获取页面/资源 | 提交表单、创建资源、执行复杂处理 |

#### 三个高频误区

##### POST 一定比 GET 安全吗

不是。GET query 更容易出现在浏览器历史、日志、截图和部分 Referer 场景里，不适合密码等敏感数据；但 POST body 也不是加密的，依然可被客户端、代理和服务器日志看到。传输机密性依靠 **HTTPS/TLS**，业务安全还要依靠认证、授权、CSRF 防护和输入校验。

##### GET 参数小、POST 参数大吗

HTTP 语义没有给 GET/POST 定一个统一的业务大小阈值。GET 通常受浏览器、服务器和代理对 URL 长度的实现限制；POST body 也会被网关和服务器限制。大文件还应考虑分片上传、超时和断点续传。

##### POST 不能缓存吗

不严谨。RFC 9110 定义了 POST 响应在包含显式新鲜度信息和匹配的 `Content-Location` 时可缓存，只是通用缓存的实际支持远不如 GET 普遍。

### 幂等性怎么理解

幂等表示对服务器发送一次和发送多次相同请求，**客户端要求的最终效果相同**。

- `GET /users/1`：查询多次不应改变资源。
- `PUT /users/1`：用同一内容整体替换多次，最终状态一样。
- `DELETE /users/1`：第二次可以返回 404，但“用户已删除”的最终状态相同。
- `POST /orders`：重复请求可能创建多个订单，默认不幂等。

支付、下单等 POST 场景可通过**幂等键**和服务端唯一约束，把业务设计成可安全重试。
