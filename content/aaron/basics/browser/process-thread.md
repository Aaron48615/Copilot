# 进程和线程有什么区别？

## 核心回答

**进程**是程序的一次运行实例，操作系统用它来做资源和隔离管理，每个进程通常拥有独立的虚拟地址空间。**线程**是进程内的执行流，也是 CPU 调度的基本单位。

同一进程内的线程共享代码、全局数据、堆和打开的资源，但每个线程有自己的调用栈、寄存器状态和程序计数器。进程之间隔离更强，通信需要 IPC；线程间共享数据更方便，但需要锁等同步机制避免竞态。

### 核心区别

| 对比 | 进程 | 线程 |
| --- | --- | --- |
| 定位 | 运行中的程序实例、资源隔离边界 | 进程内的执行流 |
| 地址空间 | 通常彼此独立 | 同进程线程共享 |
| 私有内容 | 进程地址空间和系统资源表 | 调用栈、寄存器、线程局部数据 |
| 通信 | 管道、套接字、消息队列、共享内存等 IPC | 可直接访问共享内存 |
| 隔离性 | 强，单个进程崩溃通常不会直接破坏其他进程内存 | 弱，一个线程错误可导致整个进程崩溃 |
| 创建/切换成本 | 通常更高 | 通常更低，但不能绝对化 |
| 典型问题 | IPC 、资源占用、孤儿/僵尸进程 | 竞态条件、死锁、可见性问题 |

> [!note]
> 教材里常说“进程是资源分配的基本单位，线程是 CPU 调度的基本单位”。这是很好的面试概括，具体实现依操作系统而定。

### 为什么需要多进程和多线程

#### 多进程的价值

- **故障隔离**：一个进程崩溃，其他进程可以继续运行。
- **安全隔离**：可对不同进程设置不同权限和沙箱。
- **利用多核**：多个进程可同时运行在不同 CPU 核心上。

代价是内存开销更大，IPC 和序列化也更复杂。

#### 多线程的价值

- 在同一进程中并行或并发处理多件事。
- 共享数据成本低，适合任务分工。
- 将 I/O、解码、计算等任务与交互线程分开，提高响应性。

代价是共享内存会带来竞态条件，需要互斥锁、信号量、原子操作等同步手段。

### 并发和并行的区别

- **并发**：一段时间内交替推进多个任务，单核也能实现。
- **并行**：同一时刻真的有多个任务在不同核心上执行。

事件循环能让单个 JavaScript 主线程高效处理许多 I/O 任务，这是**并发**，不等于这些 JavaScript 回调正在同一时刻并行执行。

### 进程间为什么不能直接读取对方内存

进程通常有独立的虚拟地址空间和权限边界，这也是安全隔离与故障隔离的基础。需要通过内核提供的 IPC 机制交换数据。

### 线程为什么会有死锁

多个线程各自持有一部分资源，又相互等待对方释放资源，就可能形成循环等待。常见预防方法是固定加锁顺序、缩小锁范围、避免锁嵌套或设置超时。

### 多线程一定更快吗

不一定。线程创建、上下文切换、数据传递、锁竞争都有成本。任务太小、共享数据太多或 CPU 核心不足时，多线程反而可能更慢。
