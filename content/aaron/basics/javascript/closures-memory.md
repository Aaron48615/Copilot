# 闭包是什么，和垃圾回收、内存泄漏有什么关系

## 核心回答

闭包可以理解成函数连同它能访问的外层词法环境。比较典型的情况是，外层函数已经执行完了，返回的内部函数仍然能访问外层变量。比如计数器把 count 放在函数内部，外面只能通过返回的方法增加它，就能保存状态，也避免随便从外面修改。

```js
function createCounter() {
  let count = 0;
  return () => ++count;
}
const next = createCounter();
next(); // 1
next(); // 2
```

闭包本身不是内存泄漏。真正要看的是，这些被引用的数据是否还有用。现代垃圾回收主要根据可达性判断，从根对象等出发还能找到的数据会保留，已经不可达的对象就可以回收。历史上的引用计数只看引用数量，会遇到两个对象互相引用而无法归零的问题；基于可达性的标记清除可以处理这种不可达的循环引用。

所以我会重点清理不再需要的定时器、事件订阅、缓存和对 DOM 的长期引用。比如页面已经离开，定时器却还通过闭包引用一大份列表，这才是应该检查的问题；不需要为了避免泄漏就尽量不用闭包。

【内部函数不一定非要被 return 才构成闭包，事件回调也会保留外层环境。清理应该解除不再需要的引用，普通局部变量不能靠 delete 随意删除。】

### 闭包与调用栈的关系

函数返回后，其栈帧会退出，但被闭包引用的词法环境仍可继续存活。具体如何存储由引擎决定，不能理解成“闭包把整个栈永久保留下来”。

### 常见内存泄漏来源

- 不再需要但仍被全局变量或缓存引用的对象；
- 没有清理的定时器、事件监听器和订阅；
- 已从页面移除但仍被 JavaScript 引用的 DOM；
- 无上限增长的 Map、数组和消息队列；
- 闭包意外引用了体积很大的对象。

垃圾回收只能回收“不可达”对象。业务上已经无用但仍可达的数据，在 GC 看来仍是有效对象。
