# 前端请求并发太多时怎么控制？

## 核心回答

请求多的话，先分清是任务本来就多，还是同一件事被重复触发了。如果确实有一批任务都需要做，比如批量上传文件，就可以设一个同时执行的数量，剩下的先排队，有一个结束了再补下一个。

这里队列里要放“发请求的函数”，不能先把所有请求都发出去，再把 Promise 塞进去。Promise.all 主要是等结果，如果前面 map 的时候已经调用了请求函数，并发早就开始了。

成功和失败都要把执行名额释放出来，结果最好按原来的任务下标保存，避免谁先完成就把顺序打乱。我更偏向先用一个较小的并发数，结合接口和文件大小看效果，再决定要不要调大。请求一起发出去不一定更快，如果后端有明确限制，就按它的要求来。
