# OSI 七层网络模型各层负责什么，和 TCP/IP 有什么关系？

## 核心回答

OSI 把网络通信抽象成七层，自下而上是：**物理层、数据链路层、网络层、传输层、会话层、表示层、应用层**，口诀是“物数网传会表应”。

下层为上层提供服务。发送数据时逐层封装，接收时逐层解封装。OSI 主要是解释网络职责的参考模型；现实互联网工程更多使用 TCP/IP 分层，不能认为每个协议都严格、唯一地属于 OSI 某一层。

### 七层职责与常见例子

| 层级 | 名称 | 核心职责 | 数据单元 | 常见例子 |
| --- | --- | --- | --- | --- |
| 7 | 应用层 | 为应用提供网络服务 | 数据 | HTTP、DNS、FTP、SMTP |
| 6 | 表示层 | 数据编码、压缩、加密与格式转换 | 数据 | JSON 编码、字符编码、压缩；TLS 常被用于类比 |
| 5 | 会话层 | 建立、维护、恢复和终止会话 | 数据 | 会话检查点、RPC 会话等概念 |
| 4 | 传输层 | 进程到进程通信，使用端口标识应用 | TCP 段 / UDP 数据报 | TCP、UDP |
| 3 | 网络层 | 跨网络寻址、路由和分组转发 | 数据包 | IPv4、IPv6、ICMP；路由器工作于此 |
| 2 | 数据链路层 | 同一链路上的成帧、MAC 寻址和差错检测 | 数据帧 | Ethernet、Wi-Fi、PPP、VLAN；交换机常工作于此 |
| 1 | 物理层 | 在介质上传输电、光或无线信号表示的比特 | 比特 | 网线、光纤、无线信号、中继器 |

会话层、表示层在现代 TCP/IP 应用中通常不会作为独立的软件层出现，其能力往往由应用协议、库或 TLS 等组件共同承担。因此面试时应说明“这是功能映射”，不要机械地给每种技术强行指定唯一 OSI 层级。

### OSI 与 TCP/IP 模型的对应关系

| OSI 七层 | TCP/IP 常见四层模型 |
| --- | --- |
| 应用层、表示层、会话层 | 应用层 |
| 传输层 | 传输层 |
| 网络层 | 网际层 |
| 数据链路层、物理层 | 网络接口层 |

TCP/IP 模型更贴近互联网的实际协议栈，OSI 更适合用于定位问题和解释各层职责。

### 封装与解封装

浏览器发送一条 HTTP 请求时，可以把封装过程简化为：

```text
应用数据
  ↓ 加上传输层首部
TCP 段 / UDP 数据报
  ↓ 加上 IP 首部
IP 数据包
  ↓ 加上链路层首部和尾部
数据帧
  ↓ 转换为信号
比特流
```

接收端按相反方向解封装。每层主要读取自己负责的首部信息，再把上层数据交给上一层处理。

### IP 地址、MAC 地址、端口号

| 标识 | 主要解决的问题 | 作用范围 |
| --- | --- | --- |
| MAC 地址 | 当前链路上的下一跳设备是谁 | 本地链路 |
| IP 地址 | 数据最终要到哪台主机或网络接口 | 跨网络路由 |
| 端口号 | 主机上的哪个应用进程接收数据 | 传输层端点 |

一次跨网传输中，目标 IP 通常保持为最终主机地址，但每经过一个新的链路，数据帧的源、目标 MAC 会围绕当前跳重新封装。

ARP 用于 IPv4 网络中根据 IP 地址解析链路层地址。它处于网际层与链路层的边界，资料中的分层归类可能不同，面试时说清职责比死记层号更重要。IPv6 使用 Neighbor Discovery，而不是 ARP。

### 为什么需要分层？

分层把复杂通信拆成职责清晰的模块，使上下层可以通过稳定接口协作，便于独立演进、跨厂商实现和故障定位。代价是额外封装以及跨层优化受到限制。
