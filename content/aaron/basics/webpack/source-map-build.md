# source map、构建缓存和可复现构建怎么理解？

## 核心回答

source map 是帮我们把转换、压缩后的代码位置对应回源码。线上报错如果只有压缩文件里的行列号，找起来很费劲，有匹配这个版本的 map 就更容易定位，不能拿另一个版本的映射来对。

构建缓存主要是省时间，之前处理过、输入没变化的东西可以复用。但依赖、配置或者工具版本变了，对应缓存也要更新。可复现构建则是希望同样的源码和构建条件能得到一致结果，所以锁文件和工具环境都得管理好。

所以这三件事的作用分别是方便排错、减少等待，以及让构建结果可以确认。生产 map 是否公开要按项目要求来，写了 hidden 也不等于文件就不能被下载；前端产物里本来就不应该放密钥。
