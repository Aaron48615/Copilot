# 追问：用户连续发送两条消息，或者离开页面，流式请求怎么办？

## 核心回答

每次发送都会创建独立的助手占位消息，用消息 ID 更新，内容不会混到一个气泡里。但现在发送按钮只看输入是否为空，没有生成中的限制，也没有 AbortController，后发请求可能先结束，带过去的历史也可能缺上一条还没生成完的回答。

离开页面也没主动取消读取。要严格一问一答，我会在生成中限制发送、加停止按钮；要允许并发，就保存独立上下文、请求 ID 和控制器。

【浏览器取消请求后，服务端是否停止生成还得接口配合，不能默认模型计算也停了。】

## 回答要点

- 每次发送都会创建独立的助手占位消息，用消息 ID 更新，内容不会混到一个气泡里。
- 离开页面也没主动取消读取。要严格一问一答，我会在生成中限制发送、加停止按钮；要允许并发，就保存独立上下文、请求 ID 和控制器。
- 浏览器取消请求后，服务端是否停止生成还得接口配合，不能默认模型计算也停了。

## 面试官可能追问

- 消息气泡分开为什么仍可能缺少完整上下文？
- 浏览器取消后怎样确认服务端也停止生成？
