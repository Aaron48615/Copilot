# 追问：前端已经做了防抖，为什么服务端还要限流？内存 Map 能管住所有请求吗？

## 核心回答

前端防抖只能减少正常用户连续输入的请求，别人绕过页面直接调接口，它就管不到，所以服务端还得限流。现在按 IP 统计，一分钟默认 10 次、一小时 50 次，超过就返回 429 和 Retry-After。

计数放在内存 Map 里，只对当前实例有效，多实例不共享，重启也会丢。后面要控制全站用量，就得用共享存储和原子计数，再结合用户、IP 和总预算限制。

【计数在完整读完请求体、调用模型之前登记，避免同一实例的并发请求都没算上对方。Map 最多记录 10000 个 IP，满了先清过期项，仍然满就拒绝新 IP，防止内存一直增长。】

## 回答要点

- 前端防抖只能减少正常用户连续输入的请求，别人绕过页面直接调接口，它就管不到，所以服务端还得限流。
- 计数放在内存 Map 里，只对当前实例有效，多实例不共享，重启也会丢。
- 计数在完整读完请求体、调用模型之前登记，避免同一实例的并发请求都没算上对方。
