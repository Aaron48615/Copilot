# 追问：SKU 为什么用 Set 收集规格？把规格拼成字符串匹配有什么问题？

## 核心回答

每个 SKU 是一组完整规格，比如“颜色:黑;尺码:M”。我先拆开属性，用 Set 去掉重复项，得到页面上颜色、尺码这些选项。不过 Set 只负责去重，有黑色、有 M 码，不代表一定存在黑色 M 码这一组。

之前拼字符串匹配会受顺序影响，现在已经改成按属性键值比较，并检查库存。用户选到不存在或者没库存的组合，会清空当前 SKU 并提示，不继续保留上一次的结果。

后面还能完善详情页的选项禁用，根据已经选中的属性，提前标出哪些组合不能选。对比页目前直接列完整 SKU，可以禁用缺货项；详情页逐个属性选择的交互还可以继续改。

【比如“颜色:黑;尺码:M”和“尺码:M;颜色:黑”含义一样，应该匹配到同一组规格。页面匹配正确以后，最终价格和库存仍然需要服务端校验。】

## 回答要点

- 每个 SKU 是一组完整规格，比如“颜色:黑;尺码:M”。
- 之前拼字符串匹配会受顺序影响，现在已经改成按属性键值比较，并检查库存。
- 后面还能完善详情页的选项禁用，根据已经选中的属性，提前标出哪些组合不能选。
