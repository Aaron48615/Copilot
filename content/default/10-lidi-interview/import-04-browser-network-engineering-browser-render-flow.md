# 浏览器是怎么渲染页面的？

## 核心回答

1. 浏览器收到 HTML 后可以边收边解析，逐步建 DOM，同时发现样式、脚本、图片这些资源。CSS 会解析成样式规则，再结合 DOM 算出元素最终样式。不是必须等所有图片下完才开始显示页面。

2. 接着做布局，算盒子的尺寸和位置，再生成绘制指令、栅格化、合成到屏幕上。面试里常概括成渲染树、布局、绘制、合成。`display:none` 的子树不参与布局，`visibility:hidden` 还占位置，看不见不等于节点都被删了。

3. 普通解析器插进去的经典脚本会暂停 HTML 解析，外部脚本还可能等下载和相关样式表。CSS 通常不直接挡住 HTML 解析，但会影响渲染，也会影响依赖样式的脚本执行。关键 CSS 和脚本什么时候被发现，都会拖到首屏。

4. 优化先找关键资源和主线程长任务。非关键脚本适当往后放，首屏图片尽早发现，动画尽量少改布局。`transform` 是不是只走合成，得看实际条件，最后用性能录制确认。概念图画的那些阶段，浏览器不是每次都完整重跑一遍。

5. 比如同一页只改了按钮颜色，浏览器通常可以跳过布局，不必重新解析整份文档。这次操作实际让哪些阶段失效，就减哪些不必要的更新。页面有变化，不等于整个渲染流程从头来过。

## 追问：CSS 不直接阻塞 DOM 解析，为什么仍会影响脚本？

1. 脚本可能去读计算样式或元素尺寸，比如 `getComputedStyle` 依赖前面的样式表。浏览器得遵守脚本能观察到的顺序，所以某些会挡住解析器的脚本，会等前面相关样式表，HTML 解析也就跟着停。

2. 这跟图片加载不是一回事。普通图片还没下完，一般不挡住后面 HTML 的解析；样式表没完成，却可能拖住脚本和绘制。Network 里资源大不大，说明不了它对页面的影响。

3. 排查看样式请求何时结束、脚本何时执行、主文档解析有没有停顿。必要时缩短关键 CSS，拿掉不必要的阻塞脚本。调顺序之后还得确认，脚本不会在所需 DOM 或样式还没准备好时就跑。

## 追问：display:none 和 visibility:hidden 对渲染有什么区别？

1. `display:none` 会让元素和相关子树不生成参与布局的盒子，周围内容会重新占空间。`visibility:hidden` 一般把盒子的尺寸和位置留着，只是不显示内容。藏一个按钮时，要不要留下空位，会影响选哪个。

2. 两者都不等于元素从 DOM 里删掉了，脚本照样可能找到节点。里面的图片会不会下载，也不能单靠 CSS 隐藏来保证。浏览器可能在算样式之前就已经发现并请求资源。要延迟加载，得控制实际怎么加载。

3. 切换 `display` 可能改周围布局，拿它做频繁动画通常不合适。淡出可以考虑 `opacity`，但透明元素仍可能接到事件和焦点，交互和无障碍状态还得一起处理。
