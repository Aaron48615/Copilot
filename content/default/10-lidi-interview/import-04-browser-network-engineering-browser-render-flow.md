# 浏览器是怎么渲染页面的？

## 核心回答

1. 浏览器收到 HTML 后可以边接收边解析，逐步建立 DOM，并发现样式、脚本和图片等资源。CSS 会被解析为样式规则，再结合 DOM 计算元素的最终样式，不是必须等所有图片下载完才开始显示页面。

2. 随后进行布局，计算盒子的尺寸和位置，再生成绘制指令、栅格化并合成显示。面试里常概括成渲染树、布局、绘制和合成；display:none 的子树不参与布局，而 visibility:hidden 仍占位置，不能简单说所有不可见节点都被删除。

3. 普通解析器插入的经典脚本会暂停 HTML 解析，外部脚本还可能等待下载和相关样式表。CSS 通常不直接阻塞 HTML 解析，但会影响渲染和依赖样式的脚本执行，所以关键 CSS 和脚本的发现时机都会影响首屏。

4. 优化时我会先找关键资源和主线程长任务。非关键脚本适当延后，首屏图片尽早发现，动画尽量减少布局变化；transform 是否只需合成要看实际条件，最终用性能录制确认，不能把概念图理解成浏览器每次都完整重跑所有阶段。

5. 例如同一页只有按钮颜色变化，浏览器通常可以跳过布局，不必重新解析整份文档。理解这点后，我会先看这次操作实际使哪些阶段失效，再减少不必要更新，而不是每次看到页面变化都说整个渲染流程从头执行。

## 追问：CSS 不直接阻塞 DOM 解析，为什么仍会影响脚本？

1. 脚本可能读取计算样式或元素尺寸，例如 getComputedStyle 依赖之前的样式表。浏览器需要遵守脚本可观察到的顺序，因此某些解析器阻塞脚本会等待前面的相关样式表，间接让 HTML 解析停下来。

2. 我会把它和图片加载区分开。普通图片尚未完成一般不阻止解析后面的 HTML，但样式表未完成可能延迟脚本和绘制，所以不能仅按 Network 里资源大小判断它对页面的影响。

3. 排查时看样式请求何时结束、脚本何时执行，以及主文档解析是否停顿。必要时缩短关键 CSS、去掉不必要的阻塞脚本，并确保调整顺序后脚本不会在所需 DOM 或样式尚未准备好时运行。

## 追问：display:none 和 visibility:hidden 对渲染有什么区别？

1. display:none 会使元素及相关子树不生成参与布局的盒子，周围内容会重新占据空间。visibility:hidden 一般保留盒子的尺寸和位置，只是不显示内容，所以隐藏一个按钮时是否需要留下位置会影响选择。

2. 两者都不等于元素从 DOM 中删除，脚本仍然可能查找到节点。是否下载其中的图片也不能单靠 CSS 隐藏来保证，浏览器可能在样式计算之前已经发现并请求资源，需要延迟加载时应控制实际加载方式。

3. 切换 display 可能改变周围布局，频繁做动画通常不合适。我会根据交互目的选方案，例如淡出可以考虑 opacity，但透明元素仍可能接收事件和焦点，还要同时处理交互及无障碍状态。
