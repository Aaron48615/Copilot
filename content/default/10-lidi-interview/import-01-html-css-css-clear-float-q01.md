# clear: both 是怎么起作用的？

## 核心回答

1. `clear: both` 的作用是让当前适用的块盒子避开前面左右两侧的相关浮动，必要时增加清除间隙，使它排到浮动下方。它不是把前面的元素恢复到正常流，也不是把 float 属性取消，前面的文字环绕规则仍然存在。

2. 例如先有一张向左浮动的图片，后面跟一个普通段落，段落文字可能排在图片旁边。给后面的块设置 clear: both 后，这个块会从浮动下方开始；如果只需要避开左浮动，可以用 clear: left，取决于页面实际布局。

3. clearfix 就利用了这个规则。在父元素末尾生成一个正常流的空伪元素，设置块显示和 clear: both，即使它本身没有内容，也能通过位置把父元素的自动高度延伸到浮动底部。伪元素需要有 content，不能只写 clear 而没有生成盒子。

4. 它也有作用范围，主要处理同一块级格式化上下文中相关的前置浮动，不会清除页面上任意位置的浮动。要排查无效，我会先看清除元素有没有正常生成、是否放在浮动之后，以及双方的布局上下文，再考虑是否直接用 flow-root 更合适。

5. 另外，绝对定位内容并不是浮动，不能用清除浮动顺便包含它。父容器里若同时存在两类脱离正常流的内容，我会分别确认谁导致高度不足，再决定恢复正常布局或安排明确尺寸，避免对不相关机制反复加清除规则。

## 追问：clear: both 会把所有浮动列都换到下一行吗？

1. 不会，它作用在声明所在的盒子上，不会回头重新排列前面每个浮动元素。比如两张浮动图片后面有一个带 clear 的标题，通常是标题从两张图片底部以下开始，图片彼此仍然维持原来的浮动位置。

2. 如果把 clear 加在某个浮动项本身，它会影响这个浮动项相对前面浮动的位置，可能让它开启新的一排。但这仍是对该元素的约束，不是给整个容器执行一个全局“清空浮动”操作。

3. 我会根据想换行的是标题、某一列还是后续整个内容区选择位置。先画出元素顺序和预期排版再加属性，比把 clear 同时塞到父元素和每个子元素更容易定位问题，也能避免多余的大块空白。

## 追问：clearfix 的空伪元素为什么能撑高父容器？

1. 父容器自动高度会考虑正常流内容的布局位置，清除伪元素虽然高度可以为零，但它已经被推到浮动底部。父容器为了包含这个正常流盒子，就会延伸到相应位置，因此不要求伪元素有一段可见文字。

2. 这里需要它真的生成并参与合适的块布局，所以通常使用空 content 和 block。若伪元素被设置成 absolute，或根本没有 content，原本依赖的正常流位置就不存在，单独留下 clear 不足以完成包含。

3. 检查时可以临时给伪元素加细边框观察它的位置，再恢复空装饰状态。也要留意已有 after 是否已经承担其他视觉用途，不能直接覆盖；这种情况下用 flow-root 可能比挤占同一个伪元素更自然。
