# clear: both 是怎么起作用的？

## 核心回答

1. `clear: both` 让当前这个块盒子躲开前面左右两侧相关的浮动，必要时加一段清除间隙，让它排到浮动下面。它不会把前面的元素拽回正常流，也不会把 `float` 属性取消，前面的文字环绕还在。

2. 比如先有一张向左浮动的图片，后面跟一个普通段落，文字可能排在图片旁边。给后面的块设 `clear: both`，这个块从浮动下方开始。只要躲开左浮动，用 `clear: left` 就行，看页面实际布局。

3. clearfix 就用这条规则。在父元素末尾生成一个正常流的空伪元素，设成块显示再 `clear: both`。它自己没有内容，位置也能把父元素的自动高度拉到浮动底部。伪元素需要有 `content`，只写 `clear`、不生成盒子不够。

4. 作用范围也有限，主要处理同一块级格式化上下文里、排在前面的相关浮动，清不掉页面上任意位置的浮动。无效时先看清除元素有没有正常生成、是不是放在浮动后面、双方的布局上下文，再考虑直接用 `flow-root` 更合适。

5. 绝对定位内容不是浮动，不能靠清除浮动顺便把它包住。父容器里两类脱离正常流的内容同时存在，分别确认谁导致高度不够，再决定恢复正常布局还是给明确尺寸，别对不相关的机制反复加清除规则。

## 追问：clear: both 会把所有浮动列都换到下一行吗？

1. 不会。它作用在声明所在的那个盒子上，不会回头重排前面每个浮动元素。两张浮动图片后面有一个带 `clear` 的标题，通常是标题从两张图片底部以下开始，图片彼此还是原来的浮动位置。

2. 把 `clear` 加在某个浮动项自己身上，会影响这个浮动项相对前面浮动的位置，可能让它开新的一排。这仍是对该元素的约束，不是给整个容器执行一次全局「清空浮动」。

3. 想换行的是标题、某一列，还是后面整块内容区，位置不一样。先画出元素顺序和预期排版再加属性，比把 `clear` 同时塞进父元素和每个子元素更容易定位问题，也不容易多出大块空白。

## 追问：clearfix 的空伪元素为什么能撑高父容器？

1. 父容器自动高度会考虑正常流内容排到哪。清除伪元素高度可以是零，但它已经被推到浮动底部。父容器要包住这个正常流盒子，就会伸到那个位置，所以不要求伪元素有一段看得见的字。

2. 它得真的生成，并且参与合适的块布局，所以通常用空 `content` 和 `display: block`。伪元素设成 `absolute`，或者根本没有 `content`，依赖的正常流位置就不在了，单独留下 `clear` 包不住。

3. 检查时可以临时给伪元素加细边框看它在哪，再恢复成空装饰。也要留意已有的 `::after` 是不是已经在做别的视觉用途，别直接盖掉。这种情况用 `flow-root`，往往比挤同一个伪元素自然。
