# 什么时候不该继续加 CSS？

## 核心回答

1. 一个布局要越来越多负 margin、绝对定位和特殊断点才能对齐时，先停下来看原来的布局假设。这些属性本身不是禁用的。但改一个标题长度就要修另外三个位置，往往说明父子结构、尺寸来源或布局模型没有把真实关系写出来。

2. 先画清楚哪些元素该一起动、谁提供宽高、哪些内容允许换行。比如卡片底部按钮该随正文高度自然下移，却靠 `absolute` 和固定 `top` 放，继续加媒体查询只能适配几个样例，长文案和错误提示还是会把假设打破。

3. 接着用现有结构做最小调整。卡片用纵向 Flex，由内容撑开，操作区放底部；需要跨行列对齐时评估 Grid。结构本身把相关内容拆到不同父级，就局部调 DOM，但语义、阅读顺序和组件职责得留着，别随手重写整页。

4. 改完删掉被替代的补偿规则，用短内容、长内容、窄宽度和字号放大验证。样式文件长了，不必宣布必须重构。先定位具体哪段关系不稳，再做能解释的最小修复。继续覆盖，或者为了整洁大范围改写，都不如这个有依据。

## 追问：怎样判断负 margin 是合理设计还是临时补丁？

1. 先看它是不是在表达明确的视觉关系。头像有意跨过封面边界，负间距可以很直观。如果只是为了抵消另一处没搞懂的 padding，或者每个断点都要换一组数字，通常得回头确认真正的尺寸来源。

2. 改文字长度、图片比例和容器宽度，看关系还成不成立。合理的重叠通常有清楚边界，不会把正文或操作入口盖住。补丁则常依赖某一张截图，内容一变就冒出新的空隙或重叠。

3. 确认是补丁，就把留白、对齐和重叠分别交给合适的规则，不再需要的抵消值删掉。看见负数别全部清掉，旧页面也可能有合理设计。修复时把原本有意表达的视觉关系留住。

## 追问：重构 DOM 时怎么避免破坏键盘和阅读顺序？

1. 按用户理解页面的顺序安排真实 DOM，比如标题、说明、输入和操作依次出现，再用布局完成视觉排列。别先随便放节点，再靠 `order` 或绝对定位去拼截图。键盘和辅助技术常常仍按文档顺序访问。

2. 结构调整以后，查 `label` 关联、按钮类型、标题层级和事件依赖还在不在。父子关系一变，选择器和事件委托可能受影响。外观一样，点击、提交或读屏名称也可能变，得跟着具体组件行为一起验。

3. 验证时不用鼠标完成主要操作，再看窄屏视觉顺序和 DOM 是否还合理一致。桌面为了布局把操作区挪到很远，得重新评估有没有必要。少几条 CSS，却增加理解和导航成本，不划算。
