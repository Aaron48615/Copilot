# 什么时候不该继续加 CSS？

## 核心回答

1. 当一个布局需要越来越多负 margin、绝对定位和特殊断点才能对齐时，我会先停下检查原来的布局假设。它们本身不是禁用属性，但如果改一个标题长度就要修另外三个位置，往往说明父子结构、尺寸来源或布局模型没有表达真实关系。

2. 我会先画清楚哪些元素应该一起移动、谁提供宽高、哪些内容允许换行。比如卡片底部按钮应该随正文高度自然下移，却靠 absolute 和固定 top 放置，继续加媒体查询只能适配几个样例，长文案和错误提示仍会打破假设。

3. 接着用现有结构做最小调整，例如让卡片用纵向 Flex，由内容撑开并把操作区放在底部；需要跨行列对齐时评估 Grid。若结构本身把相关内容分散在不同父级，就考虑局部调整 DOM，但要保留语义、阅读顺序和组件职责，不是随手重写整页。

4. 修改后我会删除被替代的补偿规则，并用短内容、长内容、窄宽度和字号放大验证。没有必要因为样式文件长就宣布必须重构，先定位具体不稳定关系，再做能解释的最小修复；这比继续覆盖，也比为了整洁大范围改写更有依据。

## 追问：怎样判断负 margin 是合理设计还是临时补丁？

1. 先看它是否表达明确的视觉关系，例如头像有意跨过封面边界，负间距可以很直观。如果只是为了抵消另一处不理解的 padding，或者每个断点需要换一组数字，通常需要回头确认真正的尺寸来源。

2. 我会改变文字长度、图片比例和容器宽度观察关系是否仍成立。合理的重叠通常有清楚边界，不会让正文或操作入口被覆盖；补丁则常依赖某一张截图，一旦内容变化就出现新的空隙或重叠。

3. 如果确认是补丁，就把留白、对齐和重叠分别交给合适的规则，并删除不再需要的抵消值。不能仅因为看到负数就全部清理，旧页面也可能有合理设计，修复应保留原本有意表达的视觉关系。

## 追问：重构 DOM 时怎么避免破坏键盘和阅读顺序？

1. 我会先按用户理解页面的顺序安排真实 DOM，例如标题、说明、输入和操作依次出现，再用布局完成视觉排列。不要先随意放节点，再通过 order 或绝对定位拼出截图，因为键盘与辅助技术常仍按文档顺序访问。

2. 调整结构后，检查 label 关联、按钮类型、标题层级和事件依赖是否还有效。父子关系变化可能影响选择器与事件委托，即使外观一致，点击、提交或读屏名称也可能变化，需要跟随具体组件行为一起验证。

3. 验证时不用鼠标完成主要操作，再检查窄屏视觉顺序是否与 DOM 仍合理一致。若桌面为了布局把操作区移到很远的位置，要重新评估是否真的有必要，不能为了少几条 CSS 增加用户理解和导航成本。
