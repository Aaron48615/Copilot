# CSS 选择器优先级是怎么算的？

## 核心回答

1. 选择器优先级只是 CSS 层叠的一部分，我会先确认声明是否匹配、来源和重要性、层叠层是否相同，再比较选择器。`!important` 不是给选择器加一个巨大分数，而是改变声明所在的优先顺序，所以不能用一条简单排行榜解释全部情况。

2. 在同等层叠条件下，优先级按 ID、类或属性及伪类、标签及伪元素三组数量逐位比较。例如一个 ID 的高位会胜过很多类，不能按十进制加总；通配符和组合符不增加权重，但它们仍然影响规则实际选中哪些元素。

3. 常见特殊情况是 where 的权重为零，is、not、has 自身不额外加权，主要取参数列表中最高的选择器权重。内联普通样式又有自己的位置，通常能压过作者样式表的普通规则；继承值则不会拿祖先选择器的权重来与当前元素直接声明竞争。

4. 前面的层叠条件和权重相同时，涉及 `@scope` 的规则还要比较到作用域根的接近程度，之后才看出现顺序；普通后代选择器不会仅因祖先离目标更近就获胜。排查时我会看被覆盖的声明、所属层和作用域，再确定谁应覆盖谁，避免随手加 important，让后续局部调整越来越难表达。

## 追问：为什么 :where() 适合写容易覆盖的基础样式？

1. where 连同参数的选择器权重为零，可以写出较明确的匹配范围，同时不把覆盖门槛抬高。例如一套组件基础样式希望使用方通过普通类就能调整，where 可以帮助保持低权重，而不必要求使用方增加层层祖先选择器。

2. 这不意味着它一定会输给所有规则，因为层叠来源、重要性和层仍然先参与比较。只有在相应层叠条件相同的时候，零权重的特点才解释得通；否则仅计算选择器数字可能仍会得到错误结论。

3. 我会把它用于默认值或基础外观，并让业务状态保留清晰的类名。不能为了追求低权重把全部样式都随意包进去，仍要检查哪些规则允许覆盖、哪些状态需要明确优先，避免组件的禁用或错误外观被意外冲掉。

## 追问：为什么一个普通类能覆盖带 ID 的组件库规则？

1. 一种可能是两条规则处在不同的层叠层，层的顺序先于选择器权重比较。普通声明中，后面的层优先于前面的层，未分层的普通声明也有自己的优先位置，所以类选择器可能在比较 ID 数量之前就已经胜出。

2. 还可能存在 important、内联声明或规则未匹配等因素。我会在开发者工具里确认 ID 那条真的参与竞争，是否被媒体条件排除，以及属性值是否有效；不能只根据源码中出现一个 ID 就假设它必然获胜。

3. 若需要稳定管理组件库与业务样式，可以明确基础层和覆盖层，而不是不断增加选择器长度。但 important 声明的层顺序规则与普通声明不同，规划时要单独检查，不能把普通层的结论直接套到所有声明上。
