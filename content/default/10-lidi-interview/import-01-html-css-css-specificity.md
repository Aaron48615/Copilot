# CSS 选择器优先级是怎么算的？

## 核心回答

1. 选择器优先级只是 CSS 层叠的一部分。先确认声明有没有匹配、来源和重要性、层叠层是不是相同，再比选择器。`!important` 不是给选择器加一个巨大分数，而是改声明所在的优先顺序。一条简单排行榜解释不了全部情况。

2. 同等层叠条件下，优先级按 ID、类或属性及伪类、标签及伪元素三组数量逐位比。一个 ID 的高位会胜过很多类，不能按十进制加总。通配符和组合符不加权重，但它们仍决定规则实际选中哪些元素。

3. 常见特殊情况：`:where()` 权重为零；`:is()`、`:not()`、`:has()` 自身不额外加权，主要取参数列表里最高的选择器权重。内联普通样式又有自己的位置，通常能压过作者样式表的普通规则。继承值不会拿祖先选择器的权重，来跟当前元素的直接声明抢。

4. 前面的层叠条件和权重相同时，涉及 `@scope` 的规则还要比到作用域根有多近，之后才看出顺序。普通后代选择器不会只因为祖先离目标更近就赢。排查看被覆盖的声明、所属层和作用域，再定谁该盖过谁。随手加 `!important`，后面局部调整会越来越难写。

## 追问：为什么 :where() 适合写容易覆盖的基础样式？

1. `:where()` 连同参数的选择器权重为零，匹配范围可以写清楚，覆盖门槛又不会被抬高。一套组件基础样式希望使用方用普通类就能调，`:where()` 能把权重压低，使用方不必层层加祖先选择器。

2. 这不意味着它一定输给所有规则。层叠来源、重要性和层仍然先比。只有相应层叠条件相同时，零权重这个特点才说得通。只算选择器数字，结论仍可能错。

3. 它适合默认值或基础外观，业务状态保留清晰的类名。别为了追求低权重把全部样式都随意包进去。哪些规则允许覆盖、哪些状态必须明确优先，还得查一遍，免得组件的禁用或错误外观被意外冲掉。

## 追问：为什么一个普通类能覆盖带 ID 的组件库规则？

1. 一种可能是两条规则处在不同的层叠层，层的顺序先于选择器权重。普通声明里，后面的层优先于前面的层，未分层的普通声明也有自己的位置，所以类选择器可能在比 ID 数量之前就已经赢了。

2. 还可能是 `!important`、内联声明，或者那条规则根本没匹配上。开发者工具里确认 ID 那条真的在竞争、有没有被媒体条件排除、属性值有没有效。源码里出现一个 ID，不代表它必然获胜。

3. 要稳定管组件库和业务样式，可以明确基础层和覆盖层，不必越写越长的选择器。但 `!important` 声明的层顺序规则跟普通声明不同，规划时单独查，普通层的结论不能直接套到所有声明上。
