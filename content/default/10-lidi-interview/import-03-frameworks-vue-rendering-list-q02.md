# watch 深度监听会拖慢吗？

## 核心回答

1. 可能慢。深度监听要遍历相关嵌套数据来建依赖，数据越大、层越多，成本越明显。不能一上来就说 `deep` 很危险；但对几千条记录的整棵树，只改一个小字段却盯着全部内容，通常值得重新看需求。

2. `watch` 一个 `reactive` 对象，会形成隐式深层监听。监听返回对象的 getter，默认更关心返回的引用变没变，深不深看配置。实际盯了什么要自己清楚，代码没写 `deep`，不等于没有深层遍历。

3. 优先听具体字段或 getter 数组。只关心分类和页码，就听这两个。过滤结果用 `computed`，别深度 `watch` 整个列表再复制一份。来源缩小了，活少了，回调为什么执行也更好懂。

4. 深层原地改时，回调里新旧对象可能是同一个引用。深度监听不会自动拍一份历史快照。想知道哪个字段变了，就听那个字段，或设计明确的更新动作。为了 diff 再不停深拷整棵对象，开销可能更大。

5. Vue 3.5 可以用数字限制深度，得看项目版本。限制以后，更深层的变化也可能不再通知。用真实操作量遍历和回调的活，别把回调里的排序、请求、同步更新全算到 `deep` 头上。调度和业务计算分开看。

## 追问：deep watcher 的 oldValue 为什么和 newValue 一样？

1. 深层字段原地改，外层对象没换引用，新旧参数可能指着同一份。`deep` 表示会跟踪深层访问，并不承诺每次改之前复制整份历史。不能靠这两个对象参数把以前所有字段值还原出来。

2. 只关心数量，就听具体 getter，回调拿到的原始值新旧更直接。要整体变更记录，让更新动作带上改了哪个字段，或按需要的范围自己留快照。别每次都拷整棵大对象。

3. 先问业务为什么要旧值：撤销、比较提示，还是拼接口参数。目的不同，需要的数据量不同。发现 `oldValue` 相同就立刻 `JSON` 深拷，一个本来简单的字段监听会又贵又受类型限制。

## 追问：设置较小的 deep 深度，会不会漏掉业务变化？

1. 会。限制遍历深度就是选择不跟踪更深层，不是无损优化。实际变化在更深一层，回调可能不跑，汇总或保存提示就会漏。要观察的数据范围得先想清楚。

2. 重要字段单独听，或在业务动作之后集中处理，别只因为树很深就随手设一个数字。数字深度适合结构已知、边界清楚的情况，项目还得是支持这个配置的 Vue 版本。

3. 验证要包含刚好在边界里和刚好在边界外的修改，不通知的情况得是能接受的。回调次数少了，功能还得完整，两头一起看这个配置才算合理。
