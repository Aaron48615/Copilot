# Vue 里怎么操作 DOM？

## 核心回答

1. 界面优先用数据驱动：类名、显示条件、文本绑在模板上。真需要节点能力再碰 DOM，比如聚焦输入框、读尺寸、滚动定位，或把容器交给图表库。改一段提示文字，绕过模板去改节点，容易和 Vue 打架。

2. 访问自身元素用模板 `ref`，比 `document.querySelector` 满页找更清楚，多个实例同名选择器也不会选错。挂载前、条件隐藏后、卸载后，节点可能是空的，用之前要看在不在。类型断言当不了运行时一定存在。

3. 初次访问放在 `onMounted`。刚改完状态、新 DOM 还没出来，用 `nextTick`。弹窗还在动画或异步加载中，等对应完成事件。`nextTick` 只处理 Vue 更新，保证不了容器尺寸已经稳，也保证不了第三方库已经准备好。

4. 第三方库管的区域和 Vue 要分清：Vue 提供容器，图表库操作容器内部，双方别反复改同一块内容。实例和监听卸载时释放。`KeepAlive` 还要考虑停用暂停、激活后重新量尺寸，藏着的容器拿去初始化，尺寸经常是错的。

5. 可复用的底层节点行为，可以做成自定义指令或 composable，接口写具体。Vue 3 指令钩子跟组件生命周期同名，钩子里拿到 `el` 和 `binding`。父级要控子级聚焦，走有限的公开方法，别去摸全部内部节点。状态之外，焦点和布局最好在真实浏览器再验，模拟环境绘制不完整。

## 追问：同一个组件在页面出现多次，为什么不适合固定 id 查节点？

1. 固定 `id` 可能重复。`document.getElementById` 或全局选择器会拿到别的实例。第一个弹窗正常，第二个却把焦点移到第一个输入框。这是查找范围错了，不是响应式没更新。

2. 模板 `ref` 属于当前组件实例，关系明确，不用猜页面里有几个相同元素。真要全局标识也应生成并保持唯一。组件内部常规操作，通常没必要靠全局查询找到自己刚渲染的节点。

3. 同时挂两个实例，各自操作应独立；条件移除后 `ref` 要能正确变成空。只测单实例可能一直正常，组件一复用才露馅。实例隔离是 DOM 操作设计的一部分。

## 追问：图表在隐藏弹窗里初始化后尺寸为零，怎样处理？

1. 隐藏容器常常没有可用布局尺寸，初始化读到零不奇怪。弹窗真正可见、容器尺寸可用之后，再初始化或调图表 `resize`。时机优先用弹窗打开完成回调，别随便等固定毫秒。

2. 大小之后还会变，观察容器尺寸再适当 `resize`。只听浏览器窗口，侧栏展开这种局部布局变化会漏。观察回调也要控制工作量，别每次细微变化都昂贵重绘，或改尺寸改出循环。

3. `KeepAlive` 返回、窗口缩放都要测。卸载时释放图表和观察器。保留实例就要有激活后的恢复流程：第一次隐藏就 `dispose`，下次显示还调旧实例，对不上。尺寸和实例寿命一起查。
