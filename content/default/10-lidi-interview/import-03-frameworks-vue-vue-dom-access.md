# Vue 里怎么操作 DOM？

## 核心回答

1. Vue 中我会优先通过数据驱动界面，比如绑定类名、显示条件和文本，只有确实需要节点能力时才直接操作 DOM。常见例子是聚焦输入框、读取尺寸、滚动定位或把容器交给图表库，不应该为了改一段提示文字就绕过模板更新。

2. 访问自身元素通常使用模板 ref，比 document.querySelector 全局查找更清楚，也避免多个组件实例中同名选择器选错节点。节点在挂载前、条件隐藏后或卸载时可能为空，使用前要检查存在性，不能把类型断言当成运行时一定存在的保证。

3. 初次访问可以放在 onMounted，需要等待刚修改状态产生的新 DOM 时使用 nextTick。若弹窗还在动画或异步加载中，应等待对应完成事件；nextTick 只处理 Vue 更新，不能保证容器尺寸已经稳定或第三方库已经准备完成。

4. 第三方库管理的区域要与 Vue 的职责分清，例如 Vue 提供容器，图表库操作容器内部，不要双方反复改同一节点内容。实例和监听在卸载时释放，KeepAlive 场景还要考虑停用暂停和激活后重新测量，避免隐藏容器初始化出错误尺寸。

5. 可复用的底层节点行为可以封装成自定义指令或 composable，但接口保持具体。父级需要控制子级聚焦时通过有限的公开方法，而不是访问全部内部节点；测试除了检查状态，还应在真实浏览器验证焦点和布局，模拟环境并不完整提供绘制能力。

## 追问：同一个组件在页面出现多次，为什么不适合固定 id 查节点？

1. 固定 id 可能重复，document.getElementById 或全局选择器会拿到别的实例节点。第一个弹窗正常，第二个弹窗却把焦点移到第一个输入框，这类问题来自查找范围错误，不是 Vue 的响应式更新失败。

2. 模板 ref 属于当前组件实例，访问关系更明确，不需要猜测页面里有几个相同元素。确实需要全局标识时也应生成并保持唯一，但组件内部常规操作通常没有必要借助全局查询来找到自己刚渲染的节点。

3. 我会用同时挂载两个实例的测试验证独立操作，并检查条件移除后 ref 是否正确处理为空。只测单实例可能一直正常，等组件被复用才暴露问题，因此实例隔离应作为 DOM 操作设计的一部分。

## 追问：图表在隐藏弹窗里初始化后尺寸为零，怎样处理？

1. 隐藏容器可能没有可用布局尺寸，图表初始化时读取到零并不奇怪。应在弹窗真正可见、容器尺寸可用后初始化或调用图表 resize，具体时机优先使用弹窗打开完成回调，而不是随意等待固定毫秒数。

2. 如果大小之后仍会变化，可以观察容器尺寸并适当调用 resize，避免只监听浏览器窗口而遗漏侧栏展开等局部布局变化。观察回调也要控制工作量，不能每次细微变化都引发昂贵重绘或反复修改尺寸形成循环。

3. KeepAlive 返回和窗口缩放都要验证，卸载时释放图表与观察器。保留实例时需要明确激活恢复流程，不能第一次隐藏后就 dispose，却在下次显示继续调用旧实例；尺寸问题和实例生命周期应一起检查。
