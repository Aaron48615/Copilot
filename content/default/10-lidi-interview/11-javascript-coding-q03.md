# 数组扁平化怎么写？

## 核心回答

1. 如果允许用标准库，我会先写 `list.flat(depth)`，默认只展开一层，需要全部展开时可传 `Infinity`。扁平化返回新数组，但不会深拷贝其中的对象，原数组里的普通对象仍然以原引用进入结果。

2. 手写时我先限定输入是没有循环的普通嵌套数组，并实现完全展开。用一个结果数组累计叶子值，遇到数组继续访问，避免递归中反复 `concat` 已有结果带来的重复复制。

    ```js
    function flatten(list) {
      const result = [];
      function visit(array) {
        for (let i = 0; i < array.length; i++) {
          if (!(i in array)) continue;
          const item = array[i];
          if (Array.isArray(item)) visit(item);
          else result.push(item);
        }
      }
      visit(list);
      return result;
    }
    ```

3. 比如 `[1, [2, [3]], 4]` 会按从左到右的顺序得到 `[1, 2, 3, 4]`，空数组不会加入元素。`i in array` 用来跳过不存在的索引，显式存放的 `undefined` 则会保留，二者不能混为一谈。

4. 对普通无共享的嵌套数组，耗时与访问的各层数组索引总数相关，结果空间与输出元素数相关，调用栈深度则取决于嵌套层数。很深的输入可能超过调用栈限制，`flat(Infinity)` 也不代表承诺无限资源。

5. 这段代码是教学版，不是完整的 `Array.prototype.flat` 替代品，没有实现深度参数、类数组调用和数组子类构造等标准行为；如果面试要求只展开两层，就需要增加剩余深度判断，不能直接交付完全展开版。如果数据可能自引用，要另外约定报错或处理方式，不能直接递归到程序失败。

## 追问：嵌套太深时，如何用显式栈保持展开顺序？

1. 我会用栈保存“当前数组和下一个待访问索引”的栈帧，初始只有最外层数组。每次查看栈顶，如果已经访问完就弹出，否则先推进索引，再处理当前位置的元素，这样不再依赖函数递归调用栈。

2. 遇到嵌套数组就压入新的栈帧，遇到普通值就加入结果，缺失索引继续跳过。因为始终先把当前子数组处理完，再返回父数组的下一个位置，所以自然维持从左到右的输出顺序，不需要最后反转。

3. 这个方案需要的栈帧数量与嵌套深度相关，但结果数组仍然需要内存，巨大输入也可能阻塞页面。如果只是批量消费元素，可以进一步考虑生成器或分批处理，显式栈只解决递归深度，并没有消除所有资源限制。

## 追问：数组空槽、undefined 和循环引用分别怎么处理？

1. 空槽表示对应索引不存在，例如 `[, 1]`，而 `[undefined, 1]` 的第零项实际存在。标准 `flat` 在展开的层级会跳过空槽，显式的 `undefined` 会保留；没有继续展开的嵌套数组内部空槽则可能仍然存在。

2. `for...of` 遍历数组时可能把空槽读成 `undefined`，所以直接替换教学代码的索引检查会改变结果。我会把稀疏数组单独列为样例，避免普通整数数组通过后就声称行为与标准库一致。

3. 对 `a.push(a)` 这样的循环，可以记录当前递归路径上的数组，重复进入时报告不支持循环。不能简单用全局集合把所有重复数组都跳过，因为 `[sub, sub]` 是合法共享引用，通常应该把它的内容展开两遍。
