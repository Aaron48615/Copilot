# 什么是闭包？项目中使用过吗？

## 核心回答

1. 我理解闭包是函数与它定义时能够访问的词法环境之间的联系，所以外层函数执行结束后，内部函数仍可能访问外层变量。外层返回一个函数只是常见展示方式，并不是形成闭包的必要写法，事件回调和定时器回调也会用到这种能力。

2. 以防抖为例，外层保存定时器标识，返回的函数每次触发都清除上一次定时器，再安排新的执行。多次调用能够读写同一个标识，才可以合并连续输入；如果每次调用都重新创建独立变量，就无法取消之前安排的那次任务。

3. 我在轻购搜索页的输入防抖里保存了联想请求的定时器，组件卸载时会清除定时器并取消旧请求。闭包访问的是变量绑定而不是固定快照，同一环境里的多个函数可以观察到共享变量后续发生的修改。

4. 闭包本身不等于内存泄漏，关键是函数是否仍然可达，以及它还保留了哪些业务上不再需要的数据。假设一个长期存在的监听器引用了大列表，页面离开却没清理就可能延长列表存活时间，我会先检查引用链，而不是看到闭包就全部改写。

## 追问：为什么循环里的定时器可能输出同一个值？

1. 使用函数作用域变量循环时，各个回调可能引用同一个循环变量，等定时器执行时循环已经结束。它们读取的是这个共享变量当时的值，所以常见结果是全部输出循环结束值，而不是各次注册回调时的值。

2. 在循环声明处使用块级变量时，每轮会有对应的词法绑定，回调因此可以读到各轮的值。也可以调用一个函数并传入当前值，让每次调用产生独立参数绑定，本质都是让回调访问不同的变量环境。

3. 如果多个回调刻意共享同一个对象，改成块级变量也不会自动复制对象内容，修改对象属性仍会相互影响。面试时我会分别解释变量绑定与对象引用，避免把块级声明说成对所有数据都进行快照。

## 追问：闭包保存变量为什么还会遇到旧值问题？

1. 闭包读取变量绑定并不意味着它会自动切换到后来创建的另一个环境，例如一次函数调用先计算出提示文本，再返回打印函数。即使之后修改了计数变量，已经计算好的文本也不会自动重新计算，因此仍可能打印旧内容。

2. 另一个例子是每次调用渲染函数都会产生新的局部变量，先前注册的回调仍连接到先前那次调用的环境。后来产生同名变量，并不会把旧回调的引用改接过去，所以需要弄清回调究竟来自哪一轮调用。

3. 如果要修复，我会依据需求选择在执行时重新计算、重新注册回调，或者从稳定容器读取最新值。稳定容器也不是所有情况都适合，若业务需要保留发起请求时的关键词，保留那一轮的值反而是正确行为。
