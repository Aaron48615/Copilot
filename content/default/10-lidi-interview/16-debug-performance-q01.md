# 页面白屏的具体排查顺序是什么？

## 核心回答

1. 先确认白屏的范围：是所有页面都打不开，还是某个路由、账号或浏览器才出现，刷新前后一不一致。先留出错现场和地址，再看 Console 里最早出现的有效错误，别被后面连带报错带偏。

2. 接着在 Network 看 HTML、入口脚本和动态 chunk 有没有成功加载，同时看响应类型和内容。脚本请求即使返回 200，也可能实际拿到了登录页或 HTML 回退页面。单看状态码发现不了。

3. 资源正常的话，顺着错误堆栈查路由、组件导入和渲染数据，比如接口还没回来就访问嵌套字段。可以临时缩到最简单的页面或组件，判断是应用没启动，还是某个组件渲染时抛错。

4. Console 没有异常，再看 Elements：根节点有没有内容、容器高度是不是零、是不是被 loading 遮罩盖住。有 DOM 但看不见，可能是 CSS 或状态逻辑问题，不一定是 JavaScript 崩溃。

5. 修复要对上证据。资源版本不一致就处理发布和缓存，数据异常就补明确的加载、空值和失败状态。错误边界可以限制部分渲染错误的影响，但抓不住所有事件或异步错误，入口脚本本身没加载也救不了。

## 追问：为什么刚发布后容易出现 chunk 加载失败？

1. 一种可能是用户还留着旧页面，里面引用旧构建的 chunk 文件名，新发布已经把这些文件删了。点懒加载路由时才开始下旧 chunk，所以首页能打开，不代表后续页面资源都正常。

2. 核对失败 URL、HTML 版本、缓存头和服务器实际文件，确认是不是真的版本错配。也要排除路径前缀错误、CDN 缓存和网络故障。看到动态导入失败，别直接判定是缓存问题。

3. 发布方案可以考虑入口更新策略、保留旧静态资源、发布切换的一致性。页面可以提示用户刷新尝试恢复，但别无限自动刷新，并提醒保留未提交的输入，别让恢复动作造成额外损失。

## 追问：没有报错，但页面一直 loading，怎么继续排查？

1. 看 loading 由哪些状态决定，再看对应请求是在等、失败了，还是根本没发出。比如只在成功分支关 loading，失败后界面就可能一直转圈。这是状态分支漏了。

2. 请求已经完成，就在状态更新处下断点，看返回结构是否符合判断条件，以及有没有过期请求在改状态。别只用一个布尔值糊弄多个并发请求，一个失败就可能让界面结束不了等待。

3. 再看初始化是不是在等一个不会结束的认证恢复或资源加载 Promise。确认原因后补超时、失败和重试入口。别用固定定时器强制藏掉 loading，把关键数据实际不可用给盖住。
