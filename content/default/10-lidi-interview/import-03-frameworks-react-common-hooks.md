# React 常用的 Hooks 有哪些？

## 核心回答

1. 我会先按用途介绍。useState 保存会影响界面的状态，比如搜索词、当前页和弹窗是否打开；下一次显示依赖旧状态时，用函数式更新，例如 `setCount(c => c + 1)`，避免把同一次渲染里的旧值重复写回去。

2. useEffect 用来和组件外部的东西保持同步，比如监听窗口大小、启动轮询或更新图表实例。依赖决定什么时候重新同步，清理函数负责撤销上一次的订阅或定时器，不能只写创建而不考虑离开页面。

3. useRef 保存跨渲染保留、但不需要触发界面更新的值，例如输入框节点或定时器编号。useMemo 缓存计算结果，useCallback 缓存函数引用；它们是性能工具，不能用来保证请求只发一次，也不能代替状态管理。

4. 状态变化规则较多时，我会考虑 useReducer，把新增、删除、重置等动作集中处理；跨层读取数据可以用 useContext。选择时先看数据由谁使用、什么时候变化，再决定是否需要共享，避免一个搜索框的输入就影响整个页面。

5. 比如做一个可切换条件的列表，我会让搜索词由 state 保存，结果数量直接根据列表计算，请求或订阅单独处理。这样遇到重复请求时能检查依赖，遇到显示不刷新时能检查状态，而不是把所有问题都交给一个很长的 Effect。

## 追问：useRef 和 useState 都能存值，为什么不能随便换？

1. 两者对渲染的通知不同。修改 ref.current 不会主动重新渲染，所以把购物车数量只存在 ref 中，数据虽然变了，角标可能仍然显示旧数字；需要显示的内容应由 state 驱动。

2. ref 更适合保存操作需要的句柄。比如定时器编号只在停止计时时使用，没有展示需求；将编号放入 state 会多安排一次无意义的更新，也容易让相关 Effect 多跑一遍。

3. 我还会避免在普通渲染过程中任意读写 ref 来计算界面，因为渲染可能重复执行。访问 DOM 通常放在事件或提交后的 Effect 中，并检查节点是否仍存在，这样数据用途和执行时机都比较明确。比如关闭弹窗后 ref 可能回到空值，异步聚焦回调也要重新检查，不能假设初次取到节点之后就始终有效。

## 追问：什么时候值得抽一个自定义 Hook？

1. 当一组有状态的行为需要重复使用时值得抽，例如窗口尺寸监听包含初始值、订阅和取消订阅。调用方只关心尺寸，把清理细节放在 Hook 内部，能够减少每个页面漏写释放操作的机会。

2. 接口应表达具体含义，例如 useWindowSize 返回宽高，useSearch 返回结果、状态和重试方法。不要做一个参数很多、同时负责弹窗和权限的万能 Hook，否则调用者仍然需要了解全部内部实现。

3. 自定义 Hook 复用的是逻辑，不会天然共享同一份 state。两个组件分别调用通常得到独立状态；确实需要同步时，应再通过共同父组件、Context 或外部 store 管理那一份数据。共享需求应在接口上明确，避免调用方误以为一个页面的搜索结果会自然同步到另一个页面。
