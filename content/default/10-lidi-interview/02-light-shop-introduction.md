# 请详细介绍一下轻购项目

## 核心回答

1. 轻购是一个移动端电商 Web 应用，我用 Vue 3 和 TypeScript 组织页面，Vant 提供搜索框、规格弹窗和提交栏等基础组件。Vue Router 负责页面跳转，Axios 统一普通接口请求，Vite 用于开发和构建，样式使用 SCSS，并配合移动端适配。

2. 一次购买过程是这样：用户登录后搜索商品，进入详情选择 SKU，再加入购物车或立即购买，最后选择地址并确认订单。这里需要把商品标识、规格、数量和地址传对，金额则通过后端确认，几个页面连起来不等于交易完成。

3. 轻购AI是独立导购页，用户可以输入“800 元以内的通勤耳机”。前端调用 `/guide/recommend`，把返回的推荐商品、匹配条件、缺少依据的条件和放宽限制分别展示出来，帮助用户判断推荐是否符合自己的要求。

4. 另外两处 AI 是搜索联想和商品卖点。前者处理连续输入、请求取消和旧结果覆盖，后者在商品数据到齐后生成文案；搜索联想和卖点都有本地备用内容，独立导购失败时目前主要提示重试，三者的实现不能混在一起讲。

5. 这个项目让我练习最多的是异步请求与业务状态的配合，比如换关键词后不能显示旧建议，订单确认也要重新读取价格。我负责的前端部分包括页面交互和接口集成，没有自己训练模型；支付目前是模拟流程，真实微信或支付宝支付还需要另外接入。

## 追问：你会选哪一个功能现场展开讲？

1. 现场展开的话，搜索联想最合适，因为它有明确的触发、等待和返回过程。比如从“手机”继续输入到“手机壳”，两个请求返回的顺序可能和发出的顺序不同，这比介绍用了某个组件更能把异步讲清楚。

2. 接着是三层处理：防抖减少中间输入的请求，AbortController 尝试取消旧请求，请求编号决定结果还能不能写入页面。它们各自解决不同问题，单独用防抖并不能保证最终显示的是最新结果。

3. 最后演示慢请求、失败和离开页面三个情况。重点看页面是否保留当前输入、能否继续普通搜索，以及旧任务会不会重新写入建议；还会查看相同输入下请求次数是否减少，具体改善多少需要在一致条件下测量。

## 追问：这个项目离正式商城还缺什么？

1. 更该补的是交易边界，例如库存变化、价格变化、重复提交和支付结果不确定。当前有前端下单流程，但真实支付还需要后端与支付平台配合，浏览器显示成功不能单独作为到账依据。

2. 然后补接口结构和异常反馈。现有部分数据仍使用 any，AI 结果也缺少完整运行时校验；如果继续完善，从订单和推荐结果开始检查必要字段，让错误停在接口边界，避免页面展示出不完整商品。

3. 最后安排可重复验证的用例，比如结算时返回地址页、登录失效后回到原页面、搜索响应乱序。正式上线还需要结合真实接口评估安全和容量，这些属于后续工作，不能用课程项目的正常演示代替。
