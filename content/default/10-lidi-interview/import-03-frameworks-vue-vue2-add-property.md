# Vue 2 给对象新增属性，页面会响应吗？

## 核心回答

1. Vue 2 给对象直接新增属性，通常不会自动触发所期待的更新。初始化时主要对当时已有属性用 `Object.defineProperty` 做成 getter、setter。新字段没经过这一步，`this.form.newKey = value` 以后，数据对象上键已经在，视图却可能收不到通知。数据变了和渲染变了，不是一回事。

2. 表单这类已知字段，在 `data` 里提前声明初值，暂时为空也把结构写清楚。响应式初始化能覆盖到，读代码的人也知道有哪些状态。别等某次接口碰巧返回字段，模板才知道它存在，缺失分支更难处理。

3. 已经观察过的嵌套对象上动态加字段，用 `Vue.set` 或 `this.$set`；删除用 `Vue.delete` 或 `this.$delete`。它们走框架认识的入口来建立或通知变化。运行中的根级组件状态扩展别随意这么加，根级字段优先初始化时声明。

4. 也可以给已经响应式的属性赋一个包含新字段的新对象，比如重新设置 `form`。只对旧 `form` 做 `Object.assign` 加新字段，新键往往还是普通新增。前者经过已有 setter，新对象会被观察；后者直接往旧对象上加键，还可能落到同样的检测限制。

5. 数组用索引赋值、改 `length`，也有类似边界，可以用 `$set` 或 `splice`。Vue 3 用 Proxy，新增、删除、下标这些能拦截到，没有同样的限制，但仍有解构、原始引用这些问题。维护 Vue 2 按当前版本正确更新，再在需要时 `nextTick`。等待或 `forceUpdate` 替不了把响应式通知补齐。

## 追问：为什么替换整个 form 可以，而 Object.assign 到旧 form 不一定可以？

1. `form` 是已经声明的响应式属性，给它赋新对象会走对应 setter，Vue 可以对新对象已有字段建立观察。新对象里的新增字段因此有机会进响应式系统。前提是这个赋值入口本身已经被 Vue 管着。

2. `Object.assign` 到旧 `form`，原来没有的字段本质还是普通新增，没有自动走 `Vue.set`。已有字段可能正常更新，新字段却没有通知。同一份接口回填，有的显示、有的不显示，要按字段来源看。

3. 要不要保持对象引用，决定是整份替换还是逐项 `$set`。消费者是不是还握着旧对象，也要查。替换能解决新增观察，外面长期保存的旧引用不会自动变成新对象。响应式修好了，整条数据使用关系还要对上。

## 追问：为什么不能只在新增后调用 forceUpdate？

1. `forceUpdate` 可能让当前组件重新读对象，短时间内新字段能显示。它没有把这个字段变成后续能正常通知的响应式属性。下一次只改这个字段，仍可能不刷新。问题被推迟了，不是解决了。

2. 依赖这个字段的 `computed`、子组件、监听，也不一定因为强制刷新就获得正确、持续的关系。初始化就声明，或走 `$set` 这类支持入口新增，再让正常依赖更新。每次变化通知方式才一致。

3. 第一次新增，以及之后连续修改、删除，都要验。很多临时补丁只让第一个断言过。完整生命周期测过，这个字段才算按 Vue 2 的规则真正进了响应式。
