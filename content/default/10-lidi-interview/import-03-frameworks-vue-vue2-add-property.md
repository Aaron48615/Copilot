# Vue 2 给对象新增属性，页面会响应吗？

## 核心回答

1. Vue 2 给对象直接新增属性，通常不会自动触发所期待的响应式更新，因为初始化时主要对当时已有属性建立 getter 和 setter。新字段没有经过这一步，数据对象虽然已经多了一个键，视图却可能没有收到相应通知，不能把数据变化和渲染变化混为一谈。

2. 对表单这类已知字段，我会在 data 中提前声明初值，即使暂时为空也把结构写清楚。这样既满足响应式初始化，也让读代码的人知道有哪些状态；不能等某次接口碰巧返回字段后才让模板知道它存在，缺失分支会更难处理。

3. 对已观察的嵌套对象动态新增字段，可以使用 Vue.set 或 this.$set，删除用 Vue.delete 或 this.$delete。它们通过框架知道的入口建立或通知变化，但不能随意用于运行中的根级组件状态扩展；根级字段应优先在初始化时声明。

4. 也可以给已响应式的属性赋一个包含新字段的新对象，例如重新设置 form，而不是只对旧 form 执行 Object.assign 加新字段。前者经过已有 setter，让新对象被观察；后者只是直接增加旧对象字段，仍可能落入同样的检测限制。

5. 数组索引和 length 修改也有类似边界，可以通过 $set 或 splice 等方式处理。Vue 3 的 Proxy 解决了这类直接拦截限制，但仍有解构和原始引用等问题；维护 Vue 2 时应按当前版本正确更新，再等待必要的 nextTick，不能靠等待或强制刷新代替补齐响应式通知。

## 追问：为什么替换整个 form 可以，而 Object.assign 到旧 form 不一定可以？

1. 如果 form 是已经声明的响应式属性，给它赋新对象会经过对应 setter，Vue 可以对新对象已有字段建立观察关系。新对象包含的新增字段因此有机会进入响应式系统，前提是赋值入口本身确实已经被 Vue 管理。

2. Object.assign 到旧 form 时，对原来没有的字段本质还是普通新增，没有自动经过 Vue.set。已有字段可能正常更新，新字段却没有通知，就会出现同一份接口回填中有的显示、有的不显示，需要按字段来源分析。

3. 我会根据是否需要保持对象引用选择替换或逐项 $set，并检查消费者是否持有旧对象。替换虽然能解决新增观察，但外部长期保存的旧引用不会自动变成新对象，响应式修复也要兼顾整个数据使用关系。

## 追问：为什么不能只在新增后调用 forceUpdate？

1. forceUpdate 可能让当前组件重新读取对象，短时间内显示新字段，但它没有把这个字段变成后续可以正常通知的响应式属性。下一次只修改该字段时仍可能不刷新，问题被推迟而不是解决。

2. 其他依赖该字段的 computed、子组件或监听也未必因为强制刷新获得正确持续关系。更好的做法是在初始化声明，或通过 $set 等支持入口新增，再让正常依赖更新，这样每次变化都有一致的通知方式。

3. 我会验证第一次新增和之后连续修改、删除的行为，而不是只看新增那一刻的文本。很多临时补丁只让第一个断言通过，完整生命周期测试才能说明字段已经真正按 Vue 2 的规则参与响应式更新。
