# flex:1 是哪些属性的复合属性？

## 核心回答

1. `flex` 是 `flex-grow`、`flex-shrink` 和 `flex-basis` 三个属性的简写，分别管剩余空间怎么涨、空间不够怎么缩、分配前的基础尺寸。先看基础尺寸，再看正负剩余空间。`grow` 为 1，不等于最终宽度一定相等。

2. 浏览器通常把 `flex: 1` 展开成 `1 1 0%`：允许增长、允许收缩，从零百分比基础开始分。规范和浏览器还有零长度、零百分比的差别：主轴尺寸不明确时，`0%` 解析可能不一样，特殊布局下要看计算值和实际结果。

3. `flex: auto` 对应 `1 1 auto`，会先考虑内容或已经设好的主轴尺寸，再分剩余空间。两项初始宽度不同，即使 `grow` 都是 1，分到相同的新增空间后仍然可以不等宽。增长比例分的是剩余空间，不是直接规定最终宽度比例。

4. 做等宽按钮时，同时看最小宽度、内边距和边框。长文本可能被默认最小尺寸卡住，允许收缩的子项上设 `min-width: 0`，再决定换行还是省略。`flex: 1` 是分配起点，实际尺寸还受其他约束。

5. 这些参数沿主轴工作。横向布局主要影响宽度，改成纵向就主要影响高度。一个面板希望上下等分，外层必须提供可分配的高度，只改简写参数，两块区域仍可能由内容决定。

## 追问：flex-shrink 都是 1，缩小的像素数为什么不同？

1. 收缩分配会看收缩因子和基础尺寸的乘积，不是只看 shrink 那个数字。两项基础尺寸分别是 100px 和 200px，空间不够时，即使因子相同，较大的那项通常多缩一些。

2. 没有最小尺寸等额外限制时，负剩余空间按这些加权值分。实际过程中某项可能先碰到最小宽度停住，剩下的再由别的项目承担。最终结果还要结合约束看，做一次简单比例不够。

3. 开发者工具里分别看 basis、最小尺寸和最终宽度，再判断是正常加权收缩，还是长内容卡住了。某个图标必须保持大小，可以让它不收缩，让文本区域承担变化，别盲目改所有项目的 shrink。

## 追问：flex: none 和 flex: auto 适合什么场景？

1. `flex: none` 相当于 `0 0 auto`，不参与弹性增长和收缩，基础尺寸按 `auto` 算。工具栏里固定图标区域常用这个思路。内容本身很长时，它也可能把别的区域挤瘦，所以还要考虑宽度上限。

2. `flex: auto` 是 `1 1 auto`，保留内容或显式尺寸当起点，再参与加减空间。希望输入框在已有合理宽度上再伸，可以用。多个项目起点不同，别指望它们最终自动等分。

3. 按角色组合：图标固定、输入区可伸缩、操作按钮留合理宽度，窄屏再看要不要换行。真要严格均分的网格，直接用等份 Grid 轨道说清楚，没必要所有场景都硬套 flex 简写。
