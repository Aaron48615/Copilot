# Grid 的 auto-fit 和 auto-fill 有什么区别？

## 核心回答

1. auto-fill 和 auto-fit 都可以用于 repeat，根据容器可用尺寸自动重复轨道。比如最小宽度明确、最大使用 1fr 的卡片列，浏览器先计算大致能放多少列；当所有可容纳的轨道都有内容时，两者可能看起来完全一样。

2. 区别主要出现在有空轨道时。auto-fill 保留这些轨道，所以即使只放两张卡片，也会给其他能容纳的列保留空间；auto-fit 在放置项目后折叠空的重复轨道及相关间隙，让已有卡片有机会分到更多剩余空间，但是否拉宽仍取决于最大尺寸等规则。

3. 例如宽容器最多容纳四列，却只有两张卡片，auto-fill 更容易维持四列网格的节奏，auto-fit 配合 1fr 则可以让两张卡片更宽。这里的“空”指轨道没有被项目占据，某一行最后少几张并不必然意味着整条列轨道为空。

4. 我会按设计决定是否保留空位，同时设置合理最小值和最大内容宽度。小于最小轨道宽度的容器仍可能溢出，需要用更灵活的下限或窄布局处理；这两个关键字解决的是重复与空轨道，不会自动替我们解决长标题和极窄屏。

5. 自动列数还会把列间隙纳入能否容纳的计算，同样的最小卡片宽度，增加间隙也可能导致少一列。调试断点附近的变化时，我会同时看轨道宽度和间隙，避免只按容器宽度除以卡片宽度得到错误预期。

## 追问：为什么 auto-fit 没让最后一行的两张卡片铺满？

1. 因为 Grid 的列轨道贯穿多行。如果前面的行已经在所有列里放了卡片，最后一行虽然少了几个项目，这些列整体仍然不是空轨道，auto-fit 就不会仅因为最后一行缺项而把这些列折叠。

2. 这与 Flex 每一行独立分配剩余空间不同。Grid 保持统一列线正是很多卡片矩阵需要的效果；如果设计要求最后一行单独铺满，应重新评估是否使用 Flex，或明确为这类特殊行安排不同布局。

3. 我会先用两张总卡片和多行末尾两张这两种数据量做对比，让区别能被直观看到。不能看到前者拉宽就推导所有最后一行都会拉宽，关键在整条轨道的占用情况，而不是只数当前行有几项。

## 追问：minmax(240px, 1fr) 在 200px 的容器里怎么办？

1. 最小轨道宽度仍是 240px，因此容器只有 200px 时不能靠自动重复把单列继续缩到更小。至少一列也超出容器，这是最小尺寸约束导致的结果，不是 auto-fit 没有检测到窄屏。

2. 可以根据需求把最小值写得更灵活，例如让下限取设计最小宽度与可用宽度中较小者，或者在更窄条件下改为单列可收缩布局。选择时还要检查内边距和 gap，不能只调整轨道却漏掉外层额外占用。

3. 最后放入真实内容验证单列是否仍可读。若卡片中的图表或表格有不可压缩的信息，可能应该让局部横向滚动，而不是继续压窄到文字无法辨认，最小宽度本身应来自内容需求而不是随手写一个数字。
