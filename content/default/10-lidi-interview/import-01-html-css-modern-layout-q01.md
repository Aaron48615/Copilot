# Grid 的 auto-fit 和 auto-fill 有什么区别？

## 核心回答

1. `auto-fill` 和 `auto-fit` 都能用在 `repeat` 里，按容器可用尺寸自动重复轨道。比如最小宽度明确、最大用 `1fr` 的卡片列，浏览器先算大概能放多少列。所有能容纳的轨道都有内容时，两者看起来可能完全一样。

2. 差别主要出在有空轨道的时候。`auto-fill` 会把这些轨道留着，所以即使只放两张卡片，也会给其他能容纳的列留空间。`auto-fit` 在放置项目后折叠空的重复轨道和相关间隙，已有卡片有机会分到更多剩余空间。能不能拉宽，还取决于最大尺寸这类规则。

3. 比如宽容器最多容纳四列，却只有两张卡片，`auto-fill` 更容易维持四列网格的节奏；`auto-fit` 配合 `1fr` 可以让两张卡片更宽。这里的「空」指轨道没有被项目占住。某一行最后少几张，不等于整条列轨道都空。

4. 按设计决定要不要留空位，同时设合理最小值和最大内容宽度。小于最小轨道宽度的容器仍可能溢出，得用更灵活的下限或窄布局处理。这两个关键字管的是重复和空轨道，长标题和极窄屏不会自动帮你解决。

5. 自动列数还会把列间隙算进能不能容纳。同样的最小卡片宽度，间隙加大也可能少一列。调试断点附近的变化时，轨道宽度和间隙一起看，别只拿容器宽度除以卡片宽度去估。

## 追问：为什么 auto-fit 没让最后一行的两张卡片铺满？

1. Grid 的列轨道是贯穿多行的。前面的行已经在所有列里放过卡片，最后一行虽然少了几个项目，这些列整体仍不是空轨道。`auto-fit` 不会只因为最后一行缺项就把这些列折掉。

2. 这跟 Flex 每一行独立分配剩余空间不一样。Grid 保持统一列线，正是很多卡片矩阵要的效果。设计要求最后一行单独铺满，得重新评估是不是用 Flex，或者给这类特殊行另排布局。

3. 用「总共就两张卡片」和「多行末尾剩两张」这两种数据量对照，差别一眼能看出来。前者拉宽了，推不出所有最后一行都会拉宽。关键是整条轨道有没有被占住，不是只数当前行有几项。

## 追问：minmax(240px, 1fr) 在 200px 的容器里怎么办？

1. 最小轨道宽度仍是 240px，容器只有 200px 时，不能靠自动重复把单列继续缩得更小。至少一列也超出容器，这是最小尺寸约束的结果，不是 `auto-fit` 没检测到窄屏。

2. 按需求把最小值写得更灵活，比如下限取设计最小宽度和可用宽度里较小的那个，或者更窄时改成单列可收缩布局。内边距和 `gap` 也要查，别只调轨道却漏掉外层额外占用。

3. 最后放进真实内容，看单列还读不读得了。卡片里的图表或表格有压不回去的信息，局部横向滚动可能更合适，别继续压到字都认不清。最小宽度本身应来自内容需求，别随手写一个数字。
