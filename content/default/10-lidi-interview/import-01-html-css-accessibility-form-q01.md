# 什么时候使用 aria？

## 核心回答

1. 原生 HTML 说不清名称、状态或关系时，才补 ARIA。比如按钮只有一个放大镜图标、没有文字，可以加 `aria-label="搜索"`。按钮上已经写了「搜索」，就不必再写一套名称，不然屏幕上看的是「搜索」，读屏可能念成另一句。

2. 表单里常用 `aria-describedby` 把帮助说明或错误文本挂到输入框上，校验不过再设 `aria-invalid`。这些属性不会替你做校验，对不对、什么时候清掉错误，还是页面自己定。

3. 展开面板的按钮可以用 `aria-expanded` 说现在开没开，必要时 `aria-controls` 指到那块内容。界面开了，属性也得跟着改成 true，不能初始化写成 false 就不管了；不然读屏说关着，眼前内容已经摊开了。

4. 能用 `button`、`input`、`select` 就先用原生的。给 `div` 加 `role="button"` 不会自动能 Tab、空格触发，也不会自动禁用，这些都得自己补。ARIA 只是补充语义，键盘和读屏还得实际走一遍。

5. 装饰图标可以对辅助技术藏起来，别让按钮名称里夹一句没用的「图形」。但还能聚焦的控件别一起藏。名称、描述和眼前看到的状态要对上，看计算出来的可访问名称，别只盯源码里写过一个标签。

## 追问：aria-label 和 aria-labelledby 怎么选择？

1. 界面上已经有合适的可见标题，用 `aria-labelledby` 去引用它，比如弹窗名称直接挂到标题上。标题改了不用再维护一份隐藏字符串，大家听到的和看到的是同一句。

2. 纯图标按钮没有可引用的文字，就用短的 `aria-label`，比如「删除这条记录」。列表里好几个一样的按钮，名称还得带上对应那一条，不然用户不知道删的是哪条。

3. 名称回答「这是什么」，别写成一整段帮助说明。输入要求、限制用描述关联。还要看计算后的可访问名称，别把已有文字意外盖掉。

## 追问：aria-disabled 和 disabled 有什么区别？

1. 原生 `disabled` 会让支持它的表单控件没法操作，一般也退出 Tab 顺序，提交时也不会带上。暂不可用的提交按钮直接用这个，浏览器会处理一部分行为。

2. `aria-disabled` 主要告诉辅助技术「现在不可用」，不会自动拦住点击、键盘触发或提交。如果还想让控件留在焦点顺序里，好让用户听到为什么不可用，就得自己拦截操作，并说清楚原因。

3. 两个属性不是同义词。键盘、鼠标、代码触发的入口都要测一遍。服务端也不能因为按钮变灰就省略权限和状态校验。
