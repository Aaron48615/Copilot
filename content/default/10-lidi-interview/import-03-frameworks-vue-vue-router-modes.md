# Vue Router 的 hash 和 history 模式有什么区别？

## 核心回答

1. hash 模式把前端位置放在 URL 片段里，比如 `/#/orders`。`#` 后面的变化不会当成页面路径发给服务器，靠 `hashchange` 切页面，比较适合不能配页面路径回退的静态托管。history 模式用 History API，地址可以直接是 `/orders`，站内跳转通常不用整页重载。

2. history 的关键边界是直接访问和刷新。浏览器会真的向服务器要当前路径，服务器得返回应用入口或对应服务端页面。只有首页文件、没有回退规则，站内点击正常、刷新详情却 404，这是常见部署问题。nginx 一类可以 `try_files` 把前端页面路径兜回 `index.html`。

3. 回退不能盖住所有请求。前端页面路径可以回到入口；接口和静态资源还是各走各的服务。脚本文件缺失却返回入口 HTML，浏览器会把文档当脚本解析，类型或解析错误更难查。应用内部也要处理对不上的路由，未知页面别全当正常首页。

4. Vue Router 4 里常见 `createWebHashHistory` 和 `createWebHistory`。子目录部署还要配合适的基础路径。SSR 等非浏览器环境另有历史实现，服务器上不能直接依赖浏览器地址栏。两种模式前端本质一样：改 URL 但不发整页请求，再渲染对应组件，差别是改 URL 的手段，以及要不要服务器配合。

5. 部署能配合时用 history，URL 干净，分享也方便；服务器配置动不了时用 hash。项目里默认是 history。history 不等于 SEO 自动变好，内容怎么渲染、元数据、状态码都很重要。hash 也不是完全不用配，入口和静态资源还是要能访问到。

## 追问：为什么不把所有 404 都改成返回 index.html？

1. 只有该由前端路由处理的页面路径需要这种回退。接口、脚本这些资源有自己的语义。脚本没有了却返回 HTML，浏览器会尝试把文档当脚本跑，真实的资源不存在还被成功状态盖住，排查更难。

2. 按路径前缀、文件类型、托管配置，把应用页面、接口、静态文件分开。应用内部还要有未找到路由的页面。服务端渲染场景按需要返回真实状态。别为了消掉一个刷新错误，把所有未知地址都变成首页。

3. 正常详情刷新之外，主动请求不存在的接口、图片、路由。它们应得到各自合理的格式和状态。只确认 `/orders` 不再报错不够，回退规则修好一处、破坏其他路径，测得出来。

## 追问：应用部署在子目录，路由和资源要一起检查什么？

1. 路由基础路径要反映实际子目录，不然导航可能从 `/app/` 跳到站点根。构建产物的资源基础地址也要配合。路由地址对了，脚本、样式、图片不一定从同一子目录加载，这两套配置不是一回事。

2. 服务器回退针对这个应用的页面范围，别吞掉同站点其他应用或接口。浏览器刷新深层地址，应回到这个子目录下的入口，别错误返回另一个应用的 HTML，表面上有页面却不是原来那份代码。

3. 入口访问、详情直接打开、刷新、浏览器返回都要测，并看资源请求有没有路径重复或漏。hash 模式入口和资源也要能访问。片段不发给服务器，不等于子目录部署从此没有别的约束。
