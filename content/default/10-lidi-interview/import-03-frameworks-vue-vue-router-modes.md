# Vue Router 的 hash 和 history 模式有什么区别？

## 核心回答

1. hash 模式把前端位置放在 URL 片段里，例如 `/#/orders`，片段不会发送给服务器，比较适合不能配置页面路径回退的静态托管。history 模式使用 History API，地址可以直接是 `/orders`，站内跳转通常都不需要重新加载整份页面。

2. history 模式的重要边界是直接访问和刷新。浏览器会真正向服务器请求当前路径，服务器需要返回应用入口或对应服务端页面；只有首页文件而没有回退规则时，站内点击正常、刷新详情却不存在，是常见的部署问题。

3. 回退不能简单覆盖所有请求。前端页面路径可以回到入口，接口和静态资源仍应由各自服务处理，缺失脚本不能返回入口 HTML，否则会出现类型或解析错误；应用内部也需要处理不匹配路由，不能把所有未知页面都当成正常首页。

4. Vue Router 4 中常见 createWebHashHistory 和 createWebHistory，子目录部署还要配置合适的基础路径。SSR 等非浏览器环境还有相应的历史实现，不能在服务器直接依赖浏览器地址栏，选型要结合实际运行环境而不是只看 URL 是否好看。

5. 我会在能配合部署时考虑 history，受限环境可以选择 hash，并验证深层链接、前进后退、刷新与资源路径。history 不自动等于良好 SEO，内容渲染、元数据和状态码都很重要；hash 也不是完全不用配置，入口和静态资源仍必须能被正确访问。

## 追问：为什么不把所有 404 都改成返回 index.html？

1. 只有应由前端路由处理的页面路径需要这种回退，接口和脚本等资源有自己的语义。脚本文件缺失却返回 HTML，会让浏览器尝试把文档当脚本处理，真实的资源不存在反而被成功状态掩盖，排查更困难。

2. 我会按路径前缀、文件类型和托管配置明确区分应用页面、接口与静态文件。应用内部还要有未找到路由页面，服务端渲染场景根据需要返回真实状态，不能为了消除一个刷新错误把所有未知地址都变成首页。

3. 验证除了正常详情刷新，还要主动请求不存在的接口、图片和路由。它们应该得到各自合理的格式和状态，这比只确认 `/orders` 不再返回错误更全面，能够避免回退规则修好一处却破坏其他路径。

## 追问：应用部署在子目录，路由和资源要一起检查什么？

1. 路由基础路径要反映实际子目录，否则导航可能从 `/app/` 跳到站点根部。构建产物的资源基础地址也要配合，路由地址正确不代表脚本、样式和图片一定会从同一子目录加载，这两个配置不能混为一个。

2. 服务器回退应针对该应用的页面范围，而不是吞掉同站点其他应用或接口。浏览器刷新深层地址时，需要回到这个子目录下的入口，不能错误返回另一个应用的 HTML，表面上有页面却不是原来的代码。

3. 我会测试入口访问、详情直接打开、刷新和浏览器返回，并查看资源请求是否出现路径重复或遗漏。hash 模式也要保证入口与资源可访问，不能因为片段不发服务器，就认为子目录部署从此没有其他约束。
