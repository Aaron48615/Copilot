# TypeScript 函数重载和联合参数有什么区别？

## 核心回答

1. 联合参数表示一个位置可以接受几种类型，重载则把多种完整调用方式分别声明出来。我的选择依据是输入与返回值之间有没有需要保留的对应关系，而不是觉得签名写得越多，函数就设计得越专业。

2. 假设一个长度函数同时接收字符串和数组，两种输入都返回数字，用联合参数就很直接。实现中按输入类型处理即可，调用者即使手里已经是字符串或数组的联合变量，也不必为了调用它先做额外分支。

3. 假设另一个转换函数接收文字返回数字，接收数字返回文字，重载可以让具体调用得到更准确的返回类型。若只写一个联合参数加联合返回值，调用方即使传入明确的数字，也可能仍要判断返回结果是什么类型。

4. 重载只有一份运行时实现，前面的签名供调用方选择，最后的实现签名负责承接所有合法输入。实现必须自己判断分支，重载不会在运行时替我挑选多个函数体，也不能自动校验网络传来的数据。

5. 参数之间如果存在组合限制，还可以考虑元组联合；如果只是输入类型原样关联输出，泛型可能更简洁。具体选择要兼顾调用提示、联合变量能否传入以及后续维护成本，不必把所有函数都改成重载形式。

## 追问：字符串和数组各有一条重载，为什么联合变量反而传不进去？

1. 假设长度函数分别声明字符串重载和数组重载，调用处变量却可能是其中任意一种。类型检查需要找到能接受这个完整实参类型的公开签名，而两条签名各自只接收一种，未必有一条能够匹配。

2. 编译器不会为了这次调用自动把两条重载合并成新的联合签名，即使内部实现确实支持联合输入也一样。实现签名对外不可直接调用，所以看到函数体能处理两种值，不能推导出公开调用一定通过。

3. 如果两种输入都返回数字，我会优先改成联合参数，减少无意义的签名拆分。若业务必须保留不同返回关系，则可以评估增加明确的联合重载，或者让调用方先收窄，但要接受相应的返回类型和使用成本。

## 追问：参数之间有关联时，为什么两个独立联合类型可能表达不准确？

1. 假设一个示例接口允许传文字模式和字符串，或者数字模式和数字。如果把两个参数各自声明成联合类型，就还允许文字模式配数字，这种组合虽然每个参数单独合法，却不符合接口约定。

2. 两条重载可以分别列出合法组合，元组联合也可以把模式和值放在同一组参数中描述。关键是把它们一起变化的关系保留下来，而不是只扩大每个位置的取值范围，然后指望调用方自行记住限制。

3. 实现时还要依据模式检查对应数据，不能把声明当成外部输入验证。假如组合越来越多，可以考虑带标记字段的参数对象，让字段关系更容易阅读；是否调整应看真实调用场景，不能只为了展示类型技巧。
