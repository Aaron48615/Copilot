# TypeScript 函数重载和联合参数有什么区别？

## 核心回答

1. 联合参数表示一个位置可以接受几种类型；重载是把多种完整调用方式分别声明出来。看输入和返回值之间有没有需要保留的对应关系，不是签名写得越多函数就越专业。

2. 一个长度函数同时接收字符串和数组，两种输入都返回数字，用联合参数就很直接。实现里按输入类型处理即可。调用者手里已经是字符串或数组的联合变量，也不必为了调用它先做额外分支。

3. 另一个转换函数：文字进返回数字，数字进返回文字。重载可以让具体调用得到更准确的返回类型。只写一个联合参数加联合返回值，调用方即使传入明确的数字，也可能还要判断返回结果是什么类型。

4. 重载只有一份运行时实现。前面的签名给调用方选，最后的实现签名承接所有合法输入。实现必须自己判断分支。重载不会在运行时替你挑多个函数体，也不会自动校验网络传来的数据。

5. 参数之间有组合限制，可以考虑元组联合；只是输入类型原样关联输出，泛型可能更简洁。选型要兼顾调用提示、联合变量能不能传入、后面好不好维护。不必把所有函数都改成重载。

## 追问：字符串和数组各有一条重载，为什么联合变量反而传不进去？

1. 长度函数分别声明字符串重载和数组重载，调用处变量却可能是其中任意一种。类型检查要找到能接受这个完整实参类型的公开签名。两条签名各自只收一种，未必有一条能匹配。

2. 编译器不会为了这次调用，自动把两条重载合并成新的联合签名。内部实现确实支持联合输入，也一样。实现签名对外不能直接调用。看见函数体能处理两种值，推不出公开调用一定通过。

3. 两种输入都返回数字，优先改成联合参数，少拆无意义的签名。业务必须保留不同返回关系，可以评估增加明确的联合重载，或者让调用方先收窄，同时接受相应的返回类型和使用成本。

## 追问：参数之间有关联时，为什么两个独立联合类型可能表达不准确？

1. 示例接口允许传文字模式配字符串，或者数字模式配数字。两个参数各自声明成联合类型，就还允许文字模式配数字。每个参数单独合法，合在一起却不符合接口约定。

2. 两条重载可以分别列出合法组合；元组联合也可以把模式和值放在同一组参数里描述。要把它们一起变化的关系留下来，别只扩大每个位置的取值范围，然后指望调用方自己记住限制。

3. 实现时还要根据模式检查对应数据，声明当不了外部输入验证。组合越来越多，可以考虑带标记字段的参数对象，字段关系更好读。调不调整看真实调用场景，别只为了展示类型技巧。
