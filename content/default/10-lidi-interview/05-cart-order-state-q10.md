# 轻购的收货地址新增、编辑和选择是怎么做的？

## 核心回答

1. 地址页有列表、新增和编辑模式，列表请求 `/p/address/list` 后把后端字段转换成 Vant 需要的 id、name、tel、address 与 isDefault。转换是为了适配组件，真实地址 ID 仍要保留，不能用显示顺序代替后端标识。

2. 编辑时填写姓名、手机号、详细地址，再用地区级联选省市区。当前按层加载，先取省，选择后请求下一级，减少一次加载全部地区；上级改变时应清空下级旧选择，避免省市区 ID 来自不同路径。

3. 保存时组织 receiver、mobile、addr 与省市区名称和 ID，新增调用 addAddress，编辑调用 updateAddress 并带当前地址 ID。前端格式校验方便用户修正，服务端仍要检查地址归属和地区关联，不能只相信选择器生成的参数。

4. 从购物车或确认页进入时，query.from 为 cart 或 order，页面作为地址选择页。当前选择一条地址会先设为默认再返回，原页面重新读取默认地址；这会改变长期默认值，不只是本次订单的局部选择，用户这次选择会影响下一次下单默认显示的地址。

5. 管理模式支持设置默认，当前删除默认地址前要求先更换默认地址。这个限制减少当前流程空地址情况，但不代表后端无需处理无地址；如果继续完善，我会区分本次配送选择与全局默认，并验证快速级联、保存失败和删除后的恢复。

## 追问：为什么选择一次收货地址不一定应该修改默认地址？

1. 用户可能只是这次寄到公司，以后仍想默认寄到家。当前为了让返回页面读取最新默认地址，选择时直接设置默认，实现方便但影响长期偏好；如果不说明，用户可能不知道下一单的地址也会变。

2. 如果继续完善，我会让选择模式返回本次 addrId，由确认页保存本次选择，而设置默认保留为独立管理动作。这样短期订单上下文与地址簿偏好分开，用户操作的后果更直观。

3. 返回后仍要重新读取该地址并确认费用，不能直接信任传来的完整对象。测试单次选择后默认地址是否保持、刷新后本次选择如何恢复，以及地址被删除时的提示，避免优化体验后引入失效地址。

## 追问：快速切换省份，为什么也会出现请求乱序？

1. 选择省 A 后请求城市，紧接着选省 B，如果 A 的城市最后返回并直接赋值，页面就可能显示 B 省配 A 市。这个错误不只是列表看起来奇怪，还可能把互不对应的地区 ID 提交给后端。

2. 如果继续完善，我会在上级变化时清空下级值与选项，并给城市请求绑定省 ID 或请求编号。返回后只接受仍对应当前省的结果，loading 和错误也按同样规则管理，旧失败不能覆盖新选项。

3. 后端保存时还要核对地区层级，防止绕过页面直接提交错误组合。验证让 A 省响应最后到、B 省失败、编辑旧地址后重新选择三种场景，检查显示名称和提交 ID 始终属于同一条地区路径。
