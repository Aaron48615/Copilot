# 为什么选择 Vue 3、TypeScript 和 Vant？

## 核心回答

1. 我选这套技术主要是看项目形态。轻购是移动端商城，搜索、商品卡片、地址列表和提交栏出现得很多，Vant 已经提供了这些交互，我可以把精力放在商品数据、规格选择和页面状态上，也比较容易保持操作方式一致。

2. Vue 3 的组合式 API 比较适合按功能组织逻辑。比如搜索页里，关键词、建议列表、防抖定时器和请求清理是相关的一组内容，用 script setup 可以顺着输入到结果的过程阅读；逻辑变长后，再考虑抽成组合函数。

3. TypeScript 用来写清接口结构，而不只是给变量标注 string。项目里的 GuideResult 会描述推荐商品和匹配信息，访问 prodId 或 recommendations 时能得到提示，改字段时也更容易发现影响范围，但接口真实返回值仍需要另外检查。

4. Axios 负责统一 baseURL、超时、Token 和登录失效，页面只调用业务 API。Vue Router 把不同页面拆开，并通过动态 import 按需加载；Vite 帮助启动开发环境和产出构建文件，这些工具分工比较清楚。

5. 我没有据此认定其他框架不合适。对这个规模的项目，熟悉的开发方式和移动端组件支持更重要；如果为了证明技术多而再加入几套状态管理或组件库，反而会增加学习、样式协调和维护成本。

## 追问：用了组件库，前端还需要自己处理什么？

1. 组件库解决的是基础交互，例如步进器告诉我用户想改成多少件。库存是否允许、接口要最终数量还是差值、请求失败后显示什么，都需要我根据业务接口决定，组件本身并不了解购物车规则。

2. 页面之间的数据也要自己组织。地址列表组件能展示地址，但从订单页进入时要进入选择模式，选完后还要更新确认页金额，这些涉及路由参数、接口调用顺序和状态恢复，不能靠换一个组件自动完成。

3. 我还会检查手机上的实际效果，包括长商品名、大图片、键盘弹出后的输入区域和加载时的重复点击。组件库能减少基础工作，却不能保证放进具体布局后就没有遮挡、滚动或操作反馈的问题。

## 追问：TypeScript 会不会让小项目开发变慢？

1. 开始定义接口时确实多写一些代码，尤其后端字段还在调整时需要同步修改。但购物车和导购都存在嵌套结构，提前说明哪些字段可空，比在多个模板里猜字段名更容易发现问题。

2. 我会先给关键边界补类型，例如商品、SKU、订单确认参数和 GuideResult，不会一开始设计复杂泛型。普通局部变量可以用类型推断，这样能把额外工作放在容易出错、确实需要约束的位置。

3. 如果接口暂时不确定，我会保留不确定性并检查后再使用，而不是用类型断言硬说它正确。类型检查能减少开发期错误，但无法证明价格真实或后端没有漏字段，所以也不能用通过编译代替页面验证。
