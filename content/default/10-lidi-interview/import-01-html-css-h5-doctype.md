# DOCTYPE 是干什么的？

## 核心回答

1. DOCTYPE 是 HTML 文档前面的声明，现代页面通常使用 `<!DOCTYPE html>`，主要作用是让浏览器选择标准相关的渲染模式。它不是普通 HTML 标签，也不是加载某套功能的开关；写上它不会自动让浏览器获得某个新 API。

2. 缺少声明或使用某些历史声明时，浏览器可能进入怪异模式或有限怪异模式，以兼容早期页面。怪异模式会保留一些历史布局行为，盒尺寸等表现可能与现代标准预期不同，但不能把它概括成所有元素都等同于显式设置 border-box。

3. 我通常把声明放在文档最前部、html 之前，保持模板简单一致。严格来说不必是物理上的第一行，标准允许前面有特定空白或注释等内容；面试里可以说“放在文档开头”，没有必要给出“前面一个换行都不允许”的错误限制。

4. 检查时可以看 document.compatMode：BackCompat 表示怪异模式，CSS1Compat 表示非怪异模式，但不能据此区分完整标准与有限怪异模式。它和 JavaScript 的 use strict 不同，一个影响文档兼容行为，一个约束脚本语义，排查问题时不能混用。

5. 实际项目还可能通过模板或服务端生成页面，我会检查最终返回的文档，而不是只看源码入口有声明。不同错误页或独立页面若使用了另一份模板，模式仍可能不同，这可以解释为什么同站点只有某一页尺寸异常。

## 追问：补上 DOCTYPE 后旧页面为什么反而错位？

1. 旧页面可能依赖怪异模式的历史尺寸规则，切换后同样的 width、padding 或表格布局不再得到原来的结果。声明补正确了不代表原来的样式假设也正确，因此会出现以前看起来正常、现在某些盒子变宽的现象。

2. 我会先记录原模式和具体差异，再用盒模型图检查哪些组件依赖旧计算，按需显式设置 box-sizing 或修正尺寸。不能为了恢复一张截图就把声明删回去，也不应一次全局修改所有宽高而不检查影响。

3. 改造时保留几个代表页面进行比较，尤其是表单、表格和固定尺寸区域。如果范围很大，就逐步统一模板与组件规则；最终目的是让行为有明确依据，而不是在兼容模式中继续积累无法解释的补偿值。

## 追问：DOCTYPE 和 meta charset 各自解决什么问题？

1. DOCTYPE 主要影响文档的渲染兼容模式，meta charset 说明文本编码，两者处理的问题不同。页面中文乱码时，应检查编码和响应内容，不应指望补一个 DOCTYPE 就能把已经错误解码的字符恢复正常。

2. 反过来，页面尺寸异常也不一定与 charset 有关。字符编码正确只能保证字节能被正确理解为文本，后续 DOM、样式和布局仍有自己的规则；需要根据是文字损坏还是几何位置变化选择排查方向。

3. 我会在基础模板里同时保持现代声明和 UTF-8 编码说明，并检查服务端响应头。这样能避免常见入口问题，但遇到具体异常仍要读证据，不能把两个都放在 head 附近的声明视为相同的“兼容配置”。
