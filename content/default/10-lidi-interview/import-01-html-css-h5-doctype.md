# DOCTYPE 是干什么的？

## 核心回答

1. DOCTYPE 是 HTML 文档前面的声明，现代页面通常写 `<!DOCTYPE html>`，主要让浏览器选标准相关的渲染模式。它不是普通 HTML 标签，也不是加载某套功能的开关。写上它，浏览器不会自动多出某个新 API。

2. 缺声明，或用了某些历史声明，浏览器可能进怪异模式或有限怪异模式，用来兼容早期页面。怪异模式会留下一些历史布局行为，盒尺寸等表现可能跟现代标准预期不同。别把它概括成所有元素都等同于显式设置了 `border-box`。

3. 声明放在文档最前部、`html` 之前，模板保持简单一致。严格说它不必是物理上的第一行，标准允许前面有特定空白或注释。可以说「放在文档开头」，不必说成「前面一个换行都不允许」。

4. 检查可以看 `document.compatMode`：`BackCompat` 是怪异模式，`CSS1Compat` 是非怪异模式，但区分不了完整标准和有限怪异模式。它跟 JavaScript 的 `use strict` 也不是一回事：一个影响文档兼容行为，一个约束脚本语义，排查时别混用。

5. 实际项目页面可能由模板或服务端生成，得看最终返回的文档，别只看源码入口有声明。不同错误页或独立页面如果用了另一份模板，模式仍可能不一样，这就能解释同站点为什么只有某一页尺寸异常。

## 追问：补上 DOCTYPE 后旧页面为什么反而错位？

1. 旧页面可能依赖怪异模式的历史尺寸规则。一切换，同样的 `width`、`padding` 或表格布局不再得到原来的结果。声明补对了，原来的样式假设不一定还对，以前看着正常、现在某些盒子变宽，就这么来的。

2. 先记下原来的模式和具体差异，再用盒模型图看哪些组件依赖旧计算，按需显式设 `box-sizing` 或修正尺寸。别为了恢复一张截图把声明删回去，也别一次全局改所有宽高却不看影响。

3. 改造时留几个代表页面做比较，尤其是表单、表格和固定尺寸区域。范围很大就逐步统一模板和组件规则。最终是让行为有明确依据，别在兼容模式里继续堆说不清的补偿值。

## 追问：DOCTYPE 和 meta charset 各自解决什么问题？

1. DOCTYPE 主要影响文档的渲染兼容模式，`meta charset` 说明文本编码，两件事不一样。页面中文乱码，查编码和响应内容。补一个 DOCTYPE，已经错误解码的字符恢复不了。

2. 反过来，页面尺寸异常也不一定跟 charset 有关。字符编码正确，只保证字节被正确理解成文本，后面的 DOM、样式、布局还有自己的规则。文字损坏还是几何位置变了，排查方向不一样。

3. 基础模板里同时保持现代声明和 UTF-8 编码说明，并检查服务端响应头。常见入口问题能少很多。遇到具体异常还是读证据，别把两个都放在 `head` 附近的声明当成同一套「兼容配置」。
