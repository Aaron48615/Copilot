# keep-alive 是什么？怎么工作的？

## 核心回答

1. `KeepAlive` 是 Vue 内置组件，用来缓存被切换掉的组件实例。普通动态组件切走通常卸载，再回来重新创建；包住以后局部状态还在，适合列表返回、页签切换这种还要接着刚才操作的场景。缓存的不是一张静态截图，是还活着的实例。

2. `include`、`exclude` 按组件 `name` 选缓存谁、排除谁；`max` 限制份数，超出按最近使用淘汰，Vue 3 这边是 LRU：最久没访问的先走。`name` 和 `key` 要合理。每次变化的查询参数都当成新身份，同一个页面可能留很多份，内存跟着涨。

3. 缓存组件走 `activated`、`deactivated`，组合式是 `onActivated`、`onDeactivated`。第一次挂上也会激活。停用不是最终卸载，销毁钩子这时不会跑。轮询、观察器停用时暂停，激活时恢复；真正移出缓存，不能继续用的资源还是要放掉。

4. 实例留着，不等于数据一定新、滚动位置一定对、后台任务一定停。返回订单列表可以留筛选和草稿，订单状态按业务该刷新还是要刷新。图表也可能要重新量容器。组件没重建，外面条件照样可能变了。

5. 哪些状态值得留，再定缓存范围和失效规则。路由页通常按 `RouterView` 给的组件合适地包一层，细节跟路由版本走。进入、离开、返回、淘汰、账号切换都要过，别让方便变成旧数据和残留资源。

## 追问：include 配置了名字，为什么组件仍然没有被缓存？

1. 匹配的是组件 `name`，不是路由路径，也不是随便起的标签别名。组件名称和路由记录的 `name` 是两回事。路由 `name` 写对了，`KeepAlive` 也不一定能对上那个组件，实际值要核对。

2. `script setup` 的名称推断和显式声明跟版本有关。适用版本可以用 `defineOptions` 指定。再看 `KeepAlive` 直接管的到底是不是预期那个组件。路由插槽又包一层，或 `key` 一直在变，缓存身份可能跟想的不一样。

3. 组件里输入草稿，切走再回来，同时看挂载和激活行为。页面出得快证明不了实例被缓存，代码模块和接口缓存也能让重新挂载很快。要用状态和生命周期证据区分。

## 追问：退出登录时，缓存页里的个人数据怎么处理？

1. 删掉认证信息，不会自动清空所有缓存实例。用户资料、草稿还可能留在组件状态里。缓存范围要跟身份生命周期对上：切换会话时重建相应缓存区域，或明确拿掉带个人数据的页面状态。

2. 没完成的请求要取消或标失效，免得清空以后旧响应又把数据填回去。公共分类可以按业务继续复用；个人订单、地址、权限相关内容不能无条件跨账号留着。

3. 连续登两个测试身份，返回历史页时看会不会闪一下上一个人的内容，轮询有没有重复。登录页显示成功还不够，缓存实例、查询结果、外部资源都要进新会话的正确范围。
