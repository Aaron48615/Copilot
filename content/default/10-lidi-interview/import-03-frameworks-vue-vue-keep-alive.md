# keep-alive 是什么？怎么工作的？

## 核心回答

1. KeepAlive 是 Vue 的内置组件，用来缓存被切换的组件实例。普通动态组件切走后通常卸载，再回来重新创建；被缓存后可以保留局部状态，适合列表返回、页签切换等需要继续之前操作的场景，缓存的不是一张静态截图。

2. include、exclude 可以按组件名称选择缓存对象，max 限制缓存数量，超过上限时会按最近使用情况淘汰。组件名称和 key 要合理，若把每次变化的查询参数都作为新身份，可能为同一个页面保留很多份实例，内存成本也随之增加。

3. 缓存组件使用 activated、deactivated，组合式对应 onActivated、onDeactivated。首次挂载也会激活，停用不等于最终卸载；轮询和观察器可以在停用时暂停，激活时恢复，最终移出缓存时仍要释放不能继续使用的资源。

4. 保留实例不会自动保证数据新鲜、滚动位置正确或后台任务停止。比如返回订单列表时可以保留筛选和草稿，但根据业务变化刷新订单状态；图表也可能需要重新测量容器，不能因为组件没有重建就假设所有外部条件都没变化。

5. 我会先判断哪些状态值得保留，再确定缓存范围和失效规则。路由页面通常按 RouterView 提供的组件进行合适包裹，细节遵循路由版本；验证进入、离开、返回、淘汰以及账号切换，确保缓存带来的便利没有变成旧数据和残留资源问题。

## 追问：include 配置了名字，为什么组件仍然没有被缓存？

1. 我会先确认匹配的是组件 name，而不是随意认为等于路由路径或标签别名。组件名称与路由记录名称是不同概念，写对路由 name 不代表 KeepAlive 一定能匹配到那个组件，实际值需要核对。

2. script setup 的名称推断和显式声明与版本有关，可以在适用版本通过 defineOptions 指定。再检查被 KeepAlive 直接管理的到底是不是预期组件，路由插槽包装层或 key 变化也可能让实际缓存身份与想象不同。

3. 验证时在组件里输入草稿，切走再返回，并观察挂载和激活行为。只看页面出现得很快无法证明实例被缓存，代码模块和接口缓存也可能让重新挂载很快，需要用状态与生命周期证据区分。

## 追问：退出登录时，缓存页里的个人数据怎么处理？

1. 删除认证信息不会自动清空所有缓存实例，用户资料和草稿仍可能保留在组件状态中。需要让缓存范围和身份生命周期对应，例如切换会话时重建相应缓存区域，或明确移除包含个人数据的页面状态。

2. 未完成请求也要取消或标记失效，避免清空后旧响应又把数据填回去。公共分类等数据可以按业务继续复用，但个人订单、地址和权限相关内容不能无条件跨账号保留，缓存策略必须区分数据归属。

3. 我会连续登录两个测试身份，检查返回历史页面时是否短暂出现上一人的内容，并验证轮询没有重复。单看登录页已经显示成功还不够，真正需要确认的是缓存实例、查询结果和外部资源都进入了新会话的正确范围。
