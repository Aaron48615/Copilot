# sticky 和 fixed 怎么选？

## 核心回答

1. 按要不要一直固定、属不属于局部滚动范围来选。`fixed` 通常用于全页面悬浮入口、固定底栏，退出普通文档流，不给自己留坑。`sticky` 从正常位置开始，在滚动约束下保持可见，更适合文章目录、分组标题和表头。

2. `sticky` 受最近滚动容器和包含块边界影响，滚到所属区域末尾后不会无限停着。比如商品详情区的目录，只需要在详情区存在时吸顶，用 `sticky` 比额外监听滚动再切换 `position` 更直接。前提是有阈值，也有足够的可移动空间。

3. `fixed` 常见参照是视口，但非 `none` 的 `transform` 等祖先可能改包含块，所以「全屏固定」还要求挂载结构合适。它也会挡住正常内容，固定底栏要给最后一段正文留空间。`sticky` 留着原位置，通常不需要同样的占位补偿，但仍可能盖住滚过的内容。

4. 小屏和可访问性也要看。固定区域太高会挤阅读空间，长目录吸顶可能让底部链接很难点到。滚到末尾、字体放大、软键盘出现都要测。必要时窄屏简化或取消固定，别为了全端一致硬撑同一种定位。

5. 页面已有固定导航时，局部吸顶区域还要避开导航高度，否则它虽然按零偏移吸住，实际却躲在导航下面。偏移来自明确的布局尺寸，导航换行以后是否还一致也要查。别把遮挡误判成定位方式选错。

## 追问：吸顶导航为什么不优先用 scroll 监听切换 fixed？

1. 切换 `fixed` 会让元素退出正常流，通常还要补占位高度、量阈值、处理窗口变化。导航高度因字体或文案变了，原来的测量可能失效。结构合适时，`sticky` 可以直接由浏览器处理这些布局约束。

2. 如果只是滚到顶部后保持导航可见，先验证 CSS 能不能满足，再考虑是不是真的需要 JavaScript。需要额外业务行为，比如进入某一区域更新状态，可以单独观察状态，不必因此把基础吸顶也全部改成手写滚动算法。

3. 确实超出 `sticky` 能力时，再明确监听、读写顺序和清理，避免每个滚动事件都强制量布局。看需求要不要，别因为「JS 更灵活」就默认背上更多复杂度和测试成本。

## 追问：什么情况下应该取消小屏上的 sticky 侧栏？

1. 侧栏本身很长、占了大部分可见高度，或小屏布局已经变成单列时，持续吸顶可能挡住主要内容。字体放大以后，原本不高的目录也会换行变高。桌面默认效果代表不了小屏好不好用。

2. 可以在相应宽度或内容布局下恢复普通流，把目录折成一个明确按钮，或者只在需要时展开。方案应让用户容易回到内容，别为了留一个吸顶效果，再加多个很难发现的小滚动区域。

3. 测最后一项链接、正文锚点、浏览器返回后的滚动位置。取消 `sticky` 以后阅读更顺，视觉不完全一致是可以接受的。响应式调整就是为了适应可用空间，不是强行保持所有设备定位方式相同。
