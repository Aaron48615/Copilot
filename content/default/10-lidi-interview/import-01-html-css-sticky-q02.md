# sticky 和 fixed 怎么选？

## 核心回答

1. 我会根据是否需要一直固定、是否属于局部滚动范围来选。fixed 通常用于全页面悬浮入口、固定底栏等，退出普通文档流，不为自己保留占位；sticky 则从正常位置开始，在滚动约束下保持可见，更适合文章目录、分组标题和表头。

2. sticky 受最近滚动容器与包含块边界影响，滚到所属区域末尾后不会无限停留。比如一个商品详情区的目录，只需要在详情区存在时吸顶，用 sticky 比额外监听滚动再切换 position 更直接；前提是有阈值和足够的可移动空间。

3. fixed 常见参照是视口，但非 none 的 transform 等祖先可能改变包含块，所以“全屏固定”还要求挂载结构合适。它也会遮住正常内容，固定底栏要给最后一段正文留空间；sticky 保留原位置，通常不需要同样的占位补偿，但仍可能覆盖滚过的内容。

4. 最终还要看小屏和可访问性。固定区域太高会挤压阅读空间，长目录吸顶可能让底部链接难以访问。我会测试滚动到末尾、字体放大和软键盘出现，必要时在窄屏简化或取消固定行为，而不是为了全端一致坚持同一种定位。

5. 页面已有固定导航时，局部吸顶区域还要避开导航高度，否则它虽然按零偏移吸住，实际却躲在导航下面。我会让偏移来自明确的布局尺寸，并检查导航换行后是否仍然一致，避免把遮挡误判成定位方式选错。

## 追问：吸顶导航为什么不优先用 scroll 监听切换 fixed？

1. 因为切换 fixed 会让元素退出正常流，通常还要补占位高度、测量阈值并处理窗口变化。导航高度因字体或文案改变时，原来的测量可能失效，而 sticky 可以在合适结构下直接由浏览器处理这些布局约束。

2. 如果只是滚到顶部后保持导航可见，我会先验证 CSS 能否满足，再考虑是否真的需要 JavaScript。需要额外业务行为，例如进入某一区域更新状态，可以单独观察状态，不必因此把基础吸顶也全部改成手写滚动算法。

3. 确实需要超出 sticky 能力的效果时，再明确监听、读写顺序与清理，避免每个滚动事件都强制测量布局。选择依据是需求是否需要，而不是“JS 更灵活”就默认承担更多复杂度和测试成本。

## 追问：什么情况下应该取消小屏上的 sticky 侧栏？

1. 当侧栏本身很长、占据大部分可见高度，或小屏布局已经变成单列时，持续吸顶可能挡住主要内容。尤其字体放大后，原本不高的目录也会换行变高，默认桌面效果不能直接代表小屏可用性。

2. 可以在相应宽度或内容布局下恢复普通流，把目录折叠成一个明确按钮，或者让它只在需要时展开。具体方案应让用户容易返回内容，不要为了保留一个吸顶效果，再增加多个难以发现的小滚动区域。

3. 我会测试最后一项链接、正文锚点和浏览器返回后的滚动位置。若取消 sticky 后阅读更顺畅，视觉不完全一致是可接受的；响应式调整的目的就是适应可用空间，而不是强行保持所有设备的定位方式相同。
