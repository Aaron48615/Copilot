# 表格表头吸顶要注意什么？

## 核心回答

1. 表头吸顶首先要明确滚动发生在哪里。如果表格放在固定高度、overflow: auto 的容器中，表头通常相对这个容器吸顶；如果希望跟随页面视口，就不能让中间无意出现另一个滚动祖先。先确定参照，再设置 top 等阈值，才知道它应该停在哪里。

2. 实现时可以在合适的表头单元格上使用 sticky，并设置不透明背景和明确层级，让滚动经过的正文不会透在文字后面。表头边框也要检查，尤其是折叠边框模型与粘性绘制组合时，不能仅看空表格正常就认为数据滚动后也不会出现边线异常。

3. 如果表格同时固定首列，需要分别安排正文、固定列、表头和左上角交叉单元格的层级。左上角既要随纵向吸顶又要在横向保持可见，通常需要覆盖另外两类固定区域；这是一组局部关系，不应直接把整个表格提高到页面弹窗之上。

4. 多行表头还要处理各行的偏移，不能每行都写 top: 0 相互叠在一起。我会测试横纵滚动、长表头换行、缩放以及不同目标浏览器，同时保留 th 和 scope 等语义。尽量让表头与正文共享真实列布局，避免拆成两张表后再手动同步宽度。

## 追问：表头和首列都固定时，左上角单元格怎么处理？

1. 左上角属于两个固定方向的交叉点，需要同时设置相应的顶部与行内起始偏移，并有不透明背景。只设置纵向 sticky 会在横向滚动时跟着走，只设置横向又会在纵向滚动时消失，两种约束要按实际方向组合。

2. 层级上让普通数据最低，固定列与表头高于普通数据，再让交叉单元格高于这两者。数字本身可以很小，只要在同一局部上下文里关系明确；不要为了交叉覆盖把单元格设到全页面最高，影响外部菜单和弹窗。

3. 验证时横向和纵向同时滚到中间位置，看文字是否透出、边框是否连续、交叉处是否重叠。还要检查首列宽度变化或文字换行，偏移与背景范围都应跟随真实单元格，不能只对第一屏的固定尺寸成立。

## 追问：多行表头的 top 偏移怎样避免写死后重叠？

1. 第二行需要避开第一行占用的高度，第三行还要继续累计，所以所有行都写 top: 0 会相互覆盖。如果表头高度可以明确且稳定，可以用统一的尺寸变量表达；若会换行，固定一个估计值就不可靠。

2. 我会尽量简化表头结构，并先确认能否按合适的整体表头区域吸顶。确实需要分别控制各行时，再根据实际高度管理偏移，必要时观察尺寸变化，但要避免测量更新反过来引起循环布局，增加滚动开销。

3. 测试包含长字段名称、字体放大和容器变窄，因为这些都会改变行高。表头拆成单独表格虽然看似方便，却引入列宽同步和语义问题；只有明确需要时才选择，并同时验证数据列对齐，不能只修顶部重叠。
