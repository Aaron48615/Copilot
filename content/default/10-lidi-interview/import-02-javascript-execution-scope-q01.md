# 闭包到底保存了什么？

## 核心回答

1. 闭包就是函数还能沿着定义时那层关系，用到外面的变量。不是外层函数返回时，把当时所有变量的值打包复制一遍，所以后面再读，可能看到后来的变化。

2. 外层函数创建一个计数变量，再返回一个递增函数，每次调用都能继续用这次创建的计数。外层调用已经结束，但返回的函数还在，计数那个变量就不能跟着调用结束一起丢掉。

3. 同一次外层调用返回的多个函数，可以共用同一个变量，一个改了另一个能读到。分别调用外层函数，通常各自一份环境，两个计数器可以各自涨，不是所有闭包都共用一份状态。

4. 循环里的差异常来自变量共不共享。`var` 写循环变量，多个延迟回调可能读到同一个变量的最终值。`for` 循环头部用 `let`，每一圈有自己的变量，回调才能各自拿到那一圈的值。

5. 闭包本身不等于内存泄漏，问题在于本该结束的引用是不是还留着。引擎也可能优化掉没用到的变量，不能断言它一定完整留下整个外层作用域。排查看实际保留路径，别只看函数嵌套了几层。

## 追问：两个计数函数什么时候共享状态，什么时候互不影响？

1. 一次外层调用创建变量，返回递增和读取两个函数，它们访问的是同一次调用建起来的那个变量。先递增再读取，会得到改过之后的值。闭包握的是访问关系，不是两份初始快照。

2. 外层工厂调用两次，每次内部都创建计数变量，就会得到两组独立状态。边界是创建环境的次数，不是内部函数代码长得像不像。同一段函数代码可以连着不同环境。

3. 变量指向的对象是不是来自外部，也要留意。工厂调用了两次，两次传入同一个对象，闭包仍可能共同改那个对象。变量各自一份，不意味着整条引用链上的数据都已经复制隔离。

## 追问：闭包引用了大对象，怎样判断它是否造成内存泄漏？

1. 先确认业务还要不要这个闭包：缓存回调、全局监听、定时器还有没有用途。大对象被留下不一定是泄漏。生命周期已经结束却仍放不掉，才是要排查的情形。

2. 页面关了内存还持续涨，重复打开关闭后比较堆快照，沿保留路径查是谁握着函数。重点是从长期活着的对象，到闭包，再到数据的引用链。看见闭包就下结论，太早了。

3. 确认是忘了取消订阅，候选修复是解除订阅并摘掉相应引用，再用同样操作看增长趋势。单纯把某个局部变量设成 `null` 未必够，监听列表或其他缓存可能还握着同一份数据。
