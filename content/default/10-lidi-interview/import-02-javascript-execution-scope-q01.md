# 闭包到底保存了什么？

## 核心回答

1. 闭包可以理解为函数及其定义时所关联的外部词法环境，重点是还能沿着这层关系访问外部变量。它不是外层函数返回时，把当时所有变量的值打包复制一遍，所以后续读取可能看到变化。

2. 例如外层函数创建一个计数变量，再返回一个递增函数，每次调用都能继续使用这次创建的计数状态。外层调用已经结束，但返回函数仍然可达，计数所需的绑定就不能简单随调用结束一起丢掉。

3. 同一次外层调用返回的多个函数，可以共享同一个变量，一个函数修改后另一个能读到。分别调用外层函数则通常创建独立环境，所以两个计数器可以各自增长，不是所有闭包都共用一份状态。

4. 循环中的差异常来自绑定是否共享，用 var 循环变量注册多个延迟回调，它们可能读取同一变量的最终值。使用 for 循环头部的 let 声明时，每轮会建立对应绑定，回调才会保留各自那轮的访问关系。

5. 闭包本身并不等于内存泄漏，问题在于本应结束的引用关系是否仍被保留。引擎也可能优化未使用的变量，因此不能断言它一定完整保留整个外层作用域；排查应看实际保留路径，而不是只看函数嵌套。

## 追问：两个计数函数什么时候共享状态，什么时候互不影响？

1. 如果一个外层调用创建变量，并返回递增和读取两个函数，它们访问的是同一次调用建立的绑定。先递增再读取，会得到修改后的值，这能说明闭包持有的是访问关系，而不是两份初始快照。

2. 如果外层工厂被调用两次，每次都在内部创建计数变量，就会得到两组独立状态。这个边界是创建环境的次数，而不是内部函数的代码长得是否相同，同一段函数代码可以对应不同环境。

3. 还需要留意变量指向的对象是否来自外部。即使工厂调用了两次，如果两次传入同一个对象，闭包仍可能共同修改那个对象；绑定独立不意味着整条引用链上的所有数据都已经复制隔离。

## 追问：闭包引用了大对象，怎样判断它是否造成内存泄漏？

1. 先确认业务是否还需要这个闭包，比如缓存回调、全局监听或定时器是否仍有用途。大对象被保留不一定是泄漏，只有生命周期已经结束却仍无法释放，才符合需要排查的情形。

2. 假如页面关闭后内存持续增长，我会在重复打开关闭后比较堆快照，并沿保留路径查找是谁保存函数。重点是从长期存活的对象到闭包再到数据的引用链，而不是看到闭包就直接下结论。

3. 如果确认是忘记取消订阅，候选修复应是解除订阅并移除相应引用，再用同样操作验证增长趋势。单纯把某个局部变量设为空未必够，因为监听列表或其他缓存可能仍然持有同一份数据。
