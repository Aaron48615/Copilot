# 城市视图中的地图和 3D 数据柱是怎么实现的？遇到性能问题怎么办？

## 核心回答

1. 地图用高德 JS API。初始化时加载脚本、创建实例，再按城市列表画 marker、AQI 圆圈和信息窗。实例和覆盖物放 ref，城市或环境模式变了就更新对应对象，卸载再清。别在每次 React 渲染里把整张地图重建一遍。

2. 3D 页用 React Three Fiber，用 React 组件把 Three.js 场景组织起来。用户切换人口、面积或 GDP，城市柱体按当前指标改高度，能旋转，悬停能看原始值。地图和 3D 是两套展示，别当成同一张地图图层来讲。

3. 现在柱高是当前值除以最大值，再乘 4.8 加 1.2，用来控制展示尺度。颜色按排序后的索引从固定数组里取，主要是把柱子区分开，不表示数值渐变。加了基础高度，也不是严格的零基线比例，要比准还是看原始值。

4. 性能问题先分开看：脚本加载、接口、React 更新、WebGL 绘制。首屏慢，多半是资源或初始化；拖动卡，才更像渲染。先看 Network 和 Performance 的具体表现，再决定少画标记、复用对象，还是减少高频更新。

5. 现在城市柱还是独立组件，没做实例化，也没有完整的二维降级。规模再大，先限制同时展示的数量，再评估聚合点位、`InstancedMesh` 和按需渲染。效果要在同样的城市数量和设备上比加载时间、帧率、内存，再决定这份优化留不留。

## 追问：地图和三维图都能展示城市，为何保留两种方式？

1. 地图适合看空间位置。比如某个事件在哪座城市、周边环境怎么样，用户能靠地理位置理解关系。三维柱更偏向看指标大小、转着观察。两边回答的问题不一样，不只是视觉风格不同。

2. 3D 有遮挡和透视，远处的柱子看起来可能更小，精确比较不一定比二维柱状图方便。现在悬停能看原值，方便核对。能旋转，不等于更准确，也不等于更专业的数据分析。

3. 按任务选视图更合适，二维图表或表格仍可作为准确比较的入口。三维有没有价值，看用户是不是更容易把查看任务做完，别只放一个动画就认定体验更好。

## 追问：为什么 3D 动画不适合每帧调用 setState？

1. React 状态一变就会走组件更新。柱体缩放这种逐帧变化，可以直接改 Three.js 对象。每帧都 `setState` 会多出一堆调度，柱子一多，动画工作和页面业务更新容易搅在一起。

2. 现在在 `useFrame` 里按 `delta` 推进 group 的缩放，指标切换仍走正常状态更新。`delta` 是上一帧过了多久，不同刷新率设备上动画速度更接近。每帧固定加同一个数，速度不一定相同。

3. 以后如果开按需渲染，动画期间还得请求后续帧。直接改对象，框架状态不会自动知道变了。只改 `frameloop` 参数不够，旋转、动画、悬停还得确认仍在持续更新。
