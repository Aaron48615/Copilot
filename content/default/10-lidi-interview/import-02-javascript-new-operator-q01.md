# 箭头函数能用 new 吗？

## 核心回答

1. 箭头函数不能使用 `new`，执行时会抛出类型错误。根本原因是它没有内部的构造能力，而不是函数体写得太简单；即使它返回一个普通对象，或者里面写了赋值语句，也不会因此变成可以创建实例的构造器。

2. 它也没有自己的 `this`，使用的是定义位置外层的绑定。假设把箭头函数写成商品构造器并试图给 `this` 设置名称，这不仅不能通过 `new` 使用，直接调用时也不会自动获得一个新商品对象，设计意图就与语法语义冲突。

3. 箭头函数通常没有自己的 `prototype` 属性，但不能倒过来把是否存在这个属性当成完整判据。手动添加同名属性不会赋予构造能力，而绑定函数在目标可构造时可以被构造，即使它没有自己的这个属性，所以属性外观不足以判断行为。

4. 如果需求是创建具有共享实例方法的对象，我会使用普通可构造函数或 class。若只是把输入转换成一个对象，箭头函数完全可以作为工厂直接调用，这时返回的是自己明确创建的对象，不需要借助 `new` 的实例初始化过程。

5. 类里面的箭头函数字段也要分开理解：类本身可以被构造，不代表字段里的函数也可构造。假设字段用于事件回调，它捕获实例的 `this` 可能很方便，但每个实例都要创建自己的函数，是否采用应结合绑定需求和实例数量判断。

## 追问：给箭头函数补上 prototype 为什么仍然不能 new？

1. `prototype` 是可以从外部访问的属性，构造能力则是函数对象内部的一种能力，两者不等价。给箭头函数挂一个普通对象，只是在它身上多存了一项数据，没有改变运行时创建这个函数时确定的调用种类。

2. 执行 `new` 时，运行时会先确认目标可以被构造，而不是发现有同名属性就放行。因此即使添加了看起来完整的原型方法和 `constructor` 字段，仍然会在构造检查处失败，根本走不到按这些属性初始化实例的步骤。

3. 这个例子说明手写检测不能只用 `fn.prototype` 是否存在。假设工具函数必须接受构造器，我会通过明确的接口约束和运行时构造机制处理非法输入，并说明失败行为，而不是修改函数属性来试图修补一种不存在的内部能力。

## 追问：绑定函数没有自己的 prototype 为什么还能 new？

1. 绑定函数是否可构造取决于被绑定的目标。假设用普通构造函数创建一个预先填好部分参数的绑定函数，目标本来支持构造，绑定后的函数就保留相应能力；如果目标是箭头函数，绑定并不会让它突然支持构造。

2. 用 `new` 调用可构造的绑定函数时，预先绑定的参数仍会传入，但绑定的 `this` 不会用来替代新实例。例如原先绑定了一个外部对象，构造过程中也不会因此把实例字段写到那个外部对象上，初始化仍服务于构造调用。

3. 因此我会把绑定的两个用途分开：普通调用时固定接收者，构造调用时预置参数。它说明外部可见属性和内部能力并非一一对应，也解释了为什么判断函数能否构造时，不能单靠有没有自己的原型属性得出结论。
