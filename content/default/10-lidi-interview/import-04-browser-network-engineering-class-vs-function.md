# class 和 function 定义的构造函数有什么区别？

## 核心回答

1. class 和普通构造函数都建立在 JavaScript 的原型机制上，但 class 还有明确的行为约束。class 必须使用 new，直接调用会报错；普通函数是否能安全地直接调用取决于实现，也不是所有函数都能作为构造器。

2. class 声明的方法通常位于 prototype 上，并且不可枚举，多个实例共享这些方法。普通函数也能把方法放到原型，只是直接赋值创建的属性默认可枚举；如果把函数写成实例字段，则每个实例都会拥有自己的函数对象。

3. class 体内默认使用严格模式，声明在初始化前存在暂时性死区。普通函数声明可以在声明位置之前调用，但函数表达式还要看变量如何声明，所以不能把所有 function 写法都概括成没有初始化顺序限制。

4. 继承时 extends 建立实例和构造器之间的继承关系，子类构造器通常要先调用 super 才能使用 this。我的理解是 class 让原型写法更清晰，并不意味着对象变成传统语言的固定类型；选写法时还要考虑团队习惯和真实需求。

5. 例如多个用户对象共享一个格式化名称的方法，可以把它放到原型；每个实例的姓名等数据仍由构造过程分别保存。理解方法共享与实例数据的区别，比只记 class 更现代更有用，也能避免把可变数组错误地共享给所有实例。

## 追问：类方法和箭头函数实例字段，如何选择？

1. 普通类方法放在 prototype 上，由实例共享，但取出来单独当回调时可能丢失接收者。例如把对象的方法传给事件监听器，调用时的 this 不一定还是这个对象，需要绑定或通过包装函数调用。

2. 箭头函数字段捕获实例构造时的 this，作为回调通常更方便，但每个实例会创建自己的函数。少量组件实例时成本可能可接受，若要创建大量数据对象，就不应因为写起来方便而忽略内存差异。

3. 我会优先保留普通方法，在确实需要稳定回调身份和 this 时再选择绑定或箭头字段。移除事件监听器也要拿到当初同一个函数引用，临时重新 bind 一次会得到新函数，无法移除旧监听。

## 追问：为什么子类里调用 super 之前不能访问 this？

1. 派生类构造器的 this 需要通过父类构造过程初始化，super 调用负责建立这个实例上下文。提前读取或给 this 赋值会报错，这不是单纯为了要求代码顺序整齐，而是语言定义的初始化规则。

2. 例如父类负责创建基础字段，子类应先 super(name)，再设置自己的字段。父类构造器返回对象、私有字段初始化等情况还会影响细节，所以不能把它完全等价成普通函数里的 Parent.call(this)。

3. 实际使用时我会保持构造过程简单，避免父类构造器调用可能被子类覆盖且依赖未初始化字段的方法。这样不但更容易解释，也能减少继承层次中因为初始化先后顺序产生的隐蔽错误。
