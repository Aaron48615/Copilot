# 响应式图片怎么配合？

## 核心回答

1. 容器查询负责组件怎么排版，响应式图片负责下载什么资源和如何显示，两者需要配合但不会自动互相替代。卡片由横排变竖排后，图片可用宽度可能改变，只写 `width: 100%` 能改变显示尺寸，却不一定减少下载与解码成本。

2. 使用带宽度描述符的 srcset 时，sizes 描述预计的显示槽宽，浏览器结合像素密度等因素选择资源。sizes 中常见的媒体条件依据视口，并不会自动读取 CSS 容器查询结果，所以需要根据真实页面布局提供合理描述，不能简单认为容器变窄就一定选到小图。

3. picture 适合切换裁剪方向或图片格式，例如手机显示主体更集中的竖图，宽屏展示完整横图。img 的 object-fit 则控制已有资源怎样放进显示区域，cover 会裁切，contain 可能留白；这两者分别处理资源选择和盒内呈现。

4. 我会为图片提供宽高或稳定宽高比，减少加载时布局跳动，并让离屏图片按需加载。首屏关键图片不应机械地全部懒加载，避免拖慢主要内容出现。最后检查实际网络请求与显示质量，既不要小图被放大模糊，也不要所有卡片都下载原图。

## 追问：sizes 写成 100vw 为什么可能浪费流量？

1. 100vw 表示预计图片槽宽接近整个视口，而多列卡片里的图片可能只占其中一小部分。浏览器按照过大的预计宽度选择候选资源，即使 CSS 最终把图片缩小，已经请求的资源也可能明显超出需要。

2. 我会根据页面网格、侧栏和间距估算槽宽，并用媒体条件描述常见布局变化。比如宽屏多列时用相应的列宽，窄屏单列时接近可用内容宽度，而不是直接把设计稿图片宽度当作所有屏幕的答案。

3. 容器可以出现在多种位置时，还要检查这套估算是否仍成立，必要时由使用方提供布局信息。验证直接看网络面板与 currentSrc，并在不同像素密度和宽度下重复检查，不能只凭截图清晰就判断资源选择合理。

## 追问：图片用 object-fit: cover 后主体被裁掉怎么办？

1. cover 会让图片覆盖整个盒子，比例不一致时必然裁掉部分内容，这不是资源加载错误。可以先用 object-position 调整重点位置，例如把人物面部移到更合适的区域，但它只能改变裁切窗口的位置。

2. 如果宽窄布局需要完全不同的构图，可以通过 picture 提供不同裁剪版本。这样主体和背景能按场景重新安排，比在极端长宽比中反复微调位置更可靠，同时要维护好每种资源的尺寸与替代文本。

3. 对于商品细节或图表，完整信息往往比铺满盒子更重要，可以改用 contain 并接受留白。选择取决于图片用途，不应让所有图片共享一个 cover 规则，导致关键尺寸标注或商品边缘被悄悄裁掉。
