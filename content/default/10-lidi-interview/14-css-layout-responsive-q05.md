# `rem`、`vw` 和媒体查询怎么选择？

## 核心回答

1. 这三者解决的问题不一样，不是必须三选一的适配方案。`rem` 主要表达相对根字号的长度，`vw` 相对视口宽度，媒体查询则在条件满足时换一组样式，既能改尺寸，也能改页面结构。

2. 字号和阅读间距通常适合 `rem`，可以围着统一字号体系调。但 `rem` 本身不会随屏幕自动变，只有根字号变了才会缩放。根字号如果严格绑屏宽，所有文字也会跟着变，大屏可能过大，小屏可能难读。

3. `vw` 适合确实要跟视口相关的尺寸，比如横幅留白，但不适合不加限制地管所有文字。可以用 `clamp()` 给流动尺寸设上下限。组件在窄侧栏里，视口仍然很宽，单靠 `vw` 反映不出它真正拿到的空间。

4. 媒体查询适合内容放不下时调结构，比如双栏变单栏、导航换行。先用 Flex 或 Grid 的自然伸缩，再在内容开始挤的位置设断点，并测中间宽度和字体放大。断点为内容服务，不必围着几款手机型号逐个写规则。

5. 移动页面先要有正确的视口配置，不然浏览器可能按较宽的布局视口把整页缩小，媒体断点也就不是预期效果。先确认页面可用宽度，再讨论单位，别在错误参照上继续调根字号。

## 追问：clamp() 怎么兼顾缩放和可读性？

1. 它接受最小值、偏好值、最大值，比如 `clamp(1rem, 0.8rem + 1vw, 1.5rem)`。中间值随视口变，但最终被上下限卡住，比纯 `vw` 字号在超宽屏和窄屏上更可控。

2. 这里的数字只是示例，实际按标题层级和正文阅读需求调。正文留稳定的阅读大小，标题或留白再用更明显的流动变化。别让整个界面跟着窗口拖动不断改阅读节奏。

3. 浏览器缩放和用户默认字号变化也要测。表达式里带 `rem` 有助于响应字体基准，但不等于自动满足所有可访问性要求。放大后的换行、按钮高度、内容有没有被固定尺寸裁掉，都还得看。

## 追问：为什么桌面页面不一定适合整页 rem 等比缩放？

1. 桌面窗口变宽，往往意味着可以加列、扩大内容区，不意味着所有按钮和文字都该同比变大。把一张移动设计稿机械放大，可能得到巨大间距和过长的文字行，空间利用反而更差。

2. 主体容器给最大宽度，侧栏按合理范围取值，内容区用弹性轨道。窗口较小时再用媒体查询收起侧栏或改成单栏，正文大小维持可读。结构承担大部分适配工作。

3. 同一个组件会出现在不同宽度的区域，还可以考虑容器查询。卡片按所在栏宽切换图片和文字的排列，而不是所有卡片都跟着页面级断点一起切。复用时更符合真实空间。
