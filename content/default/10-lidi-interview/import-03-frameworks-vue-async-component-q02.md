# 异步组件失败怎么办？

## 核心回答

1. 加载失败先分清是网抖了一下、资源根本没有，还是模块代码自己报错。`defineAsyncComponent` 能配加载中组件、错误组件、延迟和超时。失败了还一直转圈，或者一块空白谁也看不懂，都不行。

2. `onError` 里按错误类型和已经试了几次，决定 `retry` 还是 `fail`。短暂断网回来可能成；路径写错、发布后旧分包删了，再试还是同样的失败。重试要有上限和间隔，别无限打。

3. 超时只说明等得太久了，不等于底下那次 `import` 已经停掉。错误界面要有能点的重试或返回。点重试得真的重新走加载，别只把提示清掉，结果又读到刚才那份失败。

4. 新版本发上去，旧页面还指着已经不存在的分包，要看入口和静态资源缓存怎么留。必要时提示刷新拿新入口，还要想未保存内容会不会丢。只在本地网很好时看组件出现一次，测不到这种发布问题。

5. 组件代码加载成功了，里面的业务接口失败是另一回事，错误组件不会自动把数据请求也接住。在不在 `Suspense` 下面，加载态由谁画也不一样。代码下载、组件渲染、内部请求，这三段分开说。

## 追问：设置 timeout 后，请求就一定终止了吗？

1. 不一定。`timeout` 管的是异步组件等多久、失败怎么展示，推不出动态 `import` 的网络已经掐掉。页面显示超时，服务器或浏览器那边可能还在干活。

2. 原来那次加载稍后成功了，恢复逻辑要防着两份初始化撞车。重试、错误态、实例创建得有明确顺序，超时以后别再随手插一个同样的组件进去。

3. 提示写成“加载时间较长，请重试”就行，别说操作已经完全取消。测试里把延迟拉长，覆盖超时后又成功、一直失败，看提示切得对不对，有没有重复挂上导致泄漏。

## 追问：什么样的错误不值得自动重试？

1. 路径确定错了、资源已经被删、模块语法直接报错，马上再请求一次通常好不了。反复重试只是多等、多打请求。尽早显示失败，给返回、刷新或找人修这些能做的动作。

2. 临时网络问题可以有限重试，但也要看人是不是已经离线、这个组件还要不要显示。弹窗关了还在后台无限加载，没意义。重试时机跟当前界面一致。

3. 记下错误类型、资源地址、发布版本，别只统计一个失败总数。部署问题和网抖处理不一样：一个是资源保留策略，一个是等待和提示，别给所有错误统一加次数。
