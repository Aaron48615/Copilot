# == 和 === 的区别？

## 核心回答

1. 严格相等 `===` 不会为了比较把不同类型转成同一种。`'1' === 1` 是假。宽松相等 `==` 会按规定的分支转换，所以字符串一和数字一可以相等。但这不是「所有值都先转成数字再比」。

2. 对象跟对象比，两种运算符主要看是不是同一个对象，内容一样不够。两个接口结果各自建了一个同名用户对象，字段相同也不会严格相等。业务上要判断是不是同一用户，应比较经过确认的稳定标识。

3. 几个边界：`null == undefined` 为真，严格相等能分开它们。数字 `NaN` 跟自己用这两种运算符比都是假。正零和负零严格相等。`Object.is` 能区分正负零，并把 `NaN` 跟自己视为相同，它也不负责递归比较对象。

4. 实际判断默认用严格相等，数据进程序时先明确转换、校验类型。表单输入先看是不是有效数字，再跟业务阈值比。`value == null` 同时判断两种空值，可以当团队约定。浏览器还有 `document.all` 这种历史特殊对象，常用简写不是毫无例外的定律。

## 追问：为什么空数组和 false 用双等号比较会相等？

1. 空数组跟布尔值比，会先把 `false` 转成数字 `0`，对象再转成原始值。普通空数组这里会得到空字符串，空字符串跟数字比又变成 `0`，最后是 `0` 跟 `0`，所以为真。

2. 这不表示空数组本身是假值，`Boolean([])` 仍是真。条件判断走的是转布尔，宽松相等走的是另一套比较规则。两套过程混在一起，数组、字符串、数字的行为就很容易判错。

3. 判断数组有没有内容，明确检查类型和长度。值来自接口，还要先处理缺失或格式错误，别把非数组按数组用。把业务条件写明白，比记住冷门表达式管用。

## 追问：判断两个表单对象是否相同，直接用 JSON 字符串比较可以吗？

1. 只有数据范围和序列化规则都明确时才考虑。两个对象业务字段相同，字段插入顺序不同，字符串可能不同；被序列化省略的字段不同，又可能得到相同结果。当不了通用相等判断。

2. 要判断用户有没有改表单，先选出实际会提交的字段，空值、数字、空白怎么处理也统一。比较的含义应对上业务变化，临时校验消息、页面标记这些无关信息别算进去。

3. 真要通用深比较，还得约定日期、集合、循环引用、数组顺序这些细节。相等没有适合所有场景的万能定义。先讲清哪些差异影响业务，再选比较方法，才不容易误报或漏掉真正的修改。
