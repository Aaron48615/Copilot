# == 和 === 的区别？

## 核心回答

1. 我会先说严格相等不会为了比较而把不同类型转换成同一种类型，例如 `'1' === 1` 是假。宽松相等则按规定的分支进行转换，所以字符串一和数字一可以相等，但不能把它概括成所有值都会先转成数字再比较。

2. 对象之间比较时，两种运算符都主要看是否为同一个对象，内容一样并不够。假设两个接口结果各自创建了一个同名用户对象，它们不会因为字段相同就严格相等；如果业务想判断是不是同一用户，应该比较经过确认的稳定标识。

3. 我会特别说明几个边界：`null == undefined` 为真，严格相等能区分它们，而数字 NaN 与自身用这两种运算符比较都为假。正零和负零严格相等；`Object.is` 则能区分两者，并把 NaN 与自身视为相同，它也不负责递归比较对象。

4. 实际写判断时我倾向于默认使用严格相等，并在数据进入程序时明确转换和校验类型，例如表单输入先检查是否为有效数字，再与业务阈值进行比较。用 `value == null` 同时判断两种空值可以作为团队约定，但浏览器还有 `document.all` 这类历史特殊对象，不能把常用简写说成毫无例外的语言定律。

## 追问：为什么空数组和 false 用双等号比较会相等？

1. 比较空数组和布尔值时，会先把假转换为数字零，接着对象需要转成原始值。普通空数组在这里会得到空字符串，而空字符串与数字比较又会转换成零，最终形成零与零的比较，所以结果为真。

2. 这不表示空数组本身是假值，`Boolean([])` 的结果仍然是真。条件判断做的是转布尔值，宽松相等走的是另一套比较规则，把这两种过程混在一起，就很容易误判数组、字符串和数字的行为。

3. 我不会用这种隐式转换判断数组有没有内容，而会明确检查数组类型和长度。如果值来自接口，还要先处理缺失或格式错误，避免把非数组也按数组使用；明确表达业务条件通常比记住冷门表达式更实用。

## 追问：判断两个表单对象是否相同，直接用 JSON 字符串比较可以吗？

1. 只能在数据范围和序列化规则都明确时考虑这种方式。两个对象虽然业务字段相同，但字段插入顺序不同可能得到不同字符串；相反，被序列化省略的字段不同，又可能得到相同结果，不能当作通用相等判断。

2. 假设目标是判断用户是否修改了表单，我会先选出实际提交的字段，并统一空值、数字和空白的处理规则。这样比较的含义对应业务变化，而不是把临时校验消息、页面标记等无关信息也当成修改。

3. 如果确实需要通用的深比较，还要约定日期、集合、循环引用和数组顺序等细节。相等没有一个适合所有场景的万能定义，先讲清楚哪些差异影响业务，再选比较方法，才能避免误报或漏掉真正的修改。
