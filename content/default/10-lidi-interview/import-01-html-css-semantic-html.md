# 怎么理解语义化标签？

## 核心回答

1. 语义化就是用标签准确表达内容和操作的含义。导航用 `nav`，条目集合用列表，触发动作用 `button`，页面跳转用链接。不是给每个 `div` 都换一个新标签，而是让读代码的人、浏览器和辅助技术能从结构看出这一块是什么。

2. `button` 和可点击 `div` 的差别最直观。原生按钮带着可聚焦、键盘激活这些行为，也能表达禁用。`div` 加点击只打通了鼠标这条路，其他行为得自己补。表单里还要注意 `button` 的默认提交行为，非提交动作要明确 `type`。语义对了，配置也得对。

3. 标题层级和页面区域能帮用户理解内容怎么组织，读屏用户可以按标题或地标跳。`section` 适合有主题的章节，`article` 适合相对独立的内容，普通样式容器继续用 `div` 就行。用标题标签只为了拿大字号，或者跳着层级装饰页面，结构表达会被削弱。

4. 语义化描述的是内容含义；服务端渲染或预渲染影响的是首个 HTML 响应里有没有正文。两件事不一样。换成语义标签，客户端渲染的页面不会自动拥有完整首屏 HTML。要完善搜索访问体验，查页面返回的正文和可访问链接，再评估渲染方式。ARIA 仍只补充名称和状态，得结合键盘和读屏验证。

## 追问：按钮和链接外观一样时，应该根据什么选标签？

1. 按用户操作之后的结果选。跳到一个资源或页面，用带 `href` 的链接；提交、删除、展开面板这类改变当前状态的动作，用按钮。视觉样式可以相同，语义和浏览器原生行为不同。别按设计稿颜色决定标签。

2. 链接支持复制地址、在新标签页打开这些常见操作；按钮则有对应的键盘激活和表单行为。用 `button` 模拟所有跳转，用户可能丢掉预期操作；用无意义 `href` 模拟按钮，又可能带来位置变化或错误导航。

3. 表单里普通展开按钮要明确 `type="button"`，免得意外提交。验证既看点击结果，也看键盘和上下文菜单是否符合操作含义。只有外观一样不够，用户对两类控件的预期得对得上。

## 追问：一个页面有多个导航区域，怎样让用户分清？

1. 可以保留多个 `nav`，但不同用途要有清楚名称，比如主导航和文章目录，辅助技术的地标列表里就能分开。名称可以关联可见标题，别都叫「导航」却指向完全不同的一组链接，选择成本会上去。

2. 内部仍用有意义的链接文字和列表结构。当前页面或当前位置用适当状态表达。别只用颜色或一个装饰箭头表示当前项，看不到颜色或使用读屏的人可能不知道自己已经在哪个页面。

3. 地标数量别过多。只有主要导航区域才需要强调，不必给每一小组链接都包 `nav`。结构是帮人快速定位的，过度标记反而让导航列表变长。最后用标题和地标浏览一次，确认名称真能说明这块区域干什么。
