# 轻购项目里为什么还有 any？你会怎么改？

## 核心回答

1. 轻购里首页商品、搜索结果、购物车项和轻购AI结果已经有部分类型；但商品详情、订单、地址和后端复杂嵌套数据仍有一些 `any`，这是我接入接口时为了先跑通功能留下的技术债。
2. `any` 的问题是它会跳过类型检查。比如把商品详情当成订单数据使用，编译器不会提醒，最后可能在运行时才发现字段不存在。
3. 我会先从 API 边界开始补类型，把店铺、优惠分组、购物车项、订单确认、地址和订单列表分别定义接口，再让页面的 ref、函数参数和 API 返回使用这些类型。
4. 对接口外部数据，类型还不够，因为 TypeScript 只在编译时工作。关键接口可以加运行时校验，校验失败时显示错误或安全空状态。
5. 我不会为了消灭所有 `any` 写很复杂的类型体操。先把最常用、最容易出错的数据结构写清楚，再逐步收紧类型，代码才容易维护。
