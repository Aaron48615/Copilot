# 如何测试依赖注入组件？

## 核心回答

1. 先把依赖契约写清：注入键是什么，值里有哪些状态和方法，缺少时允不允许默认行为。Vue Test Utils 可以用挂载选项提供依赖，也可以用真实父组件包一层。别为了测试去改子组件内部实现。

2. 只测消费者时，可以给简单替身，比如一个选中值 `ref`，再加会记调用的方法。点选项后看方法收到的编号对不对；再改提供出去的 `ref`，等视图刷新，看子组件显示有没有跟着变。一边是输出动作，一边是输入还连不连着。

3. 要看提供者和后代怎么协作，用真实父子挂在一起更有用。表单提供者集中校验，输入子组件注册、注销，一起挂上才能发现最近提供者盖掉、重复注册、卸了没解除关系这些问题。

4. 每个用例自己建新的响应式状态和替身方法，别多个用例共用模块单例。`Symbol` 键必须和组件用的是同一个导出，重新 `Symbol('同名')` 不是同一个键。默认值场景单独测，别所有测试都只走注入成功那条路。

5. 断言落在用户看得见的结果和约定交互上，别去数组件读了几次 `inject`。异步先等对应 Promise，再等需要的 Vue 更新。涉及销毁就卸载，看订阅有没有放掉，把依赖从用到扔的过程盖住。

## 追问：模拟提供者时，为什么也要使用 ref？

1. 真实接口给的是 `ref`，替身也保持这个形状。组件读 `.value` 可能拿到 `undefined`，或者测试只看了初始文本，后续更新完全没覆盖到。模拟换的是数据来源，契约本身别改。

2. 先挂上确认初值，再改同一个 `ref`，等 Vue 更新看文本有没有变。这样能抓到消费者把注入值提前解包成普通变量。每次重新挂载传一个新值，测不到响应式连接还在不在。

3. 方法可以用记调用的替身，更新规则按这个用例的目的来。消费者测试可以只断言发出的动作；集成测试让真实提供者去改状态。模拟做得太像，最后等于把业务代码又实现一遍。

## 追问：什么时候应该用真实父组件，而不是 global.provide？

1. 问题出在提供范围和生命周期时，真实组合更合适。内层表单该盖掉外层的字段注册服务，只注入一个固定对象，测不出“最近的提供者生效”，也看不出嵌套结构是不是放错了。

2. 提供者管的清理也适合组合测试。输入组件挂上时注册、拿掉时注销，父级汇总字段。只模拟一个 `register`，可能确认调用发生了，卸了以后父级是不是还留着已经不存在的字段，却没人查。

3. 单元测试盯消费者接口，少量集成测试盯真实协作。两种不用互相取代。每个用例验证一个真实风险，别为了某种测试形式把页面所有依赖全模拟掉，或一次全装进来。
