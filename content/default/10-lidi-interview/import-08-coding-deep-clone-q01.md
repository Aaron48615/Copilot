# 为什么需要 WeakMap？

## 核心回答

1. 深拷贝面对的可能是一张对象引用图，不一定是一棵树。比如 `a.self = a`，直接递归属性就会不断回到 a；我需要记录“这个原对象已经对应哪个副本”，再次遇到它时直接返回副本，才能结束递归并保留循环关系。

2. 映射必须在向下递归之前建立，也就是先创建空副本，再执行 `seen.set(source, copy)`，然后填充属性。若等子属性复制完才缓存，处理 self 时还查不到记录，WeakMap 虽然存在，仍然无法阻止无限递归。

3. 它还保留共享引用，不只是处理环。假设原对象的 left 和 right 都指向同一个子对象，拷贝后这两个字段也应指向同一个新子对象；如果分别复制成两份，后续修改其中一条路径时，副本的关系就和原数据不同了。

4. WeakMap 适合以原对象身份为键保存这种辅助信息，而且不会仅因为键留在缓存中就阻止原对象被回收。不过一次同步拷贝里使用局部 Map 也能正确工作，调用结束后整个缓存可以被回收，不能把 Map 直接等同于内存泄漏。

5. 我会为每次顶层拷贝创建独立缓存，只在这一轮递归里复用。否则原对象修改后再次克隆，可能拿到上一次的旧副本；WeakMap 也不会自动判断内容是否变化，更不保证递归很深时不出现调用栈溢出。

## 追问：只用 WeakSet 记录访问过的对象可以吗？

1. WeakSet 能回答“是否见过”，但不能告诉我“副本是哪一个”。遇到 self 时如果直接返回原对象，会让副本仍然指向原数据；如果返回空对象或忽略字段，又会改变原来的结构，所以不满足保留引用关系的深拷贝目标。

2. 对单纯检测环的任务，集合可以有用，但要区分整轮访问记录和当前递归路径。共享子对象可能从两个分支被访问，却并没有形成环；若只因全局集合里出现过就报循环引用，会把合法共享关系误判为环。

3. 本题需要构建新对象图，所以键到副本的映射最直接。我会检查 `copy.self === copy`，以及 `copy.left === copy.right` 且不等于原子对象，这些断言分别覆盖循环、共享与隔离，光看内容相等还不够。

## 追问：为什么不能让所有 clone 调用共用一个全局 WeakMap？

1. 全局缓存会把不同时间的复制任务混在一起。第一次克隆后源对象更新了字段，第二次命中旧映射就直接返回旧副本，调用者期望的新快照没有产生；弱引用只影响回收，不负责缓存失效。

2. 两次本应独立的克隆还可能意外共用同一个副本，修改其中一份就影响另一份。每次顶层调用新建缓存，内部递归传同一份，才能既保持单次结果的共享关系，又让不同调用产生彼此独立的结果。

3. 如果目标确实是长期复用转换结果，我会把它当成缓存设计，另行约定输入不可变、版本标识和失效规则。那已经不是普通深拷贝的默认行为，不能因为 WeakMap 不强持有键，就忽略结果过期和对象身份这两个问题。
