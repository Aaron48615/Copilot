# ES6+ 有哪些常用新特性？

## 核心回答

1. 变量常用 `let` 和 `const`。以前 `var` 是整个函数里都能用，`if`、`for` 包不住；`let` 和 `const` 出了这个大括号就不能再用。还有，`let a` 写在后面，前面就去读会直接报错，得等这行执行到了才行，面试里常把这段叫暂时性死区。`const` 不能再赋成别的值，但如果是对象，里面的属性照样能改：`const user = { name: 'A' }`，改 `user.name` 没问题，`user = {}` 才会报错。

2. 写数据常用解构、模板字符串、展开和剩余参数。比如从接口对象里取出 `name`、`age`，用 `` `Hello ${name}` `` 拼文案，或者拷一份再改几个字段：`{ ...old, count: 1 }`。展开只拷最外面一层，里面的数组、对象还是同一份；你改了拷贝里的商品列表，原来那份也可能一起变。对象展开还是后面版本才有的，不是 ES6 当年就有。

3. 箭头函数没有自己的 `this`，会沿用外层那个，所以写回调很方便，比如在方法里 `setTimeout`，还想用当前这个对象。但它不能 `new`，也不太适合当对象方法，因为这时往往希望 `this` 指向谁调用它。异步先是 Promise，ES2017 才有 `async/await`，写起来更顺，本质还是在等 Promise。`await` 不会把很重的计算自动丢到后台，大循环照样会卡住页面。

4. 模块就是 `import` 和 `export`，按文件拆代码。Map 的键不限字符串，比如可以用节点当键；Set 适合去重。可选链 `user?.name` 和空值合并 `??` 是 ES2020 的，不能全算在 ES6 头上。`??` 只在 `null` 和 `undefined` 时才用默认值，`0` 和空字符串会留下来，这点和 `||` 不一样。

## 追问：可选链和空值合并，能不能直接替代所有条件判断？

1. 不能。`user?.name` 只是碰到 `null` 或 `undefined` 就停，返回 `undefined`。它不检查数据对不对。属性在、但不能当函数调用，照样会报错。

2. `??` 只在左边是 `null` 或 `undefined` 时才用默认值。`||` 还会把 `0`、空字符串、`false` 一起换掉。页码允许为 `0` 时，用 `??` 才能保住这个 `0`。

3. 空和不合法不是一回事。姓名是空字符串，该提示用户填，不该偷偷补默认值。允许缺的地方可以用这些语法，必填还是要单独校验。

## 追问：为什么箭头函数不适合替换所有普通函数？

1. 箭头函数没有自己的 `this`，会沿用外层。对象方法如果靠 `this` 指当前对象，改成箭头，`this` 就不是那个对象了，`call`/`bind` 也改不回来。

2. 也没有 `arguments`，收集参数要用剩余参数。不能 `new`。本来当构造函数用的，换成箭头会直接报错。

3. 事件监听如果依赖 `this` 指向当前元素，换成箭头行为也会变。这时继续用普通函数，或者自己读 `event.currentTarget`。选不选箭头，看它要不要自己的 `this`，不是看写得短不短。
