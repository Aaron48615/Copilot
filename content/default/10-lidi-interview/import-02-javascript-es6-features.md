# ES6+ 有哪些常用新特性？

## 核心回答

1. 我会按解决的问题介绍，而不是只罗列语法名称：变量声明常用 `let` 和 `const`，它们有块级作用域，并存在初始化前不能访问的暂时性死区。`const` 限制的是绑定重新赋值，不会自动冻结对象，因此仍能修改对象的属性。

2. 表达数据时常用解构、模板字符串、展开和剩余参数，能让取字段、拼文本和收集参数更直观。这里要注意对象展开是后续版本加入的能力，而且展开仍是浅拷贝；如果要改嵌套数据，只展开外层不会让内部对象自动独立。

3. 函数方面，箭头函数使用外层的 `this`，适合不需要动态接收者的回调，但不能作为构造函数。异步方面，ES2015 引入 Promise，ES2017 加入异步函数语法，让等待和错误处理更连贯，不过 `await` 不会把耗时计算自动搬到后台。

4. 模块、Map 和 Set 也是常用能力，而可选链和空值合并属于 ES2020，不能全部说成 ES6 当年新增。实际选择特性时，我会看运行环境和构建目标，同时明确空值、作用域和引用关系，避免只记住简写方式却忽略它们改变了哪些行为，例如默认值是否覆盖了合法的零，以及回调是否还拿得到预期的对象。

## 追问：可选链和空值合并，能不能直接替代所有条件判断？

1. 可选链适合某一段访问对象可能为空的情况，遇到 `null` 或 `undefined` 时返回未定义值。它不会验证数据格式，也不会保证一个存在的属性可调用，所以接口结构错误仍然可能在后续操作中暴露。

2. 空值合并只在左侧为空值时使用默认值，而逻辑或还会把零、空字符串和假当作需要替换的值。假设页数允许为零，使用空值合并能够保留这个合法值，不能为了写得短就把它替换成默认数字。

3. 是否为空和是否业务有效是两件事，例如姓名为空字符串可能应提示输入，而不是静默补默认值。我会在允许缺省的地方使用这些语法，必须满足的条件仍明确校验，防止把错误数据一路隐藏成空结果。

## 追问：为什么箭头函数不适合替换所有普通函数？

1. 箭头函数没有自己的 `this`，所以适合保持外层上下文的回调。假设对象方法需要通过调用者访问当前对象，随意改成箭头函数就可能读到外层上下文，调用方式再怎么变化也不能给它绑定新的接收者。

2. 它也没有自己的 `arguments`，需要收集参数时通常使用剩余参数，且不能通过 `new` 调用。普通函数能作为构造函数的情况，不能只因为箭头写法短就直接替换，否则代码会在执行时抛出类型错误。

3. 在浏览器事件监听里，如果依赖普通函数的接收者语义，替换成箭头函数也会改变行为。可以改为显式读取事件的当前目标，但应确认这符合原本需求；我的选择依据是函数如何使用上下文，而不只是外观简洁。
