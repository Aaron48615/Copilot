# 事件捕获、冒泡和事件委托是怎么回事？

## 核心回答

1. 浏览器把事件沿着这条路径派发，常见顺序是捕获、到达目标、再冒泡。`addEventListener` 默认听冒泡阶段，传 `capture` 可以听捕获。目标自己身上的监听也会跑，不是非要冒泡到父节点才触发。

2. 事件委托就是在共同的父节点上听，再判断实际点到了哪个子项。比如商品列表不断往上追加卡片，父节点只绑一次 `click`，用 `target.closest` 找到按钮，再读商品标识，新加进来的卡片也能走这套处理。

3. `target` 是事件真正落到的目标，`currentTarget` 是当前这个监听绑在谁身上。点到按钮里的图标时，这两个特别容易混。找到候选按钮之后，还要确认它确实属于当前这个容器，免得嵌套列表或最近祖先匹配到容器外面去。

4. `stopPropagation` 拦住继续往下传，`preventDefault` 尝试取消默认行为，两件事用途不一样。委托也有边界：`focus`、`blur` 不冒泡，可以改听 `focusin`、`focusout`，或者用捕获。子节点提前停掉传播，父级的冒泡监听也收不到。

5. 比如表格里有查看和删除，父级按动作标识分开处理，一次点击只命中一个操作。委托不等于不能再绑单独监听。需要精确控制的组件可以局部自己听。容器销毁时，不再用的回调也要放开。

## 追问：点击按钮中的图标，怎样找到正确的业务项？

1. 别要求 `target` 必须正好是 `button`，实际点击经常落到 svg 或文字容器上。先看目标能不能当 Element 用，再用 `closest` 找到带业务标识的按钮。按钮里面结构改了，逻辑也不受影响。

2. 找到按钮后，继续看父容器是不是包含它，以及它属于当前这一层列表。嵌套表格里，内层按钮的事件也可能经过外层。外层不能看见一个 `data-id` 就去删，得确认操作范围。

3. 最后按明确的 `data-action` 分发查看或删除，并看按钮是不是禁用、是不是正在提交。`dataset` 只是界面上的数据，服务端还得查资源归属。用户改 DOM 里的商品标识，不能当成改不了。

## 追问：阻止冒泡后，为什么链接仍然跳转？

1. 事件传播和默认行为是两件事。拦住冒泡只是让后面的祖先监听不再收到这个事件，浏览器照样可能去跳链接。真要取消跳转，该调 `preventDefault`，再叠 `stopPropagation` 也挡不住导航。

2. 取消默认行为还得看这个事件能不能取消，以及监听是不是标成了 `passive`。被动监听里调 `preventDefault` 不会生效，浏览器还可能给警告。一边说不拦滚动，一边又在回调里拦滚动，对不上。

3. 先确认业务是不是真要取消默认行为。自定义路由可以处理普通点击，但用户按修饰键开新标签这种习惯还得留下。所有点击一律拦截，原生链接就不好用了。
