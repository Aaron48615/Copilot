# 事件捕获、冒泡和事件委托是怎么回事？

## 核心回答

1. 浏览器把事件沿事件路径派发，常见流程是捕获、到达目标、再冒泡。addEventListener 默认在冒泡阶段监听，传 capture 可以监听捕获阶段；目标上的监听也会执行，并不是必须冒泡到父节点才触发。

2. 事件委托就是在共同父节点监听，再判断实际操作的子项。比如一个商品列表不断追加卡片，父节点只绑定一次 click，通过 target.closest 找到按钮，再读取商品标识，新加入的卡片也能使用这个处理逻辑。

3. 这里 target 是事件目标，currentTarget 是当前监听器绑定的元素，点到按钮里的图标时两者尤其容易混淆。找到候选按钮后还要检查它确实属于当前容器，避免嵌套列表或最近祖先匹配到容器之外。

4. stopPropagation 阻止继续传播，preventDefault 尝试取消默认行为，两者用途不同。委托也有边界，focus、blur 不冒泡，可以考虑 focusin、focusout 或捕获监听；子节点提前停止传播，也会让父级冒泡监听收不到事件。

5. 例如表格有查看和删除按钮，我会在父级按动作标识区分处理，并让一次点击只命中一个操作。委托不意味着不能绑定单独监听；需要精确控制的组件可以局部监听，重点是明确传播关系，并在容器销毁时释放不再使用的回调。

## 追问：点击按钮中的图标，怎样找到正确的业务项？

1. 我不会直接要求 target 必须是 button，因为实际点击可能落到 svg 或文字容器上。先检查目标能否作为 Element 使用，再用 closest 找到带业务标识的按钮，这样按钮内部结构变化也不影响逻辑。

2. 找到按钮后继续检查父容器是否包含它，以及它是否属于当前列表层级。嵌套表格里内层按钮的事件也可能经过外层，外层不能只见到一个 data-id 就执行删除，需要确认具体操作范围。

3. 最后根据明确的 data-action 分发查看或删除，并检查按钮是否处于禁用或提交中。dataset 只是界面上的数据，服务端仍要检查资源归属，不能认为用户改不了 DOM 中的商品标识。

## 追问：阻止冒泡后，为什么链接仍然跳转？

1. 事件传播和默认行为是两件事。阻止冒泡只是让后续祖先监听器不再接收这个事件，浏览器仍可能执行链接导航，因此需要取消跳转时应调用 preventDefault，而不是继续添加 stopPropagation。

2. 取消默认行为还要看事件是否可取消，以及监听器是否被标记为 passive。被动监听器中调用 preventDefault 不会有效，浏览器可能给出警告，所以不能一边承诺不阻止滚动，一边又在回调里阻止滚动。

3. 我会先确认业务是否真的需要取消默认行为。例如自定义路由导航可以处理普通点击，但要保留用户按修饰键打开新标签页的习惯；一律拦截所有点击，会破坏原生链接的可用性。
