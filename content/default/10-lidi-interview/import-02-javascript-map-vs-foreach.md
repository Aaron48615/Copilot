# map 和 forEach 有什么区别？

## 核心回答

1. 要不要转换结果，决定用哪个。`map` 把每个回调的返回值收成新数组，适合把商品对象转成展示字段。`forEach` 只逐项执行操作，整个方法返回 `undefined`，适合记日志这种不需要收集结果的场景。

2. 用 `map` 时忘了写返回值，对应位置会变成 `undefined`，不会自动留下原元素。回调写成花括号，只算了名称却不 `return`，得到的就不是名称列表。看到没用结果的 `map`，多半是方法选错了。

3. 两者都不会自动深拷贝数组元素。`map` 的新数组里也可能还装着原来的对象。回调直接改商品价格，原对象一样会变。要留住输入，得显式创建新对象；嵌套属性要不要复制，看实际改到哪一层。

4. 这两个回调都不能用普通 `break` 提前结束遍历，回调里 `return` 也只结束当前这一项。找第一条匹配用 `find`，判断有没有用 `some`。流程比较绕时用普通循环，比抛异常退出更清楚。

5. 它们也不会等待异步回调：`map` 会得到 Promise 数组，`forEach` 则直接忽略回调返回值。稀疏数组的空位通常会跳过，`map` 会保留对应空位。输入可能不完整时要确认这种行为，别把空位和显式空值混在一起。

## 追问：map 返回新数组为什么还会修改原数据？

1. 新数组只说明最外层容器不同，里面的对象不一定重新创建。回调返回原商品对象，两个数组里对应元素指向同一对象，从新数组改价格，原数组也能看到。这和数组方法有没有返回新值并不矛盾。

2. 只更新顶层价格，可以在回调里创建包含旧字段和新价格的对象。对象展开仍是浅拷贝，里面的规格数组可能继续共享。真要改规格，得沿着被改的路径继续创建相应的新数组或新对象。

3. 先明确改到哪一层，再决定复制哪些层，不必对所有数据默认做深拷贝。含函数、特殊对象或循环引用的数据，复制策略还有额外限制。要不要保留原数据，直接看输入字段和相关对象身份有没有变。

## 追问：为什么用 map(parseInt) 转数字可能出错？

1. `map` 调回调时会传入元素、索引和原数组，而 `parseInt` 的第二个参数表示进制。直接把函数引用传进去，索引就被误当成进制。错在参数含义碰巧对不上，不是遍历顺序出了异常。

2. 处理三个常见十进制字符串时，第二项索引是 `1`，会变成无效进制，第三项还可能按二进制解释。写法看着短，却把调用约定藏起来了。写成明确的回调，需要解析整数时显式指定十进制。

3. 要把整个字符串转成数字，也可以看 `Number`，但它和整数解析不是同一套规则。带单位的文本、空字符串行为都不同。先明确允许的输入格式，再选转换方式，换一个函数不等于校验做完了。
