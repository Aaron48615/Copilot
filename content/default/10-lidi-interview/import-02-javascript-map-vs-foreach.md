# map 和 forEach 有什么区别？

## 核心回答

1. 我会根据是否需要转换结果来选择。`map` 把每个回调的返回值收集成新数组，适合把商品对象转成展示字段；`forEach` 只逐项执行操作，整个方法返回 `undefined`，适合记录日志等不需要收集结果的场景。

2. 使用 `map` 时忘写返回值，会让对应位置变成 `undefined`，并不会自动保留原元素。例如使用花括号写回调时，只计算名称但不返回名称，得到的就不是名称列表；因此看到不使用结果的 `map`，我会检查是否选错了方法。

3. 两者都不会自动深拷贝数组元素，`map` 的新数组也可能仍装着原来的对象。假设回调直接修改商品价格，原对象同样变化；若要保留输入，需要显式创建新对象，而且嵌套属性是否复制还要根据实际修改范围决定。

4. 这两个回调都不能用普通 `break` 提前结束遍历，回调内 `return` 也只结束当前回调。查找第一条匹配项更适合 `find`，判断是否存在更适合 `some`，需要复杂控制流程时用普通循环，表达上会比抛异常退出更清楚。

5. 它们也不会等待异步回调：`map` 会得到 Promise 数组，`forEach` 则直接忽略回调返回值。还有稀疏数组的空位通常会跳过，`map` 保留对应空位；我会在输入可能不完整时确认这种行为，而不把空位和显式空值混为一谈。

## 追问：map 返回新数组为什么还会修改原数据？

1. 新数组只说明最外层容器不同，并没有保证里面的对象也重新创建。假设回调返回原商品对象，两个数组中的对应元素指向同一对象，从新数组修改价格自然会被原数组观察到，这与数组方法是否返回新值不矛盾。

2. 如果只更新顶层价格，可以在回调中创建包含旧字段和新价格的对象。可是对象展开仍是浅拷贝，里面的规格数组可能继续共享；若实际要修改规格，就需要沿着被修改的路径继续创建相应的新数组或新对象。

3. 我会先明确修改范围，再决定复制哪些层，而不是对所有数据默认做深拷贝。对于含函数、特殊对象或循环引用的数据，复制策略还有额外限制；判断是否保留原数据，可以直接检查输入字段和相关对象身份是否变化。

## 追问：为什么用 map(parseInt) 转数字可能出错？

1. `map` 调用回调时会传入元素、索引和原数组，而 `parseInt` 的第二个参数表示进制。直接传函数引用时，索引就被误当成进制，因此错误来自参数含义碰巧对不上，并不是遍历顺序出现了异常。

2. 例如处理三个常见十进制字符串时，第二项索引是一，会成为无效进制，第三项还可能按二进制解释。这种写法看起来简洁，却隐藏了调用约定；我会写明确的回调，并在需要解析整数时显式指定十进制。

3. 若需求是把整个字符串转换为数字，也可以评估 `Number`，但它与整数解析不是完全相同的规则。比如带单位文本和空字符串的行为不同，所以先明确允许的输入格式，再选择转换方式，不能只替换一个函数就认定校验完成。
