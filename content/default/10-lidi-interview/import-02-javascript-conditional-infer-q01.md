# 分布式条件类型是什么？

## 核心回答

1. 分布式条件类型：条件判断左边直接写类型参数，传入联合类型时会一个成员一个成员地判断，再把结果合成联合。比如把字符串或数字分别装成数组，得到的是字符串数组或数字数组，不是一个里面能混放两种元素的数组。

2. 拿 `T extends string ? T : never` 来说，传入字符串和数字的联合，字符串留下，数字变成不可能类型，最后只剩字符串。这是类型层面筛成员，没有生成循环，也不会在运行时去检查数组里的真实数据。

3. 想判断整个联合是不是都满足条件，用元组把两边包住，例如 `[T] extends [string]`，就不再逐个分发。这时字符串与数字的联合，整体不满足「是字符串」，走进否定分支。这跟逐项筛选不是一回事。

4. 结果不对时，先看左边是不是直接写类型参数，再代入具体成员一步步推，最后看空联合这些边界。不是出现联合就一定分发，也不是关掉分发就一定对。先说清：是要筛掉一部分成员，还是对全部输入做同一种判断，用具体赋值样例把两种需求分开。

## 追问：为什么判断 never 时有时得不到 true？

1. 类型参数直接参与判断的条件类型，传入 `never` 会碰上分发规则。它可以看成空联合，没有成员能走进任何分支，结果还是 `never`，不会按直觉走进肯定分支得到真值类型。

2. 目的就是检测输入是不是 `never`，用单元素元组包住再跟对应元组比。比的是整个输入，不再逐项展开，才能得到预期的布尔字面量。解决的是分发方式，不是运行时判断。

3. 普通类型、联合类型、`never` 分别代入工具类型，看结果对不对。碰到 `any` 还要单独验，它有额外特殊行为，对普通联合成立的推导，不能直接套到所有输入上。

## 追问：字符串数组联合与联合元素数组有什么差别？

1. 字符串数组与数字数组的联合，实际值得符合其中一种：要么全是字符串，要么全是数字。元素是「字符串或数字」的数组，同一数组里可以混着文本和数字。

2. 工具类型的意思是把每一种输入单独装成数组，分发得到数组联合是合理结果。需求是收集多种类型的混合值，就该让整个联合一起当元素类型。两种写法都带数组符号，不等于一回事。

3. 拿一个混合数组、两个单一元素类型的数组做赋值检查，差别会直接出现在编译结果里。按真实读写需求来，尤其是传给别的函数时参数怎么约定。别为了消报错就把类型随便放宽。
