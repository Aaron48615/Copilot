# 分布式条件类型是什么？

## 核心回答

1. 分布式条件类型指的是条件判断左侧直接使用类型参数时，传入联合类型会逐个成员进行判断，再把结果合成联合。比如把字符串或数字分别转换成数组，得到的是字符串数组或数字数组，而不是一个可以混放两种元素的数组。

2. 以 `T extends string ? T : never` 为例，传入字符串和数字的联合时，字符串被保留，数字变成不可能类型，最后只剩字符串。这里是在类型层面筛选成员，没有生成循环，也不会在程序运行时检查数组里的实际数据。

3. 如果需求是判断整个联合是否都满足条件，我会用元组包住判断两边，例如 `[T] extends [string]`，让它不再逐成员分发。这时字符串与数字的联合整体不满足字符串约束，结果会进入否定分支，语义与逐项筛选不同。

4. 排查结果时，我会先确认左侧是不是直接使用类型参数，再代入具体成员逐步推导，最后检查空联合等边界。不是只要出现联合就会分发，也不是关闭分发一定更正确，要先说清楚想筛选部分成员，还是想对全部输入作统一判断，并用具体赋值样例确认两种需求的区别。

## 追问：为什么判断 never 时有时得不到 true？

1. 如果写成让类型参数直接参与判断的条件类型，传入不可能类型时会遇到分发规则。它可以理解为空联合，没有成员可以进入任何分支，因此结果仍然是不可能类型，而不是直觉中进入肯定分支得到真值类型。

2. 如果目的就是检测输入是否为不可能类型，可以用单元素元组包裹后再与对应元组比较。这样判断的是整个输入，不再逐项展开，所以能够得到预期的布尔字面量，解决的是分发方式而不是运行时判断。

3. 我会把普通类型、联合类型和不可能类型分别代入工具类型，检查结果是否符合预期。涉及任意类型时还要单独验证，因为它会带来额外的特殊行为，不能把对普通联合成立的推导直接套到所有输入上。

## 追问：字符串数组联合与联合元素数组有什么差别？

1. 字符串数组与数字数组的联合，要求实际值符合其中一种数组类型，例如纯字符串数组或者纯数字数组。元素是字符串与数字联合的数组则可以混合两者，所以它允许同一数组中同时出现文本和数字。

2. 假设工具类型的含义是把每一种输入单独装成数组，那么分发得到数组联合是合理结果。假设需求是收集多种类型的混合值，就应考虑让整个联合一起成为元素类型，不能只看两种写法都带数组符号便认为等价。

3. 我会用一个混合数组和两个单一元素类型数组做赋值检查，让差异直接体现在编译结果里。判断应根据读取和写入的真实需求，特别是提供给其他函数的参数约定，避免为了消除报错随意扩大类型。
