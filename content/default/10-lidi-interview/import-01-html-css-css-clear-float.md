# 清除浮动有哪些方式？

## 核心回答

1. 先说清清的是哪种影响。浮动会让附近的行内内容环绕，普通父容器的自动高度也可能包不住浮动子项。常说的清浮动，是让后面的内容排到浮动下面，或者让父容器完整包住里面的浮动，不是把 `float` 属性删掉。

2. 只是希望父容器包住浮动，优先考虑 `display: flow-root`，它建立 BFC，自动高度就会包含内部浮动。图文介绍卡片里图片在漂、文字很短，父容器仍得包住整张图。这种写法直接，也不会额外裁剪溢出内容。

3. 老代码常见 clearfix：父容器末尾用 `::after` 生成空盒子，设 `display: block; clear: both`。这个正常流里的清除元素会排到前面左右浮动下面，父容器高度跟着伸下去。不必在 HTML 里为纯布局再塞一个空 `div`。

4. `overflow: hidden` 或 `auto` 也可能通过建立 BFC 包住浮动，但会带来裁剪或滚动，不能无条件用。新写的工具栏、多列区域一般更适合 Flex 或 Grid。`float` 仍适合文字环绕图片，换不换看布局目的，别只看代码年代。

5. 容器末尾是不是已经有正常流内容也要看一眼。高度看起来正常，有时只是碰巧被一大段文字撑开了。把文字换成短文案，再看边框包不包住图片，就知道方案是真包住了浮动，还是只对当前内容碰巧成立。

## 追问：为什么 clear 写在父元素上没有包住里面的浮动？

1. `clear` 处理的是当前盒子和前面相关浮动之间的关系，不会自动要求它去算内部所有浮动的高度。父容器设 `clear`，主要影响父容器自己在外部浮动旁边的位置，跟想解决的内部高度问题对不上。

2. 用清除元素方案，就把正常流的清除盒子放在内部浮动后面，比如父级 `::after`。它的顶部被推到浮动底部以下，父级再根据这个正常流盒子算高度，效果才对得上。

3. 只是包含内部浮动，直接在父元素设 `flow-root` 更简单。排查时给父级画边框，同时看浮动和清除盒子处在哪个上下文，确认它们确实在起作用，别看见 `clear` 字样就当写对了。

## 追问：旧页面的浮动布局是否应该全部改成 Flex？

1. 先看它稳不稳、要不要改交互和结构。两列导航或按钮排列用 Flex 通常更好维护，但文章图片旁边的文字环绕就是浮动擅长的，改成 Flex 可能反而丢掉需要的排版。

2. 需要迁移时，先留一组真实内容样例，包括短文本、长文本和缺图，再逐个区域替换。Flex 会改子项尺寸、外边距和换行规则，全局一把删掉 `float`，原来依赖这些规则的部分容易跑偏。

3. 做完以后比布局顺序、阅读顺序、间距和窄屏表现，已经不需要的 clearfix 再删。没有改版需求，不必为了技术偏好大范围重写。把当前问题修清楚，往往比顺手改造整页更可控。
