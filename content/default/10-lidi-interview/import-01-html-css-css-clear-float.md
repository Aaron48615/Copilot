# 清除浮动有哪些方式？

## 核心回答

1. 清除浮动首先要明确清的是哪种影响。浮动会让附近的行内内容环绕，而且普通父容器的自动高度可能没有包含浮动子项；我们通常说的清浮动，是让后续内容排到浮动下方，或者让父容器完整包住内部浮动，并不是删除 float 属性。

2. 如果只是希望父容器包含浮动，我会优先考虑 `display: flow-root`，它建立 BFC，使自动高度包含内部浮动。比如图文介绍卡片里图片浮动、文字很短，父容器仍需要包住整张图片，这种方式表达直接，也不额外裁剪溢出内容。

3. 老代码常见 clearfix，在父容器末尾用 `::after` 生成空盒子，设置 `display: block; clear: both`。这个正常流中的清除元素会排到前面左右浮动下方，父容器高度因此延伸；不必在 HTML 中为纯布局再增加一个空 div。

4. `overflow: hidden` 或 auto 也可能通过建立 BFC 包含浮动，但会带来裁剪或滚动行为，不能无条件使用。新写的工具栏和多列区域一般更适合 Flex 或 Grid，float 仍适合文字环绕图片，是否替换要看布局目的而不是只看代码年代。

5. 我也会检查容器末尾是否已有正常流内容，因为有时高度表现正常只是恰好被一大段文字撑开了。把文字换成短文案再看边框是否包住图片，能判断方案是否真正包含浮动，而不是只对当前内容碰巧成立。

## 追问：为什么 clear 写在父元素上没有包住里面的浮动？

1. clear 处理的是当前盒子与前面相关浮动之间的关系，不会自动要求它计算内部所有浮动的高度。父容器设置 clear，主要影响父容器自己在外部浮动旁边的位置，所以与想解决的内部高度问题不一致。

2. 如果采用清除元素方案，就把正常流的清除盒子放在内部浮动之后，例如父级 after 伪元素。这样它的顶部被推到浮动底部以下，父级再根据这个正常流盒子计算高度，才能得到预期效果。

3. 若只是包含内部浮动，直接在父元素设置 flow-root 更简单。排查时我会给父级画边框，同时检查浮动和清除盒子的所在上下文，确认它们确实发生作用，而不是看到 clear 字样就认为写对了。

## 追问：旧页面的浮动布局是否应该全部改成 Flex？

1. 我会先看它是否已经稳定、是否需要改变交互和结构。两列导航或按钮排列用 Flex 通常更容易维护，但文章图片旁边的文字环绕就是浮动擅长的场景，改成 Flex 可能反而失去需要的排版效果。

2. 需要迁移时，先保留一组真实内容样例，包括短文本、长文本和缺图状态，再逐个区域替换。Flex 会改变子项尺寸、外边距和换行规则，直接全局删除 float 可能让原本依赖这些规则的部分出现偏差。

3. 完成后比较布局顺序、阅读顺序、间距和窄屏表现，并删除已经不需要的 clearfix。没有改版需求时不必为技术偏好大范围重写，明确修复当前问题往往比顺手改造整页更可控。
