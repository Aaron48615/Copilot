# Flex 和 Grid 怎么根据场景选择？

## 核心回答

1. 先看布局关系是一条轴上的伸缩，还是行和列要一起约束。Flex 更适合工具栏、导航、输入框和按钮这种单行关系；Grid 更适合卡片矩阵、主侧栏、需要跨行跨列的区域。两者可以嵌套，整页不必只用一种。

2. Flex 的长处是内容驱动的空间分配。左边图标保持大小，中间输入框占剩余空间，右边按钮按内容宽度排，各项伸缩可以写得很明确。允许换行以后，每一行独立分空间，别指望不同行的列线自动对齐，这是选择前就要知道的边界。

3. Grid 先定义轨道，再把子项放进去，适合让多行卡片列对齐。自适应列可以用 `repeat` 和 `minmax`，但容器比最小轨道还窄时可能溢出。内容需要能收缩，还得留意默认最小尺寸。写几个 `fr`，不代表所有长文本都能放下。

4. 按真实内容确定最小可用尺寸，再决定换行、列数变化和断点。卡片外层用 Grid、内部按钮行用 Flex，是很自然的组合。DOM 阅读顺序保持合理，别靠视觉重排去盖结构问题。标准是关系清楚、变化可预期，不是哪个属性更新。

## 追问：Flex 换行后为什么最后一行的卡片变宽了？

1. Flex 每条换行线分别算自己的剩余空间。子项允许 `grow`，最后一行只有两个卡片时，这两个会分走该行更多空白，不会自动给上一行没出现的第三个位置留空，所以最终宽度可能比前面更大。

2. 需求是各行保持同一套列宽，考虑 Grid，让卡片沿统一轨道排。也可以靠合理的 basis 和增长限制保住 Flex 项宽度，但不同屏宽下列数和剩余空白都要处理，规则容易比 Grid 更烦。

3. 先确认设计是不是真的要求整齐列线。标签云或工具按钮希望每行把空间用满，Flex 这种行为反而合适。商品卡片矩阵通常更强调一致宽度。最后一行变宽，不是浏览器算错了。

## 追问：Grid 布局为什么仍可能被长文本撑破？

1. 弹性轨道的默认最小尺寸可能留着内容的固有最小宽度。一个断不开的长字符串会让轨道不愿意缩到预期宽度以下。`1fr` 表达的是剩余空间比例，不是无视所有内容约束强制缩小。

2. 需要轨道允许收缩时，可以用 `minmax` 的零下限，同时查 Grid 子项的 `min-width`。之后还要给文本安排换行、省略或内部滚动。盒子变窄，和内容怎么展示，是两件事。只修外框不算完。

3. 用长 URL、没有空格的标识、固定宽图片测试，看具体是谁越界。数据表和代码可能更适合保留内部横向滚动，普通卡片标题更适合换行或省略。别为了不溢出，把重要内容无声裁掉。
