# Flex 和 Grid 怎么根据场景选择？

## 核心回答

1. 我会先看布局关系是一条轴上的伸缩，还是需要同时约束行和列。Flex 更适合工具栏、导航、输入框与按钮这样的单行关系；Grid 更适合卡片矩阵、主侧栏和需要跨行跨列的区域。两者可以嵌套，不必让整个页面只使用一种布局。

2. Flex 的优势是内容驱动的空间分配。比如左侧图标保持大小，中间输入框占剩余空间，右侧按钮按内容宽度排列，就可以明确设置各项伸缩。允许换行后，每一行独立分配空间，因此不能期待不同行的列线自动对齐，这是选择前要知道的边界。

3. Grid 则先定义轨道，再把子项放进去，适合保持多行卡片的列对齐。自适应列可以使用 repeat 与 minmax，但要考虑容器比最小轨道还窄时的溢出；需要内容可收缩时，还要留意默认最小尺寸，不能只写几个 fr 就认为所有长文本都能放下。

4. 我会先根据真实内容确定最小可用尺寸，再决定换行、列数变化和断点。卡片外层用 Grid、内部按钮行用 Flex 是很自然的组合；同时保持 DOM 阅读顺序合理，不依赖视觉重排掩盖结构问题。选择的标准是关系清楚、变化可预期，而不是哪个属性更新。

## 追问：Flex 换行后为什么最后一行的卡片变宽了？

1. Flex 每条换行线分别计算自己的剩余空间。如果子项允许 grow，最后一行只有两个卡片时，这两个会分配该行更多空白，而不会自动保留上一行没有出现的第三个位置，所以最终宽度可能比前面更大。

2. 如果需求是各行保持同一套列宽，我会考虑 Grid，让卡片沿统一轨道排列。也可以通过合理的 basis 与增长限制保持 Flex 项宽度，但要处理不同屏宽下的列数和剩余空白，规则容易比 Grid 更繁琐。

3. 判断时先确认设计是否真的要求整齐列线。有些标签云或工具按钮希望每行利用空间，Flex 的行为反而合适；商品卡片矩阵通常更强调一致宽度，不能把最后一行变宽一概称为浏览器错误。

## 追问：Grid 布局为什么仍可能被长文本撑破？

1. 弹性轨道的默认最小尺寸可能保留内容的固有最小宽度。一个不可断开的长字符串会让轨道不愿意缩到预期宽度以下，所以 1fr 表达剩余空间比例，并不意味着无视所有内容约束强制缩小。

2. 需要轨道允许收缩时，可以使用 minmax 的零下限，同时检查 Grid 子项的 min-width。之后还要给文本安排换行、省略或内部滚动，盒子变窄与内容如何展示是两件事，不能只修外框就结束。

3. 我会用长 URL、没有空格的标识和固定宽图片测试，观察具体是谁越界。数据表和代码可能更适合保留内部横向滚动，普通卡片标题更适合换行或省略，避免为了不溢出而把重要内容无声裁掉。
