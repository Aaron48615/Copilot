# 函数组件和类组件有什么区别？Hooks 解决了什么问题？

## 核心回答

1. 类组件继承 React.Component，通过 this.props、this.state 和生命周期组织逻辑；函数组件在每次渲染时执行函数，通过 Hooks 使用状态和副作用。现在写新组件我通常倾向函数组件，但维护类组件时仍需要理解其生命周期。

2. Hooks 首先让函数组件能够保存状态和建立外部同步，不再只承担展示。更重要的是，可以把同一件事的建立和清理放在一起，例如消息订阅的连接和断开都写在同一个 Effect 中，不必分散到多个生命周期里。

3. 逻辑复用可以抽成自定义 Hook，多个页面按需组合，数据来源比一层层 HOC 或 mixin 式注入更显式。但 Hook 的每次调用通常拥有自己的状态，复用函数不等于几个组件自动共享一个计数器。

4. 函数组件要理解每次渲染的快照和闭包，异步回调可能读取旧值；类组件则常涉及 this 绑定、setState 合并和生命周期条件判断。不能说 Hooks 完全替代所有类能力，例如直接实现错误边界仍常用类组件或现成的边界库。

5. 如果是维护老项目，我不会仅为了语法风格一次性改完全部类组件。会先选职责清晰、能够验证的部分，保留既有交互，再逐步调整复用逻辑；重点是新写法是否把状态和清理表达得更清楚，而不是把迁移本身当成功能或性能提升。

## 追问：类组件的 setState 和 useState 的 setter 有什么区别？

1. 类组件 setState 接收对象时，会对顶层 state 做浅合并；useState 的 setter 则替换这一项状态。比如状态同时有 name 和 age，函数组件只设置 `{ name }` 会失去 age，不能照抄类组件的更新习惯。

2. 两者在下一状态依赖上一状态时，都可以使用函数形式更新。函数组件中更新嵌套字段仍需复制被修改的路径，顶层展开不会自动深复制内部对象，也不能因为类组件会浅合并就直接修改旧对象。

3. 类组件 setState 可以传提交后的回调，useState 没有同样的第二参数。函数组件应根据目的选择事件中直接使用计算出的新值，或在提交后的 Effect 中同步外部系统，不要简单用 await setter 等待更新。

## 追问：把类组件改成函数组件，是不是逐个替换生命周期就行？

1. 我会先按业务行为整理，而不是机械地把 didMount 换成空依赖 Effect。比如订阅既要在挂载时建立，也要在用户编号变化时切换，真正的依赖是编号，空数组会遗漏原更新逻辑。

2. 初始化和清理应放在同一个 Effect 中，事件触发的请求仍放在事件里，派生值直接计算。这样迁移后逻辑按功能聚合，避免把原来分散的生命周期原样搬成多个互相影响的 Effect。

3. 迁移时还要检查 state 合并差异、实例字段与 ref 的对应，以及异步回调是否读到了旧值。我会先验证原有交互和卸载清理，不能仅凭代码行数变少就判断迁移已经正确。尤其要保留重复进入和快速切换参数的测试，确认迁移没有把持续同步误写成仅初始化一次。
