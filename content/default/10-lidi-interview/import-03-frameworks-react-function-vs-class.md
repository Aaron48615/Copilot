# 函数组件和类组件有什么区别？Hooks 解决了什么问题？

## 核心回答

1. 类组件继承 `React.Component`，用 `this.props`、`this.state` 和生命周期组织逻辑。函数组件每次渲染就是把这个函数跑一遍，状态和副作用靠 Hooks。现在新写的组件基本用函数组件；老的类组件还在维护，生命周期照样得懂。

2. Hooks 让函数组件也能存状态、跟外面同步，不再只能当展示。同一件事的建立和清理可以写在一起：消息订阅的连接和断开都在同一个 Effect 里，不用拆到好几个生命周期。

3. 要复用一段带状态的逻辑，抽成自定义 Hook，几个页面按需组合。数据从哪来比一层层 HOC、mixin 灌进去更看得见。Hook 每次调用通常各有一份状态，复用函数不等于几个组件共用一个计数器。

4. 函数组件要搞清楚每次渲染是一份快照，异步回调可能读到旧值。类组件常碰到 `this` 绑定、`setState` 浅合并、生命周期里加条件。Hooks 也没把类的能力全替掉，错误边界现在还是类组件或者现成的边界库更常见。

5. 维护老项目，不为了换写法一次改完所有类组件。挑职责清楚、能验证的部分，交互先保住，再慢慢把复用逻辑挪过来。看的是状态和清理有没有说清楚，迁移本身不是功能，也不是性能提升。

## 追问：类组件的 setState 和 useState 的 setter 有什么区别？

1. 类组件 `setState` 传对象时，对顶层 state 做浅合并。`useState` 的 setter 是整项换掉。state 里同时有 `name` 和 `age`，函数组件只 `setUser({ name })`，`age` 就没了。类组件那套更新习惯不能原样抄过来。

2. 下一状态要依赖上一状态，两边都可以传函数。函数组件改嵌套字段，被改到的那条路径要拷一份，最外层展开不会自动深拷里面的对象。也别因为类组件会浅合并，就直接改旧对象。

3. 类组件 `setState` 可以带一个更新后的回调，`useState` 没有这个第二参数。事件里已经算出新值就直接用；要跟外部系统对齐，放到提交之后的 Effect。别 `await setter` 等着更新完成。

## 追问：把类组件改成函数组件，是不是逐个替换生命周期就行？

1. 按业务行为来，别把 `componentDidMount` 机械换成空依赖 Effect。订阅挂载时要建，用户编号变了也要换，真正的依赖是编号。写成 `[]`，原来更新时那段就丢了。

2. 初始化和清理放同一个 Effect。点击才发的请求仍放事件里。能算出来的派生值直接算。迁完以后按功能聚在一起，别把原来分散的生命周期原样搬成好几个互相扯的 Effect。

3. 还要核对 state 合并差在哪、实例字段对应哪个 ref、异步回调有没有读到旧值。原有交互和卸载清理先过一遍。行数变少说明不了迁对了。重复进入、快速改参数也要测，别把持续同步写成只初始化一次。
