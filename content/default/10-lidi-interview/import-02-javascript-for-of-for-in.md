# for...of 和 for...in 有什么区别？

## 核心回答

1. for...in 枚举对象的可枚举字符串属性名，既可能包含自身属性，也可能包含原型链上的属性。它不枚举符号属性，所以把它概括成遍历对象的所有键会漏掉条件，使用前要先明确想处理哪类属性。

2. for...of 使用可迭代协议，读取迭代器依次给出的值，不是把前一种循环的键直接换成值。数组通常给出元素，集合给出成员，映射给出键值对；普通对象默认没有迭代器，直接使用会报错。

3. 遍历数组元素时我会优先考虑 for...of，因为给数组额外挂一个可枚举属性，不应让它变成业务元素。稀疏数组还要注意，默认迭代器会访问空位并通常得到 undefined，而属性枚举会跳过不存在的索引。

4. 如果要遍历普通对象自己的可枚举字符串属性，我会用 Object.keys 或 Object.entries。确实需要 for...in 时，可以用 Object.hasOwn 过滤继承属性，这也避免对象自己覆盖同名检查方法造成误判。

5. for...of 的循环体可以直接使用 break、continue，在异步函数内也能等待每项处理结束。forEach 的回调返回不能退出外层函数，也不会让遍历自动等待异步回调，选择时应看中断和执行顺序的需要。

## 追问：数组多了一个自定义属性，两种循环会分别得到什么？

1. 假设数组只有两个元素，又直接给它添加一个说明属性，for...in 通常会得到两个字符串索引和这个属性名。长度属性因为不可枚举不会出现，所以结果并不是数组对象上所有属性的列表。

2. 默认的数组迭代器按索引访问元素，for...of 会给出那两个元素，不会额外给出说明文字。如果还给原型添加了可枚举属性，前一种循环可能继续枚举出来，后一种循环仍按数组迭代规则工作。

3. 如果需求是连同自定义属性一起检查数组对象，我会明确选属性相关接口；如果只是处理列表内容，就按元素语义遍历。还应避免循环期间随意增删属性，因为这样会把枚举变化和原本的数据处理混在一起。

## 追问：如何让一个范围对象支持 for...of，并允许提前结束？

1. 假设对象表示从起点到终点的一组整数，可以给它定义 Symbol.iterator 方法，返回保存当前位置的迭代器。每次调用 next 返回当前值与是否结束，循环就能依照这个约定逐项读取。

2. 我会让每次获取迭代器都创建独立的当前位置，避免两个循环共用游标、互相跳过元素。生成器也可以表达这个过程，但仍要先约定终点是否包含、步长是否合法，不能只让语法表面上跑通。

3. 如果迭代过程持有需要清理的资源，还要考虑提前 break 时的退出行为。循环提前退出会尝试调用迭代器的 return 方法，生成器可以用 finally 清理，但真实外部资源仍需要可靠的生命周期管理。
