# WeakMap 为什么不能遍历？

## 核心回答

1. WeakMap 不能遍历，是因为它不把键强行保活，键何时被垃圾回收也不是业务能控制的。要是提供完整键列表，程序就可能通过列表变化观察回收时机，同一段逻辑的结果还会受内存压力等运行环境影响。

2. 所以它只支持拿着已知键做读写、判断和删除，没有 `keys()`、普通迭代入口或 `size`。限制的是不能枚举未知条目，不是写进去就读不出来。只要还握着合法键，就能按这个键查对应信息。

3. 比如给页面节点保存一次计算结果，可以用节点当键，结果当值。节点从页面移除、别的强引用也没了以后，这张表不会仅仅因为保存了键就拦住回收，也就不用为每个失效节点单独维护缓存索引。

4. 但移除节点不等于它立刻不可达。闭包、数组或事件订阅仍可能握着引用。键还活着的时候，值也可能占很多内存。弱映射不会自动管掉所有缓存，也不会保证某个时刻一定释放。

5. 需求是展示全部缓存、统计数量或按最近使用淘汰，就用 Map，并自己定清理策略。当前规范允许弱映射用对象和未注册的 Symbol 当键，不是只能用对象；字符串业务编号仍然不适合直接放进去。

## 追问：额外用数组保存全部键能弥补不能遍历吗？

1. 数组如果直接保存每个对象键，就建了新的强引用。WeakMap 本身不保活这些键，数组却让它们一直可达。遍历能力补上了，本来想随对象生命周期释放的效果，却被另一个容器破坏了。

2. 这些键要是已经离开页面的节点，长期保存它们的调试数组也可能让相关对象一直留下。排查要看整条引用链，不能看到用了弱映射就排除缓存问题。一个辅助索引同样是要管的业务状态。

3. 真要列出全部条目，直接用 Map，在组件销毁或容量到限时删对应记录。数量和清理行为都说得清，也比同时维护一份强引用列表和一张弱映射更容易核对，免得两份数据更新不同步。

## 追问：WeakMap 的值引用自己的键会导致永远不能回收吗？

1. 只是条目内部的值回指键，不会自动让这一对数据永久存活。弱映射看的是键能不能从外部强引用路径到达，不能把它画成普通对象互相引用，再断定必然泄漏。

2. 但外部另外保存了这个值，值又保存着键，就形成了真实的外部强引用路径。比如全局数组保存元数据，元数据里带着节点，节点就仍然可达。问题出在这条外部路径，弱映射没法替其他对象解开引用。

3. 分析内存时，先找谁还握着对象，再判断缓存结构合不合适。清理要对着全局数组、订阅或闭包这些实际持有者。只把 Map 换成 WeakMap 解决不了，也不能靠固定延时断言回收已经发生。
