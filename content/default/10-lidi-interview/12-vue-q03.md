# `ref` 和 `reactive` 怎么选？

## 核心回答

1. `ref` 可以包装基本值，也可以包装对象，脚本中通常通过 `.value` 读写。比如加载状态用 `ref(false)`，列表用 `ref([])`，请求成功后直接给 `list.value` 赋新数组，仍然会触发依赖更新。

2. `reactive` 接收对象、数组以及集合等对象类型，返回代理，使用时直接访问属性。它不能把一个独立数字变成响应式变量，多个相关表单字段放进同一个 `reactive` 对象则比较自然，修改时保留这个代理引用。

3. 两者默认都可以提供深层响应式，对象放入普通 `ref` 也会进行响应式转换。所以不能按“ref 只管基础类型、reactive 才能管对象”来选，我更关注状态是否需要整体替换，以及调用代码是否清晰。

4. 直接解构 `reactive` 的基本值属性，得到的是当时的普通值，会失去与原属性的响应式关联；可以用 `toRef` 或 `toRefs` 保留连接。嵌套对象解构出来可能仍是代理，但原对象后来替换该属性时，旧引用不会自动改指向新对象。

5. 顶层模板变量中的 ref 通常会自动解包，但不能据此认为任何位置都不用 `.value`。对于经常整体替换的数据，我倾向用 ref；如果用 reactive 管表单，可以更新已有字段，并留意 `Object.assign` 不会自动删除旧对象多余的键。

## 追问：为什么重新给 reactive 变量赋值后，某些地方不更新了？

1. 响应式依赖关联的是具体代理对象及其属性，不是一个普通局部变量的所有未来取值。把 `state` 重新赋成另一个对象，不会让已经持有旧代理的函数或组件自动切换，所以容易出现不同代码读到不同状态。

2. 如果要维持同一个表单对象，可以把新值写入原代理的属性，让既有依赖继续工作。用 `Object.assign(state, data)` 时，要确认缺省字段如何重置，因为返回数据里没出现的字段仍会留在原对象中。

3. 如果需求本来就经常整包替换，我会改用 `const state = ref(initial)`，然后更新 `state.value`。这与重新声明一个 ref 变量不同：保留的是同一个 ref 容器，它的 `.value` 赋值正是可以被追踪的更新入口。

## 追问：ref 什么时候会自动解包，什么时候还要写 value？

1. 在脚本中读写一个独立 ref，一般都使用 `.value`；在模板中，作为顶层暴露变量使用时通常会自动解包。例如脚本里是 `count.value++`，模板显示可以直接写 `count`，但这不是 JavaScript 自身的语法特性。

2. 普通深层 reactive 对象的属性如果是 ref，读取该属性时可以自动解包；响应式数组的元素和 Map 里的值则没有相同保证。例如数组保存 `ref(1)`，读取其第零个元素的值时仍需要 `.value`。

3. 模板里 ref 若藏在普通对象的嵌套属性中，也不应笼统依赖自动解包，特别是参与表达式运算时。我会把需要展示的 ref 提升为明确的顶层变量，或按实际位置读取，避免字符串拼接等操作得到意外结果。
