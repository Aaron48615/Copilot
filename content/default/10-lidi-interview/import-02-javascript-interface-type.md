# interface 和 type 在项目里怎么取舍？

## 核心回答

1. 普通对象结构，接口和类型别名都能描述字段、方法、可选属性。先遵守项目已有约定。同一份对象定义从一种写法换成另一种，通常不会直接改变页面行为，也不会产生运行时对象，更不会去验证接口数据。

2. 要表达可被继续扩展的对象约定，可以选择接口：用继承表达基础结构，确有需要时再开放声明合并。一个库明确允许使用者补充配置项时，这种扩展能力有意义。普通业务类型不一定需要被隐式扩大。

3. 类型别名能直接表达联合、元组和条件类型。碰到成功或失败这样的多种结果，优先考虑它。别名也能描述对象和函数，别简单记成「接口只能写对象、别名只能写复杂类型」。核心是选能把关系讲清楚的表达方式。

4. 两者组合对象时，处理冲突的方式不一样。接口继承遇到不兼容字段通常会直接报错；交叉类型可能把冲突字段变成无法取值的类型。无论选哪一种，字段来源要容易查找。写法更短，不等于设计更合理。

## 追问：两个对象类型都有 id，但类型不同，交叉后会怎样？

1. 一个要求编号是字符串，另一个要求编号是数字，交叉类型要求同一个字段同时满足两边。普通字符串和数字没有共同取值，这个字段会变成无法正常赋值的类型，不会自动在两者中任选一个。

2. 这种错误有时在组合声明时不明显，真正创建或使用对象时才暴露。接口继承不兼容属性，通常会更早指出冲突。交叉类型能写出来，不代表合并结果一定能构造出合理的数据。

3. 业务目的确实是替换字段类型，可以先去掉原来的字段，再加入新定义，并确认调用者需要哪种格式。别用交叉表达覆盖。交叉表示同时满足要求，字段替换和字段约束叠加不是一回事。

## 追问：一个类型只在编译时存在，为什么类还能用 implements？

1. 类实现接口或合适的对象类型，是让编译器检查类的实例是否满足对应结构。它不会自动生成缺失的方法，也不会在运行时把接口挂到原型链上。实现声明和类继承不是同一件事。

2. 接口要求一个返回字符串的方法，类仍然需要自己提供实现，方法怎么工作取决于实际代码。这个检查主要针对实例这一侧，不能据此认为构造函数签名和静态成员也已经按同样要求验证过。

3. 运行时也不能直接拿接口名做实例判断，生成的代码里通常没有这个接口值。要检查外部数据能不能用，验证实际字段或能力。要检查类的原型关系，使用运行时存在的构造函数，并说明判断边界。
