# Vue 的异步组件和 keep-alive 怎么取舍？

## 核心回答

1. 异步组件和 `KeepAlive` 管的不是同一件事，可以一起用。异步组件决定代码什么时候下载，适合又大又不常打开的模块；`KeepAlive` 决定切走以后实例还在不在，适合人会反复回来的页面。一个是下载成本，一个是实例和状态。

2. 比如很少打开的复杂预览弹窗，用 `defineAsyncComponent` 拖到点开再加载，首次要有等待和失败提示。代码下载过以后，模块加载机制通常会缓存这份代码，但这不等于每次打开都是同一个组件实例。代码缓存和实例缓存要分开看。

3. 列表进详情再返回，想留着筛选和滚动，可以上 `KeepAlive`。它占内存，缓存里的监听、轮询也不会自动停。激活、停用钩子里处理看得见时才该干的活，卸载清理不够。

4. 数据新不新还得另说。回来可以按时间或失效标记决定要不要刷新，留着筛选不等于接口结果永远用旧的。`max` 能限制份数，组件 `name` 和 `key` 也要合理，别每个查询参数都变成一份长期缓存。

5. 先分清慢在第一次下载，还是每次都重新初始化；再看状态值不值得留。路由懒加载一般在路由配置里直接动态 `import` 就行，不必再套一层异步组件包装。加载失败、返回恢复、缓存淘汰、最后把资源放掉，这几条都要过。

## 追问：模块已经下载过，为什么第二次打开弹窗还会初始化？

1. 动态模块缓存的是代码，不是业务实例。弹窗用 `v-if` 关掉就卸载了，下次打开还是新实例，`setup` 和挂载会再跑一遍。图表、编辑器又初始化一次，这是正常生命周期。

2. 想少初始化，得看留着实例划不划算，比如改显示方式或加 `KeepAlive`。代价是藏着也占内存，里面的任务可能还在跑。打开变快了，页面用久了资源却一直堆，也不划算。

3. 初始化里不变的计算，有时可以单独缓存，不必把整个弹窗实例留住。真要清空编辑状态时，也能少做一遍准备工作。

## 追问：给每个路由 fullPath 当 key，会有什么缓存代价？

1. `fullPath` 带着查询参数。筛选、分页，甚至一个无关的跟踪参数一变，身份就变了。同一个列表页可能存很多份实例，内存、定时器、第三方资源跟着涨。人觉得只开了一页，缓存里已经有一堆副本。

2. 看业务要不要独立状态。不同文档的编辑页可能要按文档编号隔开；同一列表换页码，页码当内部状态就够了，不必每页缓存整个组件。缓存键对应真正要留的那份对象。

3. 上限设好，淘汰时也要能清干净。只靠 `max` 防无限涨，被挤掉的页面外面还有监听或回调，照样漏。键怎么定、能留几份、资源什么时候放，一块看才知道成本。
