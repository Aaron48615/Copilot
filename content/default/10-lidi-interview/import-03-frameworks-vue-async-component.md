# Vue 的异步组件和 keep-alive 怎么取舍？

## 核心回答

1. 异步组件和 KeepAlive 不是互斥方案。异步组件决定组件代码何时加载，适合体积较大或不常使用的模块；KeepAlive 决定组件切走后是否保留实例和局部状态，适合用户会反复返回的页面，两者处理的是不同阶段的成本。

2. 比如低频打开的复杂预览弹窗，可以用 defineAsyncComponent 延后加载，首次打开要有等待与失败反馈。代码下载后通常受模块加载机制缓存，但这不代表每次打开都保留同一个组件实例，代码缓存和实例缓存需要分开理解。

3. 列表切到详情再返回时，如果希望保留筛选和部分界面状态，可以考虑 KeepAlive。它会增加内存占用，缓存里的监听、轮询也不一定自动暂停，因此要在激活和停用钩子里处理可见期间的工作，而不是只写卸载清理。

4. 数据新鲜度仍需独立设计。回来可以根据失效标记或时间判断是否刷新，保留筛选不意味着永远使用旧接口结果；缓存数量可以通过 max 等机制限制，组件名称与 key 也要合理，避免每个查询参数都生成一份长期缓存。

5. 我的选择顺序是先确认慢在首次下载还是重复初始化，再判断状态是否值得保留。路由懒加载通常直接在路由配置使用动态 import，不需要盲目套异步组件包装；实际方案还要验证加载失败、返回恢复、缓存淘汰和最终资源释放。

## 追问：模块已经下载过，为什么第二次打开弹窗还会初始化？

1. 动态模块缓存保留的是代码加载结果，不是业务组件实例。如果弹窗通过 v-if 关闭后卸载，下一次打开仍会创建新实例、执行 setup 和挂载逻辑，所以图表或编辑器初始化可能再次发生，这是正常的生命周期行为。

2. 要减少重复初始化，可以先判断保留实例是否值得，例如使用合适的显示切换或 KeepAlive。代价是隐藏期间占用内存和可能继续运行的任务，不能只看打开速度，不考虑页面长期使用时资源是否不断累积。

3. 我会把初始化中的不变计算与实例相关工作分开，前者有时可以独立缓存，不必保留整个弹窗。这样在确实需要清空编辑状态的场景，也能减少重复准备成本，而不是为了性能强行保留所有旧状态。

## 追问：给每个路由 fullPath 当 key，会有什么缓存代价？

1. fullPath 包含查询参数，筛选、分页或无关跟踪参数改变，都可能产生新的缓存身份。同一个列表页面因此保存多份实例，内存、定时器和第三方资源跟着增加，用户以为只打开一页，实际缓存里已有很多副本。

2. 我会按业务区分是否需要独立状态。例如不同文档编辑页可能需要按文档编号隔离，而同一列表的页码通常可以作为内部状态，不一定每页都缓存一整个组件；缓存键应表达真正需要保留的对象身份。

3. 同时设置合理上限并验证淘汰清理。不能只靠 max 避免无限增长，却忽略被淘汰的页面仍有外部监听或异步回调；键策略、缓存容量和资源生命周期需要一起检查，才知道保留实例的实际成本。
