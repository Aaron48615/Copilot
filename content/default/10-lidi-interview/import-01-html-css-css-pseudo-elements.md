# 伪类和伪元素有什么区别？

## 核心回答

1. 伪类描述已有元素的状态或结构关系，例如 hover、focus-visible 和 first-child；伪元素则选择或生成元素的某个可样式化部分，例如 first-line、placeholder，以及 before、after。区别在于选择对象，不只是一个冒号和两个冒号的写法不同。

2. 我通常把伪类写成单冒号、伪元素写成双冒号。部分早期伪元素保留单冒号兼容写法，但新代码统一双冒号更清楚；不能反过来说只要看到单冒号就一定不是伪元素，阅读旧样式时要知道这个历史兼容规则。

3. before 和 after 常用于装饰线、角标背景或小箭头，通常要设置 content 才能生成内容盒子。但不是所有伪元素都需要 content，例如 first-line 只是选择已有文本的第一行。它们也不是普通 DOM 节点，不能像按钮一样独立绑定完整交互和语义。

4. 我会让关键业务内容留在 HTML 中，装饰再交给伪元素。比如必填星号可以作为视觉装饰，但必填状态还应通过表单语义和文字说明表达。伪类适合根据真实状态改变样式，不能只用颜色模拟禁用，却让按钮仍然可以被点击。

5. 伪元素的样式同样参与层叠，背景装饰可能挡住主体点击，也可能被祖先裁剪。调试时我会检查生成盒子的尺寸、定位和指针命中，而不是因为它没有单独出现在文档树里，就认为它不会影响实际交互。

## 追问：为什么不建议用 ::before 输出重要提示文字？

1. CSS 生成内容的辅助技术呈现和用户操作体验可能不一致，而且它不在普通 DOM 文本结构中。重要说明如果只存在于 content 里，复制、翻译、样式关闭或读屏时可能出现不同结果，不适合承担唯一的信息来源。

2. 我会把“此项必填”或错误原因写成真实文字，再通过 label、描述关联等方式连接到字段。before 可以画一个装饰标记，但即使这个标记不显示，用户仍然应该知道规则和下一步怎么操作。

3. 如果只是引号、分隔线或不影响理解的小箭头，伪元素比较合适。判断标准是删掉这段生成内容后是否会损失关键含义；一旦会改变业务理解或操作结果，就应优先使用有明确语义的真实节点。

## 追问：:nth-child 和 :nth-of-type 为什么选到的元素不同？

1. :nth-child 按同一父元素下的元素子节点顺序计数，不管它们分别是什么标签。比如一个标题后面有多个段落，p:nth-child(2) 会匹配作为第二个元素子节点的段落，而不是第二个段落。

2. :nth-of-type 则在同类型标签中计数，因此 p:nth-of-type(2) 表示同级段落中的第二个。它也不是按某个 class 分组计数，如果多个不同业务卡片都用 div，仍然会把同级 div 一起纳入计算。

3. 我会根据真实结构选择，并注意插入标题、广告或占位项后顺序会变化。若某一条业务数据始终需要特殊样式，用明确的状态类可能比依赖位置更稳定，位置选择器适合表达真正与排列顺序有关的规则。
