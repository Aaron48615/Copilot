# `this` 的指向怎么判断？

## 核心回答

1. 普通函数的 `this`，看实际怎么调。`user.say()` 里通常是 `user`，但 `const say = user.say; say()` 已经是独立调用。严格模式下 `this` 是 `undefined`，跟方法当初写在哪个对象上没有直接关系。

2. 非严格的普通函数，独立调用时 `this` 会换成全局对象，别一律说都是 `window`。模块默认严格模式，浏览器和其他环境顶层也不一样。看输出题先把这些前提补齐，控制台跑一次，解释不了所有脚本和模块。

3. `call` 和 `apply` 都马上调函数，并传入指定的 `this`。前者一个个传参，后者接参数列表。`bind` 返回绑定后的新函数，不会马上执行，适合把对象方法当回调传出去时钉死上下文。

4. 箭头函数没有自己的 `this`，会沿用外层那个。`call`、`apply`、`bind` 也换不了。对象字面量里写箭头，不会因为写在对象里面，就把这个对象当成 `this`。

5. `new` 调可构造函数时，函数体里的 `this` 对着新实例。箭头函数不能当构造函数。回调出问题，先看是不是把调用对象弄丢了，再决定包一层调用还是 `bind`，别到处改函数写法。

## 追问：对象方法交给定时器后，怎样保留原来的 this？

1. `setTimeout(user.say, 0)` 传进去的是函数值，不会把 `user.say()` 这种调用关系一起带上。回调最后由宿主去调，别假设它还以 `user` 为接收者。所以直接调正常，延迟调就不对，很常见。

2. 可以写成 `setTimeout(() => user.say(), 0)`，到点了再通过对象调一次；也可以先 `const say = user.say.bind(user)` 再传进去。前者执行时才读 `user.say`，后者钉死的是绑定时那一个函数。定时器等着的时候如果把对象上的方法换掉了，差别就能看出来。

3. 事件监听还要留着绑定后的那份函数引用，清理时才能交给 `removeEventListener`。每次重新 `bind` 都是不同函数，绑的是同一个对象和方法，也摘不掉之前注册的那次。

## 追问：Vue 的 methods 可以全部改成箭头函数吗？

1. Options API 里，方法要靠 `this` 访问组件状态，就不适合改成箭头。Vue 能给普通方法设组件上下文，箭头用的是外层的 `this`，框架没法绑成组件实例。

2. 普通方法里面的异步回调，倒经常适合用箭头，因为它能继续用外层方法的 `this`。组件方法本身，和方法里面的回调，是两层。别看着箭头写得短就把两层都换掉。

3. Composition API 通常通过闭包直接用 `ref`、函数和其他局部变量，不靠组件 `this`。这时普通函数和箭头，看它要不要自己的上下文。Options API 那套规则，别原样搬过来。
