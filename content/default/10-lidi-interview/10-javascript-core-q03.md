# `this` 的指向怎么判断？

## 核心回答

1. 判断普通函数的 `this`，我会先看实际调用表达式。`user.say()` 中它通常是 `user`，但 `const say = user.say; say()` 已经变成独立调用，严格模式下 `this` 是 `undefined`，和方法最初存在哪个对象里没有直接关系。

2. 对非严格普通函数，独立调用时的 `this` 会替换为全局对象，不能一律说都是 `window`。模块默认是严格模式，浏览器和其他运行环境的顶层行为也有差异，所以分析输出题时要先补齐这些前提，不能拿控制台的一次结果解释所有脚本和模块。

3. `call` 和 `apply` 都立即调用函数并传入指定的 `this`，前者逐个传参，后者接收参数列表。`bind` 返回一个绑定后的新函数，不会马上执行，适合把对象方法作为回调传递时固定上下文。

4. 箭头函数没有自己的 `this`，会沿定义时的外层环境寻找，`call`、`apply`、`bind` 不能给它换一个 `this`。因此对象字面量里的箭头函数不会因为写在对象里面，就自动把这个对象当成自己的上下文。

5. 使用 `new` 调用可构造函数时，函数体中的 `this` 会对应新创建的实例，箭头函数则不能作为构造函数。碰到回调问题，我会检查是否丢失调用对象，再选择包装调用或绑定函数，而不是到处修改函数写法。

## 追问：对象方法交给定时器后，怎样保留原来的 this？

1. `setTimeout(user.say, 0)` 传入的是函数值，不会一并保存 `user.say()` 这种调用关系。回调最终由宿主调用，不能假设它仍然以 `user` 为接收者；这也是方法直接调用正常、延迟调用异常的常见原因。

2. 可以写成 `setTimeout(() => user.say(), 0)`，执行时通过对象再次调用；也可以先得到 `const say = user.say.bind(user)` 再传入。前者会在执行时读取 `user.say`，后者固定的是绑定时那一个函数，两者并非完全一样，如果定时器等待期间替换了对象的方法，这个差别就能观察到。

3. 事件监听还要保留绑定后的函数引用，才能在清理时传给 `removeEventListener`。每次重新写一次 `bind` 都会得到不同函数，虽然绑定的是同一对象和方法，也无法用新函数移除之前注册的监听。

## 追问：Vue 的 methods 可以全部改成箭头函数吗？

1. 如果使用 Options API，而且方法需要通过 `this` 访问组件状态，就不适合改成箭头函数。Vue 可以为普通方法设置组件上下文，但箭头函数使用词法 `this`，框架无法通过绑定把它改成组件实例。

2. 普通方法内部的异步回调反而经常适合用箭头函数，因为它可以继续使用外层方法的 `this`。我会分清“组件方法本身”和“方法里面的回调”，不能看到箭头写法短就把两层都替换。

3. 使用 Composition API 时，通常通过闭包直接访问 `ref`、函数和其他局部变量，不依赖组件 `this`。这时普通函数与箭头函数可以按是否需要自身上下文来选择，也不能把 Options API 的规则机械搬过来。
