# 如果用户连续点击加号怎么办？

## 核心回答

1. 轻购里用 `updatingBasketIds` 记录正在更新的购物车项 ID。同一个商品发出修改请求以后，下一次相同商品的修改会直接返回，避免连续点击产生并发请求。
2. 步进器回调拿到的是新数量，我先用新数量减去旧数量得到差值，再把差值传给 `/p/shopCart/changeItem`。接口成功后才修改本地数量，失败时不会把页面显示成服务端没有接受的状态。
3. 如果数量减到零，项目会调用删除接口，再重新加载购物车，而不是只在前端把这一行隐藏掉。
4. 这只能减少前端重复操作，不能替代后端并发控制。服务端仍然要校验库存和购物车项是否属于当前用户；多个设备同时操作时，也要以后端结果为准。
