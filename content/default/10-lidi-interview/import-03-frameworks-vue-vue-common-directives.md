# Vue 有哪些常用指令？

## 核心回答

1. 我会按用途介绍常用指令。v-bind 绑定属性，可以简写为冒号，比如动态设置图片地址、按钮禁用和类名；v-on 绑定事件，可以简写为 @，事件处理器负责响应用户操作，不能把本应由数据决定的展示都改成手动操作 DOM。

2. v-if、v-else-if 和 v-else 控制条件分支，不满足条件时对应内容不会一直保留；v-show 则通过显示样式隐藏已有元素。低频出现且初始化昂贵的内容可以考虑 v-if，频繁切换并希望保留内部状态的区域可以考虑 v-show，同时留意隐藏组件仍然存活。

3. v-for 用来遍历数组、对象等数据，动态列表需要稳定业务 key，避免排序或删除后局部输入状态跟错项。筛选应先通过 computed 得到结果，Vue 2 和 Vue 3 的 v-if、v-for 同节点优先级不同，不应靠混写来表达复杂条件。

4. v-model 简化表单值与输入事件的同步，原生控件和自定义组件遵循不同具体协议。文本输入、复选框和选择框要按控件类型理解，组件默认模型则通过 prop 与更新事件通信，不能说所有场景都只是 value 加同一个 input 事件。

5. v-text 用于文本，v-html 会把内容按 HTML 插入，外部不可信内容需要先做合适处理。v-once 等可限制特定内容后续更新，但只能用于确实不需要变化的场景；知道指令名称之外，我会重点说明它影响的是数据绑定、节点生命周期还是显示样式。

## 追问：v-html 为什么不能直接展示任意用户输入？

1. 它把字符串当 HTML 处理，用户输入如果包含恶意标签、事件属性或危险链接，可能引入脚本执行等风险。普通文本插值会把内容当文本显示，与 v-html 的行为不同，不能因为字符串来自接口就默认可信。

2. 真正需要富文本时，应使用明确允许的标签和属性规则进行净化，服务端也要按业务处理保存和输出。不能只替换一个 script 字符串就认为安全，因为危险内容不只存在于 script 标签，事件属性和 URL 同样需要考虑。

3. 我会优先确认是否真的需要 HTML，例如评论正文只有换行时可以用文本和样式呈现。只有明确的富文本需求再使用相应方案，并验证链接和交互行为，避免为了少写展示逻辑扩大输入解释范围。

## 追问：按钮禁用应该绑定 disabled，还是点击时判断一下？

1. 一般两者有不同作用。绑定 disabled 能让用户直接看到当前不能操作，并阻止原生按钮的相应交互；处理函数中检查当前状态则可以避免其他调用路径或状态竞争导致重复执行，不能只靠按钮颜色变灰表达禁用。

2. 例如提交期间根据 submitting 禁用按钮，事件里也检查是否已有任务，并在成功或失败后恢复。样式类只改变外观，不会自动改变键盘和默认行为，因此要使用正确的属性和元素，而不是模拟一个看起来像按钮的 div。

3. 服务端仍需要处理重复或无权操作，前端禁用只是交互层控制。测试可以快速点击并用键盘触发，确认等待期间没有重复请求，失败后能够再次提交，不能为了防重复永久锁住用户。
