# Vue 有哪些常用指令？

## 核心回答

1. 天天写的是 `v-bind` 和 `v-on`。`v-bind` 绑属性，可写成冒号，比如图片地址、按钮禁用、类名；`v-on` 绑事件，可写成 `@`。展示该由数据决定的，别改成回调里手动改 DOM。

2. `v-if`、`v-else-if`、`v-else` 管条件分支，条件不满足时对应内容不会一直留着；`v-show` 是改显示样式，元素还在。不一定会用、初始化又贵的，用 `v-if`；切来切去还想留内部状态的，用 `v-show`，并记住隐藏着的组件其实还活着。

3. `v-for` 遍历数组、对象。动态列表要稳定业务 `key`，排序或删除以后，行里输入框别跟错项。筛选先用 `computed` 算出结果再遍历。Vue 2 和 Vue 3 在同一节点上 `v-if`、`v-for` 优先级不一样，别靠混写表达复杂条件。

4. `v-model` 把表单值和输入事件绑在一起。原生控件和自定义组件协议不一样：文本框、复选框、选择框按控件类型理解；组件默认模型走 prop 加更新事件。不是所有场景都是 `value` 加同一个 `input` 事件。

5. `v-text` 出文本；`v-html` 按 HTML 插进去，外部不可信内容要先处理。`v-once` 这块之后不再更新，只给确实不会变的。`v-pre` 跳过编译，花括号原样输出。`v-cloak` 是 Vue 2 常用来配合 CSS，网慢时先把未编译的模板原文藏住。知道名字之外，还要分清它动的是绑定、节点寿命，还是显示样式。

## 追问：v-html 为什么不能直接展示任意用户输入？

1. 它把字符串当 HTML 解析。用户输入里若有恶意标签、事件属性、危险链接，可能把脚本跑起来。普通文本插值当文本显示，跟 `v-html` 不是一回事。字符串来自接口，也不等于可信。

2. 真要富文本，按允许的标签和属性规则净化，服务端保存和输出也要按业务处理。只替换一个 `script` 字符串不算安全，危险不只在 `script` 标签，事件属性和 URL 也要管。

3. 先确认是不是真的需要 HTML。评论只有换行，用文本加样式就行。明确的富文本需求再用对应方案，链接和交互行为也要验。别为了少写展示，把输入解释范围放大。

## 追问：按钮禁用应该绑定 disabled，还是点击时判断一下？

1. 两件事作用不同。绑 `disabled`，人一眼能看出现在点不了，原生按钮的相应交互也会被拦住。处理函数里再看当前状态，能挡住别的调用路径或状态竞争导致的重复执行。只靠颜色变灰，禁用不算完成。

2. 提交期间用 `submitting` 禁用按钮，事件里也检查是不是已有任务，成功或失败后再恢复。样式类只改外观，键盘和默认行为不会自动变。该用按钮和正确属性，别拿一个看起来像按钮的 `div` 冒充。

3. 服务端还是要处理重复提交和没权限，前端禁用只是交互层。测试快速连点和键盘触发，等待期间不该重复请求，失败后还能再提交。防重复别做成永远锁死。
