# 路由守卫和后端权限控制有什么区别？

## 核心回答

1. 路由守卫发生在导航过程中，主要帮助正常用户走对页面。轻购里没有 Token 就转到登录页，并保存原目标路径；这样用户进入购物车时能得到合理引导，而不是先看见一个页面再收到很多接口报错。

2. 后端权限检查发生在接口处理时，需要验证凭据、用户状态与具体资源权限。比如更新地址，不仅要知道用户登录了，还要确认 addrId 对应的地址属于他，不能只检查参数里有一个合法 ID。

3. 前端逻辑是用户能够查看和修改的，别人可以绕过守卫直接发送请求。隐藏按钮也只是让界面不提供某个操作，并不能阻止手写请求，所以安全规则不能只存在于路由配置或组件条件判断里。

4. 两边可以表达相同业务限制，但目的不同：前端减少误操作并给出反馈，后端保证无论请求从哪里来都按规则处理。前端拿到权限不足后应说明原因或刷新状态，不应把所有拒绝都统一当成需要重新登录。

5. 轻购守卫主要判断 Token 是否存在，城市视图则还会按角色过滤菜单和检查路由。即使用户修改浏览器角色让管理菜单出现，管理接口仍需根据经过验证的身份重新授权，不能信任这个前端角色值。

## 追问：为什么详情接口比列表过滤更容易漏权限？

1. 列表通常按当前用户查询，看起来不会出现其他人的数据，但详情如果只用 URL 里的 ID 查记录，就可能漏掉归属判断。用户不需要在页面看到入口，也可以尝试直接访问某个详情地址。

2. 所以列表、详情、修改和删除都应使用一致的数据范围规则。以地址为例，不能列表只返回自己的地址，编辑接口却允许任意 addrId；前端选择器的候选范围也不能替代保存时的服务端校验。

3. 如果继续验证，我会用测试账号明确检查“自己的可访问、他人的被拒绝、资源不存在”的情况，并观察错误是否泄露不必要信息。只做页面截图验证不足以说明权限边界，需要实际接口层面的证据。

## 追问：菜单隐藏了，但用户输入网址进入页面怎么办？

1. 前端可以在路由层再检查当前角色或权限，避免仅隐藏菜单却仍能正常进入不适合的页面。跳转后给无权限提示或返回可访问入口，用户能理解为什么无法继续，而不是看见一片空白。

2. 即使路由也限制了，服务端仍要对页面调用的接口判断权限。浏览器路由不是服务端的数据保护机制，用户可能根本不加载前端代码，直接发起相同请求，因此两层检查不能互相省略。

3. 用户角色还可能在页面打开期间改变。若继续完善，我会在敏感请求拒绝后刷新必要权限状态，让菜单和按钮随之调整；但最终操作仍以服务端当时的判断为准，不能依赖页面早先加载的一份角色信息。
