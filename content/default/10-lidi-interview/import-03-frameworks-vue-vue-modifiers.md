# Vue 的常用修饰符有哪些？

## 核心回答

1. 修饰符把常见事件或输入处理以声明式方式写在模板中。事件修饰符如 stop 阻止传播，prevent 阻止默认行为，self 只在事件目标是当前元素自身时处理；它们各有具体含义，不能看见嵌套点击问题就全部叠在一起。

2. capture 表示捕获阶段监听，once 表示只触发一次，passive 告诉浏览器该监听不会阻止默认行为。passive 不应和 prevent 一起使用，因为一边承诺不取消默认行为，一边又要求取消，意图冲突，不能把所有修饰符都当可自由组合的性能选项。

3. 键盘和系统键修饰符可以表达 Enter、Esc、Ctrl 等条件，鼠标也有按钮相关限制。需要精确组合时注意 exact 等规则，同时保留正常的键盘可用性；删除快捷键等操作应检查输入焦点，避免用户在文本框编辑时误触页面动作。

4. 原生 v-model 的 trim 处理首尾空白，number 尝试数字转换，lazy 把默认的输入同步改为 change 时同步。lazy 不是防抖，也不等于所有控件都只在失焦时更新；密码、金额和可空字段的处理还要按业务含义决定。

5. 修饰符顺序也会影响生成的处理行为，例如 self 和 prevent 的前后可能决定来自子元素的事件是否先被阻止默认行为。自定义组件模型的修饰符需要按协议消费，不能把原生控件内置行为原样假定到所有封装组件，测试时应验证具体事件与值的结果。

## 追问：stop 和 self 处理弹窗遮罩点击，有什么不同？

1. stop 是阻止当前事件继续传播，self 是只有起始目标就是当前元素时才执行处理器。遮罩上写 self，可以让点击空白遮罩关闭，而点击内部对话框不触发这个关闭逻辑，不一定要在所有内部元素逐个阻止冒泡。

2. 如果内部控件还有自己的原生或捕获监听，stop 也不能撤回已经执行的回调。应该根据监听位置和阶段理解顺序，而不是不断增加阻断，结果让外层必要的点击统计或键盘交互也失效。

3. 我会测试点遮罩、点正文、点内部按钮，以及键盘关闭和焦点恢复。遮罩点击只是弹窗交互的一部分，正确修饰符减少事件判断代码，但不会自动建立完整的可访问弹窗行为。

## 追问：number 修饰符能保证提交的一定是合法数字吗？

1. 不能，它进行的是数值转换尝试，不是完整业务校验。空值、无法解析内容和边界输入仍需要明确规则，金额还可能限制小数位、最小值和精度，不能因为模型看起来变成数字就直接认为符合接口要求。

2. 输入过程也可能暂时出现不完整状态，例如用户正在输入负号或小数点。过早强制转换可能影响编辑体验，可以区分显示字符串与提交数据，在确认时再按规则转换，避免清空字段立刻变成零造成误解。

3. 我会测试清空、格式错误和范围超限，再由服务端执行最终校验。修饰符主要减少重复的输入处理代码，不提供权限、库存或价格计算的保证，前端反馈与业务确认仍要分开设计。
