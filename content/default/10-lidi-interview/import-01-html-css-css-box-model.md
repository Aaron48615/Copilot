# 盒模型是什么？

## 核心回答

1. 盒模型是描述元素尺寸与间距的基本方式，里面是内容区，往外是 padding、border 和 margin。比如卡片的背景通常覆盖内容与内边距，边框围在外面，margin 则用于与相邻卡片分开，不能把这些空白都理解成同一种尺寸。

2. `box-sizing: content-box` 下，声明的 width 对应内容宽度。一个内容宽 240px、左右内边距各 16px、边框各 1px 的盒子，边框盒宽度是 274px；外边距还要另算。这能解释为什么写了百分之百宽度，再加内边距后可能超出父容器。

3. `border-box` 会把 padding 和 border 算进声明宽度，所以上述盒子声明 240px 时，留给内容的是 206px。它常被用来统一组件尺寸，但更准确的说法是边框盒计算规则，不必把现代 border-box 与历史浏览器怪异模式完全等同。

4. 我会在排查中区分声明尺寸、计算尺寸和屏幕上看到的尺寸。最小宽度、Flex 伸缩以及 transform 都可能让结果与某个 width 值不同；border-box 也不包含 margin。先读盒模型图和计算样式，再定位限制来自哪里，比盲目减几像素更可靠。

5. 高度还要结合内容排版理解，字号并不等于一行文字的占用高度，行高和默认段落间距也会参与结果。比如两行提示把按钮撑高，不一定是边框盒设置失效，先确认文字行数和内部间距，才能找到真正增加的空间。

## 追问：getBoundingClientRect 的宽度为什么和 width 不一样？

1. CSS width 的含义先受 box-sizing 影响，而 getBoundingClientRect 返回的是元素在视口坐标中的外接矩形，通常包含边框和内边距。若用 content-box，直接拿声明的内容宽度与它比较，本来就可能相差一圈 padding 和 border。

2. transform 也会改变测量结果。例如一个布局宽度 100px 的盒子被放大两倍，外接矩形可以接近 200px，但它在普通布局中占用的空间并没有因此同步翻倍，后面的元素仍按原布局排列。

3. 因此拖动命中或浮层定位时，我会使用与需求相符的坐标测量；计算正常布局占位时，则需要查看布局尺寸。还要考虑小数像素和滚动位置，不能看到两个 API 数字不同就直接判定浏览器有误差。

## 追问：为什么只给 * 设置 border-box 还可能漏掉装饰元素？

1. 通配选择器选择实际元素，不会自动覆盖所有伪元素。用 before 或 after 画角标、边框时，如果它们的盒模型与主体不同，同样的宽度加上内边距后就可能出现预期之外的尺寸差异。

2. 我会把 `*::before` 和 `*::after` 一并纳入统一规则，或者让普通元素和这些伪元素继承预设的盒模型。这样组件的局部覆盖也能按一套明确的继承策略工作，而不是一部分规则写死、一部分依赖默认值。

3. 统一之后仍要检查第三方组件或局部样式有没有覆盖，以及图片、表格等元素的具体尺寸约束。全局规则可以减少计算差异，但不能代替对组件自身布局的理解，更不能保证所有子元素都不会溢出。
