# Vue 的 Diff 算法是怎么工作的？

## 核心回答

1. Vue 的 Diff 用来比较更新前后的虚拟节点，并把需要的变化提交到真实 DOM。它不会对任意两棵树求理论最优解，而是根据类型、层级和 key 等信息高效对应；组件重新计算不代表整棵 DOM 都被删除再创建。

2. 同类型节点会继续比较属性和子节点，不同类型通常需要替换。列表中的 key 表达业务身份，稳定 key 能让排序后节点和组件状态继续对应原记录；用下标或随机 key 可能造成状态错位或频繁重建，这首先是正确性问题。

3. Vue 2 的带 key 子节点更新常用双端比较思路，从两头寻找可以复用或移动的节点，未匹配部分再查找处理。Vue 3 在对应路径中会先处理共同前后部分，再针对中间变化建立映射，并利用最长递增子序列减少某些场景下的移动。

4. Vue 3 还利用编译结果识别静态内容和动态部分，通过静态提升、补丁标记等减少运行时无意义比较。这些优化依赖具体模板和更新路径，不能说每次更新都完整执行同一种列表算法，也不能简单承诺所有操作严格只需要线性时间。

5. 我在业务里更关注给框架正确的输入：稳定身份、合理状态范围和不过量的节点。大量行或昂贵模板计算仍会慢，算法优化不能替代分页和合理计算；需要解释性能时，我会结合实际更新场景，而不是只背“双端”“最长递增子序列”几个名字。

## 追问：最长递增子序列为什么能减少移动？

1. 在新顺序中查看可复用节点对应的旧位置，若一组旧位置保持递增，它们彼此的相对顺序没有被打乱，可以尽量留在原有相对位置。找到较长的这类序列，就能把移动集中在不属于该序列的其他节点上。

2. 比如旧顺序是甲乙丙丁，新顺序是甲丙乙丁，其中一部分节点仍保持相对次序，不需要全部搬动。框架结合插入位置处理剩余节点，减少真实 DOM 移动，但仍要识别新增、删除和节点类型等信息。

3. 这是针对相应 keyed children 更新路径的优化，不表示每棵树都先求一次序列。业务侧应提供稳定 key，让节点能够被可靠匹配；随机 key 使原节点无法对应，再好的移动优化也无法保留本应复用的身份。

## 追问：Vue 3 编译器知道静态内容，对更新有什么帮助？

1. 模板中某些结构和文本不会随状态变化，编译器可以把这部分标记或提升，运行时不必像完全未知的手写树那样反复做所有工作。例如一个固定说明区域，不需要因为旁边计数变化重新比较所有静态属性。

2. 对动态节点，补丁标记也能指出变化重点，比如主要检查 class、文本或特定 props。它缩小运行时需要关注的范围，但仍取决于模板表达的内容，动态插槽和复杂结构不能一概按最理想的静态路径理解。

3. 我会把它作为框架实现优势解释，不因此在业务模板里省略合理的数据设计。模板每行都调用昂贵函数，或一次渲染成千上万节点，依然需要处理实际成本；编译优化减少部分重复工作，不会让任意页面自动轻量。
