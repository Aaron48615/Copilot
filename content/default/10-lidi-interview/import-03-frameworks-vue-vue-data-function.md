# 组件里的 data 为什么必须是一个函数？

## 核心回答

1. 可复用组件里的 data 使用函数，是为了每个组件实例创建自己的状态对象。同一个组件可能在页面出现多次，如果直接复用一个对象，多个实例会读写相同引用，一边修改数量或草稿，另一边也可能跟着变化，违背实例独立的直觉。

2. 函数会在创建实例时调用，返回该实例使用的数据。例如两个商品数量组件各从一开始，修改第一份不应改变第二份；这依赖每次真正创建新对象，而不只是把共享对象放进函数再原样返回，后者仍然会共享状态。

3. 嵌套数据也要留意来源。函数返回的新顶层对象如果继续引用同一个模块级地址对象，内部编辑仍可能互相影响；需要独立草稿时，应按结构建立独立数据，而不是看到最外层花括号不同就认为全部内容都隔离了。

4. Vue 2 的根实例曾允许直接提供 data 对象，这不能推广到可复用组件；Vue 3 选项式组件的 data 按函数定义。组合式写法在 setup 内创建 ref 或 reactive，本质上也要确保每个实例得到正确的状态范围，函数形式不是唯一要理解的表面规则。

5. 如果确实需要共享状态，应使用明确的共享方案，例如祖先提供、Vuex 或 Pinia，而不是依赖错误的 data 引用碰巧同步。这样创建、重置和退出时的清理都有明确责任，也能让测试分别验证实例独立性和有意共享，而不把两类需求混在一起。

## 追问：data 是函数，但 return 同一个外部对象，为什么仍然串值？

1. 函数形式只提供每次创建的机会，不会自动深复制返回值。若函数每次都 return 模块顶层的 sharedForm，多个实例仍引用同一个对象，修改一个输入框就是修改所有实例共同的数据，问题依旧存在。

2. 应在函数调用时构造新状态，对需要独立的嵌套对象也创建相应结构。某些只读配置可以共享，但用户草稿、选择集合和可变数组不应无意共享；判断依据是这些值是否会被实例各自修改。

3. 测试可以同时挂载两个实例，改变第一份表单，确认第二份和默认初值未受影响。重新挂载还要得到干净状态，避免上一实例修改了默认对象，导致下一次创建不是从预期初值开始。

## 追问：为什么把状态放在 setup 外面也要谨慎？

1. 模块顶层代码不是每个组件实例都重新执行，放在那里的 ref 或 reactive 可能被所有调用者共享。把 Options API 改成 script setup，不等于所有外部变量都会变成实例私有，仍要看实际创建位置。

2. 需要私有状态时放在组件 setup 的实例执行范围，共享配置或明确的单例服务才放在外部。可以把创建初始状态封装为函数，每次调用返回新结构，避免复用默认对象造成表面上独立、深层却串值的问题。

3. 服务端渲染中还要考虑不同用户请求共享模块环境的风险，个人状态应按请求建立。测试和组件复用的要求是相通的：明确状态属于哪个实例、应用或请求，不能仅根据变量所在文件名称判断范围。
