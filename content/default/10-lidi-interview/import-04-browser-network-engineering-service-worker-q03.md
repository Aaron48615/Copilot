# 为什么开发环境有时关掉缓存还不行？

## 核心回答

1. 开发工具里关闭缓存，通常针对的是浏览器 HTTP 缓存，不一定挡住 Service Worker 拦截请求。worker 仍可能从 Cache Storage 返回旧 HTML 或资源。禁用缓存后页面依旧不变，不能立刻断定构建没有更新。

2. Application 里看页面由哪个 worker 控制、脚本版本、作用范围，再看 Cache Storage 条目。Network 里也能观察响应是不是来自 Service Worker。分清是请求根本没走网络，还是网络返回的内容就已经是旧版。

3. 排查可以临时绕过 worker，先看网络结果，再按需要注销对应注册、清理本应用缓存。注销不等于立刻消除当前页面全部控制状态，通常还要关掉相关页面或重新导航。其他标签也可能留着旧连接和旧版本。

4. 页面代码会自动注册 worker 的话，刷新后它可能再次出现，所以还要看开发环境的注册条件。面板上点一次注销，不代表之后整个开发会话都不受影响。为了定位问题清空同源所有私人存储，也不合适。

5. 网络直达、首次注册、已有控制者这三种状态对照着看，每一步改变了什么说清楚。生产更新仍要靠正确的版本和缓存设计。让用户手动清空站点数据，当不了正常升级流程；为了方便永久删掉离线能力，也不划算。

## 追问：注销 worker 后，为什么刷新又出现了？

1. 页面启动代码可能还在执行 `register`。注销只是删掉那一刻的注册，没有改应用里的注册逻辑。重新加载后再注册，是预期行为。入口代码或构建插件是不是在开发环境也自动启用，要查一下。

2. 临时限制开发注册条件，关掉相关客户端，确认新的访问没有控制者。worker 的作用范围也要看，可能另一处入口注册了不同脚本。只凭文件名认定只有一个来源在影响页面，可能漏。

3. 验证完成后按项目要求把配置改回去，调试用的临时开关别带进生产。长期要支持开发离线测试，就给一个明确的开启方式，让普通开发和 Service Worker 测试能分开做，别互相干扰。

## 追问：怎样区分旧内容来自 CDN 还是 Cache Storage？

1. 先看请求是不是由 Service Worker 提供，再用临时绕过 worker 的方式看网络响应。绕过后立刻拿到新版本，重点查 worker 策略。网络本身仍返回旧入口，再查 CDN、源站和 HTTP 缓存。

2. 比较入口引用的资源版本和响应头，比如 Age、验证标识、平台缓存信息，但别拿单一字段下结论。缓存头可能经过代理调整，实际内容版本往往更直观。访问的是不是同一个域名、同一套部署环境，也要对上。

3. 排查一次只改一个条件，对照结果记下来。同时清浏览器、删 worker、刷新 CDN，页面虽然变新了，却不知道真正原因，后面发布还可能再遇上同样的问题。
