# 弹窗应该怎么处理层级？

## 核心回答

1. 弹窗层级我会先确定它属于整个页面还是局部区域。全局模态弹窗通常放在靠近文档根部的统一浮层容器中，减少业务祖先的 transform、opacity 和 overflow 对它的影响；局部加载遮罩则可以留在卡片内部，不必把所有覆盖内容都挂到 body。

2. 然后约定少量清楚的层级关系，比如普通内容、固定导航、遮罩和弹窗内容，而不是每个组件各自写越来越大的数字。遮罩要在背景上方、弹窗在遮罩上方，多层弹窗还需要管理打开顺序，层级规则应能说明具体关系，而不是靠谁最后写了 999999。

3. 原生 dialog 的 showModal 会进入顶层，与普通文档中的 z-index 比较不同，适合相应模态需求。但只添加 open 属性或普通 show 并不等于同样的模态行为；原生能力仍需设置名称、初始焦点和关闭流程，不能只关心是否盖在最上面。

4. 我还会一起检查背景是否不可交互、滚动是否按预期限制，以及关闭后焦点能否恢复。视觉层级正确只是弹窗能用的一部分，尤其多个弹窗叠加时，关闭一个不能提前解除最底层的限制，最后关闭后也不能留下透明遮罩或滚动锁。

## 追问：挂到 body 的弹窗为什么仍然可能有问题？

1. 靠近 body 能避开很多业务祖先，但不是绝对保证。根部容器自身可能有影响定位的样式，弹层也可能仍处于不合适的上下文；而且挂载位置改变后，原来依赖祖先的选择器和 CSS 变量继承可能不再相同。

2. 如果弹层是跟随按钮的下拉框，还需要把按钮位置换算到所用定位坐标中，并处理滚动和窗口变化。只移动 DOM 不更新定位策略，可能从“被裁剪”变成“位置偏移”，所以要同时检查坐标来源和参照方式。

3. 我会测试主题、局部样式、点击外部关闭和键盘返回。框架 Portal 或 Teleport 能改变挂载位置，但具体事件语义和组件状态仍要按框架规则理解，不能把移到 body 当成层级、定位和交互的一键修复。

## 追问：多层弹窗关闭时怎样避免提前恢复页面滚动？

1. 可以由统一的弹窗管理逻辑记录当前仍打开的模态层，而不是每个弹窗关闭时都直接恢复 body 样式。内层关闭后外层仍然存在，页面背景就应继续保持受限，只有最后一层结束才恢复原来的状态。

2. 恢复时要保存并还原原本的样式与滚动位置，不要假定页面开始时 overflow 一定是空值。焦点也逐层返回：先回到外层触发入口，再在最终关闭时回到页面入口，两个恢复过程需要保持一致。

3. 我会检查逐层关闭、一次性关闭全部和路由切换卸载三种路径。异常路径最容易漏掉计数或残留监听，导致下一次打开弹窗后页面无法滚动；验证应观察完整状态，而不是只看最上层是否消失。
