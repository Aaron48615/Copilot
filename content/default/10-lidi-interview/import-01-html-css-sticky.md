# position: sticky 什么时候会失效？

## 核心回答

1. sticky 元素仍然参与正常布局，在滚动时根据相关方向的偏移约束调整位置，并受包含块边界限制。它不是滚到某处就永久切成 fixed；例如文章目录可以在文章范围内保持吸顶，文章结束后也要随所属区域离开，不会无限覆盖后面的内容。

2. 首先要检查相关轴上有没有非 auto 的阈值，例如纵向吸顶写 top: 0。如果没有垂直方向的偏移约束，就不会出现预期的纵向粘性效果。随后确认当前真正滚动的是窗口还是某个内部面板，sticky 的参照未必是浏览器视口。

3. 祖先 overflow 很常见，hidden、auto 等可能建立滚动容器，让 sticky 参照该祖先。即使用户实际上在滚页面，这个祖先本身没有滚动变化，也可能看起来完全不吸顶；另外父级高度太短、元素自身太高，都可能没有足够的移动空间。

4. Flex 或 Grid 的拉伸也可能让 sticky 项占满可用高度，我会检查是否需要调整 align-self 与尺寸约束。最后再看背景和层级，元素可能已经吸住却被内容盖住。排查应按阈值、滚动参照、移动空间和呈现关系逐项验证，不能看到 overflow 就直接全部删除。

5. 若页面上已经有固定顶栏，吸顶阈值通常还要考虑它的高度。标题实际上停在顶端却被导航盖住时，提升层级未必符合设计，合理的顶部偏移和滚动定位留白更能保证标题与导航同时可见。

## 追问：父容器和 sticky 元素一样高，为什么看不出吸顶？

1. sticky 受包含块边界限制，如果父容器几乎只有它自身那么高，留给它在父容器内调整位置的空间就很少。页面虽然很长，但这不代表该元素所属的那块区域也有足够高度，不能用整页滚动长度代替局部范围判断。

2. 我会给父容器和 sticky 元素分别画轮廓，查看实际高度。如果目录应该跟随整篇文章，结构上应让目录与文章共享有正确高度的外层，而不是把目录单独装进一个恰好包住自己的短容器。

3. 不建议随便给父级加一个很大的固定高度制造吸顶效果，这会增加无意义空白。应让内容或正确的布局关系提供范围，再验证短文章和长文章，确认没有内容时页面也不会被硬编码高度撑得过长。

## 追问：Flex 中 sticky 侧栏被拉伸该怎么检查？

1. 先看主轴方向和交叉轴对齐。横向 Flex 中，默认拉伸可能让侧栏高度与整行一样高，导致侧栏自身占满父级，粘性移动空间受到影响；这种情况要看最终计算高度，不能只检查 CSS 有没有写 height。

2. 可以根据布局需要尝试 align-self: flex-start，让侧栏按自身内容高度排列，同时保留父级由正文撑出的范围。若还有多层包装，则应检查设置作用在真正的 Flex 子项上，而不是里面一个不参与外层拉伸的节点。

3. 修改后测试长目录、短正文和窄屏单列。侧栏高度超过可见区域时，还要考虑内部滚动或取消吸顶，否则顶部一直可见但底部链接访问困难，解决“吸住”只是第一步，内容可访问才是目标。
