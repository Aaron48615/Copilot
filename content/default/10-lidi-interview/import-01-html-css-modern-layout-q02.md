# Flex 子项为什么会撑破容器？

## 核心回答

1. Flex 子项撑破容器，常见原因是默认自动最小尺寸跟内容有关。横向排列里，一个很长、断不开的字符串会让子项留着较大的最小宽度。即便 shrink 允许收缩，也可能先被这个下限卡住。有没有写 `flex: 1` 不够看。

2. 先确认溢出的是子项盒子，还是盒内文本或图片。盒子本身太宽，查直接参与 Flex 的那层 `min-width`、basis 和固定宽度。盒子已经缩小、文字还往外伸，再处理换行、省略或滚动。两个现象修法不同。

3. 允许横向收缩的内容区通常可以设 `min-width: 0`，再配上适合内容的显示策略。单行标题可以省略，正文可以允许长字符串换行，代码或数据表可能保留内部滚动。图标或操作按钮可以按需求不收缩，别把所有部分一起压到没法用。

4. 纵向 Flex 也有类似问题，看 `min-height`、外层高度和滚动区约束。内部列表希望滚动，却把整页撑长，往往不是缺 `overflow`，而是中间层不允许收缩。顺着嵌套层级看实际尺寸，`min-width: 0` 不是所有方向的万能补丁。

5. 图片还要查固有尺寸和最大宽度。一张原图放进可收缩区域，也不一定按设计自动缩小。把图片的显示范围说清楚并保持比例，文本和图片才都会服从外层分配。修好了文字又留下图片越界，等于只做了一半。

## 追问：省略号写了三件套为什么仍然不出现？

1. 省略号得有实际被限制的显示宽度。文本容器仍被内容撑开，没有可供截断的溢出，`white-space`、`overflow` 和 `text-overflow` 都在，也不会出现预期的省略号。问题在外层尺寸约束。

2. 先看 Flex 子项允不允许收缩，再看文字所在盒子的实际宽度。嵌套多层时，可能外层需要 `min-width: 0`，内部文本才拿得到受限空间。别只在 `span` 上重复加省略规则，它的父级仍无限扩展就没用。

3. 出现省略以后，用户还得拿得到完整信息，比如详情里保留原文，必要时给可访问的展开方式。重要错误提示通常不适合直接截断，修正要求被省略掉，人就没法操作。省略服务于内容优先级。

## 追问：纵向布局里 overflow: auto 为什么没有出现内部滚动？

1. `overflow` 只有在可用尺寸被限制住、并且产生溢出时，才会形成预期的内部滚动。容器高度被内容不断撑开，内部就没有理由滚动。先确定页面或外层高度从哪来，别只给列表写 `auto`。

2. 纵向 Flex 的中间子项还可能受默认最小高度限制，缩不到分给它的剩余空间。需要收缩的那层设 `min-height: 0`，内部滚动区域才能拿到正确的高度约束。嵌套容器必要时一层层查。

3. 短列表和长列表都测：只有需要时才滚，底部操作栏仍在看得见的范围内。为了修复给整页写一个当前屏幕的固定像素高度，软键盘和横屏时仍容易出问题。高度来源得符合页面结构。
