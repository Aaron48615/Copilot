# 谈谈 Pinia？为什么取代了 Vuex？

面试可以直接这样说：

Pinia 是 Vue 官方现在更推荐的状态管理库，主要用来做多个组件之间的全局状态共享，比如用户信息、登录状态、主题这些。

它可以理解成 Vuex 的下一代方案。Vue 3 之后官方更推荐 Pinia，因为 Pinia 的 API 更简单，和 Composition API 的风格也更统一。

Pinia 里面主要有三个概念：`state`、`getters` 和 `actions`。

`state` 用来存数据，`getters` 类似计算属性，`actions` 用来写修改状态或者异步请求这些业务逻辑。

它和 Vuex 比较明显的区别有几个：

第一，Vuex 里面有 `state`、`getters`、`mutations`、`actions`，Pinia 去掉了 `mutations`，可以直接修改 state，也可以在 actions 里面修改，所以代码会更简洁。

第二，Vuex 一般通过一个大的 store，再拆分 modules；Pinia 天然就是多个独立 store，不需要专门配置 modules，结构会更清楚。

第三，Pinia 对 TypeScript 的支持更好，类型推导更自然。

第四，Pinia 和 Vue 3 的 Composition API 配合得更好，也支持用类似 `setup` 的方式来定义 store。

所以如果是新的 Vue 3 项目，我一般会优先使用 Pinia；Vuex 更多会出现在一些老项目里。

最常见追问你记这三个：

* **Pinia 为什么没有 mutations？**

因为它允许直接修改 state，或者统一放到 actions 里处理，少了一层 mutations，写法更简单。

* **Pinia 的 getters 和 Vue 的 computed 像不像？**

很像，都是基于现有状态派生出一个新的值。

* **Pinia 的 actions 能不能写异步？**

可以，直接在 actions 里写 `async/await` 就行。
