# ECharts 和 ResizeObserver 在你的项目中是怎么配合的？

## 核心回答

1. ECharts 是依附 DOM 的外部实例，初始化前容器要存在且有合理尺寸。城市视图把它封装在 ChartRenderer，React Effect 中创建并放 ref；Vue 页面也在挂载后处理，初始化应由组件挂载与容器生命周期控制；同一容器重复 init 会复用已有实例，但把事件绑定也重复执行仍可能产生问题。

2. 数据和配置准备好后转成 option，用 setOption 更新已有实例。初始化、更新与销毁分开后，能更清楚地知道是谁创建图表、哪些变化只需要改数据；普通数据更新不应该反复分配画布和绑定事件。

3. ResizeObserver 观察图表容器，尺寸改变就调用 resize。比如侧栏收起时浏览器窗口没变化，但内容区域变宽，单纯监听 window.resize 不会覆盖这种布局改变，所以直接观察容器更符合需求。

4. 卸载时断开观察器、移除自己绑定的事件，dispose 图表并清空 ref。未结束的异步回调也要检查实例是否仍有效，不能拿旧引用继续 setOption；React 开发环境的额外 setup 与 cleanup 更能暴露不完整清理。

5. 当前城市视图主题变化会清理后按新主题重建，ResizeObserver 回调直接 resize，还没有额外限频。如果隐藏容器宽度为零，应等待显示或显示后补 resize；这些边界需要结合弹窗、Tab 和真实布局验证，不能只测初次全屏打开。

## 追问：图表在隐藏 Tab 里初始化，为什么显示后不正常？

1. 隐藏时容器可能没有可用宽高，ECharts 初始化拿到的是零尺寸或不合适尺寸。后来只把 Tab 显示出来，画布不一定自动重新得到正确布局，所以出现空白、挤压或坐标轴不完整。

2. 可以等容器真正可见并完成布局后再 init，或者显示后对现有实例调用 resize。框架完成 DOM 更新不一定意味着 CSS 过渡已经结束，需要结合容器实际尺寸或观察器回调，而不是随便延迟一个固定毫秒数。

3. 我会在隐藏初始页、切换 Tab、侧栏动画和窗口缩放下检查图表。若容器本身没有高度，反复调用 resize 也无法解决，先确认 CSS 布局，再检查实例生命周期，避免把所有空白都归为 ECharts 的问题。

## 追问：主题变化为什么可以重建，数据变化却通常不用？

1. 数据变化是现有实例的正常更新能力，setOption 就能处理大多数系列与坐标变化。主题则可能在 init 时作为实例配置传入，当前组件选择清理旧实例并使用新主题重新创建，触发原因与普通数据更新不同。

2. 重建时仍要先断开旧监听和释放实例，再关联新的 observer 与事件。不能只是把 ref 指向新对象，旧画布与回调仍可能存在，导致同一个容器多次响应尺寸变化或出现资源残留。

3. 重建也可能丢失缩放或图例选择，如果业务希望保留，应明确保存可恢复配置后再应用。当前不能保证所有交互自动保留，验证主题切换后数据与必要状态是否符合预期，比只看颜色变了更完整。
