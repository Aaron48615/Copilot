# 怎么判断 JS 的数据类型？

## 核心回答

1. 我会先问需要判断到哪一层，是区分字符串和数字，还是确认对象能满足某个业务接口。基本类型通常用 typeof，但 `typeof null` 返回 object，所以检查对象时还要排除 null，不能据此直接读取属性，避免把第一步判断当成完整保证。

2. 数组我会用 Array.isArray，因为数组和普通对象用 typeof 都得到 object。它也比拿本窗口的 Array 做 instanceof 更适合跨窗口数组，不过确认数组只解决容器种类，里面是否都是用户对象还需要逐项判断，空数组也要按需求处理。

3. instanceof 通常沿原型链判断是否包含构造函数的原型，适合检查自己控制的实例。跨窗口构造函数不是同一个对象时结果可能不符合直觉，而且自定义实例判断行为也能改变结果，所以它不能等同于业务字段校验。

4. Object.prototype.toString.call 可以辅助区分日期、正则等内置对象，但标签可能受 Symbol.toStringTag 影响。例如普通对象也可以自定义展示标签，因此我会把它用于类型识别辅助或排查，不能仅凭标签就把不可信输入当成有效实例。

5. 对接口对象，最终还是要检查实际使用的字段及取值边界，不能只说它是 object。例如金额除了是数字，还可能需要有限、非负等约束；这些是业务规则，应该明确写出来，而不是希望一个通用类型判断函数替所有场景作决定。

## 追问：typeof 得到 number，为什么还要检查 NaN 和范围？

1. number 这个类别包含普通数字，也包含 NaN 和无穷大，所以它不能直接代表可用于业务计算的金额。例如字符串转换失败会得到 NaN，继续参与加法仍会传播异常值，页面可能直到最终展示时才暴露问题。

2. 如果业务要求有限数字，可以在类型判断后使用 Number.isFinite，再检查是否允许负数或小数。这些条件要根据字段定义选择，库存数量可能要求整数，而折扣比例可能允许小数，不能给所有数字套同一条限制。

3. 我还会把输入转换和有效性检查分开，例如空字符串转换为数字可能得到零，但这不一定表示用户真的填写了零。如果字段必填，应先检查原始输入是否缺失，再做转换，避免语言的转换规则替代了业务含义。

## 追问：跨 iframe 的数组为什么可能过不了 instanceof Array？

1. 不同窗口通常有各自的内置构造函数和原型，来自另一个窗口的数组原型链不一定包含当前窗口的数组原型。因此 instanceof 返回假，并不能证明它不是数组，而是这次原型链判断没有找到指定的那个对象。

2. Array.isArray 根据数组本身的内部性质判断，所以处理跨窗口数组时更符合问题本意。相反，一个普通对象即使把原型改得像数组，也不会因此成为真正的数组，这说明判断方法要匹配我们实际关心的性质。

3. 识别数组后仍要检查内容，例如收到用户列表，要确认每一项的编号和名称可用。如果只是要接收某种可迭代输入，则可以按迭代能力设计接口，不必强行要求数组，但这应是明确的接口选择，不能混为一谈。
