# `var`、`let` 和 `const` 有什么区别？

## 核心回答

1. 我会从作用域、初始化时机和能否重新赋值三方面区分。`var` 主要是函数作用域，写在普通 `if` 块里也可能影响块外；`let` 和 `const` 是块级作用域，适合把临时变量限制在实际使用的位置。

2. `var` 的声明会提前处理，并初始化为 `undefined`，但赋值仍在原位置执行。`let` 和 `const` 的绑定也会提前建立，只是在执行到声明初始化前处于暂时性死区，读取会报错，因此不能简单说它们“完全没有提升”；即使外层有同名变量，内层声明前也不能绕过死区去读取外层的值。

3. 同一作用域中，`var` 可以重复声明同名的 `var`，容易掩盖误写；`let` 和 `const` 不允许重复声明同名绑定。内层块可以声明同名变量，但会遮蔽外层变量，我会避免没有必要的同名使用。

4. `let` 允许重新赋值，`const` 声明普通变量时必须初始化，之后不能重新绑定。比如 `const user = { name: '牛' }` 仍能修改 `user.name`，因为限制的是变量绑定，并没有冻结它引用的对象。

5. 写新代码时我会默认用 `const`，计数器或需要替换的值再用 `let`。浏览器普通脚本顶层的 `var` 通常会成为全局对象属性，但模块顶层不会，分析旧代码时还要先确认运行环境。

## 追问：为什么循环里的定时器使用 var 和 let 会输出不同结果？

1. 假设循环从零执行到二，每次用定时器打印循环变量，定时器回调会在这段同步循环结束后执行。使用 `var` 时，三个回调访问的是同一个变量，循环结束后它已经变成三，所以输出通常都是三。

2. `for (let i = 0; i < 3; i++)` 会为每次迭代建立对应的词法绑定。回调分别保留对各次绑定的访问，因此按注册顺序执行时会输出零、一、二，关键在于绑定不同，而不是定时器保存了数值快照。

3. 如果必须维护使用 `var` 的旧代码，可以用函数参数为每次调用保存独立值，或者将值作为定时器参数传入。实际改动前我会先检查回调是否真的应该读取当次值，避免把本来需要读取最新状态的逻辑也一起改掉。

## 追问：const 加 Object.freeze 能保证对象完全不可变吗？

1. `const` 只阻止重新赋值，`Object.freeze` 则限制对象自身属性的增加、删除和改写。两者处理的层面不同，冻结以后再修改属性，在严格模式下会抛错，非严格模式下某些失败赋值可能只是没有效果。

2. 普通对象的冻结是浅层的。如果配置中还有 `user.profile` 这样的嵌套对象，只冻结 `user` 并不会自动冻结 `profile`；需要逐层处理时还得考虑循环引用，不能无限递归。

3. 我不会把冻结当成所有数据类型的通用不可变方案，例如冻结 `Map` 对象并不等于禁止调用它的 `set`。业务里如果只是避免误改配置，可以约定只读访问；需要更新状态时，则复制要改的层级并产生新值。
