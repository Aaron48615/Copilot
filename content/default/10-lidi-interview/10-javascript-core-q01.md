# `var`、`let` 和 `const` 有什么区别？

## 核心回答

1. 最明显是作用域。`var` 是整个函数里都能用，普通 `if`、`for` 的大括号包不住。`let` 和 `const` 出了这个大括号就不能再用，临时变量就能圈在真正用到的地方。

2. 再就是声明之前能不能读。`var a` 写在后面，前面去读不会报错，值是 `undefined`。`let` 和 `const` 也会先占个位置，但执行到声明之前去读会直接报错，这段叫暂时性死区。别说它们完全没提升，只是提前占了也不能用。就算外面有个同名变量，进了这个块、里面那行还没执行到，也不会退回去用外面那个。

3. 同一个作用域里，`var` 可以重复声明同名的 `var`，写错了不容易发现。`let` 和 `const` 不行。内层块可以再声明同名变量，会把外层挡住，没必要就别同名。

4. `let` 能重新赋值。`const` 声明普通变量时必须赋初值，之后不能再赋成别的。比如 `const user = { name: '牛' }`，改 `user.name` 没问题，因为它锁的是指向，没有把对象冻住。`user = {}` 才会报错。

5. 新代码默认 `const`，计数器或真要换值再用 `let`。浏览器普通脚本顶层的 `var` 通常会变成全局对象上的属性，模块顶层不会。看旧代码时先确认跑在哪种环境。

## 追问：为什么循环里的定时器使用 var 和 let 会输出不同结果？

1. 循环从 0 跑到 2，每次用定时器打印循环变量。定时器回调是这段同步循环结束之后才跑。`var` 的 `i` 就一个，循环结束已经是 `3`，三个回调读到的都是 `3`。

2. `for (let i = 0; i < 3; i++)` 每一圈有自己的 `i`。回调各自读各自那圈的，就会打印 `0`、`1`、`2`。名字都叫 `i`，其实不是同一个变量。不是定时器把数字拍下来了。

3. 旧代码还得用 `var`，可以包一层函数把当前数字当参数传进去，或者当定时器参数传入。改之前先看回调是不是真该读当次值。有的逻辑本来就要读最新状态，别一起改掉。

## 追问：const 加 Object.freeze 能保证对象完全不可变吗？

1. 不能。`const` 只挡住再赋成别的值，`Object.freeze` 限制的是这个对象自身属性增删改。冻完再改属性，严格模式会报错，非严格模式有的赋值可能只是没生效。

2. 普通对象的冻结是浅的。配置里还有 `user.profile` 这种嵌套对象，只冻 `user`，`profile` 照样能动。真要逐层冻，还得小心循环引用，不能无限递归。

3. 冻 `Map` 也不等于不能调它的 `set`。业务上只是怕误改配置，约定只读就行。真要更新状态，复制要改的那一层，产出新值。
