# 盒模型是什么？`box-sizing` 有什么作用？

## 核心回答

1. 盒模型描述的是元素内容和周围空间怎么计算，从内到外是内容、内边距、边框和外边距。比如一个输入框，文字在内容区，padding 留出文字与边框的距离，margin 则控制它与其他元素的间隔，这几个部分解决的问题不一样。

2. 默认的 `content-box` 下，声明宽度只约束内容区。假设宽度是 200px，左右各有 10px 内边距和 1px 边框，那么边框盒宽度就是 222px；如果再加外边距，横向布局占用的空间还会增加，不能只看 width 的数值。

3. `border-box` 会把内边距和边框包含在声明宽度内，上面的设置会让内容区缩到 178px。表单控件需要与容器对齐时，这种计算更直观，但 margin 仍然在外面，也不能消除长文本、最小宽度或子元素溢出造成的问题。

4. 如果统一项目样式，我会让普通元素和 `::before`、`::after` 使用一致的盒模型，再在组件中按需覆盖。排查时看开发者工具的盒模型图，分别确认计算宽度、padding 和 border，而不是把所有宽度误差都归因于浏览器兼容性。

5. 外边距在纵向普通块布局中还可能折叠，实际间隔不一定等于两个数相加。做组件间距时我会看清它是内部留白还是兄弟之间的距离，前者用内边距，后者可以由父布局的间隙统一控制，避免把尺寸和间隔混算。

## 追问：设置 border-box 后为什么还是比父容器宽？

1. 先看外边距有没有额外增加宽度。一个宽度已经是百分之百的元素再加左右 margin，仍然可能溢出；border-box 只改变内容、内边距和边框的计算，不会替它扣掉这些外部间距。

2. 再查最小尺寸和内部内容。Flex 子项可能被默认最小宽度限制，固定宽度图片也可能伸出自己的盒子；前者需要考虑 `min-width: 0`，后者需要约束图片宽度，两种现象不能用同一个补丁处理。

3. 最后检查是否同时存在固定宽度、gap 和多列百分比。两列各占一半再加间隙，总和自然超过容器，可以改用 Grid 的弹性轨道分配剩余空间，让浏览器负责扣除间隙后计算列宽。

## 追问：元素高度和文字高度为什么对不上？

1. 文字排版还涉及行高，并不是 font-size 多大，内容区就一定多高。比如字号 16px、行高 24px 的两行文字，行盒通常会贡献约 48px，再叠加内边距和边框才得到整体高度。

2. 我会先查看是否有浏览器默认的段落 margin，或者子元素的外边距发生了折叠。前者可能直接增加视觉间距，后者可能跑到父元素外部，观察结果不同，不能都靠减小 height 解决。

3. 如果需求只是按钮垂直对齐，我会用 Flex 配合合理的行高和 padding，让内容决定高度。固定高度需要同时测试长文案和字体缩放，否则默认字体看起来刚好，换一行就可能被截断。测试时也应加入更长的本地化按钮文案。
