# 盒模型是什么？`box-sizing` 有什么作用？

## 核心回答

1. 盒模型说的是元素内容和周围空间怎么算，从里到外是内容、内边距、边框、外边距。比如一个输入框，文字在内容区，padding 留出文字和边框的距离，margin 管它跟别的元素的间隔。这几部分管的不是一件事。

2. 默认 `content-box` 下，声明宽度只约束内容区。宽度 200px，左右各 10px 内边距和 1px 边框，边框盒宽度就是 222px。再加外边距，横向占的空间还会增加。别只看 `width` 那个数。

3. `border-box` 会把内边距和边框算进声明宽度里。上面那套会让内容区缩到 178px。表单控件要跟容器对齐时，这种计算更直观。但 margin 仍在外面，长文本、最小宽度、子元素溢出，它也消不掉。

4. 统一项目样式时，普通元素和 `::before`、`::after` 用同一套盒模型，组件里再按需覆盖。排查看开发者工具的盒模型图，分别确认计算宽度、padding、border。别把所有宽度误差都怪到浏览器兼容上。

5. 外边距在纵向普通块布局里还可能折叠，实际间隔不一定等于两个数相加。做组件间距时分清它是内部留白还是兄弟之间的距离。前者用内边距，后者可以由父布局的间隙统一控制，别把尺寸和间隔混着算。

## 追问：设置 border-box 后为什么还是比父容器宽？

1. 先看外边距有没有额外加宽度。宽度已经百分之百的元素再加左右 margin，仍可能溢出。`border-box` 只改内容、内边距和边框的计算，不会替它扣掉这些外部间距。

2. 再查最小尺寸和内部内容。Flex 子项可能被默认最小宽度卡住，固定宽度图片也可能伸出自己的盒子。前者考虑 `min-width: 0`，后者约束图片宽度。两种现象别用同一个补丁打。

3. 最后看是不是同时存在固定宽度、gap 和多列百分比。两列各占一半再加间隙，总和自然超过容器。可以改用 Grid 的弹性轨道分配剩余空间，让浏览器扣掉间隙后再算列宽。

## 追问：元素高度和文字高度为什么对不上？

1. 文字排版还涉及行高，不是 `font-size` 多大，内容区就一定多高。比如字号 16px、行高 24px 的两行文字，行盒通常会贡献大约 48px，再叠内边距和边框才得到整体高度。

2. 先看有没有浏览器默认的段落 margin，或者子元素外边距发生了折叠。前者可能直接加视觉间距，后者可能跑到父元素外面。观察结果不同，别都靠减小 `height` 解决。

3. 需求只是按钮垂直对齐，用 Flex 配合合理的行高和 padding，让内容决定高度。固定高度要同时测长文案和字体缩放，不然默认字体看着刚好，换一行就可能被截断。更长的本地化按钮文案也要测。
