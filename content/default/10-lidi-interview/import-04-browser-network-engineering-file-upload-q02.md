# 怎么防止上传恶意文件？

## 核心回答

1. 前端检查文件类型和大小，主要是为了及时提示，不能当安全边界。用户可以绕过页面直接打上传接口。文件名、扩展名、浏览器提供的 MIME 都能伪造，所以服务端必须自己验权限和内容。

2. 采用允许类型名单，结合文件头和实际解析结果检查，别只判断名称以 jpg 结尾。图片可以经过安全解码再重新编码。SVG、HTML 这类主动内容要特别处理，不能跟普通位图一样直接嵌进站点页面。

3. 服务端还要限制单文件大小、总上传量和处理资源。压缩包展开后可能极大，解析器也可能被复杂内容拖住，需要限制展开量、层级和耗时。原始文件名不能直接拼成服务器路径，避免越界写入。

4. 存储上用服务端生成的标识，放到不可执行的位置，必要时用独立下载域名。下载响应设合适的类型、`Content-Disposition` 和 `nosniff`。私有文件读取时仍检查权限，知道地址不应自动获得访问资格。

5. 可以再加扫描或隔离处理，让待检查文件先不能公开访问，再根据结果转为可用。前端展示处理中和拒绝原因，并验证伪装类型、超大文件和未授权请求。装一个扫描工具，不等于能识别所有恶意内容。

## 追问：为什么上传图片也可能存在安全风险？

1. 图片扩展名不保证内容就是安全位图，文件可能实际是 SVG 或其他主动内容。即使是真图片，解析器也可能有缺陷，异常尺寸和压缩比还可能吃掉大量内存，所以要校验实际格式和处理上限。

2. 服务端通过可靠库解码，再按允许格式重新编码，并去掉不必要的元数据。这样能减少原始文件夹带额外内容和隐私信息的机会。但处理库本身仍需维护，转换一次不等于永远没有风险。

3. 展示时也要用正确的响应类型和独立的存储策略。业务如果只接受头像，就没必要开放所有文档和矢量格式。允许范围越明确，验证和失败提示越好做清楚，也能减少用户误传不相关内容。

## 追问：对象存储直传时，服务端是不是就不用检查了？

1. 直传只是让文件字节不经过业务服务器，业务服务的责任并没有取消。服务端签发临时上传凭据时，应限制对象路径、有效期、大小和允许操作，不能把长期高权限存储密钥交给浏览器用。

2. 上传完成后，客户端通知成功不能直接等同于文件可信。服务端应验证对象确实存在、属于当前任务，并检查大小、内容和扫描结果，再允许业务记录引用它。必要时先放在隔离区域。

3. 下载阶段仍要检查访问权限，私有文件可以用短时受控地址。还要清理上传后未提交业务记录的孤立文件，否则用户反复直传会一直占空间。这些都不是前端 `accept` 属性能处理的。
