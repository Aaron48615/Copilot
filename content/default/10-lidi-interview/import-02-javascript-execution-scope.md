# 执行上下文、词法环境和作用域链怎么理解？

## 核心回答

1. 执行上下文就是这段代码正在跑的时候，引擎要记住的状态：现在跑到哪个函数、变量上哪找。调用函数就进一层，返回再回到调用方。但这不代表函数里用过的数据马上就没了。

2. 名字和值记在环境记录里。从当前这块开始往外找变量，这套关系常叫作用域链。规范模型是用来解释语言行为的，别直接画成某一块堆内存或栈内存，再推断引擎只能那样实现。

3. 作用域链从当前环境往外找名字，找到最近的同名绑定就停。内层声明了同名的 `let`，声明前去读会进暂时性死区，不会因为这个值还没初始化，就继续去读外层那个。

4. 函数能访问哪些外部名字，主要由定义位置决定，换一个调用方，不会改去用调用方的局部变量。读姓名的函数在外层定义，传到另一个有同名变量的函数里执行，它仍沿着原来的环境找。

5. 闭包说明函数返回以后，必要的外部变量仍能通过这个函数被访问。调用栈结束，和数据还能不能活着，是两回事。`this` 要另看普通函数怎么调用，或箭头函数沿用外层，别跟变量查找混在一块讲。

## 追问：同一个函数换个地方调用，为什么读到的外部变量没变？

1. 函数创建时已经连上它定义位置的外部环境，调用时再建立这次执行用的局部环境。找名字沿这条关系往外走，不会去遍历当前调用栈，在每个调用者那里找同名变量。

2. 外层的颜色是红色，读颜色的函数也定义在外层。另一个函数把自己的颜色设成蓝色，再调用它。只要读颜色的函数没有自己的同名参数或声明，结果仍来自外层那个红色。

3. 希望调用位置提供颜色，就明确传入参数，或者创建连着另一份环境的新函数。改变调用方式可能影响普通函数的 `this`，却换不掉它已经连上的外层变量。这两条输入渠道要分开。

## 追问：函数执行结束后，局部变量一定会随调用栈一起消失吗？

1. 函数返回会结束这次栈上的执行，局部数据能不能释放，还要看是不是仍然可达。函数返回一个读取局部数组的回调，外部还握着这个回调，之后合法调用时就必须还能访问那份数组。

2. 返回的是数组本身，外部同样可以继续用数组，这个现象不要求存在闭包。可以消失的是不再需要的执行状态，不能据此认为这次调用里创建的对象也必须在同一时刻被清空。

3. 反过来，没有外部引用的数据，也不保证返回瞬间就被物理回收，时机由引擎决定。排查保留问题时，看对象到根的引用路径，别只根据函数已经执行完就判断泄漏。
