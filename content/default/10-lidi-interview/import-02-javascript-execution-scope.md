# 执行上下文、词法环境和作用域链怎么理解？

## 核心回答

1. 我会把执行上下文理解为运行一段代码时需要记录的状态，例如正在执行哪个函数、从哪里查找变量。调用函数会进入相应上下文，返回后恢复调用方，但这不代表函数用过的所有数据都会立即释放。

2. 环境记录负责描述名字与绑定的关系，词法环境相关信息决定当前查找变量的起点。它们是解释语言行为的规范模型，不能直接画成某一块堆内存或栈内存，再推断引擎只能这样实现。

3. 作用域链就是从当前环境向外查找名字的关系，找到最近的同名绑定就停止。比如内层声明了同名的 let，声明前读取会进入暂时性死区，不会因为这个值尚未初始化而继续读取外层变量。

4. 函数能访问哪些外部名字，主要由定义位置决定，不会因为换一个调用方就改用调用方的局部变量。假设读取姓名的函数在外层定义，把它传到另一个有同名变量的函数中执行，它仍沿原来的环境查找。

5. 闭包说明函数返回以后，必要的外部绑定仍可以通过函数被访问；调用栈结束与数据生命周期是两回事。this 则要另看普通函数的调用方式或箭头函数的词法规则，不能把它和变量查找合并解释。

## 追问：同一个函数换个地方调用，为什么读到的外部变量没变？

1. 函数创建时已经关联了它定义位置的外部环境，调用时再建立本次执行所需的局部环境。查找名字会沿这条关系向外走，而不是遍历当前调用栈，去每个调用者那里寻找同名变量。

2. 假设外层的颜色是红色，读取颜色的函数也定义在外层；另一个函数把自己的颜色设为蓝色，再调用它。只要读取函数没有自己的同名参数或声明，结果仍来自外层的红色绑定。

3. 如果希望调用位置提供颜色，就应明确传入参数，或者创建关联另一份环境的新函数。改变调用方式可能影响普通函数的 this，却不能顺便替换它已经关联的词法外层，这两种输入渠道需要分开。

## 追问：函数执行结束后，局部变量一定会随调用栈一起消失吗？

1. 函数返回会结束本次栈上的执行，但局部数据能否释放还要看是否仍然可达。假设函数返回一个读取局部数组的回调，外部还保存着回调，之后合法调用时就必须仍能访问那份数组。

2. 如果返回的是数组本身，外部同样可以继续使用数组，这个现象并不要求存在闭包。可以消失的是不再需要的执行状态，不能据此认为这次调用中创建的对象也必须在同一时刻被清空。

3. 相反，没有外部引用的数据也不保证返回瞬间就被物理回收，回收时机由引擎决定。假如需要排查保留问题，我会看对象到根的引用路径，而不会只根据函数是否已经执行完来判断泄漏。
