# Vue 2 和 Vue 3 有什么区别？

## 核心回答

1. 响应式实现不一样。Vue 2 对普通对象主要靠 `Object.defineProperty` 做访问器，Vue 3 的响应式对象主要用 `Proxy`。不过 Vue 3 的 `ref` 仍通过 `.value` 的访问器工作，别说所有响应式都只靠 Proxy。对象属性拦截，和容器值读写，是两回事。

2. Vue 2 初始化之后新增对象属性、数组下标直接赋值、改长度，有检测限制，常用 `Vue.set` 或 `splice`。Vue 3 能通过代理观察到这些操作，但得改代理对象。直接改原始对象，照样可能绕过追踪。

3. Options API 按 `data`、`methods` 这些选项组织代码。Composition API 更方便把同一功能的状态和逻辑放一起，抽成组合函数复用。Vue 3 仍支持 Options API，Vue 2.7 也内置了 Composition API，所以不是版本一对一的标签。

4. Vue 3 的类型推导和 `<script setup>` 更适合跟 TypeScript 一起组织组件，也支持多根节点。轻购用 Vue 3，智服工单用 Vue 2、Vuex 和路由 meta，两种写法都能把页面和状态管理做完。选哪个，还看现有组件、依赖兼容、团队维护成本。

5. 旧项目要升级，先查组件库、路由、构建工具兼不兼容，再估改造范围。Vue 2 已经结束官方常规维护，这是维护成本上的背景。但旧项目的分页、权限、业务流程，不能因此认定做不成。

## 追问：Vue 2 中新增属性和数组更新应该怎么写？

1. 组件根级的响应式数据尽量在 `data` 里提前声明，比如先声明 `loading` 和表单字段。已经观察的嵌套对象，运行时新增属性用 `Vue.set(obj, 'name', value)`，实例里也可以 `this.$set`。

2. 数组更新已有位置，用 `this.$set(list, index, value)` 或 `list.splice(index, 1, value)`。要截短数组用 `splice`，因为 Vue 2 包装了这类变更方法。直接改 `length`，等不来同样的通知。

3. 也可以把已经声明的数据属性换成新的对象或数组，让新数据重新进响应式。但别处是不是还握着旧引用，得看。`Vue.set` 不是给组件根状态随便补字段的万能办法。结构提前定好更清楚，接口缺省值和模板第一次渲染也好查。

## 追问：把 Options API 改成 Composition API，代码就会自动更好吗？

1. 不会。简单组件按选项组织也很清楚，Vue 3 没有要求全部改写。Composition API 的价值是围绕一个功能组织和复用逻辑。只是把所有代码搬进一个很长的 `setup`，可读性可能没改善。

2. 比如搜索列表，把查询参数、加载状态、请求方法和相关清理放一起，重复用时再抽成组合函数。组合函数把输入输出说清楚，别悄悄改一堆外部状态，调用方不好判断影响范围。

3. 智服工单不会只为了写法新就整份重写。确有复用需求、边界清楚的模块可以先试。还得核对实际 Vue 小版本和依赖兼容，Vue 3 文档里的每个 API，别直接往旧项目上套。
