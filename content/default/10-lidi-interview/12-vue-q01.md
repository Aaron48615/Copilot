# Vue 2 和 Vue 3 有什么区别？

## 核心回答

1. 我会先区分响应式实现和代码组织方式。Vue 2 对普通对象主要通过 `Object.defineProperty` 定义访问器，Vue 3 的响应式对象主要使用 `Proxy`；不过 Vue 3 的 `ref` 仍通过 `.value` 的访问器工作，不能说所有响应式都只靠 Proxy，面试中应区分对象属性拦截和容器值的读写。

2. Vue 2 对初始化后新增对象属性、数组下标直接赋值和修改长度有检测限制，常用 `Vue.set` 或 `splice` 处理。Vue 3 能通过代理观察这些操作，但需要使用代理对象修改，直接改原始对象仍可能绕过响应式追踪。

3. Options API 按 `data`、`methods` 等选项组织代码，Composition API 更方便把同一功能的状态与逻辑放在一起，抽成组合函数复用。Vue 3 仍支持 Options API，Vue 2.7 也内置 Composition API，所以二者不是版本的一对一标签。

4. Vue 3 的类型推导和 `<script setup>` 使用体验更适合结合 TypeScript 组织组件，也支持多根节点等能力。轻购使用 Vue 3，智服工单使用 Vue 2、Vuex 和路由 meta，所以我会结合两种写法说明区别。它们都能完成页面和状态管理，选择时还要考虑现有组件、依赖兼容和团队维护成本。

5. 如果现在考虑旧项目升级，我会先检查组件库、路由和构建工具兼容情况，再评估改造范围。Vue 2 已结束官方常规维护，这是维护成本上的重要背景，但不能因此认定旧项目的分页、权限和业务流程就不能正常实现。

## 追问：Vue 2 中新增属性和数组更新应该怎么写？

1. 组件根级的响应式数据应尽量在 `data` 中提前声明，例如先声明 `loading` 和表单字段。对于已经观察的嵌套对象，运行时新增属性可以使用 `Vue.set(obj, 'name', value)`，实例里也可以用 `this.$set`。

2. 数组更新已有位置时，可以用 `this.$set(list, index, value)` 或 `list.splice(index, 1, value)`。需要截短数组时可以用 `splice`，因为 Vue 2 包装了这类变更方法，直接修改 `length` 则无法依赖同样的通知机制。

3. 也可以把已声明的数据属性替换成新的对象或数组，让新数据重新进入响应式处理，但要注意其他地方是否仍持有旧引用。`Vue.set` 不是可以随意给组件根状态补任何字段的万能办法，提前定义状态结构更清楚，也方便检查接口缺省值和模板初次渲染的结果。

## 追问：把 Options API 改成 Composition API，代码就会自动更好吗？

1. 不会，简单组件按选项组织也很清晰，Vue 3 没有要求全部改写。Composition API 的主要价值是围绕一个功能组织和复用逻辑，如果只是把所有代码搬进一个很长的 `setup`，可读性可能没有改善。

2. 我会以搜索列表这样的功能为例，把查询参数、加载状态、请求方法及相关清理放在一起，重复使用时再抽成组合函数。组合函数应该暴露清楚的输入输出，避免悄悄修改多个外部状态，让调用方难以理解影响范围。

3. 对已有智服工单，我不会仅为了写法新就整体重写；如果继续完善，我会先选择确有复用需求、边界清楚的模块试用。还要核对实际 Vue 小版本和依赖兼容性，不能把 Vue 3 文档中的每个 API 都直接用于旧项目。
