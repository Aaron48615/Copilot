# Vue 3 的响应式是怎么工作的？

## 核心回答

1. Vue 3 的对象响应式主要通过 Proxy 实现，读取属性时记录正在使用它的响应式执行，写入或删除时通知相关依赖重新处理。模板渲染、computed 和 watch 等都在这套机制上工作，普通 JavaScript 代码随便读一次并不会自动建立永久监听。

2. 组件渲染读取 state.name，框架就能记录这个渲染与该属性的关系；之后 name 改变，会安排相应更新。新增属性、删除属性和数组下标修改也能够被代理拦截，相比 Vue 2 的逐属性转换，覆盖范围更完整，但仍要求通过正确的代理引用访问。

3. ref 则用带 value 的容器让原始值也能被跟踪，普通 ref 保存对象时通常会进行深层响应式转换。reactive 主要面向对象，整体替换和解构要留意引用关系；把代理中的数字取成普通局部变量，不会让这个变量继续跟随原属性。

4. 大对象或第三方实例不一定需要全部代理，可以根据场景使用 shallowRef、markRaw 等控制范围。代价是深层修改不会自动按普通响应式方式通知，调用方必须采用替换或明确更新协议，不能把跳过跟踪当成没有条件的性能收益。

5. 响应式通知与 DOM 刷新也不同，连续同步修改通常会被批量处理，需要读更新后元素时再等待 nextTick。我的排查顺序是确认数据来源、代理是否被保留、访问是否在跟踪范围内，再看更新时机，避免页面没变就一律强制刷新或加深度监听。

## 追问：直接修改原始对象，为什么代理视图不一定更新？

1. Proxy 只能拦截经过它的访问。创建 reactive(raw) 后，如果一直拿 raw 修改字段，就绕过了代理的写入处理，依赖没有收到对应通知；数据底层可能已经变了，但界面没有理由立即重新渲染。

2. 我会在业务代码中持续使用 reactive 返回的代理，避免同时传播 raw 和代理两种引用。后续其他更新可能让视图碰巧读到被修改后的值，但这种偶发刷新不能证明直接改原始对象是正确的数据更新方式。

3. 需要把对象交给只接受原始实例的库时，应把转换限制在明确接口处，并让库的变化通过规定入口通知 Vue。这样能够解释谁负责外部变更、谁负责界面更新，而不是依赖某次无关渲染顺带显示出来。

## 追问：Vue 会把对象所有属性都订阅到每个组件吗？

1. 通常不会，依赖收集发生在具体读取时，组件使用某个字段才建立相应关系。一个用户对象有很多字段，组件只显示昵称，并不意味着修改每个无关字段都必须让它执行完全相同的更新，这正是按访问收集的意义。

2. 但遍历对象、展开全部字段或深度 watch 会扩大读取范围，间接引入更多依赖。若为了方便把整份大对象到处展开，或者每个页面都深度监听它，原本较细的跟踪也可能被使用方式变成大范围工作。

3. 我会通过具体交互观察依赖和耗时，再缩小读取或监听来源。不能仅凭“Vue 自动追踪”就假设性能永远没问题，数据体量、模板表达式和第三方处理仍需要合理组织，自动跟踪并不会消除所有计算成本。
