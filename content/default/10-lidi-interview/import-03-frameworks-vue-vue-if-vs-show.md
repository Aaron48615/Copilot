# v-if 和 v-show 有什么区别？

## 核心回答

1. v-if 决定对应分支是否渲染，条件为假时通常不保留该分支组件和节点；v-show 会渲染元素，再通过 display 样式控制显示。二者视觉上都能隐藏内容，但实例是否存活、初次工作量和切换时的资源行为并不相同。

2. v-if 具有惰性，初始条件为假时不必创建相关组件，适合不一定会使用的昂贵区域。切换回来要重新创建，内部表单草稿、第三方实例和局部状态可能重置，不能因为希望隐藏就忽略再次显示的初始化成本。

3. v-show 首次就建立内容，后续切换通常更轻，也保留内部状态。代价是隐藏期间组件仍在，监听和定时器不会因为 display 变成 none 自动停止；如果里面有图表，隐藏时的尺寸也可能影响计算，返回后需要重新调整。

4. 我会根据使用频率和状态保留需求选择，例如低频打开的复杂设置可以考虑 v-if，频繁切换的小面板可以考虑 v-show。需要保留组件但又管理缓存范围时，还可以考虑 KeepAlive，不能把不同机制当成完全相同的显示开关。

5. v-show 不适用于 template 这种没有对应普通元素的写法，也不能与 v-else 配成条件链。权限方面两者都只是前端展示控制，隐藏按钮或不渲染页面不代表接口已授权；选择显示策略时应保留正确的业务和服务端检查，避免把隐藏当安全保障。

## 追问：v-show 隐藏以后，为什么请求还在继续？

1. v-show 只改变显示样式，组件没有卸载，之前启动的轮询或订阅仍然存在。框架不会从“不可见”自动推断这个任务不再需要，因为有些隐藏组件确实还承担后台工作，暂停与否需要业务明确决定。

2. 如果只在面板可见时更新，可以监听明确的显示状态来启动和暂停，并确保再次打开不会重复创建。若任务应该一直服务整个应用，就放到更合适的上层，由面板消费结果，不必每个隐藏面板各维护一份请求流程。

3. 测试可以隐藏后推进定时器，确认请求是否按约定停止，再显示检查只恢复一份。单看元素不可见的断言只覆盖视觉效果，无法说明网络和监听是否还在运行，资源行为需要单独验证。

## 追问：v-if 关闭弹窗会丢草稿，是否只能换 v-show？

1. 不一定，先看草稿是否有独立保存需求。可以把草稿提升到不会随弹窗卸载的位置，弹窗每次打开读取它，这样即使节点销毁也保留业务数据，不必为了几个字段一直保留整个昂贵组件实例。

2. v-show 确实能保留实例内状态，但也保留相应资源和首次初始化成本。如果用户有多个文档草稿，应按文档编号管理数据，而不是给每个文档长期创建一个隐藏弹窗，后者容易使内存和后台任务不断增加。

3. 我会明确关闭是取消编辑、暂时隐藏还是保存草稿，不同含义对应不同处理。用户点击取消可能本来就希望丢弃修改，盲目保留状态反而不符合预期；显示指令应服务这些交互规则，而不是替我们决定它们。
