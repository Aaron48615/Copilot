# 数组去重怎么写？

## 核心回答

1. 先说清楚「重复」是值一样、同一个对象，还是某个业务字段一样。普通基础值数组，用 `Set` 收唯一值再转回数组，按第一次出现的顺序留，不改原来那份。

    ```js
    function unique(list) {
      return [...new Set(list)];
    }
    ```

2. `Set` 的判断是 SameValueZero：多个 `NaN` 会合掉，正零和负零也当成同一个，数字一和字符串 `'1'` 不会合。对象按引用分，同一个对象出现两次能去重，内容一样的两个新对象还是两条。

3. 商品对象数组按 `id` 去重，留第一次出现的那条。下面用已见 ID 集合做，前提是每项都有合法、类型一致的 ID。函数返回新数组，里面还是原来那些对象引用。

    ```js
    function uniqueById(list) {
      const seen = new Set();
      return list.filter(item => {
        if (seen.has(item.id)) return false;
        seen.add(item.id);
        return true;
      });
    }
    ```

4. 这个实现只扫一遍输入，额外空间跟着不同 ID 的数量涨，通常比每次从头扫已有结果合适。规范并没有要求所有引擎都用同一种哈希结构，所以别把每一次集合操作严格说成常数时间。

5. 缺 ID 时直接按 `undefined` 去重，会把好几条错误合成一条；字符串和数字形式的 ID 也得先按接口约定处理。留第一条还是最后一条、要不要合并字段，都是业务规则，写代码前得说清楚。

## 追问：同一个 ID 要保留最后一条记录，顺序怎么处理？

1. 可以按原数组顺序写入 `Map`，ID 当键、记录当值，同名键后写的会盖住前面。但更新已有键不会把它挪到末尾，所以取 `values()` 得到的是键第一次出现的顺序，不是最后出现位置的顺序。

2. 同时还要按最后出现位置排，就倒序遍历，第一次碰到某个 ID 时留下，再把结果反转回来。也可以正序处理时先删已有键再重新加，但这条顺序规则得讲清楚。

3. 比如 ID 顺序是 `A、B、A`，留最后数据却按首次位置排会得到 `A、B`，按最后位置排则是 `B、A`。用这个小例子对一下需求，不然代码看着去重完了，显示顺序却和预期不一样。

## 追问：能不能先 JSON.stringify，再用 Set 去重对象？

1. 只有数据结构和序列化规则被明确限制住了，才可能把序列化结果当比较键。一般对象属性插入顺序可能不同，业务上觉得等价的两个对象未必生成同一串，所以不能直接当通用深相等。

2. JSON 还会省略对象里的函数和 `undefined` 属性，把日期变成字符串，碰到循环引用会失败。这样既可能让不同对象错误合并，也可能让整个去重直接抛错，问题不只是序列化快不快。

3. 按商品身份去重，优先选 ID 或明确的组合字段，通常更直观；真要按内容判断，就定义哪些字段参与、数组顺序重不重要，再选合适的比较方式。深相等规则和哈希键设计，都不是一行字符串化能顶掉的。
