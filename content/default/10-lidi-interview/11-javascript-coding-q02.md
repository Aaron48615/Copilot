# 数组去重怎么写？

## 核心回答

1. 我会先确定“重复”指值相同、同一个对象引用，还是某个业务字段相同。对于普通基础值数组，可以利用 `Set` 保存唯一值，再转回数组，结果按首次出现的顺序保留，不会直接修改输入数组。

    ```js
    function unique(list) {
      return [...new Set(list)];
    }
    ```

2. `Set` 的判断规则是 SameValueZero，多个 `NaN` 会合并，正零和负零也视为同一个值，而数字一和字符串 `'1'` 不会合并。对象按引用区分，同一个对象出现两次能去重，内容相同的两个新对象仍然会保留。

3. 对商品对象数组，我会约定按 `id` 去重并保留第一次出现的对象。下面用已见 ID 集合实现，前提是每项都有合法且类型一致的 ID，函数返回新数组，但保留原对象引用。

    ```js
    function uniqueById(list) {
      const seen = new Set();
      return list.filter(item => {
        if (seen.has(item.id)) return false;
        seen.add(item.id);
        return true;
      });
    }
    ```

4. 这个实现只遍历一次输入，额外空间随不同 ID 数量增长，通常比每次从头扫描已有结果更合适。不过规范并没有要求所有引擎都用同一种哈希结构，因此不能把每一次集合操作严格保证为常数时间。

5. 如果缺少 ID，直接按 `undefined` 去重会错误合并多条记录；字符串和数字形式的 ID 也要先按接口约定处理。保留第一条还是最后一条、是否合并字段都属于业务规则，应在写代码之前明确。

## 追问：同一个 ID 要保留最后一条记录，顺序怎么处理？

1. 可以按原数组顺序写入 `Map`，以 ID 为键、记录为值，同名键后写入的值会覆盖前值。但更新已有键不会把它移动到末尾，因此取 `values()` 得到的是首次出现键的顺序，不是最后出现位置的顺序。

2. 如果需求同时要求按最后出现位置排序，可以倒序遍历，第一次遇到某个 ID 时保留，再把结果反转回来。也可以在正序处理时先删除已有键再重新加入，但要把这条顺序规则讲清楚。

3. 比如输入的 ID 顺序是 `A、B、A`，保留最后数据但按首次位置排列会得到 `A、B`，按最后位置排列则是 `B、A`。我会用这个小例子核对需求，避免代码看似完成去重，显示顺序却和预期不同。

## 追问：能不能先 JSON.stringify，再用 Set 去重对象？

1. 只有在数据结构和序列化规则受到明确限制时，才可能把序列化结果用作比较键。一般对象的属性插入顺序可能不同，业务上认为等价的两个对象未必生成相同字符串，所以不能直接当成通用深相等。

2. JSON 还会省略对象中的函数和 `undefined` 属性，把日期变成字符串，遇到循环引用会失败。这样既可能让不同对象错误合并，也可能让整个去重过程抛错，问题并不只是序列化速度。

3. 如果按商品身份去重，优先选 ID 或明确的组合字段，通常更直观；如果确实按内容判断，就定义哪些字段参与、数组顺序是否重要，并选合适的比较方式。深相等规则和哈希键设计都不能靠一行字符串化替代。
