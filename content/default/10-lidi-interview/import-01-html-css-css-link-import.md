# link 和 @import 引入 CSS 有什么区别？

## 核心回答

1. `link` 是 HTML 元素，`rel="stylesheet"` 用来引入样式表；`@import` 是 CSS 规则，从一份样式里再引入另一份。两者最终都可能参与层叠，但发现资源的时机和组织方式不同。不是一个能用、另一个已经失效。

2. 外部样式里的 `@import`，通常得先拿到并解析包含它的那份 CSS，才能发现后面的资源，容易形成请求依赖链。直接写在 HTML 里的 `link` 更容易被解析器或预加载扫描器早点发现。`import` 也不是一定等整页加载完才开始下。

3. 加载早晚不直接决定谁盖过谁，样式生效还是看层叠规则和源码顺序。`@import` 还有允许出现的位置等语法限制，得写在样式表前部合适的地方。首屏关键样式一层层导入，网络往返可能变多，排查看请求瀑布，别只比语法长短。

4. 工程里还要分清浏览器的 CSS `@import` 和构建工具处理的模块导入。有的引用构建时就展开了，有的留到产物里；Sass 也有自己的模块机制。看最终 CSS 和 HTML，确定用户浏览器实际发了哪些请求，再判断要不要改组织方式。

5. 资源路径也是检查点。样式里的相对地址通常以这份样式表的地址为基准。文件一移动或合并，背景图和字体路径可能要靠工具重写。样式文件加载成功，不等于里面引用的资源都还能找到。

## 追问：CSS 后下载完成就一定覆盖先下载的 CSS 吗？

1. 不是。网络完成顺序不等于层叠顺序。两条普通声明在同一来源和层里竞争，还要比选择器优先级，条件相同再看样式表里的顺序。某个文件网络更慢，浏览器不会临时给它加权重。

2. 元素面板里看具体哪条规则赢了，再回到 HTML 的 `link` 顺序和导入位置解释原因。动态插入样式确实可能改文档里的顺序，那是插入位置和规则变了，不是下载耗时本身决定的。

3. 别靠人为延迟加载来「保证覆盖」。想管住基础样式和业务覆盖，整理层叠层、选择器和文件顺序，再用最终产物验证。开发环境碰巧正常，打包后顺序不同，样式就会跑偏。

## 追问：怎么判断 @import 是否造成了首屏请求瀑布？

1. 网络面板关掉缓存重新加载，看关键 CSS 的发起者和开始时间。第二份 CSS 由第一份 CSS 发起，而且必须等前者可解析后才被发现，就能看到依赖关系，不只是两条并排请求。

2. 接着确认这些样式是不是首屏必需、有没有多层导入、构建后能不能合并或提前用 `link` 引入。看见 `import` 别全部改写，开发源文件里的导入可能已经被工具展开，浏览器并没有真的多发请求。

3. 改完以后，同样条件下比资源发现时间和首屏显示，并检查媒体条件、层叠顺序有没有被改。减少请求依赖，得建立在样式行为还正确上。数字好看、页面所需样式却拖到闪一下才出来，不划算。
