# `z-index` 设置很大却不生效，可能是什么原因？

## 核心回答

1. 先确认 `z-index` 有没有参与当前元素的层叠。普通 `static` 元素直接写数字通常不起作用，但 Flex 和 Grid 子项是重要例外，不必为了让数字生效就一律加 `relative`。开发者工具里同时看显示方式、定位、实际命中的声明。

2. 就算属性生效，也不是整页按数字统一排序。父容器层级是 1，旁边浮层是 2，父容器里的按钮写 9999 仍可能被盖住。两个父级上下文先比，按钮只能在自己的上下文内部竞争。

3. 定位元素配合非 `auto` 的 `z-index`、`fixed`、`sticky`、非 `none` 的 `transform`、低于 1 的 `opacity` 等，都可能建立层叠上下文。沿着祖先往上找双方第一次相遇的上下文，再决定调哪个父级。别从目标元素开始一路加数字。

4. 还要分清层叠和裁剪。下拉框超出父元素后被 `overflow` 裁掉，抬层级往往没用。原生模态 `dialog` 进了顶层，也不是普通 `z-index` 能直接越过的。可能要调裁剪容器，或改弹层挂载位置，对上真正的原因。

5. 动画状态也值得看。父元素进入时改透明度或变换，可能临时产生新的上下文。菜单如果只在动画过程中被盖住，开始、播放、结束三种状态分开比。别只看停住以后那份看起来正常的样式。

## 追问：怎么构造最小例子验证是父级层叠的问题？

1. 留下两个重叠的兄弟容器，分别设明确的层级，再在较低容器里放一个很大的子级数字。去掉业务样式后如果仍被覆盖，就能直观看到子级跨不过父级上下文。

2. 接着只改较低容器的层级，看它和里面所有内容是不是一起上来。整块区域都盖到前面，单独调子元素却无效，说明比较发生在父级。这比猜某个组件库有问题更明确。

3. 验完还要回到页面，确认这个父级该不该整体提高。抬整张卡片，可能让其他按钮压住导航。只需要菜单越过边界，把菜单挂到统一浮层容器，通常比抬高整块业务内容更合适。

## 追问：为什么给透明遮罩加层级后按钮点不了了？

1. 看起来透明，不等于不参与命中测试。遮罩就算 `opacity` 是零，只要还盖着按钮并允许指针事件，就可能先接到点击。到元素面板看遮罩范围，别接着调按钮文字颜色或点击代码。

2. 遮罩只是装饰，可以考虑 `pointer-events: none`。它负责挡住背景操作，就不能这样处理，关闭时要同步隐藏或移除。两种用途不同，修之前先确认遮罩的交互职责。

3. 还要用键盘看背景按钮能不能被 Tab 到。指针事件设置不管键盘焦点。模态场景需要让背景不可交互。不然鼠标看着正常，键盘仍可能操作被挡住的页面。层级对了，不等于功能对了。
