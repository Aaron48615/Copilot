# `z-index` 设置很大却不生效，可能是什么原因？

## 核心回答

1. 我会先确认 z-index 是否参与当前元素的层叠。普通 static 元素直接写数字通常不起作用，但 Flex 和 Grid 子项是重要例外，不必为了让数字生效就一律添加 relative。开发者工具里要同时看显示方式、定位和实际命中的声明。

2. 即使属性生效，也不是整页按数字统一排序。假如父容器在层级 1，旁边浮层在层级 2，父容器里的按钮写 9999 仍可能被盖住，因为两个父级上下文先比较，按钮只能在自己的上下文内部竞争。

3. 定位元素配合非 auto 的 z-index、fixed、sticky、非 none 的 transform、低于 1 的 opacity 等都可能建立层叠上下文。我会沿祖先向上找双方第一次相遇的上下文，再决定调整哪个父级，而不是从目标元素开始不断加数字。

4. 还要区分层叠与裁剪。下拉框超出父元素后被 overflow 裁掉，提升层级往往没有帮助；原生模态 dialog 进入顶层后，也不是普通 z-index 能直接超越的。解决方式可能是调整裁剪容器或弹层挂载位置，要对应真正的原因。

5. 动画状态也值得检查，父元素在进入时改变透明度或变换，可能临时产生新的上下文。菜单如果只在动画过程中被盖住，我会分别比较开始、播放和结束三种状态，而不是只查看停住以后那份看起来正常的样式。

## 追问：怎么构造最小例子验证是父级层叠的问题？

1. 我会保留两个重叠的兄弟容器，分别设置明确的层级，再在较低容器里放一个很大的子级数字。去掉业务样式后如果仍被覆盖，就能直观看到子级无法跨越父级上下文的限制。

2. 接着只修改较低容器的层级，观察它和里面所有内容是否一起上移。如果整个区域都盖到前面，而单独调子元素无效，说明比较发生在父级，证据比直接猜测某个组件库有问题更明确。

3. 验证后仍要回到页面确认这个父级是否应该整体提高。提升整张卡片可能让其他按钮压住导航，若只需要菜单越过边界，把菜单挂到统一浮层容器通常比抬高整块业务内容更合适。

## 追问：为什么给透明遮罩加层级后按钮点不了了？

1. 视觉透明不等于不参与命中测试。遮罩即使 opacity 是零，只要仍覆盖按钮并允许指针事件，就可能先接收到点击；我会在元素面板查看遮罩范围，而不是继续调按钮文字颜色或点击代码。

2. 如果遮罩只是装饰，可以考虑 `pointer-events: none`；如果它负责阻止背景操作，就不能这样处理，而应确保关闭时同步隐藏或移除。两种用途不同，修复必须先确认遮罩的交互职责。

3. 还要用键盘检查背景按钮能否被 Tab 到。指针事件设置不控制键盘焦点，模态场景需要让背景不可交互；否则鼠标似乎正常，键盘仍可能操作被遮住的页面，层级正确也不代表功能正确。
