# 如何实现一个元素水平垂直居中？

## 核心回答

1. 普通页面里，我会先用 Flex 或 Grid 居中，因为内容仍然参与布局，文字变多时父容器也比较容易处理。比如空状态区域用 Flex，父元素写 `justify-content: center` 和 `align-items: center`，同时给出合理的最小高度，否则没有多余的垂直空间可以分配。

2. Flex 的对齐要看主轴方向。默认横向排列时，前一个属性控制水平、后一个控制垂直；改成 `flex-direction: column` 后两者对应的方向会交换。用 Grid 时可以在父容器上写 `place-items: center`，只调整单个子项则给它写 `place-self: center`；这控制的是子项在网格区域内的对齐，不等于居中整组轨道。

3. 如果是需要覆盖内容的提示层，可以让外层定位，内层用 `top: 50%; left: 50%`，再加 `translate(-50%, -50%)`。前面的百分比参照包含块，平移百分比通常参照元素自己的盒子，因此不必预先知道文字撑出的宽高。

4. 最后我会检查内容超过容器时怎么办。登录表单、长弹窗不能为了视觉居中让顶部跑到屏幕之外，可以设置最大高度和内部滚动，或者在小屏下改为靠上排列。单行文字的行高居中只适合简单场景，内容换行后就不可靠了。

5. 还有一个细节是多个子元素会分别参与排列。如果希望标题、说明和按钮作为整体居中，我会先用一个内容容器把它们组织起来，再让这组内容居中，否则给每项居中可能得到与设计不同的间距和分布。

## 追问：为什么写了 height: 100% 还是不能垂直居中？

1. 百分比高度需要有可解析的参照。如果祖先高度一直由内容撑开，子元素写百分比通常得不到预期的整屏高度；此时问题在容器尺寸，而不是少写了一条对齐属性。

2. 我会在开发者工具里逐层看实际高度。假如父容器高度和按钮一样高，就没有空白可供上下居中，可以按需求给容器明确高度，或用视口相关的最小高度建立空间。

3. 页面有顶部导航时，还需要扣除导航占用的高度，不能直接给内容一整屏再叠加导航。移动端可以评估动态视口单位，同时实际测试地址栏变化和软键盘弹出后的可见区域。

## 追问：未知宽高的弹窗怎么避免居中后溢出？

1. 我会让遮罩负责排列，弹窗负责尺寸限制，比如宽度取可用空间并设置最大宽度，两侧保留间距。这样内容变化时不用重新计算定位坐标，也不会在窄屏上紧贴屏幕边缘。

2. 高度方面给弹窗设置可用视口内的上限，把长内容放进内部滚动区，标题和操作按钮是否固定则根据需求决定。只加居中而不限制高度，会让长弹窗的开头或关闭按钮难以访问。

3. 验证时我会用长标题、多行错误提示和放大的文字检查，而不是只看默认示例。同时用键盘移动到最后一个按钮，确认滚动能把焦点带到可见位置，视觉居中和实际可操作都要成立。
