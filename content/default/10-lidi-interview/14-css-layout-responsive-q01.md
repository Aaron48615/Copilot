# 如何实现一个元素水平垂直居中？

## 核心回答

1. 普通页面里，Flex 或 Grid 居中更合适，因为内容还参与布局，文字变多时父容器也比较好处理。比如空状态区域用 Flex，父元素写 `justify-content: center` 和 `align-items: center`，同时给一个合理的最小高度。没有多余的垂直空间，对齐也没处使。

2. Flex 的对齐要看主轴方向。默认横向排列时，前一个属性管水平，后一个管垂直；改成 `flex-direction: column` 后两者对应的方向会换。Grid 可以在父容器上写 `place-items: center`，只调单个子项就给它 `place-self: center`。这管的是子项在网格区域内的对齐，不等于把整组轨道都居中。

3. 需要盖住内容的提示层，可以让外层定位，内层用 `top: 50%; left: 50%`，再加 `translate(-50%, -50%)`。前面的百分比参照包含块，平移百分比通常参照元素自己的盒子，所以不必预先知道文字撑出来的宽高。

4. 内容超过容器时怎么办也要看。登录表单、长弹窗不能为了视觉居中让顶部跑到屏幕外面。可以设最大高度和内部滚动，或者小屏下改成靠上排。单行文字用行高居中只适合简单场景，内容一换行就不稳了。

5. 多个子元素会分别参与排列。标题、说明、按钮希望作为整体居中，先用一个内容容器把它们包起来，再让这组内容居中。给每一项分别居中，间距和分布可能跟设计不一样。

## 追问：为什么写了 height: 100% 还是不能垂直居中？

1. 百分比高度需要有能解析的参照。祖先高度一直由内容撑开，子元素写百分比通常拿不到预期的整屏高度。这时问题在容器尺寸，不是少写了一条对齐属性。

2. 开发者工具里一层层看实际高度。父容器高度和按钮一样高，就没有空白可供上下居中。可以按需求给容器明确高度，或用视口相关的最小高度把空间撑出来。

3. 页面有顶部导航时，还得扣掉导航占用的高度，别直接给内容一整屏再叠导航。移动端可以评估动态视口单位，同时实测地址栏变化、软键盘弹出来之后的可见区域。

## 追问：未知宽高的弹窗怎么避免居中后溢出？

1. 遮罩负责排列，弹窗负责尺寸限制。比如宽度取可用空间并设最大宽度，两侧留间距。内容变了不必重新算定位坐标，窄屏上也不会贴死屏幕边缘。

2. 高度给弹窗设可用视口内的上限，长内容放进内部滚动区。标题和操作按钮固不固定，按需求定。只加居中不限制高度，长弹窗的开头或关闭按钮可能够不着。

3. 用长标题、多行错误提示、放大的文字检查，别只看默认示例。键盘移到最后一个按钮，确认滚动能把焦点带到看得见的位置。视觉居中和实际能操作，都要成立。
