# React 的懒加载失败和错误边界怎么处理？

## 核心回答

1. `React.lazy` 按需加载组件代码，一般配合动态 `import`，暂时用不到的模块晚点再取。外层 `Suspense` 在代码还在等时显示占位。网络断了、脚本不存在是失败，加载动画自己变不成错误提示。

2. `lazy` 的加载 Promise 拒绝后，错误交给最近的错误边界。边界给出能看懂的说明和恢复入口，记下模块、页面、应用版本这些必要信息。别只丢一段堆栈，用户不知道是继续等、重试还是返回。

3. 按功能区放边界，详情加载失败导航还在。普通按钮事件、Effect 里请求的失败要自己处理，边界不是全局 `try/catch`。服务端渲染还有框架对应的错误机制。客户端边界的职责扩不到所有环境。

4. 重试要确认加载会不会真的再执行。`lazy` 会把加载相关结果缓存住，单纯重置边界，同一个失败的 lazy 不一定再发请求。可以在加载层做有限重试，或走框架支持的恢复。别在组件 `render` 里不停创建新的 lazy 类型。

5. 发布时删了旧脚本，还开着旧 HTML 的用户可能去请求一个已经不存在的文件。看部署和缓存策略，必要时提示刷新，没保存的内容要护住。离线、旧版本资源、恢复联网这些场景都要过。有边界不等于不会白屏。

## 追问：动态 import 失败时，应该自动刷新页面吗？

1. 不是所有失败都立刻刷新。用户断网，刷新变不出文件，原来还能用的部分也可能一起没了。编辑页还有没保存的内容。先说明情况，给可控重试，让用户知道刷新会丢掉什么。

2. 确认是新版本发布导致旧文件不可用，刷新拿到新入口可能有效。自动刷新次数要限制，缓存配错可能刷个不停。也可以提示先保存当前内容再更新，一次模块错误别变成整页不停重载。

3. 后面查构建资源留多久、入口怎么缓存，减少旧页面引用已经失效的文件。前端边界负责把情况说清楚；部署策略负责让能引用的资源还在。两件事分开处理，重试按钮盖不住资源发布问题。

## 追问：错误边界放最外层一个就够了吗？

1. 最外层能拦住没处理的渲染错误，不让它直接打到根上。但所有异常都走它，一个小部件出错也整页替换。导航和正在填的内容可能一起没了，恢复范围跟问题大小对不上。

2. 独立功能再加局部边界，比如图表、富文本预览、详情，各自给合适的失败提示。公共布局外再留总边界接没预料到的错误。粒度来自业务上能独立用的区域，不是每个小按钮套一层。

3. 测边界自己渲染失败、以及重置行为，确认还有外层能接。恢复时别把无关状态清掉。错误记录还要防多层把同一次异常报好几遍，日志很多，真实故障发生了几次反而看不清。
