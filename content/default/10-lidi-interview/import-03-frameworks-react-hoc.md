# 高阶组件 HOC 是什么？

## 核心回答

1. 高阶组件是接收组件并返回增强组件的函数，例如 withPermission 接收一个业务组件，返回一个先判断权限再渲染它的组件。它通过组合增加能力，不应该修改原组件的原型或偷偷替换原组件的方法。

2. 它适合复用包裹行为，例如注入用户信息、统一布局或根据加载状态选择内容。被包裹组件通过 props 使用这些能力，剩余 props 应继续透传；要明确哪些名称由 HOC 提供，避免把调用方传入的属性意外覆盖。

3. 多层 HOC 会让组件树更深，也让属性来源难追踪。静态属性不会因为包裹自动全部继承，ref 的转发也需要按 React 版本和组件接口设计；React 19 可以把 ref 作为 prop 传递，旧版本常通过 forwardRef 处理。

4. 我会在组件外部创建增强组件，避免每次渲染都产生新的组件类型而导致子树重建。只复用有状态逻辑时，自定义 Hook 通常更直接；但需要包装组件本身，或维护 react-redux connect 等既有代码时，理解 HOC 仍有价值。

5. 包装行为也应可测试，例如用户信息加载期间显示等待，确认无权限后显示说明，获得权限后完整传递业务参数。若增强层把所有失败都当作未登录，或者吞掉原组件需要的属性，外层看起来统一了，实际却会改变原有交互语义。

## 追问：为什么不能在父组件 render 里调用 withAuth？

1. 如果 withAuth 每次返回一个新组件函数，React 会看到同一位置的组件类型发生变化。即使输出看起来一样，也可能卸载旧子树再挂载新子树，输入框草稿、焦点和局部 state 都会丢失。

2. 我会把 `const ProtectedPage = withAuth(Page)` 放在模块作用域，让组件类型稳定。变化的用户状态通过 props 或 Context 传递，由增强组件内部判断，不需要为了身份变化重新创建组件定义。

3. 排查时可以给业务组件增加挂载和卸载观察，输入几个字后触发父级无关更新，确认草稿是否保留。问题的核心是类型身份变化，给 props 加 useMemo 或给列表换 key 都不是对应的修复方式。确认修复时要触发不相关的父级更新，而不只是重新打开页面，否则很难看出局部状态是否在原位置持续保留。

## 追问：权限 HOC 能保证接口数据安全吗？

1. 它能控制前端界面是否展示，但不能代替服务端授权。用户仍可能绕过页面直接请求接口，所以接口必须根据可信登录身份检查资源访问权，不能只相信前端传来的角色或按钮是否隐藏。

2. 前端包装组件还应区分“身份正在加载”和“明确没有权限”。加载阶段直接跳登录可能造成闪跳，未登录和已登录但无权访问也应给出不同反馈，方便用户理解下一步操作。

3. 如果异步权限检查期间用户切换账号，旧检查结果不能重新放行页面。我会让检查结果和当前账号对应，并在退出时清理相关缓存；这属于需要设计的实现边界，不应只写一个 token 存在判断就称为完整鉴权。
