# Object.create 和 class extends 是什么关系？

## 核心回答

1. `Object.create(proto)` 创建一个以指定对象为内部原型的新对象，主要解决属性查找从哪里继续的问题。它不会执行某个构造函数，也不会把原型上的字段复制成自己的字段，所以能找到方法并不意味着实例数据已经初始化。读取继承属性时继续沿链查找，与对象自身真正持有这个属性，需要明确区分。

2. 对普通构造函数执行 `new` 时，实例通常会连接到构造函数的原型，并执行初始化逻辑。如果构造函数显式返回另一个对象，最终结果还可能是那个对象，因此不能只用创建原型连接来概括所有构造行为。

3. `class Child extends Parent` 会建立两条重要联系：子类原型连接父类原型，子类构造函数连接父类构造函数。前者支持实例方法继承，后者支持静态成员查找，另外还有父类调用和派生构造函数初始化等规则。

4. 寄生组合继承会用创建原型对象的方式避免额外执行父构造，这与类继承有共同基础，但并不完全等价。如果实际需要父类初始化或私有字段，单独创建一个挂着父类原型的对象是不够的，我会按需求选择创建普通对象还是构造类实例。

## 追问：Object.create(User.prototype) 得到的对象算 User 实例吗？

1. 在普通实例判断规则下，它的原型链含有用户类的原型，所以实例判断可以得到真值。但这只能证明连接关系成立，不能证明构造函数执行过，更不能保证名称、编号等实例属性已经写入对象。

2. 如果原型方法读取的是普通字段，调用时可能得到未定义的结果；如果读取的是类的私有字段，通常会因为对象没有对应的私有字段而抛错。这说明能访问某个方法和满足方法运行需要是两件不同的事。

3. 因此我不会把实例判断当成完整的数据验证，也不会用这种方式跳过必须的初始化。只有确实想创建委托给某个原型的普通对象时才直接使用它，若要得到可正常工作的类实例，就应走相应的构造过程。

## 追问：类的静态方法为什么也能被子类访问？

1. 静态方法放在构造函数对象上，而不是实例原型上。类继承会把子类构造函数的内部原型指向父类构造函数，所以查找子类上没有的静态方法时，可以继续到父类构造函数上寻找，不需要复制方法。

2. 通过子类调用继承来的静态方法时，方法内部的当前接收者通常是子类。假如方法根据当前接收者上的普通静态属性工作，子类可以有自己的属性值，因此继承方法并不等于所有调用都固定使用父类的数据。

3. 静态私有字段需要特别小心，它属于声明它的那个类，不能因为存在继承链就随意从子类接收者上读取。如果父类静态方法通过当前接收者访问该字段，换成子类调用可能抛错，设计时应明确接收者要求。
