# Object.create 和 class extends 是什么关系？

## 核心回答

1. `Object.create(proto)` 创建一个以指定对象为内部原型的新对象，主要解决属性查找从哪继续。它不会执行某个构造函数，也不会把原型上的字段复制成自己的字段。能找到方法，不意味着实例数据已经初始化。读到继承属性，和对象自身真正握着这个属性，要分开。

2. 对普通构造函数执行 `new` 时，实例通常会连到构造函数的原型，并执行初始化逻辑。构造函数显式返回另一个对象，最终结果还可能是那个对象。不能只用「创建原型连接」概括所有构造行为。

3. `class Child extends Parent` 会建立两条重要联系：子类原型连接父类原型，子类构造函数连接父类构造函数。前者支持实例方法继承，后者支持静态成员查找。另外还有父类调用、派生构造函数初始化这些规则。

4. 寄生组合继承会用创建原型对象的方式避免额外执行父构造，跟类继承有共同基础，但并不完全等价。实际需要父类初始化或私有字段，单独创建一个挂着父类原型的对象不够。按需求选择：创建普通对象，还是构造类实例。

## 追问：Object.create(User.prototype) 得到的对象算 User 实例吗？

1. 普通实例判断规则下，它的原型链含有用户类的原型，实例判断可以得到真值。这只能证明连接关系成立，证明不了构造函数执行过，更保证不了名称、编号这些实例属性已经写进对象。

2. 原型方法读的是普通字段，调用时可能得到未定义；读的是类的私有字段，通常会因为对象没有对应的私有字段而抛错。能访问某个方法，和满足方法运行需要，是两件事。

3. 别把实例判断当成完整的数据验证，也别用这种方式跳过必须的初始化。确实只想创建委托给某个原型的普通对象，才直接用它。要得到能正常工作的类实例，走相应的构造过程。

## 追问：类的静态方法为什么也能被子类访问？

1. 静态方法放在构造函数对象上，不在实例原型上。类继承会把子类构造函数的内部原型指向父类构造函数。查找子类上没有的静态方法时，可以继续到父类构造函数上找，不必复制方法。

2. 通过子类调用继承来的静态方法时，方法内部的 `this` 通常是子类。方法根据当前这个对象上的普通静态属性工作，子类可以有自己的属性值。继承方法，不等于所有调用都固定用父类的数据。

3. 静态私有字段要特别小心，它属于声明它的那个类，不能因为有继承链就随便从子类这个对象上读。父类静态方法通过当前的 `this` 访问该字段，换成子类调用可能抛错。设计时把 `this` 指向谁要写清楚。
