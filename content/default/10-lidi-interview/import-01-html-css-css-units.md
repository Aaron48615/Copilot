# px、em、rem 有什么区别？

## 核心回答

1. `px` 是 CSS 像素，不等于设备上的一个物理像素，也不是永远不会缩放的长度。浏览器缩放和设备像素密度会影响它最终占多少物理像素。适合表达明确的界面细节，但用了 `px` 不代表页面在所有屏幕上物理大小完全一样。

2. `em` 跟字体有关。用在 `font-size` 上通常参照父元素算字号，用在 `padding` 这类长度上通常参照当前元素字号。按钮字号变大后希望内边距也同比增加，可以用 `em`。连续嵌套又反复设 `em` 字号，可能叠乘，排查时逐层看基准。

3. `rem` 在常见字号和间距场景下参照根元素字号，多个组件可以共用一个基准，不会像逐层 `em` 那样累乘。它本身不感知屏幕宽度，只有根字号变了才跟着变。把根字号绑到视口是额外的适配策略，不是 `rem` 的默认行为。

4. 按关系选单位：阅读字号和统一间距可以用 `rem`，组件内部跟字号联动的距离用 `em`，确实固定的细节可以用 `px`。`vw`、`vh` 适合跟视口相关的尺寸，极端情况要限制。最后用文字放大和窄屏检查。单位是为了可读，不是追求全页只用一种。

## 追问：嵌套 em 字号为什么会越来越大？

1. 假设父元素字号是 16px，子元素设 `1.2em`，算完是 19.2px；再往下又设 `1.2em`，就会基于上一层继续放大。每一层都有相对声明，倍率连续相乘，不是浏览器把同一个值算错了好几遍。

2. 如果只是继承、没有再次声明 `1.2em`，就不会每下一层自动乘一次。计算样式里找真正声明了 `font-size` 的节点，分清继承值和新的相对计算，别把所有深层嵌套都当成必然累乘。

3. 整页标题始终基于同一个尺度，用 `rem`；某个按钮的图标和留白要跟着按钮字号一起变，`em` 仍然合适。把参照关系说清楚就行，不必禁止 `em`，它在局部组件里很自然。

## 追问：CSS 的 1px 在高分屏上为什么看起来可能偏粗？

1. CSS 像素是布局单位，高像素密度屏幕上一个 CSS 像素可能映射到多个设备像素。设计如果期待接近单个设备像素的细线，直接写 `1px` 就可能比预期更明显。这不说明 CSS 的像素定义坏了。

2. 按设计需要可以试半像素边框，或者用伪元素配合缩放画细线，但不同缩放比例和设备上的栅格化要实际看。别把 `scale` 到某个固定倍数当成所有屏幕的统一答案，缩放也可能发糊。

3. 先确认细线是不是真的碍眼，再选简单、好维护的方案。分隔线还得有足够对比度，过细在某些屏幕上几乎看不见。保持清晰可辨，有时比追求一个物理像素更符合实际使用。
