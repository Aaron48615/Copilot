# px、em、rem 有什么区别？

## 核心回答

1. px 是 CSS 像素，不等于设备上的一个物理像素，也不是永远不会缩放的长度。浏览器缩放和设备像素密度会影响它最终占用多少物理像素；它适合表达明确的界面细节，但不能因为使用 px 就认为页面在所有屏幕上物理大小完全相同。

2. em 与字体有关，用在 font-size 上通常参照父元素计算字号，用在 padding 等长度上通常参照当前元素字号。比如按钮字号变大后，希望内边距也同比增加，可以用 em；但连续嵌套并反复设置 em 字号可能叠乘，排查时要逐层看基准。

3. rem 在常见字号和间距场景下参照根元素字号，多个组件可以共享一个基准，不会像逐层 em 那样累乘。它本身不会感知屏幕宽度，只有根字号改变才会跟着变；把根字号绑定视口是一种额外适配策略，不是 rem 的默认行为。

4. 我会按关系选单位：阅读字号和统一间距可以用 rem，组件内部与字号联动的距离用 em，确实固定的细节可以用 px。vw、vh 则适合视口相关尺寸，但要限制极端情况。最后用文字放大和窄屏检查，单位选择应服务于可读性，而不是追求全页只用一种单位。

## 追问：嵌套 em 字号为什么会越来越大？

1. 假设父元素字号是 16px，子元素设置 1.2em，计算后就是 19.2px；再往下的元素又设置 1.2em，就会基于上一层继续放大。这里每一层都有相对声明，所以倍率连续相乘，不是浏览器重复错误地计算同一个值。

2. 如果只是继承而没有再次声明 1.2em，就不会每下一层自动乘一次。我会在计算样式里找真正声明 font-size 的节点，区分继承值和新的相对计算，避免把所有深层嵌套都认为必然发生累乘。

3. 希望整页标题始终基于同一个尺度时，可以使用 rem；希望某个按钮的图标和留白随按钮字号一起变化时，em 仍然合适。解决方式是明确参照关系，不是禁止 em，因为它在局部组件中有很自然的用途。

## 追问：CSS 的 1px 在高分屏上为什么看起来可能偏粗？

1. CSS 像素是布局单位，高像素密度屏幕上一个 CSS 像素可能映射到多个设备像素。设计如果期待接近单个设备像素的细线，直接写 1px 就可能比预期更明显，但这并不说明 CSS 的像素定义出了问题。

2. 可以根据设计需要尝试半像素边框，或者用伪元素配合缩放绘制细线，但不同缩放比例和设备上的栅格化效果要实际观察。不能把 scale 到某个固定倍数当作所有屏幕的统一答案，缩放也可能带来模糊。

3. 我会先确认细线是否真的影响视觉，再选择简单且可维护的方案。分隔线还需要足够对比度，过细可能在某些屏幕上几乎消失；保持清晰可辨有时比追求一个物理像素更符合实际使用需求。
