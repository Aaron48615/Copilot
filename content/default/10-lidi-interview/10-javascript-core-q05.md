# 深拷贝和浅拷贝有什么区别？

## 核心回答

1. 浅拷贝会新建外层容器，里面的嵌套对象还可能共用引用。比如复制一个带 `profile` 的用户对象，改副本的姓名不影响原对象，改 `copy.profile.city` 却可能把原来那份一起改了。

2. 对象展开和 `Object.assign` 都是浅拷贝，拷的是可枚举的自有属性值，不是对象内部所有信息。数组展开和 `slice` 也一样，元素是对象的话，新数组里还是原来那些对象。

3. 深拷贝要把支持的类型一层层拷出来，让能改的部分和原数据分开。但不是所有对象都能无损复制。循环引用、同一对象被多处引用，得记下已经拷过的，不然会无限递归，或者把原来的共享关系弄丢。

4. JSON 来回一趟，适合能序列化的简单数据，当不了通用深拷贝。函数和值为 `undefined` 的属性会被省掉，日期通常变成字符串，循环引用会报错，普通 `BigInt` 默认也序列化不了。

5. `structuredClone` 支持循环引用和不少内建类型，但函数、DOM 节点不在通用支持里，自定义类的原型也不会原样留下。只改列表里一件商品，拷数组和被改的那一项就行，没必要把整棵数据树都拷一遍。

## 追问：手写深拷贝为什么要用 WeakMap 记录对象？

1. 对象可能指向自己，比如 `a.self = a`，也可能两个字段指向同一个子对象。只递归，前一种会无限调下去，后一种会生出两个独立副本，原来的共享关系就没了。

2. 先查缓存，有副本就直接返回；没有才建新容器，在遍历子属性之前就把对应关系记上。顺序是：检查原始值、查缓存、创建容器、写入缓存、再递归填充。把写缓存放到递归后面，循环引用还是解不了。

3. `WeakMap` 能用原对象当键，也不会单独挡住键被回收。一次短暂调用用 `Map` 也能记对关系。缓存只解决重复访问。日期、集合、属性描述符、原型怎么处理，还得另定规则。有了缓存，不等于实现了通用克隆。

## 追问：编辑表单时，什么时候需要深拷贝原数据？

1. 弹窗允许取消编辑，又直接拿列表项的嵌套对象当表单状态，用户还没保存就可能把列表改了。这种要独立草稿。拷哪些字段，看表单会改到哪一层。

2. 只改姓名这类基本值，做一个只含可编辑字段的新对象通常就够。地址是可编辑的嵌套对象，再拷地址。只读展示、方法、组件实例别一起塞进草稿，拷得少，意外也少。

3. 保存时校验草稿，按接口结果更新原状态；取消就丢掉草稿。编辑期间还可能收到服务端新数据，要不要提示冲突得另定。深拷贝只能隔开本地引用，过期问题它解不了。
