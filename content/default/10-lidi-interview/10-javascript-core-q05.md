# 深拷贝和浅拷贝有什么区别？

## 核心回答

1. 浅拷贝会创建新的外层容器，但嵌套对象仍然可能共用引用。例如复制一个包含 `profile` 的用户对象后，改副本的普通姓名字段不会影响原对象，改 `copy.profile.city` 却可能影响原数据。

2. 对象展开和 `Object.assign` 都常用于浅拷贝，它们复制的是可枚举的自有属性值，不是完整复制对象的所有内部信息。数组的展开和 `slice` 也一样，如果元素是对象，新数组里仍然装着原来的对象引用。

3. 深拷贝要按照支持的类型复制嵌套数据，使可修改部分与原数据隔离，但不能承诺所有对象都能无损复制。循环引用以及同一对象被多处引用时，还需要记录已经复制过的对象，否则会无限递归或破坏原有引用关系。

4. JSON 往返适合可序列化的简单数据，不能当成通用深拷贝。对象中的函数和 `undefined` 属性会被省略，日期通常变成字符串，循环引用会报错，普通 `BigInt` 默认也不能直接序列化。

5. `structuredClone` 支持循环引用和多种内建数据类型，但函数、DOM 节点等不在通用支持范围，自定义类的原型也不会原样保留。若只是修改列表里一个商品，我会复制数组和被修改的那一项，避免无必要地复制整个数据树。

## 追问：手写深拷贝为什么要用 WeakMap 记录对象？

1. 对象可能引用自身，例如 `a.self = a`，也可能两个字段引用同一个子对象。只做递归会在前一种情况中无限调用，在后一种情况中生成两个独立副本，改变数据原本的共享关系。

2. 我会先查询缓存，有副本就直接返回；没有才建立新容器，并在遍历子属性前记录对应关系。伪代码顺序是“检查原始值、查询缓存、创建容器、写入缓存、递归填充”，把写缓存放在递归后面就不能解决循环。

3. `WeakMap` 可以用原对象作键，且不会单独阻止键被回收，不过一次短暂调用用 `Map` 也能正确记录关系。缓存只解决重复访问，日期、集合、属性描述符和原型如何处理，仍然需要另外定义，不能因此声称实现了通用克隆。

## 追问：编辑表单时，什么时候需要深拷贝原数据？

1. 如果弹窗允许取消编辑，又直接拿列表项的嵌套对象作为表单状态，用户还没保存就可能改动列表。这个场景应建立独立草稿，但具体复制哪些字段，要看表单会修改到哪一层。

2. 如果只修改姓名这类基本值，构造一个只包含可编辑字段的新对象通常就够了。地址是可编辑嵌套对象时再复制地址，不把只读展示数据、方法或组件实例也一起塞进草稿，能减少复制成本和意外行为。

3. 保存时校验草稿并根据接口结果更新原状态，取消时丢弃草稿。如果同时可能收到服务端新数据，还要决定是否提示冲突；深拷贝只能隔离本地引用，不能自动解决编辑期间的数据过期问题。
