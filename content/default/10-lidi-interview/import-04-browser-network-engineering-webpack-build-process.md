# Webpack 的构建流程是怎样的？

## 核心回答

1. Webpack 构建可以按准备配置、建立依赖图、组织产物、输出这几步来理解。启动时读入口和各项选项，创建 `compiler` 并注册插件。一次具体编译由 `compilation` 管。开了监听，后面更新会再走相应的编译过程。

2. 从入口出发，Webpack 解析模块引用、定位文件，按规则跑 loader 做内容转换，再分析依赖继续处理。不是所有资源都简单转成一段 JavaScript。资源模块可以把文件当独立资产输出，转换方式取决于配置。

3. 模块和依赖组成图之后，还要决定哪些模块进初始 chunk、哪些进异步 chunk。动态导入、共享依赖提取、运行时组织都会影响结果。每个入口或每个 `import` 固定只对应一个最终文件，这理解不准确。CSS 和其他资源也可能单独输出。

4. 后面按生产配置做导出使用分析、压缩这些优化，生成资源，再通过输出文件系统写入。插件在各阶段用钩子参与。开发服务器可能用内存文件系统，磁盘上看不到 dist，不一定代表没有编译产物。

5. 我主要用过 Vite。遇到 Webpack 问题，先核对版本和配置，再用最小入口复现，分清是依赖找不到、转换失败，还是输出路径错了。沿配置、模块解析、转换、输出逐步定位，盯第一处有效错误。构建成功后还要验证页面资源路径、接口、懒加载，编译日志过了不等于页面对。

## 追问：module、chunk 和最终资源文件是什么关系？

1. module 是构建系统处理的模块单元，可能来自脚本、样式或其他资源。chunk 是组织模块和加载边界的中间概念。多个模块可以进同一个 chunk，一个模块也可能通过优化被多个页面共享。不是文件一对一复制。

2. 最终输出的是浏览器能请求的资源，包括 JavaScript、CSS、图片、映射等。一个 chunk 不一定只产出一个文件。样式提取、运行时组织都会改对应关系。chunk 和磁盘上的 bundle 不能永远当成同一个词。

3. 看构建统计里的模块、chunk、assets 关联，再解释某个大文件里有什么。分析体积时先确定层级。模块源码大小简单相加，当不了用户实际下载量。压缩、去重、共享都会改结果。

## 追问：开发服务器没有 dist，浏览器为什么还能加载代码？

1. 开发中构建结果可以写进内存文件系统，再由开发中间件响应请求，不必每次都落到真实磁盘。浏览器只关心对应 URL 能不能返回有效资源，不要求这些内容一定以同名文件存在项目目录里。

2. 编译成不成功、开发中间件的公开路径对不对，先看，再查请求状态。某个外部工具必须从磁盘读产物，再按需求配置写盘。暂时看不到 dist，就反复跑生产构建来掩盖开发路径错误，会把问题搅在一起。

3. 直接看浏览器拿到的资源和更新行为，同时分清开发产物和生产产物。内存编译能跑，不代表正式构建的压缩、缓存、公共路径已经正确。部署前仍要独立测生产输出。
