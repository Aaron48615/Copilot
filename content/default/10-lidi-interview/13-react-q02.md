# `useEffect` 为什么需要清理函数？

## 核心回答

1. 清理函数是撤销上一次 Effect 建立的外部连接或资源。React 移除组件时会调用它，依赖变化需要重新设置 Effect 时也会先调用，所以我不会把它只理解成组件卸载回调。理解这两个时机，才能正确处理页面内切换订阅对象的情况。

2. 比如监听窗口变化，设置时调用 `addEventListener`，清理时用同一个函数引用移除监听；启动定时器，就保存对应 ID 并清除。否则每次进入页面都可能增加一个回调，出现一次操作触发多次更新的问题。

3. 城市视图涉及图表和尺寸变化，检查这类代码时，我会关注 ECharts 实例释放和 ResizeObserver 断开。如果再增加定时刷新，还需要配套清理定时器；只释放图表实例，仍可能留下访问旧实例的刷新回调。

4. 对数据请求，清理除了节省不必要的网络工作，还要保证旧结果不能更新当前页面。我会根据请求库使用 AbortController，并判断结果是否仍属于当前 Effect，因为取消请求不等于撤销所有已经执行的后续逻辑。

5. 开发环境 Strict Mode 的额外设置、清理、再设置，能帮助发现资源没有正确释放的问题。我会让清理与设置一一对应，而不是加一个“已经执行过”的标记把第二次执行直接挡住。

## 追问：取消请求和忽略旧结果有什么区别？

1. 取消请求是通知支持取消的请求实现停止工作，能减少后续传输或处理。它不保证服务端没有收到请求，也不能撤销已经完成的写入，所以不能把 abort 当成数据库回滚。提交类请求尤其要区分取消等待与业务取消。

2. 忽略旧结果是在更新界面之前检查有效性，例如每次 Effect 有自己的 active 标记，清理时设为 false。即使网络层未能及时取消，已经过期的结果也不会进入当前组件状态。

3. 对会快速切换查询条件的页面，我会分别检查成功、失败和 finally 分支是否仍然有效。只拦住成功赋值还不够，旧请求结束时若关闭了新请求的 loading，用户仍会看到错误状态。

## 追问：图表切换数据时，必须销毁后重新创建吗？

1. 不一定，数据改变与实例失效是两件事。图表容器仍然存在时，通常可以复用实例更新配置和数据；如果每次都重新初始化，可能产生闪烁，还会丢失缩放等交互状态。

2. 我会把容器对应的实例生命周期与数据同步逻辑分开，实例创建后保存引用，后续更新使用它。容器真正离开页面时再释放实例，同时断开尺寸观察，避免回调访问已销毁对象。

3. 也要考虑图表类型或容器身份发生变化的情况，这时可能确实需要重建。具体是否复用要看图表库的更新规则，不能只为了减少初始化次数，把旧系列和新数据错误地合并在一起。
