# Git 和 SVN 这类工具有什么区别？

## 核心回答

1. Git 是分布式版本控制，普通完整克隆会在本地保存对象和历史，所以查看历史、创建分支和提交不必一直连接服务器。浅克隆和部分克隆可能没有全部对象，不能把每一种 clone 都理解成一份完整备份。

2. SVN 更偏集中式，提交需要与中央仓库交互，但部分工作区比较和还原也能离线进行。两者差异主要是历史如何保存和协作如何组织，不是简单说 Git 所有操作都快，SVN 所有操作都必须联网。

3. Git 分支主要是指向提交的引用，创建分支不需要复制整个目录。SVN 的仓库内分支也支持廉价复制，不能说它一定复制全部文件所以很慢；Git 的本地分支、合并及分布式协作方式是我更关注的区别。

4. 日常使用 Git 会经过工作区、暂存区和本地提交。暂存区允许我选择本次要提交的改动，避免把临时调试或无关修改一起提交；远端仓库用于同步，commit 与 push 是两步不同的操作。

5. 协作时 fetch 获取远端信息，pull 则还会根据配置执行合并或变基等整合。选择工具也要看团队权限、历史规模和资产类型，不能仅靠分布式这个名字断言它适合所有项目，操作之前先确认仓库和当前分支。

## 追问：既然本地有历史，为什么还需要远端仓库？

1. 本地历史解决离线工作和版本记录，远端提供团队同步的位置，也常与评审、持续集成和权限控制结合。一个人完成本地提交后，其他人并不会自动得到它，仍需要按协作流程推送和获取更新。

2. 远端还可以作为备份的一部分，但不能只靠本机一份仓库保护成果。反过来，已经推送也不意味着所有相关内容都备份了，例如忽略的配置、外部文件和浅克隆缺失的对象，需要按项目情况管理。

3. 我会把个人开发和共享历史区分开，先在任务分支整理并验证，再按授权同步。遇到远端冲突先获取最新状态，避免为了让推送成功就强制覆盖，因为远端可能已经包含同事刚完成的工作。

## 追问：git add 和 git commit 为什么要分成两步？

1. git add 把选定内容放入暂存区，git commit 把暂存区快照记录为提交。这样同一个工作区可以暂时存在多项修改，但本次只提交一个完整主题，评审和之后定位问题都会更清楚。

2. 例如修复表单错误时顺手加了调试日志，可以只暂存修复部分，把日志留在工作区。不过暂存后再次编辑文件，新的修改不会自动进入已暂存快照，因此提交前要检查 staged diff，而不只看编辑器。

3. 我会尽量按相关文件或改动片段选择，避免默认全部加入。尤其多人共享工作区时，无关修改可能属于别人；清楚暂存区包含什么，才能避免把别人的未完成内容带入自己的提交。
