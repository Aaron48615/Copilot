# 轻购里的加入购物车和立即购买有什么区别？

## 核心回答

1. 加入购物车的目的是先保存这件商品，用户可以继续浏览再统一结算。当前调用 `/p/shopCart/changeItem`，带 basketId: 0、商品 ID、SKU ID、店铺 ID 和数量，成功后提示并关闭面板，服务端负责保存购物车项。

2. 立即购买跳过购物车持久化，把当前商品、SKU、数量和店铺组成 orderItem。再与空 basketIds、地址和优惠券相关字段放入 sessionStorage 的 confirmOrder，进入订单确认页，所以它缩短的是购买路径，不是跳过交易校验。

3. 两条入口都必须使用当前选中的 SKU，并保持购买数量一致。比如用户选了白色大码，不能仍传默认第一条黑色小码；商品 ID 只说明买哪种商品，skuId 才能明确这次购买的具体规格。

4. 到订单确认页后，两种来源都会重新读取地址与确认金额。详情页价格可能是某个规格的展示价，购物车也可能在用户停留期间发生变化，因此前端临时对象只是购买意图，不能直接决定最终金额或库存。

5. 我会把入口参数分别组织，但复用后面的确认流程。当前支付是模拟流程，购物车保存成功也不代表库存已锁定；如果继续完善，需要处理加购失败、无效规格及直接购买参数缺失等情况。

## 追问：为什么立即购买还要保存临时数据？

1. 详情页与确认页是不同路由，离开组件后不能只依靠详情页的局部变量。确认页需要知道商品、规格和数量，sessionStorage 能让同一标签页跳转或刷新后仍读取本次选择，适合当前简单流程。

2. 保存的是意图，不是完整结算结果。确认页仍请求服务端获取最新地址、商品与金额，避免详情页里旧的价格或库存被当成现时事实；字段可以被浏览器修改，所以后端不能省略校验。

3. 创建订单并取得订单号后要清理这份临时数据，后续付款围绕已存在的订单进行。如果继续扩展多份购买草稿，则需要明确标识与覆盖规则，不能一直用同一个键而让两次操作互相替换。

## 追问：加购按钮点击后没收到响应，能再点一次吗？

1. 需要先弄清接口语义，尤其 changeItem 可能表达增加数量。请求超时不表示服务端没执行，直接重复一次可能把原本想买的一件变成两件，因此不能在公共请求层自动重放所有写操作。

2. 前端可以在请求期间禁用当前操作，结束后提示结果不确定，并重新读取购物车确认数量。如果接口支持幂等请求标识，再按照约定安全重试；没有这种后端能力时，单靠按钮锁不能覆盖网络重试和多设备操作。

3. 验证时会模拟服务端已经更新但响应迟到的情况，检查用户不会被引导盲目重复加购。还会重新查询购物车检查数量，前端重复点击保护不能单独保证幂等，服务端需要识别重复请求并按库存规则处理。
