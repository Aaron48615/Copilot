# CLS 怎么从代码里预防？

## 核心回答

1. CLS 衡量页面在没有预期的情况下发生的布局位移，用户常见感受是刚要点击的按钮突然挪走。它不只发生在首次加载，后续插入内容和字体变化也可能造成位移，所以我会在实际浏览和交互中一起观察。

2. 从代码预防时，图片、视频和异步卡片提前提供尺寸或宽高比，让浏览器先分配空间。广告或推荐模块如果尺寸不确定，应设计合理保留区域；不能内容一到就插到用户正在阅读的段落上方，推走已有内容。

3. 字体替换也会改变字宽和行高，导致整段文字重新换行。可以选择尺寸接近的回退字体，合理调整字体指标和加载方式；只设置 font-display 并不保证没有位移，需要观察目标字体加载前后的实际几何变化。

4. 动画尽量避免反复改变占位几何，适合时用 transform 实现视觉移动。异步数据更新保留稳定容器，骨架屏尺寸也要与最终内容接近，否则虽然有占位，替换时仍会让页面明显跳动，并没有达到预防目的。

5. 定位时我会看 Layout Shift 记录与受影响元素，进一步找真正触发变化的节点。位移评分有输入排除等规则，但用户体验不能只按是否计分判断；即使某次移动没进入 CLS，也应避免让点击目标不可预测地改变位置。

## 追问：性能工具标出的元素一定是造成位移的原因吗？

1. 不一定，被标出的是发生移动的元素，它可能只是受影响者。比如顶部图片原来没有高度，加载后把下面标题推走，工具记录标题移动，但真正应该修的是图片占位，而不是给标题随便加固定定位。

2. 我会对照位移发生前后的画面和 DOM 变化，检查新增内容、字体、容器高度与样式切换。先找到谁改变了可用空间，再决定预留尺寸或调整插入位置，避免只把被移动元素强行钉住造成重叠。

3. 修复后按同样的慢加载或异步条件复现，确认后续内容位置稳定。还要测试不同文本长度与视口，因为一个固定高度在本地刚好合适，换设备后可能裁剪内容或再次引发位移。

## 追问：用户点击展开内容，产生位移一定算 CLS 吗？

1. 不一定，指标对符合规则的近期用户输入相关位移有排除机制，所以点击后马上展开与无操作时突然插入广告并不相同。但这个排除有条件和时间范围，不能把所有发生在点击之后的变化都视为不计分。

2. 尤其是点击后等待很久才返回的数据，或者与当前操作无关的模块变化，仍需要单独检查。滚动也不能简单当作允许任意位移的输入，因此无限列表加载时仍应保护当前阅读位置和可点击目标。

3. 我会先判断变化是否符合用户预期，再看测量结果。即使某次移动没有计入 CLS，如果用户点错按钮或丢失阅读位置，体验仍有问题，不能为了指标规则而忽略真实交互上的不稳定。
