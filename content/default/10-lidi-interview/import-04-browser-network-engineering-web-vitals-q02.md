# CLS 怎么从代码里预防？

## 核心回答

1. CLS 衡量的是页面在没有预期的情况下发生的布局位移。常见感受是刚要点的按钮突然挪走。它不只发生在首次加载，后面插入内容、字体变化也可能造成位移。实际浏览和交互里都要观察。

2. 图片、视频、异步卡片提前给尺寸或宽高比，浏览器能先分配空间。广告、推荐模块尺寸不确定，就设计合理的保留区域。内容一到就插到用户正在读的段落上方，把已有内容推走，最容易点错。

3. 字体替换会改字宽和行高，整段文字可能重新换行。选尺寸接近的回退字体，合理调字体指标和加载方式。只设 `font-display` 不保证没有位移，目标字体加载前后几何实际怎么变，要看一眼。

4. 动画尽量少反复改占位几何，适合时用 `transform` 做视觉移动。异步数据更新留稳定容器，骨架屏尺寸也要跟最终内容接近。有占位但替换时仍明显跳动，预防目的就没达到。

5. 定位看 Layout Shift 记录和受影响元素，再找真正触发变化的节点。位移评分有输入排除这类规则，但用户体验不能只按计不计分判断。某次移动没进 CLS，点击目标不可预测地改位置，体验照样差。

## 追问：性能工具标出的元素一定是造成位移的原因吗？

1. 不一定。被标出的是发生移动的元素，它可能只是受影响的那个。比如顶部图片原来没有高度，加载后把下面标题推走，工具记录标题在动，真正该修的是图片占位，不是给标题随便加固定定位。

2. 对照位移发生前后的画面和 DOM 变化，查新增内容、字体、容器高度、样式切换。先找到谁改变了可用空间，再决定预留尺寸或调整插入位置。只把被移动的元素强行钉住，可能叠在一起。

3. 修好后按同样的慢加载或异步条件再走一遍，确认后续内容位置稳定。不同文本长度、不同视口也要测。一个固定高度在本机刚好合适，换设备可能裁内容，或再次引发位移。

## 追问：用户点击展开内容，产生位移一定算 CLS 吗？

1. 不一定。指标对符合规则的、跟近期用户输入相关的位移有排除机制。点击后马上展开，跟没操作时突然插入广告，不是一回事。这个排除有条件和时间范围，点击之后发生的变化不都计为零。

2. 尤其是点击后等很久才返回的数据，或跟当前操作无关的模块变化，仍要单独看。滚动也不能简单当成允许任意位移的输入。无限列表加载时，当前阅读位置和可点击目标还是要保护。

3. 变化是否符合用户预期，先判断，再看测量结果。某次移动没计入 CLS，用户却点错按钮或丢了阅读位置，体验仍有问题。为了指标规则忽略真实交互上的不稳定，不划算。
