# ref 和 reactive 有什么区别？

## 核心回答

1. `ref` 原始值、对象都能包，靠 `value` 这个容器属性参与响应式。`reactive` 主要用于对象、数组、集合，返回代理。普通 `ref` 保存对象时，内部通常还是走深层响应式转换。不能说 `ref` 只有一层、`reactive` 才支持深层。浅层版本另有对应 API。JS 里原始值按值传递，本身没法劫持，所以要挂在对象的 `value` 上，读写时收集依赖、触发更新。`.value` 是实现需要，不是怪写法。

2. 脚本里用 `ref` 通常要读写 `.value`，`reactive` 直接访问代理属性。模板在适用场景会自动解包 `ref`，不是所有嵌套都一样。响应式数组或集合里的 `ref`，不会按普通对象属性那套规则自动解包。

3. 经常整份替换的结果或表单，用 `ref` 更顺，换 `value` 以后外面还连着同一个容器。`reactive` 适合一组围着稳定对象操作的字段。局部变量重新指向新对象，已经拿着旧代理的消费者不会自动跟上，更新方式要规划。

4. `reactive` 的原始值属性直接解构可能断开，继续对象访问，或用 `toRef`、`toRefs`。`ref` 也有引用问题：先把 `value` 取出来长期存着，整体替换后局部还可能是旧对象。关键是分清读的是容器、代理，还是当时那个普通值。

5. 按数据结构和怎么改来选，不必整个项目只准一种。简单数字、异步列表用 `ref` 很直接；一组稳定表单字段用 `reactive` 也清楚。第三方实例可以考虑 `shallowRef`，先明确哪些变化该触发界面，工具选法和实际更新方式别拧着。

## 追问：reactive 对象需要整体加载新数据，应该怎么办？

1. 对象身份要保持，就把新数据写进原代理对应属性，常见是合并字段。合并不会自动删掉新数据里没有的旧字段。表单重置、接口结构变了，这些残留要不要清，得说清楚。

2. 业务本来就是不断替换完整结果，改用 `ref` 保存对象更直接，消费者通过同一容器读当前 `value`。只把 `reactive` 那个变量重新赋值，以前传给子函数或注入后代的旧代理，不会一起换成新的。

3. 接口字段变少、切换记录、嵌套对象整份替换，都要测，别留下上一条记录的数据。保持身份还是整份替换，看消费者怎么用、草稿要不要留，不看哪个赋值表达式更短。

## 追问：模板里什么时候还需要显式使用 value？

1. 顶层渲染上下文里的 `ref` 通常会解包，常见模板直接写 `count`。`ref` 放在数组、Map 或某些嵌套访问里，顶层规则不能无条件推广。表达式读到的是 `ref` 对象还是已经解包的值，要看路径。

2. `reactive` 数组里存 `ref`，按下标取出来的项仍可能要访问 `.value`。对象属性的自动解包又是另一套规则。“模板里一律不用 `.value`” 这句口诀会失效，得看数据结构和访问路径。

3. 返回接口尽量好用，比如 composable 返回明确的顶层 `ref`，少搞复杂嵌套容器。显示异常先查类型和层级，别在模板里加减 `.value` 试到能显示为止。后面改结构也更好懂。
