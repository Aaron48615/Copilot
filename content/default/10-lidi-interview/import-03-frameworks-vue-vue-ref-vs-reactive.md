# ref 和 reactive 有什么区别？

## 核心回答

1. ref 可以保存原始值和对象，通过 value 这个容器属性参与响应式；reactive 主要用于对象、数组和集合，返回代理对象。普通 ref 保存对象时通常也会转换成响应式对象，因此不能简单说 ref 只有一层、reactive 才支持深层变化，浅层版本另有对应 API。

2. 在脚本中使用 ref 通常要读写 value，reactive 则直接访问代理属性。模板会在适用场景自动解包 ref，但不是所有嵌套结构都完全一样，例如响应式数组或集合中的 ref 不会按普通对象属性的规则自动解包，回答时要保留这个边界。

3. 需要经常整体替换的结果或表单，我通常倾向 ref，替换 value 后外部仍连接到同一容器。reactive 适合一组围绕稳定对象操作的字段；直接把局部变量重新指向新对象，不会让已经持有旧代理的消费者自动跟随，更新方式需要规划。

4. reactive 原始值属性直接解构可能失去连接，可以继续对象访问或使用 toRef、toRefs。ref 也不是没有引用问题，若先把 value 取出来长期保存，整体替换后局部引用仍可能是旧对象，所以关键是理解读取的是容器、代理还是当时的普通值。

5. 我会按数据结构和修改方式选择，不追求整个项目只允许一种写法。简单数字和异步列表用 ref 很直接，一组稳定表单字段用 reactive 也清楚；第三方实例可考虑 shallowRef，使用前明确哪些变化应该触发界面，避免工具选择和实际更新方式互相矛盾。

## 追问：reactive 对象需要整体加载新数据，应该怎么办？

1. 如果对象身份需要保持，可以把新数据写入原代理的对应属性，常见形式是合并字段。但合并不会自动删除新数据中没有的旧字段，所以表单重置或接口结构变化时，要明确是否需要清除这些残留内容。

2. 如果业务本来就是不断替换完整结果，改用 ref 保存对象通常更直接，消费者通过同一容器读取当前 value。不能只把 reactive 变量重新赋值，然后假设以前传给子函数或注入后代的旧代理引用也一起替换。

3. 我会测试接口字段减少、切换记录和嵌套对象替换，确认没有保留上一条记录的数据。选择保持身份还是整体替换，取决于消费者如何使用以及草稿是否需保留，而不是单纯哪个赋值表达式更短。

## 追问：模板里什么时候还需要显式使用 value？

1. 顶层渲染上下文中的 ref 通常会解包，所以常见模板直接写 count。若 ref 放在数组、Map 或某些嵌套访问结构里，就不能把顶层规则无条件推广，具体表达式要看读到的是 ref 对象还是已解包的值。

2. 例如 reactive 数组里保存 ref，按索引取出的项仍可能需要访问 value。对象属性的自动解包又有不同规则，这些细节容易让“所有模板都不用 value”的口诀失效，实际应确认数据结构和访问路径。

3. 我会尽量设计易于使用的返回接口，例如 composable 返回明确的顶层 ref，减少复杂嵌套容器。遇到显示异常时先检查类型和层级，不靠在模板里随意增删 value 试到能显示为止，这样后续修改结构也更容易理解。
