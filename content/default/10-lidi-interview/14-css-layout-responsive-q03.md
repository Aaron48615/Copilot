# `position` 有哪些常见值？

## 核心回答

1. `static` 是默认定位，元素按正常布局排列，top、left 这类偏移不会让它移动。大部分正文和普通组件不需要主动设置 position，先让 Flex、Grid 或普通文档流完成排列，结构通常更容易理解。

2. `relative` 会保留原来的布局位置，再从那里偏移，所以旁边元素不会自动填补它移动后的空白。它常用于给角标提供定位参照；`absolute` 则脱离普通文档流，通常寻找最近的定位祖先，某些 transform 等属性也能建立包含块。

3. `fixed` 适合页面悬浮按钮或固定操作栏，通常相对视口定位，也不会为自己保留正常流空间。但祖先如果有非 none 的 transform 等属性，参照可能改成该祖先，因此组件内部的 fixed 不一定等于全屏固定。

4. `sticky` 保留正常布局位置，并在滚动到指定偏移后受到粘性约束，适合局部标题和表头。它受最近滚动容器和包含块边界限制，要设置相关轴上的 top 等阈值，也要有足够的移动空间；不能把它简单理解成滚动后永久变成 fixed。

5. 定位也不能代替内容的阅读顺序。比如把提交按钮绝对定位到表单顶部，键盘访问时仍可能在全部字段之后才到达它；我会尽量让文档顺序和用户看到的结构一致，再用定位完成必要的装饰或覆盖。

## 追问：绝对定位子元素为什么不能撑开父元素？

1. 因为 absolute 已经退出普通文档流，父元素按正常流内容计算高度时，不会把它当成普通子项。比如卡片里只剩一张绝对定位图片，父元素又没有高度或内边距，高度就可能接近零。

2. 我会先判断图片是否本来就应该参与排版。如果它是卡片主体，就恢复普通布局；如果是覆盖在封面上的图标，则让封面本身或 `aspect-ratio` 提供高度，图标只负责覆盖，职责更清楚。

3. 不建议为了撑高父容器，随便补一个与当前图片高度相同的固定值。图片比例、文案和断点一变就容易失配，可以由正常流内容、比例容器或明确的组件尺寸规则提供可靠的空间。

## 追问：固定底部按钮挡住正文怎么处理？

1. 固定按钮不会自动推开正文，所以需要为正文预留操作栏占用的空间。这个空间应包含按钮区域、上下内边距以及设备底部安全区，否则最后一段文字或最后一个输入框仍可能被遮住。

2. 如果按钮区域高度会因为文案换行而变化，我会优先考虑用页面 Flex 布局，把滚动区域和底栏分开。确实需要覆盖式 fixed 时，再让内容预留空间与底栏实际高度保持一致，避免维护两套写死数字。

3. 还需要测试软键盘、横屏和文字放大。视口高度变化时，固定栏可能压缩编辑空间；可以根据交互需要暂时调整底栏显示方式，但不能只在桌面模拟器里看到位置正确就认为完成了适配。
