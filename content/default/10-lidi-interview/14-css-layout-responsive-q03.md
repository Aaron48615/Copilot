# `position` 有哪些常见值？

## 核心回答

1. `static` 是默认定位，元素按正常布局排，`top`、`left` 这类偏移不会让它动。大部分正文和普通组件不必主动设 `position`。先让 Flex、Grid 或普通文档流把排列做完，结构通常更好懂。

2. `relative` 会留下原来的布局位置，再从那里偏移，旁边元素不会自动填它挪走后的空白。常用来给角标提供定位参照。`absolute` 则脱离普通文档流，通常找最近的定位祖先，某些 `transform` 等属性也能建立包含块。

3. `fixed` 适合页面悬浮按钮或固定操作栏，通常相对视口定位，也不会给自己留正常流空间。但祖先如果有非 `none` 的 `transform` 等属性，参照可能改成那个祖先。组件内部的 `fixed` 不一定等于全屏固定。

4. `sticky` 保留正常布局位置，滚动到指定偏移后受到粘性约束，适合局部标题和表头。它受最近滚动容器和包含块边界限制，还要设相关轴上的 `top` 等阈值，也得有足够的移动空间。别把它理解成滚过去就永远变成 `fixed`。

5. 定位也不能代替内容的阅读顺序。比如把提交按钮绝对定位到表单顶部，键盘访问时仍可能在全部字段之后才到它。文档顺序和用户看到的结构尽量一致，再用定位做必要的装饰或覆盖。

## 追问：绝对定位子元素为什么不能撑开父元素？

1. 因为 `absolute` 已经退出普通文档流。父元素按正常流内容算高度时，不会把它当成普通子项。比如卡片里只剩一张绝对定位图片，父元素又没有高度或内边距，高度就可能接近零。

2. 先判断图片是不是本来就该参与排版。它是卡片主体，就恢复普通布局；它是盖在封面上的图标，就让封面本身或 `aspect-ratio` 提供高度，图标只负责覆盖，职责更清楚。

3. 别为了撑高父容器，随便补一个跟当前图片高度相同的固定值。图片比例、文案、断点一变就容易对不上。可以由正常流内容、比例容器或明确的组件尺寸规则提供可靠空间。

## 追问：固定底部按钮挡住正文怎么处理？

1. 固定按钮不会自动把正文推开，所以正文要预留操作栏占用的空间。这个空间应包含按钮区域、上下内边距，以及设备底部安全区。不然最后一段文字或最后一个输入框仍可能被挡住。

2. 按钮区域高度会因为文案换行而变，优先考虑页面 Flex 布局，把滚动区域和底栏分开。确实需要覆盖式 `fixed` 时，再让内容预留空间和底栏实际高度对上，别维护两套写死数字。

3. 软键盘、横屏、文字放大都要测。视口高度一变，固定栏可能把编辑空间压得很小。可以根据交互需要暂时调整底栏显示方式。桌面模拟器位置对了，不等于适配完成。
