# script setup 是干什么的？

## 核心回答

1. script setup 是 Vue 单文件组件中使用组合式 API 的编译期语法，它把顶层逻辑组织为组件的 setup，减少显式 return 和组件注册等代码。顶层变量、函数及导入的组件能直接用于模板，但组件实例仍各自建立状态，不是把所有内容变成模块单例。

2. defineProps、defineEmits 等是编译器宏，用来声明输入和事件，不需要按普通运行时函数引入。它们的参数有编译和提升规则，不能随意读取稍后才创建的局部状态；TypeScript 声明提供类型帮助，也不能替代所有运行时业务校验。

3. 组件默认不把全部内部绑定公开给父级实例 ref，需要通过 defineExpose 暴露必要能力。比如只公开 focus 和 reset，避免父级直接控制内部所有状态；模板可访问内部变量与父组件能访问组件实例，是两个不同范围。

4. 版本能力要分清，defineOptions 可用于声明选项，defineModel 在 Vue 3.4 起简化模型通信，Vue 3.5 支持特定 props 解构的响应式编译处理。不能把最新示例直接套到旧编译环境，普通 reactive 解构也不会因为使用 script setup 自动变成持续引用。

5. 我会把它理解为更直接的组件组织方式，并保持状态、派生值和外部同步的职责。编译器还能够利用模板与 setup 的关系优化生成代码，但不能仅凭改用语法糖就宣称页面明显加速；实际收益仍看组件内容、构建结果和相同操作下的测量。

## 追问：script setup 顶层代码是每次 render 都执行吗？

1. 通常不是，它对应组件实例的 setup 执行，在创建实例时建立状态和监听，之后响应式依赖驱动相应渲染。不能把它与 React 函数组件每次渲染重新执行整个函数的模型混同，普通局部变量和闭包的理解也应跟随各自机制。

2. 导入和模块级代码则按模块执行语义处理，不会因为每个实例都重新导入一次。若要共享常量可以在合适的模块范围定义，但用户草稿应在实例范围创建，避免两个组件实例意外使用同一份可变对象。

3. 我会通过同时创建两个组件、更新其中一个和重新挂载来理解范围。渲染更新不应重复建立同一份外部监听，实例重建却需要自己的资源，清理也必须与实例对应，不能仅因为代码写在顶层就忽略生命周期。

## 追问：defineProps 写了类型，为什么接口数据还需要校验？

1. TypeScript 主要在开发编译阶段检查已知类型，运行时接口返回可能不符合声明。声明商品价格是 number，不会把服务器意外返回的字符串自动变成合法数值，也不能保证字段范围、权限和业务关系正确。

2. Vue 可以从部分类型声明生成运行时 props 信息，但它不是完整的接口数据验证系统，复杂类型转换也有编译限制。数据进入应用时仍应按业务检查必需字段和可接受值，错误情况给出合理反馈，避免模板直接访问缺失层级崩溃。

3. 我会把类型提示、组件接口检查和业务校验分别理解。前者减少写代码时的错误，后两者处理运行时边界；测试可以传入缺失或异常数据，确认组件能按约定降级，而不是只因为编辑器没有红线就断言数据可靠。
