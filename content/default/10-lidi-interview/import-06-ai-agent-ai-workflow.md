# 你平时如何使用 AI 和 Agent 开发？

## 核心回答

1. 目标自己先明确，再让 AI 读相关代码、提出修改范围。普通问答适合解释概念。能读文件、改代码、执行命令的 Agent 可以帮忙往前推，但当前项目的约束还是要自己给。只说「把功能做好」不够。

2. 拿轻购智能导购来说，前端要提交选购需求、接收推荐商品和匹配信息，现有接口封装也一并提供。服务端怎么解析、怎么筛，按真实约定来。别让工具看见一个页面名称，就自己假设后端功能已经有了。

3. 实现时一次做一个能检查的小范围。比如先接通请求和基本状态，再核对结果展示。读差异时容易判断每笔修改的目的，工具顺手改公共代码、加依赖、偏离原需求，也能及时发现。

4. 改完先看关键逻辑，再按实际改动选检查和操作场景。导购要看成功、无商品、接口失败、条件放宽提示是不是分开的。异步入口还要看旧结果会不会盖住新结果。页面第一次出现卡片，不算全部完成。

5. 最后整理实际改了什么、验到什么、还剩什么问题，再决定接受哪些。没跑的测试不写成通过，没确认的后端行为不写成个人成果。AI 提高执行效率，需求判断、代码理解、结果确认还是自己的。

## 追问：Agent 可以连续执行命令，为什么还要限定任务范围？

1. 连续执行提高的是操作能力，不等于它自动知道哪些改动符合项目目标。一个页面问题可能只需要改状态判断。范围没写清，工具可能重装依赖、改公共配置，本来很小的任务变得很难审。

2. 允许改哪些文件、现有代码规范、该跑哪些检查，都说清楚，每条命令干什么也盯着。读文件、跑测试、发布服务，影响面不一样。允许了前两种，推不出后面的远程变更也授权了。

3. 发现它开始处理无关问题，就拉回当前目标，先检查已有差异再继续。不是每一步都重新讨论，是让最终结果的范围能讲清楚。多人协作时，尤其别覆盖别人正在改的文件。

## 追问：AI 连续修了几轮仍然报错，你会怎么调整？

1. 停下来，别继续叠补丁。把最短复现步骤和当前实际错误重新记一遍，确认还是不是最初那个问题。连续修改可能把现象改了，一直沿用第一轮的猜测，新错误也会被当成旧原因。

2. 每轮差异和错误变化对一下，把问题缩到最小函数或最少配置，再提一个能验证的假设。比如怀疑响应顺序，就把请求编号和返回顺序记清楚。别再让工具笼统地「优化异步逻辑」。

3. 跟当前任务无关的修改，逐项核对归属再处理，别用清空工作区省事。最后还是确认不了原因，就留着复现证据、说明卡在哪。比不断换依赖、直到偶然不报错，更方便接着定位。
