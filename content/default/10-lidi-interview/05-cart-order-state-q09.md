# 我的订单页面的分页和状态切换是怎么做的？

## 核心回答

1. 我的订单有待付款、待发货、待收货和已完成四个 Tab，当前映射后端状态为 1、2、3、5。每个分类分别维护页码、列表、loading 和 finished，不能用一个共享数组承接所有状态，否则切换后容易混入上一类订单。

2. 加载时调用 getMyOrderInfo，每页十条，第一页替换、后续页追加。需要明确请求对应的状态与页码，不能响应回来才读取当前 Tab，因为用户可能已经切换，此时旧请求仍属于原分类。

3. 空数组、达到总页数或约定下最后一页不足十条时设 finished，停止继续触发加载。这里要依赖后端分页契约，不能所有接口都一律用少于十条判结束；加载失败也不能被误判为没有更多数据。

4. 当前切换会重置目标 Tab 并重新加载第一页，操作付款或确认收货成功后也刷新当前分类，让状态以服务端为准。订单可能因动作离开当前分类，所以只在前端改一段状态文字并不够。

5. 如果继续完善，我会处理失败后的页码回退、同页重复请求和切换乱序。当前先增加页码的流程，失败后若继续加会跳页；这些需要专门验证，不能因为 Vant List 提供 loading 和 finished 就认为分页边界已经全部完成。

## 追问：第二页加载失败，下一次应该请求第几页？

1. 应重试第二页，而不是直接跳第三页。页码表示已成功加载的位置与正在请求的位置时容易混淆，当前先加页码再请求的写法，要在失败时回退，或者改成成功后才确认已加载页码。

2. 列表已有第一页时可以保留，不要因为翻页错误把用户已经看到的订单全部清空。错误提示应出现在加载更多区域，并允许重试同页，同时防止重复点击启动两个第二页请求导致重复追加。

3. 验证第一页成功、第二页失败再成功，检查 ID 不重复且没有缺页。finished 只根据成功响应与分页规则决定，网络失败不能设成 true，否则用户会被误告知没有更多订单。

## 追问：付款后订单从待付款消失，其他 Tab 要不要刷新？

1. 当前会刷新操作所在 Tab，待付款订单消失是合理的，因为服务端状态已经改变。但其他 Tab 如果保留旧缓存，可能暂时看不到迁入的订单，所以需要明确切换时重新拉取或标记相关分类失效。

2. 当前切换目标 Tab 会重置加载第一页，这能让用户进入新分类时重新读取。不能为了即时感只把同一对象直接搬到另一个数组，因为后端可能还返回新的金额、时间或配送状态，前端对象未必完整。

3. 如果继续做更细缓存，我会让操作成功后标记受影响分类需要刷新，而不强制立即请求所有列表。验证支付与确认收货两种动作，检查原分类移除、目标分类出现以及重复返回时不会看到相互矛盾的记录。
