# `computed` 和 `watch` 的区别？

## 核心回答

1. `computed` 适合从已有响应式状态算出一个值。比如按商品价格和数量算购物车合计。它按响应式依赖缓存，依赖没变，重复读可以复用结果，不用再另存一份总价自己去同步。

2. 计算属性的 getter 保持纯粹，主要负责算出并返回值，别在里面发请求、改别的状态、操作 DOM。`Date.now()` 本身不是响应式依赖，单独塞进计算属性，时间也不会自己一直刷新。

3. `watch` 适合指定数据变了再做副作用，比如查询条件变了去拉列表，或同步第三方地图实例。默认创建时不会立刻跑回调，初始化就要跑可以设 `immediate`。这和计算属性按读取求值，用途不一样。

4. 监听对象属性时传 getter，比如 `watch(() => state.keyword, callback)`，别把当下那个字符串值传进去。大对象开深度监听要谨慎，嵌套遍历有成本，原地改的时候新旧值可能还指向同一个对象。

5. 异步监听要清旧请求，或核对请求序号，别让旧结果盖住新结果。需要在所属组件 DOM 更新后再读尺寸，可以用 `flush: 'post'`。普通默认回调发生在该组件 DOM 更新前，别假定任何 watcher 都已经看到最新 DOM。

## 追问：watch 和 watchEffect 应该怎么选？

1. `watch` 把监听源和回调分开，适合明确规定「只有商品 ID 变了才重新请求」。回调里读到的其他响应式值，不会自动都加进监听源。某个辅助字段变了，就不会意外再打一次请求。

2. `watchEffect` 会马上执行，并自动追踪同步执行期间读到的响应式依赖，适合依赖关系简单的副作用。回调如果是异步函数，通常只有第一次 `await` 之前访问到的依赖会被收集，后面读的值别指望自动被监听。

3. 看依赖要不要显式控制，别看哪个写得短。算展示值仍优先 `computed`，别拿 `watchEffect` 当计算属性用。不然又多维护一份状态，数据从哪来更不好追。

## 追问：监听搜索词发请求时，旧请求应该怎样清理？

1. 每次回调新建一个 `AbortController`，把 `signal` 交给请求，再注册清理函数取消这次请求。清理要在发起异步等待之前安排好，别等搜索词已经变了，旧请求才迟迟登记取消逻辑。

2. Vue 3 的 `watch` 回调第三个参数提供 `onCleanup`。Vue 3.5 起还可以用 `onWatcherCleanup`，但它必须在同步执行阶段调用，不能放到 `await` 后面。按项目版本选 API，别假定所有 Vue 3 项目都有新方法。

3. 主动取消通常不用显示成网络故障。loading 和结果更新也要保护，只让有效请求改它们。不能可靠取消的异步操作，用失效标记或递增序号过滤结果。取消和结果校验是相关但不一样的两件事。
