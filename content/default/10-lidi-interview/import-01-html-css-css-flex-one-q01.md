# flex: 1 为什么有时也没能等宽？

## 核心回答

1. `flex: 1` 不等于无条件等宽，它只是让项目按同一套弹性参数去分空间。浏览器通常当成 `1 1 0%`。容器尺寸明确、其他约束也差不多时，容易看起来等分。但最终盒子还受最小尺寸、最大尺寸、内边距和边框影响。

2. 最常见是内容最小宽度。一个子项里有断不开的 URL，默认自动最小尺寸可能让它不愿意再缩小，另一项就被挤得更窄。横向布局通常给真正需要缩小的那一层设 `min-width: 0`，文本再选换行还是省略。

3. 其次是两项装饰尺寸不同。一项左右 padding 更大，即使基础分配看起来一样，最终边框盒也未必等宽。外层尺寸约束尽量统一，不同的内部留白交给子层。都写了 `flex: 1`，别的参与宽度计算的属性照样算数。

4. 还有 `0%` 和零长度的边界：主轴尺寸不确定时，百分比 basis 不一定按预期变成零。排查先确认容器方向和可用尺寸，再看各项的计算样式。约束找清楚，再决定补 `min-width`、调结构，还是换成 Grid 等分。

5. 等宽也要说清比的是内容区，还是带边框的整体。按钮背景看起来宽度不同，可能来自外层留白，不是弹性比例。直接量各层盒子，把视觉装饰和实际列宽分开，再决定要不要统一包装层。

## 追问：为什么 min-width: 0 加在文本上还是没用？

1. 真正限制收缩的可能是外面那层 Flex 子项。比如右侧区域里面又套了一层文本容器，只有内部段落允许变窄，外层仍按默认最小内容宽度参与分配，整个右侧还是撑着父级。

2. 从发生溢出的节点往上查每一级，找到直接参与 Flex 的子项，嵌套的其他 Flex 层是不是也有最小尺寸限制。只给需要收缩的层设约束，别全局把所有元素最小宽度都打成零，别的布局会受影响。

3. 随后再处理文本怎么呈现，比如单行省略，或者允许长字符串换行。`min-width` 只允许盒子变窄，不会自动让内容变得可读。配套处理不到位，外框等宽了，里面的字仍可能越界，或者被无声裁掉。

## 追问：严格三等分时用 Grid 是否更简单？

1. 要求是三列轨道严格等分，Grid 的 `repeat(3, minmax(0, 1fr))` 通常写得更直接。零最小值允许轨道在内容很长时仍按可用空间分，不会让固有最小宽度把某一列撑开。

2. 轨道等宽仍不代表内部内容自动合适。长标题、固定宽图片、不同 padding 还得处理。间隙交给 `gap`，内边距尽量统一在卡片内部，别再叠三列百分比宽度加外边距，把容器撑超。

3. 整体布局决定方案：工具栏需要按内容伸缩，留 Flex；规则卡片矩阵，考虑 Grid。改用 Grid 以后还要验窄屏列数、阅读顺序和长文案，别为了修一个样例就把整个组件模型换掉。
