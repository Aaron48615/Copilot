# 取消能解决旧响应覆盖吗？

## 核心回答

1. 取消请求解决不了旧结果盖住新结果。取消只是通知异步操作停下来，已经完成的事情撤不回去。比如先搜手机再搜电脑，手机那次可能已经跑完，或者结果已经进了后续处理，这时还得判断它是不是当前这次查询。

2. 每轮查询给一个递增序号，发请求时记下本轮编号，准备写页面时跟最新编号比。对得上才写入列表。错误提示和加载状态也要过这一关，不然旧请求收尾时，仍可能把新请求的加载动画提前关掉。

3. 新查询开始时可以先取消上一轮，少传一点没用的数据和正文处理，然后再建新的控制器。序号管的是结果能不能交上去，取消管的是别再白跑。后面要是还要异步转换数据，转完也得再对一次当前轮次。

4. 用轮次比对关键词更稳。用户可能先搜手机、再搜电脑、最后又搜手机，第一轮那个「手机」结果不一定还有效。核对时要覆盖：旧响应晚到、旧请求失败、连续重复查询，分别看列表、错误和加载状态。

## 追问：旧请求的 finally 为什么也会影响新页面？

1. 第一轮还没结束，第二轮已经把加载设成 true，接着第一轮因为取消走进收尾。要是它无条件把加载关掉，第二轮明明还在等，页面却已经允许再点，问题出在列表之外。

2. 收尾也要带着请求编号，只有编号对得上才改共享的页面状态。旧请求自己的监听器和临时资源照样该放掉，局部清理不该因为过期就跳过，不然可能留下没用的引用。

3. 核对时让两轮完成顺序反过来：旧请求先收尾，新请求继续没完成。这时还该显示加载，等新请求真正结束再关，并且旧轮的错误不能再弹出新的错误提示。

## 追问：分页加载也能直接丢弃所有旧请求吗？

1. 分页要先分清查询条件和页码，较早发出的请求不一定都作废。同一筛选下第一页和第二页并行拉，两次结果可能都要，只是回来的先后不一样。

2. 并行分页的话，整组查询共用一个版本，结果按页码分别存，展示时再按页码拼。筛选条件变了，旧版本才整体失效。这样第二页先回来，也不会盖住第一页，或者把记录顺序打乱。

3. 普通的加载更多，也可以先限制一次只拉一页，逻辑更好对。重复点击、相同记录去重、是不是最后一页，这些还得自己管。取消只负责停掉没用的请求，分页规则不会跟着自动修好。
