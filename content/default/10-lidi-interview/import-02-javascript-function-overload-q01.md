# 回调参数为什么有时不能少写？

## 核心回答

1. 先分清少写形参和少传实参。回调省略不用的形参通常允许。数组遍历会传入元素和索引，只声明元素参数也能用，不必为了接收后忽略索引再多写一个变量。

2. 少传实参是调用函数时没提供它要求的数据。函数声明需要姓名和年龄，直接只传姓名可能报错。接口承诺会传几个值，和回调作者愿意接收几个值，是两个方向的约束，结论不能混用。

3. 参数类型过窄又是另一件事。事件接口可能传鼠标事件或键盘事件，回调却只会读鼠标坐标。回调数量完全没变，碰到键盘事件也可能出问题。严格函数类型检查会限制这类不安全赋值。

4. 可选参数表示调用方有权省略该实参，不是表示回调可以不用它。索引每次都会传入，就不应仅为了允许作者省略形参，把索引声明成可选。真用索引的代码反而要处理「可能不存在」。

5. 报错时先看发生在调用处还是赋值处，再核对参数数量、类型范围、可选性。严格函数类型检查对方法声明还有兼容性例外。某个方法碰巧编译过了，证明不了窄参数一定安全。

## 追问：遍历回调的索引参数，为什么不该为了方便省略而写成可选？

1. 遍历接口内部始终用元素和数字索引调用回调，类型应当把这个事实写清楚。使用者只关心元素时，本来就可以只声明第一个形参，不必把第二个参数改成可能缺失。

2. 索引一旦声明成可选，接口就允许实现只传元素，接收方看到的索引也可能是 `undefined`。开了严格空值检查，直接做数字运算会受限。麻烦来自调用约定写错了，不是检查太严。

3. 对照调用回调的实际代码决定可不可选，再分别检查只用元素、同时使用索引这两种调用方式。某些分支确实不传索引，就保留可选并解释业务含义。别为了消提示强行保证它存在。

## 追问：只接受鼠标事件的函数，为什么不能处理任意事件的回调位置？

1. 回调位置声明能收到任意事件，意味着注册方有权传入键盘事件等其他事件。只接受鼠标事件的函数可能直接访问坐标字段，它对输入要求更高，履行不了这个位置原本承诺的处理范围。

2. 严格函数类型检查适用的函数赋值场景里，把参数范围缩窄的这种替换会被拒绝。反过来，能处理一般事件的函数，用在只接收鼠标事件的位置，通常没这个风险，因为实际输入没有超出它的能力。

3. 业务确实只注册点击处理，让事件名称和回调参数类型对上，别用断言绕过检查。来源保证不了事件类别，就在回调里先判断再读专属字段，运行时边界也补上。
