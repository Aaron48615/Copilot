# Map、Set、WeakMap 和 WeakSet 怎么选？

## 核心回答

1. 选型先看需求是保存对应关系，还是只关心某个值有没有出现。Map 保存键和值，适合按商品编号找到商品。Set 只保存成员，适合记录已选编号或给原始值去重。两者都能查数量，也都能按插入顺序遍历。

2. Map 的键可以是任意类型，数字和同内容字符串不会混成一个键。Map 和 Set 对对象按引用身份区分，两个字段一样的新对象仍是不同成员。业务要按编号判重，得自己抽出编号，不能直接把对象丢进集合。

3. WeakMap 与 WeakSet 更适合让附加信息跟着键或成员的生命周期走。比如给节点保存元数据，或标记是否处理过。当前规范允许对象和未注册 Symbol；字符串、数字，以及通过全局注册表得到的 Symbol，不满足这种弱持有要求。

4. 弱集合不提供完整遍历和数量查询，也不会仅因为集合里的弱关系就拦住对应对象被回收。适合按已知对象去访问信息，不适合展示所有条目、持久保存编号或定期扫描过期数据。选它就要接受这些能力限制。

5. 弱集合也不是内存泄漏的通用修复。别的数组或闭包还握着对象，它就仍然活着。需要容量上限、过期时间和能看见的统计，用普通 Map 再显式删除。业务清理和垃圾回收各管各的部分。

## 追问：Set 去重时 NaN 和正负零怎样处理？

1. Set 用的相等规则，会把多个 `NaN` 当成同一个成员，也把正零和负零当成同一个成员。这和直接用严格相等比较 `NaN` 的结果不一样，不能完全拿 `==` 或 `===` 的记忆来解释集合去重。

2. 数字 `1` 和字符串 `"1"` 仍然不同，对象仍看引用。表单收到的编号有时是数字、有时是字符串，直接建 Set 可能留两项。要不要先转类型，得由编号规则决定，尤其别把有意义的前导零丢掉。

3. 用特殊数字、混合类型编号、两个相同字段对象分别举例核对。这样能分清语言层面的相等规则和业务层面的重复概念。别为了消掉一个重复展示，就给所有输入做不可逆的字符串或数字转换。

## 追问：节点移出页面后 WeakSet 标记会马上消失吗？

1. 不会保证马上消失。移出页面只是断开了一部分连接。数组还保存着这个节点，或后续回调还要用它，它就仍然可达，WeakSet 的标记也能继续通过这个已知节点查询。移除不等于销毁对象。

2. 就算外部引用全没了，回收发生的具体时间也由运行时决定。业务不能靠等固定毫秒数判断标记清没清。弱集合本身不能遍历，也不适合承担「统计当前页面节点数量」这种看得见的状态管理。

3. 需求是节点离开页面立刻取消处理资格，就在对应生命周期里明确调用删除，并清掉相关订阅。弱持有只负责不让集合额外保活对象，业务资格何时失效还得代码自己写清楚。同一个节点再插回来，行为也就明确。
