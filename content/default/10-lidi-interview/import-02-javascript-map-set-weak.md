# Map、Set、WeakMap 和 WeakSet 怎么选？

## 核心回答

1. 我会先看需求是保存对应关系，还是只关心某个值是否出现。Map 保存键和值，适合按商品编号找到商品；Set 只保存成员，适合记录已选编号或给原始值去重，两者都能查询数量并按插入顺序遍历。

2. Map 的键可以是任意类型，数字和同内容字符串不会混成一个键。Map 和 Set 对对象按引用身份区分，因此两个字段一样的新对象仍是不同成员；如果业务要按编号判重，需要自己提取编号，而不是直接把对象丢进集合。

3. WeakMap 与 WeakSet 更适合让附加信息跟随键或成员的生命周期，例如假设给节点保存元数据或标记是否处理过。当前规范允许对象和未注册 Symbol，字符串、数字以及通过全局注册表得到的 Symbol 不满足这种弱持有要求。

4. 弱集合不提供完整遍历和数量查询，也不会仅因集合中的弱关系阻止对应对象被回收。这个特性适合按已知对象访问的信息，却不适合需要展示所有条目、持久保存编号或定期扫描过期数据的业务，选择时要接受能力上的限制。

5. 我也不会把弱集合看成内存泄漏的通用修复。如果其他数组或闭包仍保存对象，它就仍然存活；需要容量上限、过期时间和可观察统计的缓存，我会选择普通 Map 加显式删除，让业务清理和垃圾回收各自负责合适的部分。

## 追问：Set 去重时 NaN 和正负零怎样处理？

1. Set 使用的相等规则会把多个 `NaN` 视为同一个成员，也把正零和负零视为同一个成员。这一点与直接用严格相等比较 `NaN` 的结果不同，因此不能完全用双等号或三等号的记忆来解释集合去重。

2. 数字一与字符串一仍然不同，对象则仍看引用。假设表单收到的编号有时是数字、有时是字符串，直接创建 Set 可能保留两项；要不要先转换类型必须由编号规则决定，尤其要避免把有意义的前导零丢掉。

3. 我会用特殊数字、混合类型编号和两个相同字段对象分别举例验证。这样能区分语言层面的相等规则和业务层面的重复概念，避免为了消除一个重复展示问题，就给所有输入做不可逆的字符串或数字转换。

## 追问：节点移出页面后 WeakSet 标记会马上消失吗？

1. 不会保证马上消失，移出页面只是断开了一部分连接。假设一个数组仍保存这个节点，或者后续回调还要使用它，它就仍然可达，WeakSet 的标记也可以继续通过这个已知节点查询，移除操作不等于销毁对象。

2. 即使外部引用全部消失，回收发生的具体时间也由运行时决定。业务不能靠等待固定毫秒数判断标记是否清除，而且弱集合本身不能遍历，所以它不适合承担“统计当前页面节点数量”这样的可观察状态管理。

3. 如果需求是节点离开页面立即取消处理资格，我会在对应生命周期明确调用删除，并清理相关订阅。弱持有只负责避免集合额外保活对象，业务资格何时失效仍然应由代码表达，这样重新插入同一个节点时也有明确行为。
