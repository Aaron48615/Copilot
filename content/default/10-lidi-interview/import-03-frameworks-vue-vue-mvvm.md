# MVVM 和 MVC 有什么区别？

## 核心回答

1. MVC 和 MVVM 都在谈界面和数据怎么分工，各框架实现不一样。MVC 里 Model 是数据和业务，View 负责展示，Controller 协调输入和处理。Controller 不一定直接操作所有 DOM，这种模式也不等于天生难维护，关键是责任怎么划。

2. MVVM 多了一层 ViewModel，提供视图要用的状态和行为，靠绑定让视图和状态连上。开发者更多描述“当前数据该显示成什么样”，不必每个事件里分别找到文本、按钮、错误区域逐个改。常规交互的数据关系更清楚。

3. Vue 的响应式系统和模板渲染就是这套数据驱动。不必把每个 Vue 概念硬塞进经典 MVVM 的一个框。组件状态变了，依赖它的展示跟着更新；模板里的事件调用明确的处理逻辑。Vue 官方也说过它没有完全遵循 MVVM，核心思想一致，这么答就够。

4. 表单双向绑定也不是所有数据任意两边改。`v-model` 把传值和输入事件回写拼在一起，组件 props 仍是父级传入、子级报告变化。子组件直接改共享对象，变化从哪来就不清楚，本来想要的可理解数据流反而没了。

5. 拿搜索页说：状态里存输入和请求结果，模板展示列表和加载提示，事件或监听触发查询。请求失败、竞态还是业务逻辑自己处理，框架不会因为数据驱动就自动搞定。架构模式帮划分责任，替不了缓存、权限、错误恢复这些具体设计。

## 追问：数据驱动之后，还需要理解 DOM 吗？

1. 需要。框架最后还是在浏览器里展示，聚焦、布局、滚动、原生事件都有具体 DOM 行为。日常少了手动更新，不代表可以忽略节点什么时候存在、元素语义、浏览器怎么算尺寸。

2. 显示优先用模板绑定。真需要 DOM 能力，通过 `ref` 和合适的生命周期访问。打开弹窗后聚焦输入框，得等节点挂上。改 `state` 不会自动把焦点管理和键盘体验全做完。

3. 第三方图表、编辑器也要划清操作边界：Vue 管容器和配置，库管自己的内部节点。两边都改同一块会互相盖。理解 DOM，反而能在声明式界面里更安全地接外部能力。

## 追问：双向绑定会不会让数据变化来源难以追踪？

1. 简单输入的双向绑定通常清楚，对应一个值和一个更新事件。难追的是多层组件共享同一份可变对象、好多监听互相写回，或者输入和已保存数据不分。那种来源才会糊。

2. 状态只让一个人拥有，子组件用明确事件报告修改，复杂编辑走草稿加提交。模板上写的是 `v-model`，也能讲清底层谁传值、谁发事件。语法简写不等于取消组件边界。

3. 字段之间互相派生，优先用 `computed` 或一次更新规则，别建两个 `watch` 互相赋值。能不能追，看数据归属和转换清不清，不是简单禁用所有双向绑定就能得到。工具用对了，一样能透明。
