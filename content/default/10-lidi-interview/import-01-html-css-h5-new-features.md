# HTML5 有哪些新特性？

## 核心回答

1. 结构上多了 `header`、`nav`、`main`、`article`、`section`、`aside`、`footer`。比如一个站点：顶栏用 `header`，导航用 `nav`，中间正文用 `main`，一篇文章用 `article`，旁边再用 `aside`。这些标签不会自动变好看，样式还是自己写 CSS。主要是看起来清楚，读屏也更好认。布局的盒子继续用 `div` 就行，没必要每个框都套成 `article`。文档声明也简单了，开头写 `<!DOCTYPE html>` 就行。

2. 媒体有 `audio`、`video`，不用再塞 Flash。加上 `controls` 就能出播放按钮。不同浏览器能播的格式不一样，一般要准备几个 `source`，比如 mp4 和 webm。字幕可以用 `track`；加载失败、播不了，还得自己做提示。`canvas` 是一块画布，用脚本画图，图表、签名、简单动画都能做。但画上去的字和按钮不是真元素，读屏摸不到，也不能 Tab 过去，表单和导航还是用普通 HTML。

3. 表单多了 `email`、`date`、`number`、`search`、`file`，还有 `required`、`placeholder`、`min`、`max`。手机上会好用很多：`date` 能直接弹出日期，`email` 键盘上会有 `@`。浏览器也能先拦一层，邮箱里没有 `@`、必填项空着，会提你。但它不管这个邮箱是不是公司内部的、有没有被注册过，`type="email"` 只是看长得像不像邮箱。这种还得自己查，服务端再验一遍。`pattern` 也能写规则，别写太死，把本来能用的地址拒了。

4. 本地存储有 `localStorage` 和 `sessionStorage`。前者关浏览器还在，后者关标签页就没了。都只能存字符串，对象要先 `JSON.stringify`，大概几 MB，别当数据库用。页面脚本能读到，密码和登录态别随手放。`Worker` 是另开一个后台去算，比如解析很大的 JSON、处理图片，算完再把结果传回来，页面滚动不会跟着卡。

5. 另外还有拖拽和 `history.pushState`。文件可以拖进页面上传；`pushState` 能改地址栏，但不会整页刷新，单页应用切页面常用。WebSocket 适合聊天、推送这种一直连着的；定位能拿经纬度，但要用户同意。这两样也常被叫 HTML5，其实不是新标签，是浏览器另给的接口。

## 追问：用了 input type="email"，还需要自己校验吗？

1. 还需要。浏览器只能拦长得不像邮箱的，比如没有 `@`。是不是公司内部邮箱、有没有被注册过、能不能收到信，它都不知道，还得自己查、服务端再验。

2. 前端可以提前提示填错了，但别写太死的正则，把本来能用的地址拒掉。最终以服务端返回为准，错误要贴到对应输入框上。浏览器这一层是早点发现格式问题，不是安全的唯一关卡。

3. 如果自己做错误样式，别跟浏览器自带的气泡叠两套互相打架的提示。空着、格式不对、服务端拒绝，每种失败都要告诉用户下一步怎么改。

## 追问：Canvas 和普通 HTML 内容应该怎样分工？

1. `canvas` 适合自己画图，比如图表、签名、小动画。画上去的字和按钮不是真元素，读屏摸不到，也不能 Tab 过去。表单、导航、主要按钮还是用普通 HTML。

2. 比如图表：图用 `canvas` 画，标题、图例、筛选按钮放在外面。用户不用靠看懂像素才能操作，键盘也能点到真按钮。

3. 不是一有图形就上 `canvas`。能缩放的简单图可以考虑 SVG，普通卡片用 HTML 和 CSS 就行。先看图形要干什么，再选做法。
