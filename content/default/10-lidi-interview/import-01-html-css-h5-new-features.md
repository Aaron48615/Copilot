# HTML5 有哪些新特性？

## 核心回答

1. 我会按页面结构、媒体、表单和相关平台能力来回答，同时说明大家口中的 HTML5 经常泛指一批现代 Web 技术。现在 HTML 持续演进，WebSocket、地理定位等又有各自规范，所以不能把同一时期流行的 API 都当成 HTML 标签本身的新语法。

2. 结构上，header、nav、main、article 等标签帮助表达页面区域和内容关系。它们不是为了自带更漂亮的样式，而是让代码、浏览器和辅助技术更容易理解内容；普通布局容器仍然可以用 div，不需要把每个盒子强行包装成文章或章节。

3. 媒体和绘图方面，audio、video 提供原生媒体元素，canvas 可以通过脚本绘制图形。表单则有 email、date 等类型以及 required 等约束，能帮助输入和基础校验，但不能替代服务端校验；视频也仍需要考虑字幕、格式与播放策略。

4. 相关平台能力还包括 Web Storage、Worker 等，可以分别处理本地状态和独立计算。我会挑能说明实际用途的部分展开，而不声称自己都做过；querySelector 属于 DOM API，JSON 方法属于 JavaScript 标准，框架和绘图库则是另一层，回答时要分清来源。

5. 例如要播放教学视频，原生视频元素可以承担播放，但字幕、加载失败提示和用户可操作的控件仍需要安排。介绍新能力时把这些边界一起讲出来，才能说明知道如何使用它，而不是只记得浏览器多了一个标签。

## 追问：用了 input type="email"，还需要自己校验吗？

1. 浏览器能提供基本的格式约束和适合的输入体验，但它不理解所有业务要求。比如邮箱必须属于某个组织、是否已被注册或是否真正可用，都不能仅靠 type=email 判断，需要应用和服务端进一步处理。

2. 前端可以补充清晰的输入提示和错误反馈，但不要随意写一个过窄的正则拒绝合法地址。提交时以服务端规则为准，并把返回错误关联到字段；浏览器校验是帮助用户尽早发现问题，不是安全和业务约束的唯一入口。

3. 如果使用自定义错误界面，还要保持键盘与辅助技术体验，避免既弹浏览器气泡又出现另一套相互矛盾的提示。测试时覆盖空值、格式问题和服务端拒绝，确保每一种失败都告诉用户下一步怎么做。

## 追问：Canvas 和普通 HTML 内容应该怎样分工？

1. Canvas 适合大量自定义图形和像素绘制，例如绘图区域或某些动态图形，但里面画出的文字和按钮不会自动成为普通语义节点。表单、导航和主要操作仍适合 HTML，让浏览器处理布局、焦点和可访问性。

2. 比如一个图表可以用 Canvas 画图形，同时在外部保留标题、图例、筛选按钮和必要的数据说明。这样用户不必依赖看懂像素才能理解结果，键盘也能操作真实控件，不需要在画布里手动模拟完整界面。

3. 是否使用 Canvas 还要看数量、交互和性能，不是图形一出现就必须选它。简单可缩放图形可以考虑 SVG，普通卡片直接用 HTML 和 CSS；先明确图形需求，再选实现方式，比为了展示技术栈复杂化页面更合理。
