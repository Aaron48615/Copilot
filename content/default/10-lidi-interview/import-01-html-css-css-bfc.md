# BFC 是什么？有什么用？

## 核心回答

1. BFC 是块级格式化上下文，可以理解成一块按特定规则独立安排块盒子和浮动的区域。它不是某个单独属性，也不是“清浮动”的同义词；理解它主要是为了说明浮动、自动高度和外边距折叠为什么出现不同结果。

2. 比如普通父元素里只有浮动图片时，自动高度可能没有把图片包含进去。给父元素设置 `display: flow-root`，让它建立 BFC，自动高度就能包含内部浮动。这样背景和边框可以包住图片，不必为了撑高再写一份固定高度。

3. BFC 还能隔开内部子元素与外部的外边距折叠，并避免自己的边框盒与同一外部环境中的浮动重叠。但两个普通兄弟块各自建立 BFC，它们自己的相邻外边距仍可能折叠，不能把“形成 BFC”背成“所有 margin 都不会合并”。

4. 浮动、绝对定位、inline-block 和部分 overflow 值等也能建立 BFC，但同时会改变其他行为。单纯需要独立块布局时，我倾向 flow-root；用 overflow: hidden 虽然常能达到包含浮动的效果，却可能把下拉框或阴影裁掉，要先看需求再选方式。

5. 比如图文区域旁边需要一个不与浮动图片重叠的独立块，也可以利用这个布局边界，但可用宽度不足时仍需要检查排列结果。它解决的是特定格式化关系，不会替我们做响应式断点，也不能隔离脚本或任意样式污染。

## 追问：父元素和第一个子元素的 margin 为什么会一起往下跑？

1. 普通块布局中，如果父元素顶部没有边框、内边距或其他阻隔，首个子元素的顶部外边距可能与父元素折叠。视觉上像子元素没有在父元素里面留空，而是把整个父元素从上面的内容旁边推开了。

2. 如果需求是父容器内部留白，我会直接使用 padding，这个含义最清楚。如果确实需要隔开内部与外部的折叠，可以给父元素建立 BFC；不要为了阻止折叠偷偷加一条透明边框，却不解释它存在的原因。

3. 排查时用不同背景区分父子范围，再查看盒模型数值，就能看出间距发生在哪里。还要检查尾部外边距和空块，因为折叠不只发生在相邻兄弟之间，不能看到 margin 数值正确就认为布局一定正确。

## 追问：为什么清浮动更倾向 flow-root 而不是 overflow: hidden？

1. flow-root 直接表达“这里建立独立块布局区域”，不额外要求裁剪内容。对包含浮动图片的正文卡片来说，父容器需要包住图片，但超出边界的装饰或提示层未必应该被隐藏，这两个需求应分开。

2. overflow: hidden 除了建立 BFC，还涉及裁剪和滚动容器行为，可能影响 sticky 后代的参照。为了修复卡片高度而顺便破坏吸顶标题，会让问题转移到另一处，排查成本比一开始选择明确属性更高。

3. 当然，如果这个区域本来就要求裁掉超出内容，hidden 也有合理用途。我会根据组件职责选择，并验证浮动高度、阴影、菜单和滚动行为，而不是把某个写法当成任何情况下都正确的口诀。
