# Vue 的响应式原理是什么？

## 核心回答

1. Vue 响应式的共同思路是让数据访问与使用它的逻辑建立关系，数据变化后通知相应更新。组件渲染读取某个字段时收集依赖，修改后触发依赖处理；并不是每次修改都遍历整个页面检查所有节点，也不是所有普通局部变量都会自动被监听。

2. Vue 2 主要通过 Object.defineProperty 转换已有属性，在 getter 中收集依赖，在 setter 中通知更新。它可以继续转换通过正确入口加入的属性，但无法自动发现普通方式新增或删除的字段，因此需要 Vue.set、Vue.delete 或替换已响应式属性承载的新对象。

3. Vue 2 数组还通过增强常见变更方法处理通知，例如 push 和 splice；直接按下标赋值或修改 length 有检测限制。实际写法应按这些限制更新，而不是看到数据对象已经变了就认为视图一定同步，nextTick 也不能补一次没有触发的通知。

4. Vue 3 对象主要使用 Proxy，可以拦截新增、删除和数组索引等操作，嵌套对象在访问时进行相应响应式处理。ref 用 value 容器支持原始值，代理仍有使用边界：修改原始对象、解构原始值或重新绑定局部变量，都可能绕开预期连接。

5. 通知后视图通常进入批量更新队列，连续同步修改可以合并处理。需要读更新后的 DOM 才等待 nextTick，数据计算用 computed，外部动作按需 watch；排查时先确认版本、数据是否被正确跟踪和使用，再判断刷新时机，避免强制更新掩盖数据流问题。

## 追问：Vue 2 为什么 push 能更新，而 arr[0] 赋值不行？

1. Vue 2 无法像 Proxy 一样统一拦截数组任意索引写入，所以对常用数组变更方法做了增强。调用 push 或 splice 时，除了原有数组操作，还能观察加入的数据并通知依赖，普通下标赋值没有经过这条处理路径。

2. 更新某个位置可以用 Vue.set 或 splice，调整长度也可以通过相应变更方法表达。不是 JavaScript 不允许下标赋值，而是赋值之后 Vue 2 无法按这种实现自动通知，数据改变与响应式通知需要区分。

3. 我会通过实际组件操作验证结果，不在测试或业务里随意 forceUpdate。强制刷新可能让当前文本正确，却没有解决后续同类修改的检测问题，其他依赖仍可能保持旧结果，正确更新入口比补刷新更可靠。

## 追问：Vue 3 有 Proxy 后，是不是所有响应式问题都消失了？

1. 没有，Proxy 扩大了可拦截操作范围，但仍要求使用代理和保持引用连接。把 reactive 中的数字解构成局部变量，它不会继续读取代理；直接修改创建代理前的 raw 对象，也可能绕过通知，界面不更新仍有原因。

2. shallowRef 和 markRaw 还会有意减少转换和跟踪范围，适合大数据或外部实例，但调用方要遵守替换或手动通知约定。不能一边选择浅响应式，一边期待所有内部字段像普通 reactive 一样自动更新。

3. 异步请求、状态重复和错误清理也不是代理能解决的问题。两个响应先后覆盖同一列表，哪怕每次赋值都成功触发视图，最后显示仍可能是旧查询结果，所以响应式正确不等于完整业务流程已经正确。
