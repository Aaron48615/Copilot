# position 有哪些值？分别什么场景用？

## 核心回答

1. `position` 常用值有 `static`、`relative`、`absolute`、`fixed` 和 `sticky`，从还参不参与正常布局、参照谁来分。`static` 是默认，`top` 这类偏移不起作用。正文和普通布局保持默认就行，不必每个元素先设一遍定位。

2. `relative` 仍占着原来的位置，偏移只改显示位置，常用作角标的定位参照。`absolute` 退出普通文档流，不给自己留坑，通常相对最近的定位祖先。但 `transform` 等属性也能建包含块，「只找最近非 static 祖先」是常见情况，不是完整规则。

3. `fixed` 也退出正常流，没有特殊祖先影响时相对视口，适合悬浮入口、固定工具栏。它不会自动给正文腾地方。祖先上非 `none` 的 `transform` 可能改它的包含块。「固定按钮跟着卡片走」时先查祖先，别只改 `z-index`。

4. `sticky` 在正常位置上再受滚动偏移约束，适合目录和表头。得有 `top` 等相关方向的阈值，还受滚动容器和包含块边界限制。先问这是内容内部吸顶还是全页面固定，再看要不要占位。本来 CSS 能做的，不必用复杂监听去模拟。

5. 常见组合是封面图保持正常布局，右上角角标绝对定位：封面负责撑开卡片，角标只负责盖上去。比起把图片和所有文字都绝对定位，内容一变要手维护的坐标更少，职责也更清楚。

## 追问：relative 位移和 margin 调整有什么区别？

1. `relative` 的偏移不改原来的正常布局占位，旁边元素仍按它没移动时的位置排。按钮向右偏了，左边可能留下原位置的空，右边则可能盖住邻居，整行不会重新分空间。

2. `margin` 参与盒子之间的布局关系，调它通常会影响相邻内容的位置。具体表现还受布局模型和外边距折叠影响，别把 `margin` 当成另一种 `top`、`left`，二者阶段和需求都不同。

3. 图标轻微视觉校正，可以考虑相对定位或变换；元素之间要保持距离，用 `gap`、`margin` 或 `padding`。分清视觉移动和布局留白，响应式一变，就不容易堆出一堆说不清的偏移值。

## 追问：绝对定位四边都写 0 会发生什么？

1. 常见非替换元素、宽高为 `auto` 时，左右偏移一起约束可用宽度，上下约束高度，所以 `inset: 0` 常用来让遮罩盖住包含块。前提是包含块已经建对，别以为它一定盖住父元素的内容区。

2. 又指定了固定宽高，约束就不再是单纯拉伸，浏览器要按定位规则消化多余约束。已知尺寸配合自动外边距可以居中，但得理解具体方向和可用空间，别把所有属性叠上去指望自动排到想要的位置。

3. 元素面板里看包含块边界、内边距和最终尺寸，内容溢不溢出也要测。覆盖层适合这种写法。正文容器通常别靠四边定位撑满，否则父级高度和滚动空间得额外维护，布局会脆。
