# 简历里写了很多技术，你真正能讲到什么程度？

## 核心回答

1. 我会按实际使用范围解释技术掌握程度，而不是把简历里的关键词都说成精通。轻购中 Vue 3、TypeScript、Vue Router、Axios、Vant 和移动端页面是我能结合业务讲的部分，框架底层原理则要具体到问题再说明。

2. 对一个页面，我能从进入路由开始，讲清接口参数、加载状态、结果展示和失败提示。比如登录后的返回地址怎样保存、请求拦截器在哪一步带 Token，都应能沿着代码解释，而不是只记住“使用路由守卫”这句话。

3. 对交互复杂的功能，我能继续说为什么这样处理以及有哪些限制。搜索的防抖、取消与请求编号分别处理频率和过期结果；购物车按商品标记更新状态能限制重复操作，但不能替代后端对数量与库存的校验。

4. AI 相关部分，我能讲搜索联想、商品卖点和导购结果的前端处理。`/guide/recommend` 背后的意图解析与推荐算法不属于这个前端实现，前端展示匹配依据也不代表我掌握了服务端完整计算过程。

5. 我会用具体函数、输入样例和修改理由支持自己的回答，并区分已验证的行为与改进计划。能独立完成常见业务，不等于深入掌握所有库的源码；如果某项技术只试过示例，我会调整简历措辞，避免让面试官产生错误预期。

## 追问：你说熟练使用 Vue，面试官可以追问到哪里？

1. 我可以先从项目中的状态变化讲起，例如一个请求开始后哪个状态变成加载中，返回后哪些数据触发页面更新。这个层面需要把用户操作和组件代码对应起来，不能只解释响应式这个名词。

2. 再往下可以讨论状态放在组件内还是共享位置、重复逻辑是否值得提取，以及组件离开后的异步结果怎么处理。我会结合现有代码回答取舍，如果某处没有处理完善，就指出具体遗漏而不是补写经历。

3. 如果继续问编译器或依赖收集源码，我会说明自己了解的范围，并区分原理解释和实际读过的实现。能够解释常用功能是业务熟练的证据，但不能因此声称自己可以完整重写 Vue 的生产实现。

## 追问：同一个技术在多个项目里出现，怎么避免重复介绍？

1. 我会按它在各项目里解决的具体问题来讲，而不是三个项目都重复“用了 Vue 和 TypeScript”。能确认的场景才展开，我能从轻购的具体实现展开，就优先用它说明状态、接口和路由之间的关系。

2. 比较城市视图和智服工单时，我会挑具体页面来讲。前者重点可以放在数据如何进入图表、图表什么时候更新，后者可以放在工单状态怎样决定可用操作。这样面试官能听出同一种状态管理思路在不同业务里解决了什么问题。

3. 一个技术如果在多个项目里用法确实相近，我会简要说明复用的经验，把时间留给有区别的难点。没有必要硬凑三种高级用法，能够清楚说明适用边界，比每个项目都堆满技术名词更有说服力。
