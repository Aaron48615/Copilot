# 你如何使用 Codex、Claude Code 和 Cursor？如何保证代码是自己理解的？

## 核心回答

1. Codex、Claude Code、Cursor 用来辅助读代码、拆需求、改局部逻辑。不靠工具名字判断方案靠不靠谱。动手前先写清：这个页面要完成什么、相关文件有哪些、什么结果算对，再决定给工具多大范围。

2. 比如轻购的 AI 导购，前端怎么调 `/guide/recommend`，`intent`、商品列表、匹配信息怎么进页面，这些能顺着代码讲。后端怎么解析需求、给商品排序，得对着后端实现才能确认，接好接口不等于自己写了算法。

3. 理解一段代码，就顺着一次操作看：输入从哪来、异步请求怎么发、状态怎么更新、失败从哪出去。搜索联想里，防抖是少发请求，取消是停掉还支持取消的那次，请求编号是拦住过期结果，三件事解决的问题不一样。

4. 接受 AI 的修改前先读差异，再用具体输入对行为。连续输两个关键词，慢回来的旧结果会不会盖住新的；接口失败之后，加载状态能不能结束。第一次打开有内容，不够。

5. 碰到 Token、金额、用户输入，数据从哪来、权限边界在哪，都要单独看。前端按钮限制不等于服务端鉴权，构建成功也不等于业务对。接口拒绝、页面提示、失败后状态能不能恢复，分开查。比如按钮不能连点，还要看服务端认不认得出重复提交。

## 追问：AI 解释得很清楚，但你仍看不懂代码怎么办？

1. 缩到一个函数，自己写出一组输入和预期结果，再逐行看变量怎么变。某个字段到底来自接口还是本地状态都说不清，就先追来源，先别往上加功能。

2. 陌生 API 去查对应版本的官方说明，再做一个只覆盖这个行为的小例子。比如请求取消之后实际进哪个异常分支，用跑出来的结果去对它的解释，别把模型写的字当成运行证据。

3. 再自己改一个相关条件，改之前先说出哪些地方会受影响。离开 AI 就讲不清为什么这么改，就继续拆，或者换成自己能讲清的实现。把注释背下来不算理解了。

## 追问：怎样避免把敏感信息一起交给 AI？

1. 给它解决问题真正需要的上下文就行，通常是接口结构、脱敏样例、错误出在哪。真实 Token、用户地址、完整请求日志没必要一起扔进去。排查失败原因，不等于要把原始数据全传上去。

2. 问题跟认证有关，就留状态码、请求顺序、字段名，凭据换成明确的占位。这样还是能聊拦截器怎么走，生成的示例和提交差异里也不会带上能用的密钥。

3. 能执行命令的 Agent，还要看当前目录、允许改的范围、操作权限。碰到远程发布、改数据，先看具体要干什么、影响面有多大。同一轮里已经允许读代码，不代表后面每条命令都合理。
