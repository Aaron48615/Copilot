# 迭代器、可迭代对象和生成器有什么关系？

## 核心回答

1. 迭代器就是带 `next()` 的对象。每次调用返回一个结果，里面通常有 `value` 和 `done`：`value` 是这一轮拿到的值，`done` 是还没结束还是已经走完。消费者就靠这两样判断这一轮是什么、整段还要不要继续。

2. 可迭代对象则提供 `Symbol.iterator`。调用它能得到迭代器。数组、字符串能直接 `for...of`，就是因为有这个入口。一个普通对象就算字段很多，也不会因此自动能按顺序取值。

3. 生成器函数用 `function*` 声明。调用时先返回生成器对象，函数体不会马上跑到底。第一次 `next()` 才开始执行，遇到 `yield` 产出数据并暂停，再 `next()` 从暂停处继续，所以局部变量和进度能自然留下来。

4. 生成器对象同时满足可迭代和迭代器协议，它的迭代入口返回自身。所以循环可以直接消费它，但同一个对象通常是一次性的：消费完再遍历不会重放，要重新调用生成器函数才有新的执行过程。

5. 需要逐个产生编号或遍历树节点时，生成器能让消费者按需取值，不必预先构造全部结果。但它本身不会把同步计算丢到后台，每次取值仍可能卡住页面。数据很少、还要反复随机访问时，直接用数组更清楚。

## 追问：只有 next 方法的对象能直接用于 for...of 吗？

1. 不一定。`for...of` 先找可迭代入口，不会因为对象有 `next` 就直接用。手写对象就算每次返回结果都对，缺 `Symbol.iterator` 时，还是不能直接丢进这种循环。

2. 一种做法是让这个方法返回对象自身，这就得到同时可迭代的迭代器。适合单次流式读取，但两个循环共享的是同一份游标：前一个消费多少，后一个就从剩下的位置继续，不能当成两个独立列表。

3. 希望每轮遍历从头开始，入口就该创建新的迭代器，各自保存当前位置。比如一个范围对象，要分别测重复遍历和嵌套遍历，确认两次取值不会互相抢进度。只测第一次能输出数字不够。

## 追问：yield 的值和 next 传入的值有什么区别？

1. `yield` 后面的表达式是生成器向外给出的值，会出现在这次 `next()` 返回结果的 `value` 里。下一次 `next` 传入的参数，是外部向暂停处送回去的值。方向相反，不能按普通函数传参来理解。

2. 比如内部写 `const answer = yield question`，第一次取值让外部拿到问题。下一次传入回答，才会成为内部变量的值。第一次调用的参数没有前一个暂停表达式可以接，所以不会直接变成函数体里的输入。

3. 这种双向通信适合分步骤协作，但调用方会更依赖执行顺序。业务只是分页读取时，用清楚的参数和异步接口更直接。真要保留多步暂停状态再用这种交互，简单流程别写成难追踪的来回传值。
