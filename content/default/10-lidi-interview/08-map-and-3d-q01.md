# 地图组件卸载时需要做什么？

## 核心回答

1. 地图卸载要清理组件创建的外部资源，不只是让容器从 React 页面消失。城市视图在 ref 里保存地图、marker、AQI 圆圈和信息窗，这些对象有自己的事件与 DOM 或渲染资源，框架卸载不会替所有 SDK 自动完成处理。

2. 先停止自己创建的定时任务，移除地图和覆盖物事件，关闭信息窗并清理覆盖物集合。事件解绑需要使用正确的事件名与处理函数引用，重新写一个相同内容的匿名函数，并不一定能移除原来注册的监听。

3. 再调用高德地图的 destroy 释放实例，并把相应 ref 清空。具体 API 以使用版本的官方文档为准，不能把 ECharts 的 dispose 方法名直接套到地图；每种第三方实例都应使用自身生命周期约定。

4. 还要处理未结束的脚本加载与数据请求。如果用户离开时 SDK 尚未加载完成，回调之后不能再向已移除容器创建地图；请求可取消时取消，无法取消时用失效标记或版本检查忽略结果。

5. 清理应只影响自己拥有的资源，共享的 SDK 脚本或其他页面地图不能随意删除。如果继续验证，我会重复进入退出并检查实例、事件与旧请求行为，不把一次页面关闭后看不到地图当作资源都已释放的证明。

## 追问：SDK 脚本是多个页面共用的，卸载时要删吗？

1. 一般不能因为某个地图组件卸载就删除共享脚本，其他组件可能正在使用它。脚本加载与单张地图实例的生命周期不同，应该明确谁管理共享加载状态，谁只负责创建和销毁自己的地图。

2. 可以复用一个加载 Promise，让多个调用等待同一次脚本加载，但每个组件仍需检查完成时自己是否有效。即使共享脚本最终成功，已经离开的组件也不应继续创建实例，取消使用不等于必须取消共享加载。

3. 验证两个页面或组件先后进入、其中一个提前退出，检查剩余地图仍可工作。共享资源需要统一所有权，不能为了避免泄漏就把所有全局对象都清掉，造成另一个正常使用者突然失败。

## 追问：destroy 后还要把 ref 设为 null 吗？

1. destroy 负责 SDK 内部释放，ref 置空则表达组件已经没有可用实例。否则后续代码看到 ref 仍非空，可能继续调用已销毁对象的方法，尤其迟到的接口回调只检查“有没有对象”时容易出错。

2. 清空引用也能减少组件长期保留旧对象的机会，但它本身不替代 destroy。只设 null 会失去调用清理的入口，实例内部监听或其他引用仍可能存在，所以顺序通常是先清理外部对象，再移除自身引用。

3. 我会让清理可以重复执行，并在异步返回处检查对应生命周期版本。测试离开后迟到响应、立即重新进入和开发环境重复挂载，确认旧回调不会操作新地图，也不会因为空引用引发异常。
