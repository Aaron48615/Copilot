# canvas 和 svg 有什么区别？

## 核心回答

1. Canvas 是一块绘图表面，普通二维用法里用脚本把像素画上去。SVG 用图形元素描述形状，每个图形可以进 DOM，也能走样式和事件。SVG 的矢量形状适合缩放；Canvas 则要处理画布像素尺寸和显示尺寸对不上的问题。

2. 选型看图形数量、更新频率和交互方式。大量点位、画面刷得很勤，可以考虑 Canvas；数量适中、需要单独选中和编辑的流程节点，可以考虑 SVG。不存在到了某个固定节点数 SVG 就必然卡的界线。

3. 事件上，SVG 可以直接给图形绑监听。Canvas 通常只有整块画布接收事件，得点的坐标对照图形模型做命中检测。Canvas 也不必每次整块重画，可以缓存静态背景或局部更新，只是这些管理更多由代码或图形库来做。

4. 以 ECharts 为例，默认的 Canvas 渲染器已经包了很多交互细节，也提供 SVG 选项。按实际数据量、缩放和导出要求去比，别把默认设置当成性能结论。无障碍文字和键盘操作也要单独考虑。

5. 比如可编辑流程图要选中节点、连线、键盘操作，可以先看 SVG 的节点模型是不是更直接；换成大规模点位动画，再去比 Canvas。性能判断用实际图形复杂度和交互，别给两种技术各贴一个永远快或永远慢的标签。

## 追问：Canvas 在高清屏上模糊，应该怎么处理？

1. CSS 显示大小和画布内部像素大小是两回事。画布显示成一块固定区域时，可以按 `devicePixelRatio` 把内部宽高设大一些，再缩放绘图坐标，让一个逻辑像素用更多设备像素来表示。

2. 改 `canvas.width` 或 `height` 会重置绘图上下文状态，尺寸变了之后要重新设变换和样式，并重新画。反复累加 `scale` 也会出问题，通常先回到一个确定的变换，再按当前比例设置。

3. 像素数上去，内存和绘制成本也会上去，不是分辨率越高越好。窗口缩放或跨屏移动时还要重新看比例。用真实设备看文字和线条清不清晰，再决定很大的画布要不要限制内部尺寸。

## 追问：Canvas 怎样判断点中了哪个图形？

1. 先把指针相对视口的位置转成画布逻辑坐标，画布位置、CSS 缩放、内部像素比例都要算进去。坐标系搞错时，常见现象是按钮看着在这儿，实际可点区域偏到旁边。

2. 再按图形类型做命中检测，矩形看范围，路径可以用 `isPointInPath` 这类能力。多个图形重叠时，按绘制或交互层级拿最上面那个，别总返回数组里第一个匹配项。

3. 图形很多时可以用空间索引缩小候选范围，避免鼠标一动就遍历全部数据。如果用的是 ECharts 这类库，优先走它提供的事件接口，同时留着业务对象标识，别把像素位置当成稳定的数据身份。
