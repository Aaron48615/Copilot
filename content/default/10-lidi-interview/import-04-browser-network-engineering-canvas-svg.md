# canvas 和 svg 有什么区别？

## 核心回答

1. Canvas 提供绘图表面，普通二维使用中我通过脚本画出像素结果；SVG 用图形元素描述形状，每个图形可以参与 DOM、样式和事件系统。SVG 的矢量形状适合缩放，Canvas 则要处理画布像素尺寸和显示尺寸的关系。

2. 选型时我会看图形数量、更新频率和交互方式。大量点位、频繁刷新的画面可以考虑 Canvas，数量适中、需要单独选择和编辑的流程节点可以考虑 SVG；不存在到了某个固定节点数 SVG 就必然卡顿的界线。

3. 事件处理上，SVG 可以直接给图形绑定监听，Canvas 通常只有画布接收事件，需要用坐标和图形模型做命中检测。Canvas 也不必每次整块重画，可以缓存静态背景或局部更新，只是这些管理工作更多由代码或图形库承担。

4. 以 ECharts 为例，默认使用的 Canvas 渲染器已经封装很多交互细节，也提供 SVG 选项。我会根据实际数据量、缩放和导出要求比较，而不是把默认设置当成性能结论；无障碍文字和键盘操作也要单独考虑。

5. 比如可编辑流程图需要选中节点、连接和键盘操作，我会先评估 SVG 的节点模型是否更直接；如果换成大规模点位动画，再比较 Canvas。性能判断应使用实际图形复杂度和交互，而不是给两种技术各贴一个永远快或慢的标签。

## 追问：Canvas 在高清屏上模糊，应该怎么处理？

1. 我会区分 CSS 显示大小和画布内部像素大小。画布显示为一块固定区域时，可以按 devicePixelRatio 设置更大的内部宽高，再缩放绘图坐标，让一个逻辑像素使用更多设备像素表示。

2. 调整 canvas.width 或 height 会重置绘图上下文状态，所以尺寸变化后需要重新设置变换和样式，并重新绘制。反复累加 scale 也会出问题，通常先恢复确定的变换，再按当前比例设置。

3. 像素数增加会提高内存和绘制成本，因此不是分辨率越高越好。窗口缩放或跨屏移动时还要重新检查比例，用真实设备观察文字和线条清晰度，再决定是否为很大的画布限制内部尺寸。

## 追问：Canvas 怎样判断点中了哪个图形？

1. 先把指针相对视口的位置转换成画布逻辑坐标，需要考虑画布位置、CSS 缩放和内部像素比例。坐标系弄错时，常见现象就是按钮看着在这里，实际可点击区域却偏到旁边。

2. 然后按图形类型做命中检测，例如矩形范围判断，路径可以使用 isPointInPath 等能力。多个图形重叠时要按绘制或交互层级选最上面的目标，不能总返回数组中的第一个匹配项。

3. 图形很多时可以使用空间索引缩小候选范围，避免每次鼠标移动都遍历全部数据。若使用 ECharts 等库，就优先调用它提供的事件接口，同时保留业务对象标识，不把像素位置当作稳定的数据身份。
