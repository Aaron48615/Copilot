# 这个项目的前端目录是怎么拆的？

## 核心回答

我主要按职责来拆。`pages` 放业务页面，比如仪表盘、地图、3D、AI、图表管理和系统管理；`components` 放可以复用的组件，比如统一的图表渲染器、路由鉴权和错误边界；`layouts` 放后台整体布局和菜单。

接口统一放在 `api`，按认证、城市数据、仪表盘、图表、数据源和后台管理拆文件。接口对应的数据结构放在 `types`，这样页面不用自己重复声明。全局登录和主题状态放在 `store`，路由集中在 `router`，下载、图表转换、权限判断和请求实例这些公共逻辑放在 `utils`。

这样拆的好处是找代码比较直接：页面展示问题先看 `pages`，接口地址或请求参数看 `api`，数据结构看 `types`，跨页面状态看 `store`。项目规模还不算特别大，所以没有为了分层再引入很重的架构。

## 追问：为什么 API 和类型要分开？

API 文件负责请求路径、方法和参数，类型文件负责说明数据长什么样。分开以后，同一个城市或图表类型可以被多个页面复用，请求函数也不会塞进大量界面代码。修改接口字段时，可以通过类型检查更快找到受影响的位置。

## 追问：所有组件都应该放进 components 吗？

不是。只被某个页面使用的组件可以跟着页面放，像 3D 页里的城市柱和光环就是页面内部组件。真正跨页面复用，或者承担基础能力的组件，再放到公共 `components`，这样不会为了看起来整齐把相关代码拆得太散。
