# 轻购为什么要保存 redirect，登录后为什么用 replace？

## 核心回答

1. redirect 是为了保留登录前的目标。例如用户想进购物车却没有登录，如果守卫只跳登录而不记录原位置，登录成功后就只能回首页，用户还要自己找回刚才的操作，流程会被打断。

2. 当前守卫保存 to.fullPath，包含路径、查询参数和 hash。登录页成功后读取 route.query.redirect，是字符串时作为目标，没有则进首页；完整路径比只保存 pathname 更能保留商品 ID 或页面定位等上下文。

3. 使用 router.replace 是因为登录通常只是中间页面，用它替换当前历史项后，返回时不容易再次落到刚才的登录页。它替换的是当前这一条记录，不会清空整个浏览器历史，也不能保证此前所有登录页都消失。

4. redirect 参数可以被用户修改，字符串类型并不等于目标安全。当前内部生成的是站内路径，如果继续完善，我会限制协议、来源和允许的路由，并排除登录页自身等循环目标；不能只因它最初来自守卫就永远信任。

5. 回到原页面后还需要重新加载业务状态。用户登录期间商品价格、地址或购物车可能变化，保留路径只是继续任务的入口，不是承诺之前的所有数据仍然有效，订单确认不能直接复用过期金额。

## 追问：保存 fullPath 会不会把敏感数据留下来？

1. 路径和 query 本来可能进入浏览器历史、日志或分享链接，如果业务把敏感信息放在 URL，再复制到 redirect 就会扩大保留范围。因此应该只在 URL 保存必要标识和可公开筛选，不把密码、Token 或详细个人资料放进去。

2. 对购物车到确认页的复杂参数，当前项目使用 sessionStorage，而不是把整个对象放到 redirect。两者各自承担任务：一个记住页面位置，一个临时记录购买意图，但它们都不能替代后端权限与参数检查。

3. 如果继续完善，我会检查允许回跳的页面和参数白名单，对不合理目标退回安全首页。验证时包含编码字符、重复 query 和缺失参数，避免看似恢复了路径，实际上把用户带到无法正常工作的页面。

## 追问：用户登录后仍然没有目标页面权限怎么办？

1. 登录只能证明身份，不能保证能访问原目标。例如原来保存的是一个管理员页面，普通用户完成登录后仍不该进入；应重新执行路由与服务端权限判断，而不是因为 redirect 存在就绕开检查。

2. 前端可以显示无权限说明并提供可访问入口，不要再次无条件跳登录，否则会形成“登录成功又登录”的循环。目标不存在或已经失效时也要有合理返回，不能让用户落在空白页里。

3. 如果继续验证，我会覆盖不同角色登录、已删除商品链接以及 redirect 指向登录页的情况。关键是保留意图但重新检查条件，路径恢复不能高于当前身份、资源存在性和页面规则。
