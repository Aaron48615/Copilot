# 请介绍一下你做过的项目，哪个项目最值得展开？

## 核心回答

1. 我目前主要做过三个个人项目。轻购是用 Vue 3 和 TypeScript 做的移动端商城，城市视图是用 React 和 TypeScript 做的城市数据展示平台，智服工单是用 Vue 2 做的售后工单系统。它们分别让我练习了购物流程、数据展示和业务状态处理，其中我最熟悉、也最想展开的是轻购。

2. 轻购围绕一次购物来组织页面。用户从首页或者分类页找商品，进入详情选择规格和数量，再加入购物车或者直接购买，最后选择地址并提交订单。我做这个项目时，重点是把页面之间的数据传递和接口调用接起来，例如用户在详情里选的规格，到了订单确认页不能变成另一种规格。

3. 比较值得展开的是 AI 相关功能。其中“轻购AI”允许用户直接描述预算、用途和偏好，前端请求推荐接口，再把商品和对应的匹配条件展示出来。如果有条件没满足，也会单独展示，用户能知道为什么推荐这个商品，而不是只看到一段听起来很肯定的文字。

4. 另外两处 AI 功能是搜索联想和商品卖点。搜索联想要处理用户连续输入时的请求顺序，商品卖点则要等商品基础信息回来再生成。这两处还保留了本地备用内容，让 AI 请求出问题时，用户仍然能搜索和查看商品。

5. 这些都是个人练习项目，我会把自己完成的前端部分和后端提供的能力分开说。比如推荐算法不是我训练的，支付也不能等同于真实支付平台接入。我能具体展开的是页面如何发请求、结果如何进入状态，以及失败时用户还能怎么操作。

## 追问：为什么最想讲轻购，而不是另外两个项目？

1. 因为轻购里各个页面的联系比较多，我能用一次购物把自己的工作说明白。比如商品详情传的是商品和规格，购物车提交的是选中项，订单确认还要重新获取金额和地址，这些都需要理解业务数据才能接好。

2. AI 功能也给了我一些单纯写静态页面遇不到的问题。例如用户连续输入两次，第二次结果先回来时，第一次结果就不能再覆盖它。我可以把出现问题的过程和处理办法解释清楚，而不只是报出几个技术名词。

3. 另外两个项目我也会按实际做过的部分回答，比如图表的数据更新和工单的状态展示。如果面试官对 React 或 Vue 2 更感兴趣，我会切换到相应项目，不会为了突出轻购把别的项目说成没有价值。

## 追问：如果让你挑一个功能现场讲代码，你会选什么？

1. 我会选搜索联想，因为它的输入、请求和展示过程比较容易看清楚。先从输入框的事件看关键词如何变化，再找到定时器和请求函数，说明为什么不是每输入一个字就立即请求。

2. 然后重点讲两次请求顺序相反的情况。取消旧请求可以减少无用工作，请求编号则用来判断这个结果是否还对应最新输入；更新建议和结束加载时，都要注意不能让过期请求影响新请求。

3. 最后我会补充空输入、请求失败和离开页面这几个分支。这样面试官看到的是一个能解释正常和异常情况的功能。如果代码里还有没有处理好的地方，我会指出现状，再说明准备怎么补，而不把计划说成已经做完。
