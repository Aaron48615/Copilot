# v-model 修饰符怎么传？

## 核心回答

1. 组件 v-model 的修饰符会作为模型相关信息传给子组件，但自定义修饰符的具体含义需要子组件实现。比如 v-model.capitalize 表示调用方希望执行首字母转换，Vue 不会仅凭这个名称猜出业务规则并自动修改文本。

2. Vue 3.4 及之后可以从 defineModel 返回结果中取得模型 ref 和修饰符对象，并通过 get、set 转换模型读写。较早的显式写法中，默认模型使用 modelModifiers，具名模型对应名称加 Modifiers，事件仍按模型名称发送。

3. 例如组件收到 trim 的要求，可以在向父级发出更新前整理首尾空白，但要明确空输入和非字符串如何处理。不要对所有值直接调用字符串方法，也不要在一次输入过程中反复改变格式，导致输入法组合或光标位置异常。

4. 原生表单的内置修饰符与组件自定义协议要分清。原生文本输入的 lazy 使用 change 同步，不是防抖；组件若要延迟提交，需要明确实现什么时候发事件，不能把一个未处理的 lazy 标记当成已有的延迟行为。

5. 我会把转换是否影响父级值写成明确接口，并测试多个具名模型不会混用修饰符。例如标题允许 trim，密码不应擅自裁剪空格；这类选择来自字段含义，不能为所谓统一处理把用户本来有效的输入改掉。

## 追问：具名模型的修饰符为什么不能都从 modelModifiers 读取？

1. 多个模型分别有自己的名称和转换规则，若都读取同一份默认修饰符，就无法区分父级要求处理的是标题还是查询词。显式协议里具名模型使用对应的名称加 Modifiers，事件同样对应各自名称。

2. 使用 defineModel 时，可以分别声明模型并读取各自返回的修饰符信息。比如标题启用 capitalize，备注只保留原样，子组件应在相应模型的写入路径执行转换，而不是在一个全局 input 回调里处理所有字段。

3. 我会构造同一组件同时绑定两个模型的测试，只给其中一个加修饰符，确认另一个值不受影响。这个测试比只测单一默认模型更能发现接口混用，也能防止重构时把转换逻辑误抽成无差别处理。

## 追问：自定义 number 修饰符，为什么要特别处理空字符串？

1. 空输入常表示用户尚未填写，而不是数值零。如果直接用 Number 转换，空字符串会变成零，父级可能据此认为字段已填且有效，用户清空输入后界面也可能马上跳回零，影响正常编辑。

2. 应根据字段协议区分空值、有效数字和无法解析的文本，并在提交时完成需要的校验。金额还涉及小数精度和格式，不能仅因加了 number 名称就保证数据符合业务规则，模型转换与业务校验是两件事。

3. 我会测试清空、负号、小数点等输入过程中的中间状态，以及父级异步回填。转换时机需要兼顾可编辑性，可以保留内部显示字符串再在确认时输出数值，不能为了类型整齐让用户无法顺畅输入。
