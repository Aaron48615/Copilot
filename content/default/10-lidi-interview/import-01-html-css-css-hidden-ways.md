# "visibility: hidden、opacity: 0、display: none 有什么区别？"

## 核心回答

1. 三种都能让内容看不见，布局和交互不一样。`display: none` 让元素和后代不再生成通常的布局盒子，原来的空间收回去，普通指针和键盘也到不了它。DOM 节点还在，不是从文档或内存里删掉了。

2. `visibility: hidden` 通常占着布局空间，但看不见，也不能像可见控件那样拿焦点、被点。后代可以显式改成 `visible` 再露出来，这点和 `display: none` 不同。隐藏内容一般也不当普通内容暴露给辅助技术。

3. `opacity: 0` 只是让整个元素和后代最终透明，空间、命中测试、可聚焦性通常还在。透明按钮仍可能挡住下面的内容，键盘也可能停在看不见的地方。子元素设 `opacity: 1` 抵消不了祖先整组透明，交互状态得一起想。

4. 不占位的收起内容用 `display`；留位置但暂时看不见用 `visibility`；淡入淡出通常用 `opacity`。现代 CSS 已经能在相应条件下给 `display` 这类离散属性做过渡，别再绝对说它不可过渡。兼容性、初始样式、关掉以后焦点落哪，还是要处理。

5. 性能上也不能把三者标成永远只重排或只重绘，开销看变更范围和浏览器实现。先按占位、交互、动画需求选对行为，再拿记录优化，别为一个没测过的性能口诀选错隐藏方式。

## 追问：只加 pointer-events: none 能让透明按钮完全不可操作吗？

1. 不能。它主要影响指针命中，不会自动把元素移出键盘的 Tab 顺序。透明按钮可能鼠标点不到，键盘用户仍会停在上面，甚至触发操作，结果看不见当前焦点，页面状态却变了。

2. 整块区域暂时不该交互，可以按需求用 `inert`、真正隐藏或卸载。单个表单控件不可用，考虑原生 `disabled`。选之前先确认要不要留布局、读屏要不要访问、关掉以后焦点移到哪。

3. 鼠标和键盘都要查，还要看隐藏时焦点已经在内部会怎样。先把焦点转到合理的可见入口，再藏交互区，通常比藏完以后让浏览器自己找落点更清楚，也好测。

## 追问：如何做既能淡出又不会留下隐形遮挡的面板？

1. 视觉过渡和最终隐藏分成明确状态：显示时面板看得见、点得到；关闭时先按需要停掉交互并播透明度变化，结束以后再真正隐藏或卸载。重新打开要能取消旧的关闭过程，快速连点容易把状态搅乱。

2. 用 CSS 离散过渡，检查 `transition-behavior`、起始样式和目标浏览器支不支持。靠结束事件清理，也要处理动画被取消、减少动态效果导致事件路径变了的情况，别把所有清理只押在某一个事件上。

3. 面板原来握着焦点，关闭时把焦点交还合理入口，展开状态也同步改。重点验快速开关、键盘关闭、无动画设置。慢速录屏里淡出好不好看不够，交互残留同样重要。
