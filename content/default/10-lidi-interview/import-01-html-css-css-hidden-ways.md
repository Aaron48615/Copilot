# "visibility: hidden、opacity: 0、display: none 有什么区别？"

## 核心回答

1. 这三种方式都能让内容看不见，但布局和交互不同。display: none 会让元素及其后代不再生成通常的布局盒子，原来的空间被收回，普通指针和键盘交互也无法到达它；DOM 节点仍然存在，不能说元素已经从文档或内存中删除。

2. visibility: hidden 通常保留布局空间，但元素不可见，也不能像可见控件那样接收焦点和点击。后代可以显式改成 visible 恢复可见，这与 display: none 不一样；隐藏内容一般也不作为普通内容暴露给辅助技术。

3. opacity: 0 只是让整个元素及其后代最终透明，空间、命中测试和可聚焦性通常还在。透明按钮仍可能挡住下面的内容，键盘也可能停在看不见的地方；子元素设置 opacity: 1 不能抵消祖先整组透明的结果，要同时考虑交互状态。

4. 选择时，不占位的收起内容适合 display，保留位置但暂不可见可以用 visibility，淡入淡出通常使用 opacity。现代 CSS 已支持在相应条件下为 display 等离散属性安排过渡，不能再绝对说它不可过渡；不过兼容性、初始样式和关闭后的焦点仍需要处理。

5. 从性能角度也不能把三者简单标成永远只重排或只重绘，具体开销取决于变更范围和浏览器实现。我会先按占位、交互和动画需求选对行为，再看记录优化，避免为了一个未经测量的性能口诀选错隐藏方式。

## 追问：只加 pointer-events: none 能让透明按钮完全不可操作吗？

1. 不能，它主要影响指针命中，不会自动把元素移出键盘的 Tab 顺序。透明按钮可能无法被鼠标点到，但键盘用户仍会停在它上面，甚至触发操作，导致看不到当前焦点却能改变页面状态。

2. 如果整个区域暂时不应交互，可以根据需求使用 inert、实际隐藏或卸载；如果只是单个表单控件不可用，可以考虑原生 disabled。选择前先确认是否保留布局、是否需要读屏访问，以及关闭后应该把焦点移到哪里。

3. 我会同时用鼠标和键盘检查，并观察隐藏时若焦点已经在内部会发生什么。先把焦点转移到合理的可见入口，再隐藏交互区，通常比隐藏完以后让浏览器自行决定落点更清楚，也更容易测试。

## 追问：如何做既能淡出又不会留下隐形遮挡的面板？

1. 把视觉过渡和最终隐藏分成明确状态：显示时面板可见可操作，关闭时先按需要停止交互并播放透明度变化，结束后再真正隐藏或卸载。重新打开时要能取消旧的关闭过程，避免快速点击造成状态错乱。

2. 采用 CSS 离散过渡时，要检查 transition-behavior、起始样式和目标浏览器支持；采用结束事件时，也要处理动画被取消或减少动态效果导致事件路径变化的情况，不能把所有清理工作只押在某一个事件上。

3. 如果面板原来持有焦点，关闭时应把焦点交还合理入口，并同步更新展开状态。验证重点是快速开关、键盘关闭和无动画设置下的结果，不能只看慢速录屏里淡出效果是否好看，交互残留同样重要。
