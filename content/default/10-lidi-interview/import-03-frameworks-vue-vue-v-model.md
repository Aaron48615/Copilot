# v-model 的原理是什么？

## 核心回答

1. v-model 的核心是把值绑定和事件回写组合成简写，数据改变驱动展示，用户操作再把新值写回状态。它没有让任意对象自动双向修改，具体读取哪个属性、监听什么事件，要区分原生表单类型与自定义组件协议。

2. 原生文本输入通常围绕 value 与 input 同步，复选框和单选框关注 checked 与 change，选择框也有自己的选项值与 change 行为。Vue 3 并没有把原生 input 全部改成 modelValue，这个名称主要属于自定义组件的默认模型约定。

3. Vue 3 组件默认接收 modelValue，并发出 update:modelValue；Vue 2 组件默认使用 value 和 input，可通过 model 选项自定义。Vue 3 还支持具名模型和多个模型，Vue 3.4 的 defineModel 只是简化声明，底层仍能解释为父传值、子发更新事件。

4. 原生表单的 lazy 改为 change 时同步，trim 处理首尾空白，number 尝试数字转换。lazy 不是防抖，number 不是完整业务校验，空输入和密码空格等应按字段含义处理；输入法组合期间的同步行为也由框架按控件实现照顾，封装时不应随意破坏。

5. 我会让模型代表明确的当前输入，把确认搜索、保存或取消作为独立动作。比如弹窗编辑可以有本地草稿，确认后才通知父级保存，不能因为 v-model 写得方便，就让所有未确认修改直接进入已保存数据；方便的语法仍需要清楚的数据归属和提交规则。

## 追问：复选框的 v-model 为什么可以得到数组？

1. 一个复选框可以表示布尔勾选状态，多选组则可以把多个选项的值收集到同一个数组。框架根据控件和绑定数据约定处理加入、移除，用户勾选的是具体选项值，而不是把输入框的普通文本 value 当成最终布尔状态。

2. 每个选项要有明确且稳定的值，不能用可能重复的显示名称代替真实编号。接口返回的已选值也要与选项类型对应，例如字符串编号与数字编号混用，可能让初始勾选不符合预期，先规范数据比手动改 DOM 更合理。

3. 我会测试勾选、取消、初值回填和选项列表变化，确认提交数据只包含允许选项。前端同步数组不等于服务端认可这些编号，实际提交仍需校验可选范围，不能因为复选框界面限制了选项就信任任意请求内容。

## 追问：v-model 能不能直接用在文件选择框上？

1. 文件选择由浏览器和用户控制，不能像普通文本输入一样通过绑定字符串指定本地文件。通常监听 change，通过事件或 ref 读取 files，保存需要上传的 File 对象，再显示文件名和上传状态。

2. 清空选择和重新选择也要按文件输入的实际接口处理，不能把一个服务端文件地址写进 value 就期望浏览器选中它。已有附件的展示与新文件选择是两类状态，可以分别管理，避免界面看起来有文件却没有真实可上传内容。

3. 文件大小和类型的前端检查能帮助用户尽早发现问题，但服务端仍须验证上传内容。提交时还要处理取消、失败和重复选择同一文件等行为，v-model 的普通文本同步协议不能代替这些文件上传流程。
