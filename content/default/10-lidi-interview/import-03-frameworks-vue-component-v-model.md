# Vue 组件上的 v-model 是怎么工作的？

## 核心回答

1. Vue 组件上的 v-model 是父子通信约定的简写。Vue 3 默认把值作为 modelValue prop 传入，子组件用 update:modelValue 事件报告新值；父组件接到事件后更新自己的状态，再把新值传回来，并不是子组件直接控制父级变量。

2. 比如封装一个搜索输入框，子组件展示收到的模型值，用户输入时发出更新，父组件保存搜索词。子组件还可以有提交搜索的独立事件，用来区分“文字正在变”和“用户确认查询”，避免每次改一个字都被当成业务提交。

3. Vue 3.4 及之后的 defineModel 简化了 prop 和更新事件的声明，得到可读写的模型 ref。需要兼容更早版本时可以显式写 props 和 emits；父子两边仍要约定初值，不能依赖子级默认值自动让未定义的父级状态一致。

4. 具名模型用来表达多个可编辑值，例如 v-model:title 对应 title 与 update:title。修饰符信息也可传入，由子组件按约定处理；Vue 2 组件默认是 value 与 input，也能通过 model 选项调整，不能把不同版本协议混在一起。

5. 原生表单的绑定由控件类型决定，文本框仍使用 DOM 的 value 和相应事件，复选框关注 checked。组件协议中的 modelValue 不是浏览器输入框的新属性；回答原理时先区分原生元素和自定义组件，才能解释文本、勾选和多个模型的实际行为。

## 追问：defineModel 为什么仍然算单向数据流？

1. 它简化的是声明和使用方式，底层仍由父级传值、子级发出更新事件。子组件写模型 ref，会按约定通知父级，而不是获得父级任意变量的直接写入权，组件边界依然可以通过输入和事件来理解。

2. 父组件可以记录更新、执行校验，或者将该模型连接到自己的可写 computed。子级不需要知道父级值存在 ref、路由参数还是某个 store 里，只要遵守模型协议，这种解耦也是封装输入组件的价值。

3. 对象模型的深层修改仍要谨慎，直接修改共享对象字段未必经过完整的模型替换事件。需要明确通知时，应生成新对象或通过专门动作表达，不能因为使用了宏就放弃检查真实的引用和事件行为。

## 追问：组件内部需要防抖，模型值也应该一起延迟吗？

1. 要看父级期望得到的是即时输入还是已确认查询。通常模型表达当前文字，应及时同步；防抖的是请求或查询动作，这样父级显示字数、清空按钮和表单校验都能使用当前值，不必等待延迟结束。

2. 可以单独发出 search 事件，或由父级监听即时模型后安排防抖请求。若组件明确设计成延迟输出模型，则要说明清空、失焦和提交时是否立即同步，不能让调用者误以为 v-model 随时代表屏幕上的内容。

3. 无论延迟放在哪层，都要清理待执行任务并处理请求竞态。用户点击清空后，旧防抖任务不能稍后把查询词重新带回；测试需要覆盖快速输入、立即提交和卸载，才能确认组件协议在边界动作下也成立。
