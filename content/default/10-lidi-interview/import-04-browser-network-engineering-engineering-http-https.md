# HTTP 和 HTTPS 的区别？HTTPS 是怎么保证安全的？

## 核心回答

1. HTTPS 可以理解成用 TLS 保护 HTTP 通信，主要提供传输机密性、完整性，以及对端身份验证。它解决的是路上被窃听、篡改或冒充，不负责判断业务接口允不允许某个用户删某条数据。

2. 建立常见的 HTTPS 连接时，客户端和服务端协商 TLS 版本和算法，服务端出示证书。浏览器检查信任链、域名、有效期这些信息，并验证对端确实拿着相应私钥。看见一张证书，不等于直接相信这台服务器。

3. 现代 TLS 常用临时密钥交换材料协商共享秘密，再派生通信密钥，证书签名用来做身份认证。后面大量数据用对称加密，再加上完整性保护。别把所有 TLS 版本都说成：客户端拿证书公钥直接加密一个会话密钥。

4. TLS 1.3 把握手简化了，符合条件的恢复连接还可以发早期数据，但早期数据有重放风险。下单这类有副作用的操作，不能为了少等一次就随便用。实际策略由客户端、服务端和协议实现一起决定。

5. 项目里除了打开 HTTPS，还要避开混合内容，Cookie 和重定向也要设对。浏览器开发工具能看到本机解密后的请求，这是正常现象，不代表网络在明文传。终端或服务端被攻破，也不是 HTTPS 单独能解决的。

## 追问：HTTPS 为什么还可能遇到中间人读取内容？

1. 正常情况下，攻击者没有可信证书和服务器私钥，不能只靠截获网络流量就冒充服务器。但如果设备安装并信任了某个代理的根证书，代理可能给站点签发浏览器信任的证书，从而建立两段 TLS 连接。

2. 这类情况常见于用户自己配的调试代理，或者组织管理的环境，信任前提已经变了。浏览器自身和服务端也能看到解密后的数据，所以传输加密从来不表示数据在所有处理位置都看不见。

3. 通过证书颁发者和信任链确认当前连接情况，别随便忽略证书警告，也别乱装陌生根证书。开发排查用受控账号和必要数据。能抓包，解释不成「线上用 HTTPS 没价值」。

## 追问：TLS 1.3 的 0-RTT 为什么要防重放？

1. 早期数据在完整的新握手确认之前就发出去了，协议对它的重放保护，跟普通握手后的数据不一样。攻击者可能重放抓到的早期请求，所以内容即使加密了，服务端仍可能重复看到某个操作。

2. 查询类请求可以按实际语义判断适不适合；创建订单、转账这些操作，不能接受重复执行。服务端要拒绝不合适的早期请求，或者结合可靠的业务幂等设计，别只看请求方法的名字。

3. 对前端来说，这是协议优化的适用边界，`fetch` 里别随便承诺打开 0-RTT。最终由基础设施和服务端配置决定，并验证业务重复请求时的结果。只比较一次连接的速度，不够。
