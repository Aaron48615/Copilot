# 弹窗打开后焦点怎么处理？

## 核心回答

1. 弹窗打开后，焦点要进到弹窗里合适的位置，同时记下打开前那个触发按钮。普通填写弹窗可以落到第一个输入框；内容比较长、得先看说明的，可以把标题临时设成可聚焦。不是所有弹窗一打开就该跳到确认按钮。

2. 模态弹窗开着的时候，背景不该还能点、还能 Tab 进去。Tab 和 Shift+Tab 要在当前弹窗里打转。优先用原生 dialog 的 `showModal()`，或者组件库已经做好的行为，再补业务细节。只画一层遮罩、键盘还能钻进背后的表单，等于没做模态。

3. 关掉时焦点一般还回触发按钮，但得确认这个按钮还在。比如弹窗里删完一条，对应那一行已经没了，焦点就放到相邻条目或列表的操作入口，让人还能接着干活，别落到已经不存在的节点上。

4. Escape、关闭按钮、内容异步变了，都要管。弹窗里一个可聚焦的子项都没有时，也得有个落点。卸掉时清监听，页面上被改过的状态也要还原。打开、正着 Tab、倒着 Tab、关掉、再开一次，都要过，别只测第一次点击。

5. 焦点移动要等弹窗节点真出来，设了打开状态不等于子元素已经画完。有进入动画的话，落点也别被滚到屏幕外面，打开就能看见接下来要操作的地方。

## 追问：删除确认弹窗初始焦点应放在哪个按钮？

1. 看风险和说明有多长。删除很难恢复时，焦点常放在取消这类更安全的操作上，免得人手一按回车就删了。这是交互选择，不是所有弹窗统一一条规矩。

2. 正文很长时，直接聚焦底部按钮可能把前面的说明滚走。可以先落到标题或开头说明。静态节点用负值 tabindex 拿程序焦点就行，不必进日常 Tab 顺序。

3. 从触发按钮用键盘打开，看第一眼看到什么、读屏宣布什么，再确认 Tab 能自然到两个操作。危险按钮的文案要说清动作，别只写模糊的「确定」，也不说删的是哪条。

## 追问：弹窗内容异步加载时如何避免焦点丢失？

1. 先把焦点放到稳定的标题或容器上，加载状态要看得见。别立刻去聚焦还没挂上的输入框，也别每次数据刷新都再 `focus` 一次，用户刚开始填就会被拽走。

2. 加载完了，再看任务要不要移到第一个字段。用户已经主动点进某个控件，就留在原地；如果人还在等着填，节点确实渲染完再有意移一次。

3. 内容一刷新，当前按钮可能没了，得另找附近合理的落点，可聚焦范围也要重算。失败时要有重试和关闭入口，别只剩一个加载占位、键盘找不到出口。关掉之后焦点回哪，同样要验。
