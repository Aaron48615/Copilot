# 手写题写不出来怎么办？

## 核心回答

1. 卡住了就把卡住的位置说具体，比如「线性时间的做法暂时没想到，但能先写双循环」。对面能知道题目理解到哪一步，也好判断要提示的是数据结构、边界还是语法。

2. 接着确认输入输出和限制，比如两数之和要下标还是值、能不能用同一个元素、没答案怎么返回。再用一个最小样例手动走一遍，先把步骤想清楚，别急着把没想明白的条件塞进复杂表达式。

3. 允许先给基础方案，就写一个符合约定的版本，比如输入是普通有限数字数组，找不到返回 `null`。下面双循环从 `i + 1` 开始，避免重复用同一元素，找到任意合法答案就返回。

    ```js
    function twoSum(nums, target) {
      for (let i = 0; i < nums.length; i++) {
        for (let j = i + 1; j < nums.length; j++) {
          if (nums[i] + nums[j] === target) return [i, j];
        }
      }
      return null;
    }
    ```

4. 写完自己走一遍空数组、重复数字、没答案，再说双循环是平方级时间、额外空间是常数级。优化可以用 `Map` 记下已经见过的数字和下标，先查补数再存当前值，避免把同一个位置配给自己。

5. 剩余时间不够，就说哪部分写完了、哪部分还是思路，哪些限制还没验证。别把伪代码说成已经跑通，也别靠不停重写把问题盖过去；面试后再针对这次真正卡住的知识补练。

## 追问：什么时候该停下优化，先检查现有代码？

1. 基础版本刚写完，先用题目样例和一个边界样例检查，别马上换写法。比如两数之和里 `[3, 3]` 配目标六，能直接检验两个不同位置的相同数行不行，也能把下标处理问题露出来。

2. 约束允许当前复杂度，时间又紧，正确且能讲清楚的版本更值得留。输入规模很大、题目明确要线性时间，基础版本就只能当中间步骤，得继续说它为什么达不到要求。

3. 优化后再用刚才那些样例，重点看新增状态的更新顺序。比如哈希版本先存当前元素再查找，就可能错误复用当前下标；复杂度变好了，正确性不会自动跟着保留，得对着新逻辑再推一遍。

## 追问：面试官给了提示后，怎样继续而不只是照着写？

1. 先复述提示解决了哪个困难，比如「用哈希表是为了避免每个数都扫后面全部元素」。确认理解的是查找方式变了，不是只记住要新建一个 `Map`。

2. 再把提示变成可执行步骤：遍历当前值，查目标差值对应的旧下标，找到就返回，没找到才存当前项。再用重复数字的例子讲这个顺序为什么不会复用同一个元素，代码依据才说得清。

3. 某个 API 还是不会，就坦白语法记不准，先写准确伪代码，把键和值的含义说清楚。拿到提示是正常协作，但正确性、复杂度和边界还得自己讲，看懂提示不等于已经完整解决。
