# 手写题写不出来怎么办？

## 核心回答

1. 我会先把卡住的位置说具体，例如“我暂时没想到线性时间的做法，但能先写双循环版本”。这样面试官能知道我理解题目到哪一步，也方便判断需要提示的是数据结构、边界条件还是语言语法。

2. 接下来确认输入输出和限制，比如两数之和要返回下标还是值、能不能用同一个元素、没答案怎么返回。然后用一个最小样例手动执行，先形成清楚的步骤，不急着把没有想明白的条件写进复杂表达式。

3. 如果允许先给基础方案，我会写一个符合约定的版本，例如假设输入是普通有限数字数组，找不到返回 `null`。下面双循环从 `i + 1` 开始，避免重复使用同一元素，找到任意合法答案就返回。

    ```js
    function twoSum(nums, target) {
      for (let i = 0; i < nums.length; i++) {
        for (let j = i + 1; j < nums.length; j++) {
          if (nums[i] + nums[j] === target) return [i, j];
        }
      }
      return null;
    }
    ```

4. 写完后我会自己走一遍空数组、重复数字和无解情况，再说明双循环是平方级时间、额外空间是常数级。优化时可以用 `Map` 记录已经见过的数字和下标，先查补数再存当前值，避免把同一个位置配给自己。

5. 如果剩余时间不够，我会明确哪部分已完成、哪部分还是思路，并指出尚未验证的限制。不会把伪代码说成已经运行成功，也不会用不断重写掩盖问题；面试后再针对这次真正卡住的知识补练。

## 追问：什么时候该停下优化，先检查现有代码？

1. 当基础版本刚写完，我会先用题目样例和一个边界样例检查，而不是马上换写法。比如两数之和中 `[3, 3]` 配目标六，能直接检验是否允许两个不同位置的相同数，也能暴露下标处理问题。

2. 如果约束允许当前复杂度，而且时间有限，正确且能解释的版本更值得保留。如果输入规模很大、题目明确要求线性时间，基础版本就只能作为中间步骤，需要继续说明它为什么达不到要求。

3. 优化后我会复用刚才的样例，重点检查新增状态的更新顺序。例如哈希版本先保存当前元素再查找，就可能错误复用当前下标；复杂度变好了不代表正确性自动保留，必须针对新逻辑重新推演。

## 追问：面试官给了提示后，怎样继续而不只是照着写？

1. 我会先复述提示解决了哪个困难，例如“用哈希表是为了避免每个数都扫描后面的全部元素”。这样能确认我理解的是查找方式的变化，而不是只记住要创建一个 `Map`。

2. 然后把提示转换成可执行步骤：遍历当前值，查找目标差值对应的旧下标，找到就返回，没找到才保存当前项。再用重复数字的例子解释这个顺序为什么不会复用同一个元素，让代码依据说得清楚。

3. 如果仍然不会某个 API，我会坦白语法记不准，先写准确伪代码并描述键和值的含义。得到提示属于面试中的正常协作，但最终要自己说明正确性、复杂度和边界，不能把“看懂提示”当成“已经完整解决”。
