# JS 有哪些继承方式？

## 核心回答

1. 继承靠原型链，不同写法差在数据和关系怎么接。原型链继承让子类原型指向父类实例，能复用父类方法。父类实例上的数组等引用属性，也可能被子类实例共享，某个实例改数组，别的实例跟着变。

2. 借用构造函数是在子类构造时执行 `Parent.call(this)`，让父类把属性初始化到当前对象上，所以可以传参，实例数据也各有一份。但它没有接到父类原型上，只有这种调用时，子类拿不到父类原型上定义的方法。

3. 组合继承把这两种方式合在一起。代价是设置原型时调用一次父构造，创建每个子实例时还要再调。寄生组合继承改用 `Object.create(Parent.prototype)` 接原型，设置原型时就不必多执行一次父构造，实例初始化仍要保留。

4. 现在需要类继承，倾向用 `class extends`。它还会建立构造函数之间的继承关系，静态成员才能被查到。正常初始化路径里，派生构造函数必须先执行 `super()` 才能用自己的 `this`。类继承不是「手动把一个对象接上去」那么简单。

5. 能不能继承，还看子类型能不能合理替代父类型。仅仅共用几个方法，不一定适合继承。两个对象都需要格式化时间，抽出普通函数就行，别为了复用一点代码建立很难解释的父子关系。

## 追问：父类中的数组为什么有时共享、有时不会共享？

1. 关键看数组放在哪，以及每次创建实例时有没有重新创建数组。数组在所有实例都能访问的原型对象上，实例读到的是同一份引用，调用添加元素的方法就会改大家共用的那一个数组。

2. 构造函数每次执行时都把一个新数组赋给当前实例，每个实例就有自己的属性和数组。共享的通常可以是操作数组的方法，实际数据分别放在实例里。行为能复用，状态也不会串。

3. 还要分清改数组和重新赋值。实例给同名属性赋一个新数组，通常会创建自己的属性，挡住原型上那个。这个操作没有替其他实例更换数组。判断影响范围时，别只看属性名字是不是相同。

## 追问：为什么不能用 Parent.call(this) 完全代替 super()？

1. 普通构造函数可以直接调用；类构造函数要求通过构造方式执行，直接对父类使用 `call` 会抛错。旧式借用构造函数的写法，不能原样套到用类语法声明的父类上。语法和运行语义都有差别。

2. 派生类里，父构造过程会参与创建和初始化当前实例，返回后才建立起可用的当前实例引用。手动调用普通函数没有这些步骤，也不会自动完成类字段、父类私有字段这些初始化。

3. 类继承同时联系实例方法和静态方法的查找，单独调用父函数也不会建立这些关系。只想复用初始化逻辑，可以抽出接收参数的辅助函数。那是组合代码，谈不上实现了同样的继承。
