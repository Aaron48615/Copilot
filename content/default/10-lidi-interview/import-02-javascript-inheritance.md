# JS 有哪些继承方式？

## 核心回答

1. 我会先说明继承依赖原型链，再比较不同写法。原型链继承让子类原型指向父类实例，能复用父类方法，但父类实例上的数组等引用属性也可能被子类实例共享，某个实例修改数组会影响其他实例。

2. 借用构造函数是在子类构造时执行 `Parent.call(this)`，让父类把属性初始化到当前对象上，因此可以传参并分别创建实例数据。但它没有建立到父类原型的连接，只有这种调用时，子类拿不到父类原型上定义的方法。

3. 组合继承把这两种方式结合，代价是设置原型时调用一次父构造，创建每个子实例时还要调用。寄生组合继承改用 `Object.create(Parent.prototype)` 连接原型，避免设置原型时多执行父构造，但实例初始化仍需要保留。

4. 现在需要类继承时我倾向使用 `class extends`，它还会建立构造函数之间的继承关系，让静态成员能够被查找。在正常初始化路径中，派生构造函数必须先执行 `super()` 才能使用自己的 `this`，不能把类继承简单理解为手动连接一个对象。

5. 是否继承还要看子类型能否合理替代父类型，仅仅共用几个方法并不一定适合继承。假如两个对象只是都需要格式化时间，我会考虑抽出普通函数，避免为了复用一点代码建立难解释的父子关系。

## 追问：父类中的数组为什么有时共享、有时不会共享？

1. 关键要看数组放在哪里，以及每次创建实例时有没有重新创建数组。若数组存在于所有实例都能访问的原型对象上，实例读取到的是同一份引用，调用添加元素的方法就会修改共同使用的那一个数组。

2. 如果构造函数每次执行时都把一个新数组赋给当前实例，那么每个实例拥有自己的属性和数组。共享的通常可以是操作数组的方法，而实际数据分别放在实例中，这样既能复用行为，也不会串改彼此状态。

3. 还要区分修改数组与重新赋值：实例给同名属性赋一个新数组，通常会创建自己的属性，遮住原型属性。这个操作没有替其他实例更换数组，所以判断影响范围时不能只看属性名字是否相同。

## 追问：为什么不能用 Parent.call(this) 完全代替 super()？

1. 普通构造函数可以被直接调用，而类构造函数要求通过构造方式执行，直接对父类使用调用方法会抛错。所以旧式借用构造函数的写法，不能原样套到使用类语法声明的父类上，语法和运行语义都有区别。

2. 在派生类中，父构造过程会参与创建和初始化当前实例，返回后才建立可用的当前实例引用。手动调用普通函数并不具备这些步骤，也不会自动完成类字段、父类私有字段等相关的初始化工作。

3. 另外，类继承同时联系实例方法与静态方法的查找，单独调用父函数也不会建立这些关系。如果只是想复用初始化逻辑，可以抽取接收参数的辅助函数，但这属于组合代码的方式，不能据此声称实现了同样的继承。
