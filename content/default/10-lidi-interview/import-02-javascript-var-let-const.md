# var、let、const 有什么区别？

## 核心回答

1. 我会从作用域、初始化和重新赋值三个方面区分它们，日常默认用 const，需要改绑定时才用 let。var 的局部作用域主要由函数决定，普通代码块不能把它隔离；let 和 const 则受块级作用域约束，更容易看清一个变量在哪些位置可以使用。

2. var 声明在执行赋值前已经建立并初始化为 undefined，因此在同一作用域里提前读取，通常得到未定义值而不是后面的赋值。let 和 const 的绑定也会提前建立，但执行到初始化之前处于暂时性死区，提前读取会抛错，不能简单说它们完全没有提升。

3. const 禁止的是绑定重新赋值，不是禁止对象内容变化，例如常量数组仍可以追加元素。若改成另一个数组就会报错，所以它表达的是这个变量一直引用同一个值，而不是整个数据结构不可变，理解这一点才能解释常量对象为何还能被修改。

4. 循环配合异步回调可以看出绑定差异，假设从零循环到三之前，用 var 的三个回调共享一个变量，稍后执行时通常都读到三。改用 let 后每轮有自己的绑定，回调分别读取对应轮次的值，关键在变量如何被保存，而不是定时器改变了作用域。

5. 如果希望对象只读，还要区分类型层限制和运行时限制，Object.freeze 也只是浅冻结普通对象自身属性。嵌套对象仍可能变化，所以我不会把 const 或一次冻结当成深度不可变保证，具体是否需要递归处理要看数据结构和共享修改的风险。

## 追问：循环回调打印相同数字，是闭包复制错了值吗？

1. 不是复制错误，闭包保留的是访问外层绑定的能力，并不自动在创建时复制变量当前的值。例如用 var 计数并注册定时器，循环结束后共享变量已经变成三，回调再读取，自然都会看到那个最终值。

2. for 循环头使用 let 时，每轮会建立对应的绑定，回调捕获的是各自那一轮的变量。它们虽然名称相同，但并不是同一个绑定，因此按注册顺序执行时能得到零、一、二，差异来自语言对循环环境的处理。

3. 也可以通过调用一个接收当前数字的函数，让函数参数形成独立绑定，再在里面创建回调，但现代代码通常直接用 let 更清楚。如果回调改为同步执行，即使 var 也会在每次迭代时读到当前值，所以还要同时看执行时机。

## 追问：为什么对暂时性死区里的变量使用 typeof 也会报错？

1. typeof 对完全未声明的标识符可以返回 undefined 字符串，但对已经存在却尚未初始化的词法绑定并不提供这个保护。例如进入代码块后，在后面的 let 声明执行之前读取同名变量，仍然会触发暂时性死区错误。

2. 即使外层有一个已经赋值的同名变量，内层声明也会在整个块里遮蔽它，读取不会自动退回外层。例如外层名称是字符串，块内先检查名称再声明 let，检查命中的仍是尚未初始化的内层绑定，所以不能靠外层值兜底。

3. 我会把声明和初始化放在首次使用之前，并尽量避免不必要的同名遮蔽，让执行顺序更容易理解。如果确实要判断某个全局能力是否存在，可以通过明确的全局对象属性检查，但这与读取局部变量不是同一个问题。
