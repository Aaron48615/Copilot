# var、let、const 有什么区别？

## 核心回答

1. 最明显是作用域。`var` 是整个函数里都能用，`if`、`for` 的大括号包不住。`let` 和 `const` 出了这个大括号就不能再用。所以现在基本不写 `var`，默认 `const`，真要重新赋值才用 `let`。

2. 再就是声明之前能不能读。`var a` 写在后面，前面去读不会报错，值是 `undefined`。`let` 和 `const` 提前读会直接报错，得等这行执行到。这段叫暂时性死区。它们其实也会先占个位置，不是完全没提升，只是提前占了也不能用。

3. `const` 不能再赋成别的值。但如果是对象或数组，里面照样能改：`const list = [1]`，`list.push(2)` 没问题，`list = []` 才会报错。它锁的是指向，不是里面的内容。真要对象也不能改，还得 `Object.freeze`，而且只冻最外层，里面嵌套的对象还能动。

4. 面试常问 `for` 循环加 `setTimeout`。用 `var` 声明 `i`，三个回调过一会儿打印全是 `3`，因为共用一个 `i`，循环结束已经是 `3`。换成 `let`，每一圈有自己的 `i`，就会打印 `0`、`1`、`2`。不是定时器改了作用域，是 `let` 每圈都是新变量。

## 追问：循环回调打印相同数字，是闭包复制错了值吗？

1. 不是复制错了。闭包抓住的是外面那个变量，不是当时的数字。`var` 的 `i` 就一个，定时器跑的时候循环早结束了，`i` 已经是 `3`，三个回调读到的都是 `3`。

2. `for` 里用 `let`，每一圈有自己的 `i`。回调各自读各自那圈的，就会打印 `0`、`1`、`2`。名字都叫 `i`，其实不是同一个变量。

3. 也可以写成函数传参，把当前数字传进去，每次调用有自己的参数。现在直接用 `let` 更清楚。要是回调是同步执行的，`var` 也不会全是 `3`，因为那时候循环还没跑完。

## 追问：为什么对暂时性死区里的变量使用 typeof 也会报错？

1. `typeof` 一个完全没声明的名字，会得到 `"undefined"`。但 `let a` 已经占了这个名字，只是还没赋值，`typeof a` 照样报错。

2. 就算外面已经有个同名变量，进了这个块、里面的 `let` 还没执行到，读到的也是里面这个还没就绪的，不会退回去用外面那个。

3. 所以声明写在用之前。真要判断浏览器有没有某个全局能力，去查 `window` 上的属性，别 `typeof` 一个后面才 `let` 的局部变量。
