# 配置错误怎么处理？

## 核心回答

1. 配置本身不合法，和配置合法但数据暂时取不到，要分开。折线图缺时间维度是配置错误，接口超时是运行错误。两种情况的提示和处理入口应该不一样，别都让用户重新填表。

2. 编辑时先校验必填项、字段类型、取值范围，再查字段之间的关系。统计金额可以求和，文本字段不能直接求和，开始日期不能晚于结束日期。错误最好出现在对应输入框旁边，告诉用户具体怎么改。

3. 前端校验过了，服务端仍要查数据源权限、指标白名单、查询范围。配置只描述允许的查询意图，用户不能直接提交任意 SQL 或脚本。就算绕过编辑器发请求，也查不到无权访问的数据。

4. 预览按卡片隔离错误，显示卡片名称、问题字段、可以怎么处理。失败时草稿留着，其他卡片继续展示。如果保留上次结果，要标明它属于旧配置，别让用户把旧数据当成修改后的预览。

5. 保存时带上配置版本，读取时按版本校验或迁移，新编辑器别直接误读旧配置。碰到暂不支持的新版本，给出明确提示，禁止覆盖保存。多人同时编辑还要查修订号，后保存的人别悄悄盖掉前一个人的修改。

## 追问：字段都填对了，为什么图表仍然画不出来？

1. 字段合法，不代表它们能组成有效图表。饼图分类过多，或者指标返回了字符串，都会画不出来。先查接口返回结构跟配置约定是否一致，确认维度、数值、单位，再决定是改配置还是做数据适配。

2. 数据为空、所有值为零、接口失败，分开展示，别统一画一张空白图。查询日期没有记录，提示调整时间范围；响应缺必需字段，提示数据格式异常。别把服务故障解释成业务没有数据。

3. 容器有没有实际宽高也要看。隐藏面板里初始化的图表，可能拿不到正确尺寸。等容器可见后再初始化或调大小，单卡展示失败状态。别为了修一张图把整个大屏重新加载。

## 追问：升级配置格式时，已有大屏怎么兼容？

1. 给格式加独立的版本字段，列出每一版新增、删除、改名的字段。它和每次保存递增的修订号不是一回事：前者决定怎么解析，后者用来发现并发修改。混用之后很难判断失败原因。

2. 能明确转换的变化可以写迁移函数，比如把旧的单指标字段变成指标数组。迁移之后还要重新校验，原始配置应可恢复。指标业务含义改了，只换字段名说不成兼容。

3. 当前客户端理解不了这个配置版本，可以查看必要的版本说明，但不让它按旧格式保存。迁移验证用各版本的固定样例，查图表类型、筛选条件、单位有没有保住。只判断 JSON 能解析不够。
