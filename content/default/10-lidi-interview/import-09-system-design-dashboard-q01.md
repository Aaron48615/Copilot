# 配置错误怎么处理？

## 核心回答

1. 我会先区分配置本身不合法，还是配置合法但数据暂时取不到。比如折线图缺少时间维度属于配置错误，接口超时属于运行错误，两种情况的提示和处理入口应该不同，不能都让用户重新填表。

2. 编辑时先校验必填项、字段类型和取值范围，再检查字段之间的关系。比如统计金额可以求和，文本字段不能直接求和，开始日期不能晚于结束日期；错误最好出现在对应输入框旁，告诉用户具体怎么改。

3. 前端校验通过后，服务端仍要检查数据源权限、指标白名单和查询范围。配置只描述允许的查询意图，不让用户直接提交任意 SQL 或脚本；即使绕过编辑器发请求，也不能查到无权访问的数据。

4. 预览按卡片隔离错误，显示卡片名称、问题字段和可执行的处理方式。失败时保留草稿，其他卡片继续展示；如果保留上次结果，要标明它属于旧配置，避免用户把旧数据当成修改后的预览。

5. 保存时带上配置版本，读取时根据版本校验或迁移，避免新编辑器直接误读旧配置。遇到暂不支持的新版本，我会给出明确提示并禁止覆盖保存；多人同时编辑时还要检查修订号，防止后保存的人悄悄覆盖前一个人的修改。

## 追问：字段都填对了，为什么图表仍然画不出来？

1. 字段合法不代表它们能组成有效图表，比如饼图的分类过多，或者指标返回了字符串。我会先检查接口返回结构与配置约定是否一致，确认维度、数值和单位，再决定是修改配置还是处理数据适配。

2. 数据为空、所有值为零和接口失败要分别展示，不能统一画一张空白图。比如查询日期没有记录时提示调整时间范围，响应缺少必需字段时则提示数据格式异常，避免把服务故障解释成业务没有数据。

3. 还要看容器是否有实际宽高，隐藏面板里初始化的图表可能拿不到正确尺寸。我会等容器可见后初始化或调整大小，并让单卡展示失败状态；不会为了修一张图而重新加载整个大屏。

## 追问：升级配置格式时，已有大屏怎么兼容？

1. 我会给格式增加独立的版本字段，并列出每一版新增、删除和改名的字段。它和每次保存递增的修订号不是一回事，前者决定怎么解析，后者用来发现并发修改，混用后很难判断失败原因。

2. 能明确转换的变化可以写迁移函数，例如把旧的单指标字段变成指标数组。迁移后还要重新校验，原始配置应可恢复；像指标业务含义改变这种情况，不能只换字段名就声称兼容。

3. 如果当前客户端无法理解配置版本，我会允许查看必要的版本说明，但不让它以旧格式保存。迁移验证可以使用各版本的固定样例，检查图表类型、筛选条件和单位是否保留，而不是只判断 JSON 能解析。
