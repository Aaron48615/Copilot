# `==` 和 `===` 有什么区别？

## 核心回答

1. `===` 是严格相等，类型不同就返回假，不会为了比较去转类型。`==` 是宽松相等，会按双方类型走一套转换。数字 `1` 和字符串 `'1'` 宽松相等，严格比较不相等。

2. 宽松相等别概括成「全部转成字符串」或「全部转成数字」。`null == undefined` 是专门规则，`null == 0` 却是假。对象和基本值比较还可能触发对象转基本值，得按规则看，不能凭感觉。

3. 对象之间两种比较通常都看是不是同一份引用，不会逐个比字段。两个分别创建的 `{ id: 1 }` 内容一样，严格相等仍是假。要判断是不是同一件商品，按约定比商品 ID，并先确认接口里标识类型一致。真要比完全部内容，再另定字段级规则。

4. 严格相等也有数字边界：`NaN === NaN` 是假，正零和负零严格相等。判断是不是 `NaN` 用 `Number.isNaN`。要区分正负零这类特殊值，再考虑 `Object.is`。

5. 业务里优先严格相等，在接口或表单入口把类型统一，非法输入单独校验。`value == null` 可以顺手判断空值，但要守项目规范。浏览器历史对象 `document.all` 还有特殊兼容行为。

## 追问：为什么空数组与 false 宽松相等，但放进 if 又为真？

1. `if ([])` 只做布尔转换，对象包括空数组都是真值。数组没有元素，也不会因此变假。判断空不空，看 `length`，别只判断数组对象本身。

2. `[] == false` 走的是宽松相等。布尔先变成数字 `0`，数组再转成基本值。空数组通常得到空字符串，再跟数字比会转成 `0`，所以这个表达式是真。两种场景用的转换过程不一样。

3. 业务条件别依赖这种结果。比如「没有选中商品」，就明确看选中数组的长度。输入既可能是数组又可能是布尔，先把数据结构规范好，别让一个判断既猜类型又做业务判断。

## 追问：表单里的数字字符串应该先转数字再比较吗？

1. 字段业务含义真是数量，先检查空字符串，再转换并验证结果。直接 `Number('')` 会得到 `0`，「没填」和「填了零」可能不是一回事。转成功了，不等于输入符合要求。

2. 转完还得按字段要求看有限数、整数、允许范围。购买数量一般不能是负数或小数。`Number.isFinite` 和 `Number.isInteger` 管的不是同一件事，别只跟零比一次就完。

3. 字段是商品编号或订单编号，就算看起来全是数字，也可能要留前导零，或者超过安全整数范围。这种更适合留字符串，两边类型统一后再比，别为了让严格相等通过就硬转成数字。
