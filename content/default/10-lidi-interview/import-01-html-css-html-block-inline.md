# 块级元素和行内元素有什么区别？

## 核心回答

1. 日常说块级和行内，主要是在讨论 CSS 盒子的显示与排版方式，不是 HTML 标签永远不可改变的身份。div 默认常按块排版，span 默认常按行内排版，可以通过 display 改变外观布局，但标签本身的语义和合法内容结构不会因此改变。

2. 普通块盒子通常从新的一行开始，宽度为 auto 时会利用可用的行内空间，可以设置宽高、内边距和外边距。它不一定永远占满父元素，例如显式宽度、浮动或不同布局上下文都会改变表现，所以“独占一行”是常见普通流现象，不是所有情况的定义。

3. 普通非替换行内元素跟随文字排布，width 和 height 通常不按块盒那样起作用，垂直 margin 不会像块间距一样推开上下行。行内 padding 和 border 可以绘制，但不一定相应撑开行盒，过大的装饰可能与其他行重叠，需要看行高。

4. inline-block 对外作为行内级盒子排列，内部可以有自己的块布局和尺寸约束。img 等替换元素也有固有尺寸，不能套用 span 的全部规则。实际选择时我会同时看语义、外部排列和内部布局，并用 Flex 处理明确的一维对齐，而不是靠行内空白反复凑位置。

5. 源码空白在行内排版中也可能形成可见间距，几个行内块之间的换行就会体现为文字空格。需要严格控制按钮间隔时，我会优先用布局间隙表达，而不是依赖删掉源码换行或全局把父级字号归零。

## 追问：行内图片底部为什么常有一条空隙？

1. 行内图片默认参与行盒的基线对齐，文字的基线下面还要给某些字母下伸部分留空间。图片底部靠基线放置时，行盒下方就可能有可见空隙，这通常不是图片文件底部多了一条透明边。

2. 如果图片本来就是独立的整块内容，可以设成 display: block；如果它必须与文字同行，则考虑合适的 vertical-align。两种方案改变的排版含义不同，不能在所有图片上盲目把行高或字号设成零。

3. 排查时我会先确认图片实际像素内容和父级行盒，再看对齐方式。使用 block 后还应检查原来是否依赖行内排列，避免修掉下方空隙却让旁边文字换行，问题从垂直间距变成整体结构变化。

## 追问：把 div 设置成 inline，就能合法放进 p 里面吗？

1. 不能，CSS display 改的是呈现方式，HTML 的内容模型仍由元素语义决定。p 允许的是短语内容，往里面放 div 仍然不符合相应结构要求，浏览器的解析结果也可能与源码缩进表达的父子关系不同。

2. 浏览器遇到这类结构可能提前结束段落，形成看起来意外的兄弟节点。此时你在 CSS 中写的 p 内部选择器可能不匹配，前端框架也可能对结构或水合发出提示，问题不只是视觉上的一行或两行。

3. 我会先在元素面板确认实际 DOM，再选择符合含义的标签。需要段内强调用 span 等合适元素，需要包含多个内容块就用外层容器；语义和布局分别处理，比用 display 去掩盖不合法嵌套更稳妥。
