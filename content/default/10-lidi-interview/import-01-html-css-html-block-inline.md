# 块级元素和行内元素有什么区别？

## 核心回答

1. 日常说块级和行内，主要在说 CSS 盒子怎么显示、怎么排，不是 HTML 标签永远改不了的身份。`div` 默认常按块排，`span` 默认常按行内排，可以用 `display` 改外观布局。标签本身的语义和合法内容结构，不会因此改变。

2. 普通块盒子通常从新的一行开始，宽度为 `auto` 时会用上可用的行内空间，可以设宽高、内边距和外边距。它不一定永远占满父元素。显式宽度、浮动、不同布局上下文都会改表现。「独占一行」是常见普通流现象，不是所有情况的定义。

3. 普通非替换行内元素跟着文字排，`width` 和 `height` 通常不像块盒那样起作用，垂直 `margin` 也不会像块间距那样推开上下行。行内 padding 和 border 可以画出来，但不一定把行盒撑开，装饰太大可能跟其他行重叠，得看行高。

4. `inline-block` 对外当行内级盒子排，内部可以有自己的块布局和尺寸约束。`img` 这类替换元素还有固有尺寸，不能全套 `span` 的规则。选的时候语义、外部排列、内部布局一起看。明确的一维对齐用 Flex，别靠行内空白反复凑位置。

5. 源码空白在行内排版里也可能变成看得见的间距，几个行内块之间的换行会变成文字空格。按钮间隔要严格控制，优先用布局间隙说，别依赖删掉源码换行，或把父级字号全局打成零。

## 追问：行内图片底部为什么常有一条空隙？

1. 行内图片默认参与行盒的基线对齐，文字基线下面还要给某些字母的下伸部分留空。图片底部靠基线放时，行盒下方就可能露出一条空隙。通常不是图片文件底部多了一条透明边。

2. 图片本来就是独立的整块内容，可以设成 `display: block`；必须跟文字同行，再考虑合适的 `vertical-align`。两种改的排版含义不同，别在所有图片上盲目把行高或字号设成零。

3. 排查先确认图片实际像素内容和父级行盒，再看对齐方式。改成 `block` 以后，还要看原来是不是依赖行内排列。修掉下方空隙却让旁边文字换行，问题就从垂直间距变成整体结构变了。

## 追问：把 div 设置成 inline，就能合法放进 p 里面吗？

1. 不能。CSS `display` 改的是呈现方式，HTML 的内容模型仍由元素语义决定。`p` 允许的是短语内容，往里面放 `div` 还是不符合结构要求。浏览器解析结果，也可能跟源码缩进看起来的父子关系不一样。

2. 浏览器碰到这类结构，可能提前结束段落，弄出看起来意外的兄弟节点。这时 CSS 里写的 `p` 内部选择器可能匹配不上，前端框架也可能对结构或水合给提示。问题不只是视觉上多一行少一行。

3. 先在元素面板确认实际 DOM，再选符合含义的标签。段内强调用 `span` 这类合适元素；要包含多个内容块，用外层容器。语义和布局分开处理，比用 `display` 去盖不合法嵌套稳。
