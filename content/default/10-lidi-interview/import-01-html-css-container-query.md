# 容器查询和媒体查询怎么选？

## 核心回答

1. 媒体查询按页面环境改样式，比如视口宽度、减少动态效果、有没有悬停。容器尺寸查询按组件祖先容器还剩多少空间改内部布局。同一张卡片放主栏和侧栏，浏览器窗口没变，排列也可以不一样。

2. 做尺寸查询，合适的祖先上设 `container-type: inline-size`，再用 `@container` 判断行内方向尺寸。通常外层给宽度，里面的卡片跟着这个宽度变。别指望元素查自己的尺寸再无限改自己，尺寸隔离就是为了少这种循环依赖。

3. 商品卡片在宽容器里图片和文字横排，窄容器里上下排，这很适合容器查询。页面整体什么时候收导航，还是媒体查询的事。两者可以一起用：页面决定空间怎么分，组件在分到的空间里决定细节，不必为了复用卡片写一堆页面专用类。

4. 断点看内容什么时候挤不下。嵌套容器起清楚的名字，别查到错误的祖先。基础样式先保证窄布局能用，支持范围内再开增强规则。侧栏收缩、组件单独嵌进别处都要测，只拖浏览器窗口不够。

## 追问：为什么要查询父容器，而不是卡片自己？

1. 卡片按自己的宽度切换样式，新样式又改自身宽度，规则容易互相咬。容器查询把祖先和尺寸约束说清楚：外层先分空间，内部再按已经拿到的空间排版，关系更稳。

2. 实际结构可以是一个负责占网格列的外壳，里面放卡片内容，查询条件作用在内容上。不必每个小元素都再套一层，已有的布局父节点够用就行，别无意义嵌套。

3. 还要留意收缩包裹的容器。`inline-size` 尺寸包含会改内容怎么参与祖先固有尺寸计算。外层宽度本来完全靠卡片撑开，得先确定它宽度从哪来，再建查询，不然可能得到意外的窄容器。

## 追问：如何给不支持容器查询的环境提供可用页面？

1. 先写不依赖查询的基础布局，比如图片在上、文字在下，宽度不超出父容器，按钮可以换行。浏览器忽略容器规则以后，内容仍完整可读，主要操作还在。

2. 再按项目支持范围用 `@supports` 判断相关能力，支持时再加横向卡片这类增强。必要时用媒体查询给较粗的宽屏调整，但它依据的是视口，复制不了组件按所在栏宽变化的效果。

3. 验证时主动关掉增强规则，看默认样式和真实内容，尤其长标题和图片比例。降级不要求每个像素一样，但内容顺序要合理、操作够得到。别只留一句「旧浏览器走兼容」，却没有具体基础样式。
