# Vue 组件之间怎么通信？

## 核心回答

1. 父传子最常见的是 props，子传父通过 emit 发送事件。例如父级传商品和禁用状态，子级点击收藏时发出商品编号，由父级决定是否调用接口并更新列表；子级不直接修改 prop，让数据由谁持有、谁确认变化保持清楚。

2. 兄弟组件可以把共同状态提升到最近的父级，分别通过 props 与事件参与。搜索条件和列表结果不应各存一份再互相通知同步，否则快速修改时容易不一致；没有共享需求的临时状态则继续留在各自组件，避免无意义地扩大更新范围。

3. 组件 v-model 是 prop 加更新事件的约定，适合输入类组件，多个具名模型能表达独立值。需要父级定制展示时可以用插槽，作用域插槽由子级提供必要数据；通信不只是传变量，也包括清楚划分谁拥有数据、谁决定展示方式。

4. 深层子树共用环境依赖可以使用 provide 和 inject，例如表单校验或尺寸配置；跨页面的共享业务状态可以考虑 Pinia。事件总线也能实现通知，但订阅关系和清理更隐含，我不会把它作为常规父子通信的默认选择。

5. 父组件用模板 ref 调用子组件公开方法，适合聚焦、重置等明确命令，script setup 子组件可通过 defineExpose 限定接口。不要把全部内部状态都暴露给父级逐个修改，否则组件封装很容易失效；日常数据变化仍优先用 props 和事件表达。

## 追问：组件 emit 的事件会像 DOM 事件一样一直冒泡吗？

1. 组件自定义事件不会自动沿祖先组件树逐层冒泡，直接父级需要明确监听。孙组件 emit 一个 save，祖父级不会仅因层级关系自然收到；中间层可以转发，也可以根据共享范围改用其他明确的通信方式。

2. 我会先看中间层是否应该了解这个事件。如果它本来就是业务容器，转发或转换成更有意义的动作很合理；若只是布局包装，不断替许多事件中转可能说明接口不合适，可以考虑插槽组合或祖先提供的动作。

3. 不应把组件事件和原生点击传播混在一起排查。一个按钮点击可能有 DOM 冒泡，同时触发组件 emit，它们有不同机制；测试时分别检查父级监听和原生传播，避免靠 stopPropagation 试图阻止不相关的组件事件。

## 追问：什么时候用 expose 方法比 v-model 更合适？

1. focus、scrollTo 等命令依赖具体节点能力，不一定对应一个应由父级持续保存的值。父级在合适时机调用公开方法，子组件内部处理节点存在与可用性，比为了聚焦专门建立一个来回切换的布尔模型更直接。

2. 输入值、是否打开等持续状态则适合 props 或 v-model，让父级能读取并决定当前状态。不能把所有数据更新都做成 setName、setVisible 等命令，否则界面状态分散在子级内部，父级很难知道真实结果。

3. expose 只暴露少量稳定能力，并考虑调用时节点尚未挂载或组件已经停用的情况。测试应验证公开方法的效果，而不是让父级依赖内部 ref 名称，这样子级换一种 DOM 结构时，外部使用方式仍可保持稳定。
