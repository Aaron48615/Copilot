# Vue 组件之间怎么通信？

## 核心回答

1. 父传子最常见是 props，子传父用 `emit` 发事件。父级传商品和禁用状态，子级点收藏发出商品编号，父级再决定调不调接口、怎么更新列表。子级不直接改 prop，数据谁拿着、谁确认变化，才清楚。

2. 兄弟组件把共同状态提到最近的父级，一边 props 一边事件。搜索条件和列表结果别各存一份再互相通知，改得快时容易对不上。没有共享需求的临时状态继续留在各自组件，别无故把更新范围撑大。

3. 组件上的 `v-model` 是 prop 加更新事件的约定，适合输入类，多个具名模型能表达独立值。父级要定制展示用插槽，作用域插槽由子级提供必要数据。通信不只是传变量，也包括谁拥有数据、谁决定怎么展示。

4. 深层子树共用环境依赖，用 `provide` / `inject`，比如表单校验、尺寸配置。跨页面的共享业务状态可以上 Pinia；Vue 2 项目常见是 Vuex。事件总线也能通知：Vue 2 常拿空实例当 EventBus，Vue 3 去掉了 `$on`、`$off`，要用得引 `mitt` 这类库。项目里能提升到共同父组件就提升，事件总线撒多了，数据从哪来很难追。

5. 父组件用模板 `ref` 调子组件公开方法，适合聚焦、重置这类明确命令。`script setup` 子组件用 `defineExpose` 限定接口。别把内部状态全暴露给父级逐个改，封装就没了。日常数据变化还是优先 props 和事件。

## 追问：组件 emit 的事件会像 DOM 事件一样一直冒泡吗？

1. 组件自定义事件不会自动沿祖先组件树一层层冒。直接父级要明确监听。孙组件 `emit('save')`，祖父不会因为层级关系自然收到。中间层可以转发，也可以按共享范围改用别的明确方式。

2. 中间层该不该认识这个事件。它本来就是业务容器，转发或转成更有意义的动作很合理。只是布局包装，却替许多事件中转，接口可能不合适，可以考虑插槽组合，或祖先提供的动作。

3. 组件事件和原生点击传播别混着查。按钮点击可能有 DOM 冒泡，同时触发组件 `emit`，两套机制。测试时分别看父级监听和原生传播，别靠 `stopPropagation` 去拦不相关的组件事件。

## 追问：什么时候用 expose 方法比 v-model 更合适？

1. `focus`、`scrollTo` 这类命令依赖具体节点能力，不一定对应一个该由父级持续保存的值。父级在合适时机调公开方法，子组件内部处理节点在不在、能不能用。为了聚焦专门做一个来回切的布尔模型，反而绕。

2. 输入值、开没开这些持续状态，适合 props 或 `v-model`，父级能读到、也能决定当前是什么。别把所有数据更新都做成 `setName`、`setVisible` 这种命令，界面状态散在子级内部，父级很难知道真实结果。

3. `expose` 只露出少量稳定能力，还要考虑调用时节点还没挂上、组件已经停用。测试验证公开方法的效果，别让父级依赖内部 `ref` 名字。子级换一套 DOM 结构，外面用法还能稳。
