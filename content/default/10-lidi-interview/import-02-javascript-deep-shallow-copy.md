# 深拷贝和浅拷贝的区别？

## 核心回答

1. 深浅拷贝差在嵌套对象还共不共享。浅拷贝会新建外层对象，里面的对象属性仍指向原来那份。改副本的姓名，原值不动；改副本里地址对象的城市，原来那份也可能一起变。

2. 对象展开和 `Object.assign` 都是浅拷贝，数组的 `slice` 也不会递归复制元素。要改列表里某一项的地址，沿着列表、该项、地址这条修改路径，一层一层建新对象，没改到的部分还可以共享。

3. 深拷贝一般要把需要隔离的嵌套数据也复制出来，但得先说清支持哪些类型。`structuredClone` 能处理循环引用，以及日期、集合这类数据，却不能复制函数，也不会留下自定义类的原型。别把它当成任意对象的完整复制工具。

4. 默认别用 JSON 序列化去复制所有数据。日期会变成字符串，循环引用会报错，对象里有些属性还会丢。先看数据是不是普通数据、有没有特殊类型、要复制多大范围。别为了改一个字段把整个大列表都拷一遍，也别把方法和页面资源当成普通数据来处理。

## 追问：为什么 JSON 拷贝会让某些字段丢失？

1. JSON 只能表达有限几种数据，不是完整的 JavaScript 对象。属性值是 `undefined`、函数或符号时，普通序列化会把这些属性省略掉，解析回来连属性在不在都可能变了。

2. 数组里对应位置碰到这些值，通常会变成 `null`，不是一律删掉。日期默认走自己的序列化，变成字符串；普通 `Map` 不会自动变成键值对数组，后面再调原来的方法就会失败。

3. 循环引用没法用这种树状文本直接表达，默认处理 `BigInt` 也会抛错。只复制确认过的接口纯数据，JSON 可以考虑；要留日期或共享引用关系，就换方案，并把结果核对一遍。

## 追问：手写深拷贝怎样同时处理循环引用和重复引用？

1. 用一个映射记下原对象和副本的对应关系，递归进去先查是不是已经复制过。两个字段原本指向同一个地址对象，第二次碰到它应返回同一个副本，不然复制完关系就变了。

2. 空副本一创建就要马上登记，再递归填属性。对象指向自己时，才能取到已经登记的副本。等所有属性都复制完才登记，递归会一直走下去，最后把调用栈撑爆。

3. 可以用 `WeakMap` 存这种对应，但示例通常只支持普通对象和数组。日期、集合、属性描述符都要另定规则，共享内存也未必隔离。几十行递归，不是无损的通用实现。
