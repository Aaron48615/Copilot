# 深拷贝和浅拷贝的区别？

## 核心回答

1. 我理解深浅拷贝的区别，关键在于嵌套对象是否继续共享。浅拷贝会新建外层对象，但其中的对象属性仍然指向原来的对象，所以修改副本的姓名不会影响原值，修改副本里地址对象的城市却可能影响原值。

2. 对象展开和 `Object.assign` 都是常见的浅拷贝方式，数组的 `slice` 也不会递归复制元素。假设要编辑列表里某一项的地址，我会沿着列表、该项、地址这条修改路径逐层创建新对象，其他没有变化的部分仍可共享。

3. 深拷贝通常希望把需要隔离的嵌套数据也复制出来，但必须先约定支持哪些类型。`structuredClone` 支持循环引用以及日期、集合等数据，却不能复制函数，也不会保留自定义类的原型，因此不能把它当成任意对象的完整复制工具。

4. 我不会默认用 JSON 序列化来复制所有数据，因为日期会变成字符串，循环引用会报错，对象中的部分属性还会丢失。选择方案时会先看数据是不是普通数据、是否包含特殊类型以及复制范围，避免为了改一个字段复制整个大列表，也避免把方法和页面资源误当成普通数据处理。

## 追问：为什么 JSON 拷贝会让某些字段丢失？

1. JSON 表达的是有限的数据格式，不是完整的 JavaScript 对象。对象属性值是 `undefined`、函数或符号时，普通序列化会省略这些属性，所以解析回来后连属性是否存在都可能变了。

2. 数组对应位置遇到这些值通常会变成 `null`，不能简单概括成全部删除。日期默认通过自己的序列化方法输出字符串，而普通 Map 不会自动变成键值对数组，后续调用原来的方法自然会失败。

3. 循环引用无法用这种树状文本直接表达，默认处理 BigInt 也会抛错。如果只是复制经过确认的接口纯数据，JSON 方案可以考虑；一旦需要保留日期或共享引用关系，就应该换方案并验证结果。

## 追问：手写深拷贝怎样同时处理循环引用和重复引用？

1. 我会用一个映射记录原对象和副本的对应关系，进入递归时先查是否已经复制过。比如两个字段原本引用同一个地址对象，第二次遇到它时应返回同一个副本，否则复制后的关系就改变了。

2. 创建空副本后要立即登记，再递归填充属性。这样遇到对象指向自身的情况，就能取到已经登记的副本；如果等所有属性复制完才登记，递归仍然会一直走下去，最后导致调用栈溢出。

3. 面试中可以用 WeakMap 保存这种对应关系，但我会限定示例只支持普通对象和数组。日期、集合、属性描述符等都需要额外规则，共享内存也未必隔离；不能把几十行递归宣称为无损的通用实现。
