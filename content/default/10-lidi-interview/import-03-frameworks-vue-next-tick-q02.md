# nextTick 和 setTimeout 有什么区别？

## 核心回答

1. nextTick 表达的是等待 Vue 已安排的 DOM 更新刷新完成，setTimeout 表达的是把回调安排到至少指定延迟后的任务中。二者都可能让代码稍后执行，但关联的完成条件不同，不能因为某次都读到新 DOM 就认为可以相互替代。

2. Vue 为了合并同步修改，会把组件更新加入队列。修改显示条件后 await nextTick，再访问模板 ref，是在明确等待这次视图更新；如果先等待再修改，等待的就不是后面那次变化，使用顺序也会影响是否得到目标节点。

3. setTimeout 的零延迟也不是立即执行，还受当前任务、队列和浏览器调度影响。它常常发生在微任务刷新之后，但这是一般事件循环关系，不如 nextTick 清楚表达对 Vue 更新的依赖，固定几十毫秒更容易受设备快慢影响。

4. nextTick 完成不代表浏览器已经把画面显示出来，也不保证过渡动画、图片和字体已就绪。读取某些布局信息可以得到当前布局结果，但如果还会被后续资源改变，需要等待相应事件或持续观察尺寸，而不是把当前结果当最终结果。

5. 我会按需求选：读 Vue 更新后的元素用 nextTick，真正延迟提示或防抖用定时器，逐帧动画用合适的浏览器接口。比如新增聊天消息后滚动需要先等列表更新，但图片消息继续增高时还要有后续定位策略，不能只靠一个零延时解决全部情况。

## 追问：nextTick 一定比 setTimeout 更快吗？

1. 它们的设计目标不是速度比较。nextTick 通常随着 Vue 的微任务刷新处理，而定时器进入后续任务，但主线程工作量、当前是否已有更新和浏览器调度都影响实际时刻，不能承诺某个固定时间差。

2. 选择 nextTick 是因为它描述“Vue 更新完成后”，代码读者能够知道等待原因。若需求是用户停止输入一段时间再查询，即使 nextTick 更早执行也不合适，因为它没有表达防抖需要的时间窗口。

3. 我会避免把调度细节背成绝对执行图，尤其不同版本的历史实现存在差异。验证重点是目标条件是否满足、界面是否正确，而不是依靠本机几次打印证明所有环境中固定先后和性能差距。

## 追问：用 nextTick 之后再 requestAnimationFrame，能保证动画结束吗？

1. 不能，requestAnimationFrame 回调通常在下一次绘制之前运行，它适合安排与画面刷新相关的工作，不代表某个持续数百毫秒的过渡已经结束。组合两个等待 API，也不会自动变成动画完成通知。

2. 如果需要在弹窗进入动画结束后测量或聚焦，可以使用组件库回调或 transition 的完成事件。若只是想让初始样式和下一帧样式分开，requestAnimationFrame 可能有用途，但这与等待整个动画完成是不同需求。

3. 我会测试动画被取消、用户快速关闭和系统减少动画设置等情况，确保后续逻辑不会永远等待或操作已销毁节点。可靠性来自匹配真实完成条件，不是把常见异步 API 按顺序全部串起来。
