# nextTick 和 setTimeout 有什么区别？

## 核心回答

1. `nextTick` 等的是 Vue 已经排好的 DOM 更新刷完；`setTimeout` 是把回调丢到至少那么久之后的任务里。两者都可能让代码稍后跑，完成条件不一样。某次都能读到新 DOM，不能当成可以互换。

2. Vue 为了合并同步修改，会把组件更新推进队列。改完显示条件，`await nextTick`，再访问模板 `ref`，等的就是这一次视图更新。先等待再修改，等的就不是后面那次变化，顺序错了节点可能还没有。

3. `setTimeout(fn, 0)` 也不是立刻执行，还看当前任务、队列、浏览器怎么调度。它常常排在微任务清完之后，这是事件循环的一般关系，不如 `nextTick` 把“等 Vue 更新”说清楚。写死几十毫秒，设备快慢一变就不准。

4. `nextTick` 完了，不等于浏览器已经把画面画出来，也不保证过渡、图片、字体就绪。有的布局信息当时能读到，后面资源一加载高度又变，还得听对应事件或接着观察尺寸。

5. 读 Vue 更新后的元素用 `nextTick`；真要过一会儿再提示、做防抖，用定时器；跟帧走的动画用浏览器那套接口。聊天列表追加消息后滚动，先等列表更新；图片消息继续变高，还要有后面的定位办法，一个零延时包不住。

## 追问：nextTick 一定比 setTimeout 更快吗？

1. 这两个不是比谁快。`nextTick` 通常跟着 Vue 的微任务刷新走，定时器进后面的任务。主线程忙不忙、这一轮有没有更新、浏览器怎么排，都会改实际时刻，没有固定时间差可以承诺。

2. 用 `nextTick` 是因为它说的是“Vue 更新完了”，读代码知道在等什么。需求是人停手一段时间再查询，就算 `nextTick` 更早跑也不合适，它没有那段防抖窗口。

3. 调度细节别背成绝对执行图，历史版本实现也不完全一样。验证看目标条件满不满足、界面对不对，别拿本机几次 `console.log` 证明所有环境都是这个先后和这个性能差。

## 追问：用 nextTick 之后再 requestAnimationFrame，能保证动画结束吗？

1. 不能。`requestAnimationFrame` 一般在下一次绘制前跑，适合跟画面刷新绑在一起的工作，不等于持续几百毫秒的过渡已经结束。两个等待 API 串起来，不会自动变成动画完成通知。

2. 弹窗进入动画结束后再测量或聚焦，用组件库回调或 `transition` 的完成事件。只是想让初始样式和下一帧样式分开，`requestAnimationFrame` 可能有用，那是另一件事。

3. 动画被取消、人很快关掉、系统开了减少动画，这些都要测。后续逻辑别永远等，也别操作已经没了的节点。对上真实完成条件才稳，不是把常见异步 API 按顺序全串一遍。
