# 多个 v-model 怎么写？

## 核心回答

1. Vue 3 可以在同一个组件上声明多个带参数的 v-model，例如分别绑定 title 和 visible。每一个名字对应独立的 prop 与更新事件，title 对应 title 和 update:title，visible 对应 visible 和 update:visible，父组件分别持有这两份状态。

2. Vue 3.4 及之后，可以在子组件里用 defineModel 声明具名模型，得到便于读写的 ref。较早的 Vue 3 项目则显式声明 props 和 emits；两种方式表达同一个通信约定，不需要为了使用多个模型强行升级现有项目。

3. 比如编辑弹窗接收是否打开和标题草稿，点击关闭只发出 visible 的更新，输入标题只更新 title。这样父组件可以分别决定两种变化，而不是子组件每次变化都构造一个不透明的大对象，让父级猜哪些字段被改了。

4. 多模型适合相对独立、确实需要双向绑定的值，不代表所有组件参数都要做成 v-model。禁用状态、最大长度等通常是单向配置；“点击保存”是动作，应该通过明确事件表达，不应伪装成某个布尔值变化让父组件间接猜测。

5. 如果多个字段必须一起校验或原子提交，也可以使用一个明确的草稿对象与提交事件。选择时看父组件是否需要逐字段同步，避免把开始日期和结束日期拆成独立模型后短暂出现无效范围，又靠很多监听器互相修正。

## 追问：多个 v-model 和传一个 form 对象有什么取舍？

1. 多模型让每个字段的输入输出更明确，父组件可以单独监听和绑定，适合标题与打开状态这类相对独立的值。但字段很多时接口会变长，调用者需要管理许多参数，未必比一个结构化对象清楚。

2. 一个 form 模型适合表达完整草稿，尤其多个字段需要一起替换时。子组件更新应构造新对象并发出更新事件，不能因为拿到的是对象就直接改深层字段，让父级绕过预定事件被悄悄修改。

3. 我会看提交和取消语义：实时编辑器可能希望逐项同步，而需要确认后才生效的弹窗应保留本地草稿。不要只从“写起来短”选择模型数量，应确保父级能区分正在编辑和已经保存的数据。

## 追问：父组件没有给某个模型初值，会有什么风险？

1. 子组件若声明了默认值，父组件对应值却是 undefined，初始阶段两边可能不一致。例如子组件内部数量默认一，但父级提交时读取的仍是空值，不能认为 defineModel 的默认值一定已经自动同步到父级。

2. 我会优先在拥有状态的父组件给出明确初值，并为必需的模型声明约束。可选模型则应说明缺省时行为，例如不受控内部状态还是等待父级赋值，不能一边按默认值显示，一边又要求父级随时掌握同一内容。

3. 测试应覆盖未传值、显式空值和之后异步赋值，并检查更新事件是否符合预期。接口定义越明确，越不需要靠 mounted 时主动发一遍更新来修补双方初始化不同的问题。
