# 智能文本检索与源码接入验证

2026-09-07，任务分支 `codex/complete-smart-retrieval`，基于上游 `511421d`。

## 已实现

- 移除内置语音采集、转写接口及相关实现，豆包输入法、键盘、粘贴统一走文本输入。
- 输入稳定 800 ms 自动查全部当前用户题库，支持输入法 composition、Enter、暂停、取消和过期响应保护。
- 标题/别名完整匹配直接返回；词项与原检索融合召回，语义核对最多 16 条候选，覆盖不足自动流式生成。
- 题内追问自动定位；候选首项与用户已确认上下文分离，模型只在追问时继承上下文。
- 服务启动时加载两个项目索引，语义阶段产生项目范围及源码查询词，生成收到真实片段与文件行号。
- 普通布局、横屏工作台显示来源片段；停止或失败不会把半截答案标为完整回答。
- `npm run projects:setup` 下载缺失的已配置仓库，不覆盖已有目录；API 只使用服务器定义的用户资料和项目。

## 验证边界

最终检查：`npm test` 69/69，通过；`npm run test:e2e` 8/8，通过；`npm run build` 通过（保留现有整库包体积警告）；`git diff --check` 通过。

单元/API/检索评测和浏览器测试使用模拟模型，不消耗真实模型额度。24 条固定中文评测只检查主题是否进入前 16 个候选，不等于回答正确率；语义选择仍需模型核对。

当前机器没有 `.env.local` 或 `OPENROUTER_API_KEY`。实际本地 `/api/resolve` 的无 Key 精确命中请求返回 HTTP 200；需要模型的问题返回 HTTP 503 和配置说明。**未完成真实 OpenRouter 联调，不能据此声称真实语义选择、生成质量或首字延迟已通过。**

配置 Key 后需真实验证至少：一个口语题库命中、一个轻购源码问题、一个城市视图源码问题，并检查回答引用是否支持结论。在 `.env.local` 设置 `OPENROUTER_API_KEY` 后运行 `npm run dev`；不应把 Key 提交到仓库。

已知限制：模型可能遗漏候选或错误解读代码，源码检索有数量与长度上限，静态站点仍需要 Node API 服务；构建现有整库前端包仍有体积警告。用户 ID 过滤不是登录鉴权，公开部署需入口访问控制。
