# 面试话术库

面向前端实习面试的 AI 题库检索工具。问题和答案使用 Markdown 管理；输入面试官的完整问题后，用本地语义向量与关键词混合检索现有回答，没有明确匹配时再结合源码生成。

## 开发

需要 Node.js 24+。

```bash
npm install
cp .env.example .env.local
# 查题无需 Key；需要生成答案时填写 DEEPSEEK_API_KEY
npm run dev
```

`npm run dev` 同时启动 Vite 和本地 API（默认 `127.0.0.1:3001`），网页通过 Vite 的 `/api` 代理访问后端。修改 Key 或模型后重启命令。已有 `.env.local` 时直接编辑，不要覆盖。

生产运行：`npm run build && npm start`，由 Node 服务同时提供 `dist` 页面与 API。单独发布静态 `dist` 不会提供检索和 AI 接口；部署时需要保留 `server`、`src`、`content` 和运行依赖，或将 `/api` 反向代理至该服务。

## 自动查题与回答

直接在普通输入框输入或粘贴完整问题。关键词候选即时更新；输入稳定 800 ms 后，在当前用户的全部题库中做本地语义检索。Enter 立即提交；中文输入法选词期间不发送请求。没有语音入口、暂停/立即查找工具栏。

标题/别名精确匹配直接返回；其余问题使用中文 BGE-small-zh-v1.5 的量化向量与词项召回进行 RRF 融合，包含题内追问。明确提到的框架和项目约束候选范围。两路检索一致且差距足够时打开现有回答；不确定时显示相近题目供选择，候选不合适可点击「这些都不符合，生成补充回答」。没有明确相关候选或需要跨项目比较时，使用源码片段调用 DeepSeek V4 Flash 流式生成（关闭思考模式）。相似度是启发式指标，不能当作答案正确概率，口语改写仍可能漏召回。

语义模型在 Node Worker 中使用 CPU 运行，不需要云端 Key。首次启动需从 Hugging Face 下载模型并建立所有用户的题库向量，耗时取决于网络和机器；期间可使用关键词候选，不自动调用付费模型。缓存保存在忽略提交的 `.cache/semantic`，后续启动复用；题库变化后重启会按内容哈希重建。需要可写缓存目录及下载网络（Node 支持时使用环境代理），下载失败会提示本地语义不可用。模型只下载到服务端，不进入网页包。

切换用户、编辑、清空或点选候选会取消旧任务。已确认题目才作为上下文，简短承接式追问才继承上下文，搜索第一名不会自动成为上下文。停止生成保留已收到的片段并标注不完整。AI 回答不会写入题库。普通布局和横屏工作台都能查看源码片段、相对路径、行号和索引版本；召回片段不等于模型已引用，模型引用使用 `[S1]` 等标记。

## 接入两个项目

`config/projects.json` 将原作者的两个公开仓库只读关联至 `default`（牛）：

- [轻购 mobile-shop](https://github.com/imeelinew/mobile-shop)：默认 `../mobile-shop`
- [城市视图 datapilot-rebuild](https://github.com/imeelinew/datapilot-rebuild)：默认 `../datapilot-rebuild`

首次部署可执行 `npm run projects:setup` 下载缺失仓库（已有目录只验证来源，不覆盖或更新）；也可以自行克隆后修改 `root`。`PROJECTS_CONFIG` 可指定另一份服务端配置，`root` 相对 Copilot 根目录解析。新机器需提供这些目录，静态网页无法自行读取你的电脑源码。源码不会复制进前端包，也不安装或执行项目的依赖。

索引仅扫描 Git 已跟踪文本文件，排除隐藏文件、依赖、构建目录、锁文件、符号链接及常见密钥文件，并对常见内联凭据脱敏。每个项目最多 2000 个文件、单文件 512 KiB、总输入 20 MiB；返回的状态包含实际文件数和跳过项，并不代表完整仓库审计。源码片段最多返回 6 条；多项目比较保留各项目候选。源码以当前工作区为准，修改/删除在下次请求中刷新（检查间隔 3 秒）。不要把未审核的私密仓库加入配置。

`GET /api/projects?userId=default` 查看索引状态；Aaron 请求不会取得这两个项目的状态或片段。用户 ID 是资料过滤条件，不是登录鉴权。公开部署应在入口层做访问控制。

**启动检查**：请使用 `npm run dev` 同时运行网页和 API。单独运行 `npm run dev:web` 只启动网页；若已有网页服务，可另运行 `npm run dev:api`。页面会提示后端未连接、语义索引准备中或不可用；未配置 Key 时本地查题仍可用，只有生成才提示配置。配置 `.env.local` 后重启 API；`/api/health` 返回 `configured: true` 仅表示已读取 Key，实际有效性还需发起一次真实问题请求。

服务端变量：`AI_PROVIDER`（deepseek/openrouter）、`DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`（默认 `deepseek-v4-flash`）、`OPENROUTER_API_KEY`、`OPENROUTER_ANSWER_MODEL`、`API_PORT`（3001）、`API_HOST`（127.0.0.1）、`ALLOWED_ORIGINS`（额外允许来源，逗号分隔）、`PROJECTS_CONFIG`。均不使用 `VITE_` 前缀。先读取 `.env.local` 再读取 `.env`，进程环境变量优先。修改配置后重启服务。

## 内容格式

题库位于 `content/<用户 ID>/`。每道问题对应一个 Markdown 文件，主要字段包括：

- `id`：用户题库内唯一的题目 ID（必填）
- `title`：标准问题（必填）
- `aliases`：面试官可能采用的其他问法
- `category`：所属分类
- `projects`：关联项目
- `keywords`：用于召回的关键词
- `priority`：是否优先复习

项目题统一使用一段核心回答和多条独立追问，每条追问都有可以直接说出口的答案：

```markdown
## 核心回答

第一次被问到时说的简短回答。

## 追问：为什么这样设计？

只回答这个追问，说明具体原因。

## 追问：请求失败怎么办？

讲清实际处理方式，尚未实现的改进要明确说明。
```

追问标题必须非空且在本题内唯一，答案不能留空。不要把实现细节和长篇补充堆进核心回答，也不要只列追问而不写答案。`代码证据` 可作为核对来源。

界面默认显示核心回答，底部列出各条追问入口，一次点击直接打开对应答案。顶部固定的「追问速查」可以随时切换，支持按本题的追问标题和回答正文筛选；切换题目会回到核心回答并清空筛选。核心与追问不会同时展示，代码参考默认折叠。全局搜索也能匹配追问标题，中文和拼音都可以直接输入，例如 `qinggou` 会找到「轻购」，命中的中文会在列表和当前题目标题中高亮。

旧题的 `30 秒回答`、`标准回答`、`深入回答`、`展开回答`、`回答要点` 和 `面试官可能追问` 仍可读取。旧展开内容放在追问区的「补充说明」中，尚未配答案的旧追问会单独折叠显示。

## API 与外部 Agent

自动流程使用内置 `POST /api/resolve`，请求 `{ "question": "问题", "userId": "default", "contextQuestionId": "可选已确认题目ID" }`。服务端验证用户并从仓库取资料，不接受客户端提供的源码或个人经历。

命中返回 JSON `{ "kind": "library", "match": { "questionId": "...", "followupIndex": 0 } }`；不确定返回 `{ "kind": "candidates", "candidates": [], "reason": "说明" }`；生成返回 SSE，先发送 `{ sources, projects }`，然后发送 OpenAI 兼容 `choices[0].delta.content` 和 `[DONE]`。本地模型加载失败降级为关键词候选，不把失败当作无匹配。模型 Key 仅保留在服务端。

`/api/answer` 保留为直接生成 API，页面统一使用内置 `/api/resolve`。`VITE_AGENT_ENDPOINT` 不参与当前页面查题，不能用它代替服务端模型配置。

## 质量检查

```bash
npm test
npm run build
npx playwright install chromium  # 首次运行浏览器测试
npm run test:e2e
```

测试使用 Node.js 24 的原生 TypeScript 支持，覆盖题库与用户隔离、自然语言候选、语义分流、源码过滤和更新、流式解析与取消。浏览器测试模拟 API，验证稳定输入、输入法、取消、证据展示和两种布局，不消耗 API 额度。

可运行 `node scripts/evaluate-semantic.mjs` 做真实本地向量检索的探索性评测（首次需要下载模型），报告前 3 候选命中和单次耗时。报告包含失败样例，不是回答准确率或云端模型验证。

## 多用户题库（仓库维护）

用户列表和题库随网站一起发布，不依赖浏览器保存题目。点击右上角头像切换用户；任何浏览器访问**同一次部署**都能看到相同的用户和题库，无需登录或服务器数据库。

```text
content/
  users.json                 # 固定用户列表，id 对应下面的目录名
  default/                   # 用户「牛」，保留原有 137 道题
    00-profile/...
    01-html-css/...
  aaron/                     # 用户「Aaron」，122 道非项目题和 215 道自己的项目题
```

### 添加用户和题目

1. 在 `content/users.json` 添加用户，例如 `{ "id": "xiaoli", "name": "小李", "projects": [], "identityMarkers": [] }`，并补充该用户的项目和专属标记。ID 必须唯一，只用小写字母、数字、连字符或下划线，不要随意修改已有 ID（它也是本地收藏的关联键）。
2. 创建 `content/xiaoli/`，把该用户的 Markdown 题目放进去，可按分类建立子目录。空目录可放 `.gitkeep`。
3. 运行 `node --test tests/*.test.mjs` 和 `npm run build` 检查格式、重复 ID 和归属。
4. 提交文件并重新部署网站。只推送分支或创建 PR 并不会必然更新线上网站，取决于部署配置。

例如给 Aaron 新增一道题，创建 `content/aaron/react-state.md`：

```markdown
---
id: react-state
title: React 中如何更新状态？
category: react
keywords: [状态, setState]
---

## 核心回答

通过状态更新函数提交新值，避免直接修改已有状态对象。
```

题目 ID 在同一用户内不能重复，不同用户可以相同。未在用户列表中登记的目录不能放题目。修改或删除题目直接编辑对应文件，再重新部署即可。用户名称取自 `users.json`，旧浏览器数据不会覆盖它。

`users.json` 的 `projects` 声明该用户的项目名称，`identityMarkers` 声明专属身份、网站或代码路径等标记。题目的项目标签必须属于当前用户；正文、别名和代码证据也不能包含其他用户的项目或身份标记。添加用户时一并维护这些字段，复制题目时逐段检查个人经历。构建前、加载题库和迁移导入都会执行归属检查，导入失败时不会写入文件。

通用技术题使用普通示例，不把别人的项目实践改名后当成自己的经历。两人讨论相同知识点是允许的，题目 ID 仍按用户独立管理。个人资料没有依据时不补写学校、奖项、网站或工作经历。此校验检查已登记的标记，不能代替对个人经历真实性的人工核对；它也不提供登录或访问控制。

追问既可以写成某道题内的 `## 追问：...` 小节，通过「追问速查」查看；也可以像 `content/aaron/05-projects/*/followups/` 一样拆成独立题目，并在标题前加 `追问：`。独立追问题会作为单独的搜索结果和复习项，不会归入另一道题的追问面板。

### 迁移旧版本地题库

网页不再提供本地新建用户和导入入口，以免把本地数据误认为已发布的题库。旧数据不会被删除：在原浏览器、原网站地址打开新版，会显示「导出旧数据」，下载 JSON 备份。

使用 Node.js 22.18+，先查看备份内的用户：

```bash
node scripts/import-local-bank.mjs ~/Downloads/interview-local-backup.json
```

再把指定用户导入已配置的仓库用户（下面的 `旧用户ID` 用上一步输出替换）：

```bash
node scripts/import-local-bank.mjs ~/Downloads/interview-local-backup.json 旧用户ID aaron
```

工具把原始 Markdown 写入 `content/aaron/imported/`，导入前检查格式和重复 ID，不覆盖已有文件；迁移不自动提交或发布。**请检查题目内容后再提交，不要把整份 JSON 备份提交到仓库。**如果旧浏览器已经清理了数据，需要从原始 Markdown 文件恢复。

### 保存范围

- 用户和题库：来自仓库，随网站发布，跨浏览器可见。
- 当前选择和收藏：只保存在本浏览器，按稳定的用户 ID 隔离；默认用户继承旧收藏。
- 旧版本地题目：只提供备份导出，需主动迁移后才能跨浏览器访问。

所有随网站发布的题库均可被访问，此方案不提供隐私访问控制，不适合存放私密资料。

Agent 请求携带 `question`、`userId`、`userName` 和可选的 `contextQuestionId`。内置服务端按用户从仓库选择上下文，前端不会上传整份题库；切换用户会取消尚未完成的请求。

用户隔离与迁移测试（Node.js 22.18+）：

```bash
node --test tests/*.test.mjs
```

### 横屏工作台

点击顶部「横屏工作台」进入集中复习布局，支持至少 `667×360` 的横向视口。竖屏点击后显示提示，旋转到合适尺寸会自动进入；返回普通布局或旋转设备不会清除当前用户、分类、搜索、主问题及工作台追问选择。刷新后恢复普通布局。横屏手机可点击左侧窄栏展开题库分类。

顶部主问题保持不变，点击右侧已整理追问切换回答，使用「返回核心回答」恢复。答案、分类、题目及追问列表独立滚动。代码依据直接显示在右上角盒子内，随当前回答变化并重置滚动位置，长内容可独立滚动；这里只展示现有说明、路径和行号，不访问本机源码。「待整理」仅为尚无答案的提示。

主问题 frontmatter 可增加可选字段：

```yaml
followupIds: [same-project-followup-id, another-followup-id]
```

关联目标必须存在于**同一用户题库**、标题以 `追问：` 开头且有核心回答；不能自关联或重复。构建和测试会校验这些规则。显式关联按数组顺序显示，然后追加题内 `## 追问：...`。关联追问使用自身代码依据，题内追问沿用主问题依据。同一追问可被多个主问题复用；只有规范化后标题完全一致的待整理提示会去重。

Aaron 的项目关联写在各项目 `normal/` 元数据中，覆盖现有 95 道 `followups/` 独立追问题。维护时按设计原因、具体实现、异常及安全边界、验证的顺序组织，并运行 `npm test` 和 `npm run build`。原有题库保护测试仅豁免本次新增的关联字段，原始元数据和答案仍按原始哈希校验。
